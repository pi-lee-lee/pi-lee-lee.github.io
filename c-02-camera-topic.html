컨테이너에서 영상 토픽 — libcamera 와 camera_ros

호스트에서 동작하는 카메라를 컨테이너의 ROS 2 노드(camera_ros)가 열어 /stereo/left/image_raw 를 발행하게 한다. 넘어야 할 것은 둘이다. 장치 파일을 컨테이너에 전달하는 것과, libcamera 를 호스트와 같은 판으로 컨테이너에 빌드하는 것이다. 이 가이드에서 시간이 가장 오래 걸리는 쪽이다(이미지 빌드 20 ~ 40 분).

이 쪽이 끝나면 보이는 것
  • 컨테이너 안에서 /dev/video* · /dev/media* · /dev/dma_heap 이 보인다.
  • 컨테이너의 libcamera 가 호스트와 같은 판으로 빌드되어 cam -l 에 imx708 두 대가 나온다.
  • camera_ros 가 빌드되고, 패키지 rpi5_vision 의 런치 파일 하나로 카메라 노드가 뜬다.
  • /stereo/left/image_raw 가 30 fps(주기 33 ms), 인코딩 bgr8, 프레임 id stereo_left_optical_link 로 발행되고 Foxglove 에 영상이 보인다.

필요한 것 — C1 에서 정한 센서 모드와 렌즈 위치 값, 학습 단계 02 의 컨테이너 이미지.

환경Pi 호스트 컨테이너 벤치
선행C1, 학습 단계 02
만드는 것docker/Dockerfile 의 libcamera 블록, ros2_ws/src/drivers.repos, 패키지 ros2_ws/src/rpi5_vision(런치 · 설정 파일)
적는 곳없음

1. 개요

컨테이너 안의 경로는 이렇다. 아래 두 층은 호스트 커널의 것이고, 위 두 층을 이 쪽에서 만든다.

컨테이너   camera_ros 노드  ──►  /stereo/left/image_raw · /stereo/left/image_raw/compressed · /stereo/left/camera_info
컨테이너   libcamera (Raspberry Pi 판, 소스 빌드 — 호스트 패키지와 같은 태그)
호스트     커널 드라이버 imx708 · PiSP
호스트     /dev/media*  /dev/video*  /dev/dma_heap   ← compose 의 장치 규칙으로 컨테이너에 연다

이 쪽이 만드는 파일은 넷이다.

파일하는 일
docker/Dockerfile 의 libcamera 블록컨테이너 이미지에 libcamera 를 호스트와 같은 판으로 빌드해 넣는다
ros2_ws/src/drivers.repos외부 소스(camera_ros)의 주소를 적는 파일. vcs import 가 읽는다. 소스 자체는 저장소에 넣지 않는다
rpi5_vision/launch/camera.launch.py카메라 노드를 네임스페이스 stereo, 이름 left 로 띄운다(스테레오의 왼쪽 카메라)
rpi5_vision/config/camera.yaml해상도 · 센서 모드 · 색 형식 · 초점 · 프레임 id. 뒤 쪽은 이 파일만 고친다

2. 원리

2-1. 장치 파일 셋과 장치 규칙

compose 는 /dev 전체를 컨테이너에 마운트한다. 그래도 장치 규칙(device_cgroup_rules — 컨테이너가 쓸 수 있는 장치를 제한하는 리눅스 기능의 설정)에 그 장치의 major 번호가 없으면 열 수 없다.

  • /dev/video* 의 major 는 81 로 고정이다.
  • /dev/media* 와 /dev/dma_heap 의 major 는 커널이 부팅 때 빈 번호에서 골라 주므로 부팅마다 바뀔 수 있다(이 프로젝트의 Pi 에서 media 가 511 · 237 · 238). 그래서 compose 는 번호 대신 docker/.env 의 MEDIA_MAJOR · DMA_HEAP_MAJOR 를 읽고, 그 값은 부팅 때 docker/majors.sh 가 적는다(02 §2-3).
  • /dev/dma_heap 은 카메라 영상 버퍼를 할당하는 장치다. Pi 5 에서 이것이 없으면 libcamera 가 카메라를 열지 못한다. 컨테이너에서만 카메라가 안 보일 때 첫 번째로 의심한다.
  • /run/udev 를 읽기 전용으로 마운트하는 줄도 compose 에 있다. libcamera 가 장치를 찾을 때 쓴다.

2-2. libcamera 를 소스로 빌드하는 이유

  • 컨테이너의 Ubuntu 22.04 가 apt 로 주는 libcamera 는 Pi 5 의 영상 처리기(PiSP)를 모른다. Raspberry Pi 가 관리하는 판을 써야 한다.
  • 호스트 패키지 판 0.7.2+rpt20260817-1 에서 뒤의 -1 을 뗀 v0.7.2+rpt20260817 이 소스 태그다. 태그를 추측해서 넣지 않는다. 호스트 커널 드라이버와 다른 세대의 libcamera 는 카메라를 열지 못한다.
  • libcamera 가 함께 빌드하는 libpisp 도 호스트 판(v1.7.0)으로 맞춘다. 태그의 기본 설정은 v1.5.0 을 가리키므로 빌드 전에 바꾼다.
  • Ubuntu 22.04 의 meson(0.61)은 이 빌드에 부족하다. pip 로 최신 meson 을 넣는다.

2-3. RGB888 을 요청했는데 인코딩은 bgr8 이다

libcamera 의 형식 이름은 32비트 값 안의 순서(R:G:B)로 짓고, ROS 와 OpenCV 는 메모리에 놓이는 바이트 순서로 짓는다. 같은 데이터가 메모리에서는 B, G, R 순서라 ROS 인코딩은 bgr8 이 된다. 버그가 아니고, OpenCV 의 기본 순서와 같아서 C4 에서 변환 없이 쓴다.

2-4. 노드 이름이 토픽 이름을 정한다

camera_ros 는 ~/image_raw 처럼 노드의 전체 이름(네임스페이스 + 노드 이름)을 접두어로 발행한다. 네임스페이스가 stereo, 노드 이름이 left 면 /stereo/left/image_raw 다. 파라미터 파일(YAML)의 맨 위 키도 그 전체 이름(/stereo/left)이어야 한다. 키가 다르면 파라미터가 오류 표시 없이 무시된다.

이 로봇의 카메라는 Camera Module 3 일반 모델 두 대를 좌우로 나란히 둔 스테레오 한 쌍이다. 이 쪽은 왼쪽 카메라(CAM0) 하나만 띄운다. 오른쪽(CAM1, 이름 right)을 함께 띄우는 일은 뒤에 이어지는 스테레오 쪽에서 다룬다.

2-5. 전송량

640 × 480 × 3 바이트 × 30 장 = 초당 약 27 MB 다. 유선이 아닌 Wi-Fi 로는 보내지 못한다. 노드가 JPEG 로 압축한 /stereo/left/image_raw/compressed 를 함께 발행하므로, Mac 의 Foxglove 는 그 토픽을 본다. Pi 안의 노드끼리는 압축 없는 /stereo/left/image_raw 를 쓴다.

3. 실습

3-1. 장치 파일이 컨테이너에 보이는가 Pi 호스트

ls -l /dev/dma_heap/ /dev/media0 /dev/video0
#   쉼표 앞 숫자가 major. video 는 81 고정, 나머지는 부팅마다 바뀔 수 있다
cd ~/ros2_rpi5/docker && ./majors.sh --check
#   ✓ .env 의 major 번호가 지금 값과 같다   ← 다르다고 나오면 ./majors.sh 를 실행한다

cd ~/ros2_rpi5/docker && docker compose run --rm dev ls -l /dev/video0 /dev/media0 /dev/dma_heap/
#   컨테이너 안에서 같은 파일이 보이면 된다

3-2. Dockerfile 에 libcamera 빌드 블록을 넣는다 Mac Pi 호스트

Mac 에서 docker/Dockerfile 을 연다. # ── 4. 비root 사용자 블록 앞에 아래 블록을 넣는다(root 로 설치돼야 한다). 태그 두 개는 C1 §3-5 에서 대조한 호스트 값이다.

# ── 3-C. libcamera (Raspberry Pi fork) built from source — camera guide C2 ──────────
#  Tags must match the host packages (hardware/INVENTORY.md section 4). Re-check after a host upgrade.
ARG LIBCAMERA_TAG=v0.7.2+rpt20260817
ARG LIBPISP_TAG=v1.7.0
RUN apt-get update && apt-get install -y --no-install-recommends \
      python3-jinja2 python3-yaml python3-ply python3-pip \
      libssl-dev openssl libdw-dev libunwind-dev \
      libudev-dev libyaml-dev pkg-config \
      libgnutls28-dev libtiff-dev libevent-dev \
    && rm -rf /var/lib/apt/lists/*

# jammy's apt meson (0.61) is too old for this build; take the current one from pip.
RUN pip3 install --no-cache-dir --upgrade meson ninja

RUN git clone --depth 1 -b ${LIBCAMERA_TAG} \
      https://github.com/raspberrypi/libcamera.git /tmp/libcamera \
 && cd /tmp/libcamera \
 && sed -i "s/^revision = .*/revision = ${LIBPISP_TAG}/" subprojects/libpisp.wrap \
 && meson setup build --buildtype=release \
      -Dpipelines=rpi/vc4,rpi/pisp -Dipas=rpi/vc4,rpi/pisp \
      -Dv4l2=true -Dgstreamer=disabled -Dtest=false -Dlc-compliance=disabled \
      -Dcam=enabled -Dqcam=disabled -Ddocumentation=disabled \
 && ninja -C build install && ldconfig \
 && rm -rf /tmp/libcamera

# camera_ros build/run dependency. Installed in the image: rosdep inside a `docker compose run --rm`
# container installs it into that container only, and it is gone when the container exits.
RUN apt-get update && apt-get install -y --no-install-recommends \
      ros-humble-camera-info-manager \
    && rm -rf /var/lib/apt/lists/*

Pi 로 보내고 이미지를 다시 빌드한다. 빌드 중에는 다른 일을 한다.

# Mac
./scripts/sync-to-pi.sh
# Pi 호스트
cd ~/ros2_rpi5/docker && docker compose build          # 20 ~ 40 분
docker compose run --rm dev cam -l                      # 컨테이너의 libcamera 가 카메라를 보는가
#   Available cameras:            ← 두 대가 다 보여야 한다 (경로 부분은 줄였다)
#   1: 'imx708' (…/i2c@88000/imx708@1a)
#   2: 'imx708' (…)
docker compose run --rm dev find / -name 'imx708.json' 2>/dev/null
#   /usr/local/share/libcamera/ipa/rpi/pisp/imx708.json   ← 튜닝 파일. 없으면 카메라가 열리지 않는다

3-3. camera_ros 소스를 받는다 Mac 컨테이너

Mac 에서 ros2_ws/src/drivers.repos 를 만든다. 이 파일만 저장소에 넣고, 받은 소스는 넣지 않는다.

repositories:
  camera_ros:
    type: git
    url: https://github.com/christianrauch/camera_ros.git
    version: 0.8.1           # tag — pin a tag, not a branch (main moves)
# Mac
echo 'ros2_ws/src/camera_ros/' >> .gitignore
./scripts/sync-to-pi.sh

컨테이너에서 받고 의존 패키지를 확인한다. --skip-keys=libcamera 가 중요하다. 이것이 없으면 apt 의 libcamera 가 설치되어 3-2 에서 빌드한 것과 섞인다. 빌드 · 실행에 필요한 camera_info_manager 는 3-2 의 Dockerfile 블록이 이미지에 넣었다. docker compose run --rm 컨테이너에서 rosdep 이 설치한 것은 컨테이너를 닫으면 사라지기 때문이다.

# Pi 호스트 → 컨테이너
cd ~/ros2_rpi5/docker && docker compose run --rm dev
# 컨테이너 안
cd /ros2_ws
vcs import src < src/drivers.repos
rosdep install --from-paths src --ignore-src -r -y --skip-keys=libcamera

sync-to-pi.sh 는 drivers.repos 에 적힌 이름의 디렉터리를 보내지도 지우지도 않는다. 그래서 Pi 에만 있는 camera_ros 소스가 다음 동기화에서 지워지지 않는다.

3-4. camera_ros 빌드 컨테이너

cd /ros2_ws
export PKG_CONFIG_PATH=/usr/local/lib/aarch64-linux-gnu/pkgconfig:$PKG_CONFIG_PATH
pkg-config --modversion libcamera                      # 0.7.2 가 나와야 한다 (3-2 에서 /usr/local 에 설치됐다)
colcon build --symlink-install --packages-select camera_ros --parallel-workers 2
source install/setup.bash

pkg-config 가 값을 내지 않으면 ldconfig 가 실행됐는지, /usr/local/lib/aarch64-linux-gnu/pkgconfig/libcamera.pc 가 있는지 본다.

3-5. 패키지 rpi5_vision — 런치와 설정 파일 컨테이너

이 가이드의 노드가 전부 들어갈 패키지를 만든다. 지금은 런치와 설정 파일만 있고, C4 부터 C++ 노드가 들어간다.

cd /ros2_ws/src
ros2 pkg create rpi5_vision --build-type ament_cmake --license Apache-2.0
mkdir -p rpi5_vision/launch rpi5_vision/config

rpi5_vision/CMakeLists.txt 를 아래 내용으로 바꾼다.

cmake_minimum_required(VERSION 3.8)
project(rpi5_vision)

find_package(ament_cmake REQUIRED)

install(DIRECTORY launch config
  DESTINATION share/${PROJECT_NAME})

ament_package()

rpi5_vision/package.xml 을 아래 내용으로 바꾼다. 이름과 메일은 자기 것으로 바꾼다.

<?xml version="1.0"?>
<?xml-model href="http://download.ros.org/schema/package_format3.xsd" schematypens="http://www.w3.org/2001/XMLSchema"?>
<package format="3">
  <name>rpi5_vision</name>
  <version>0.1.0</version>
  <description>Camera guide: camera launch, OpenCV node, YOLO detector, overlay</description>
  <maintainer email="you@example.com">you</maintainer>
  <license>Apache-2.0</license>

  <buildtool_depend>ament_cmake</buildtool_depend>

  <exec_depend>camera_ros</exec_depend>
  <exec_depend>ros2launch</exec_depend>

  <export>
    <build_type>ament_cmake</build_type>
  </export>
</package>

rpi5_vision/launch/camera.launch.py:

"""Camera node launch (camera guide C2).

    ros2 launch rpi5_vision camera.launch.py

Namespace 'stereo' + node name 'left' (left camera of the stereo pair) makes the topics
/stereo/left/image_raw, /stereo/left/image_raw/compressed and /stereo/left/camera_info.
The YAML file's top-level key must be the full name /stereo/left.
"""
from launch import LaunchDescription
from launch.substitutions import PathJoinSubstitution
from launch_ros.actions import Node
from launch_ros.substitutions import FindPackageShare


def generate_launch_description():
    params = PathJoinSubstitution([FindPackageShare('rpi5_vision'), 'config', 'camera.yaml'])
    camera = Node(
        package='camera_ros',
        executable='camera_node',
        namespace='stereo',
        name='left',
        output='screen',
        parameters=[params],
    )
    return LaunchDescription([camera])

rpi5_vision/config/camera.yaml. 센서 모드와 렌즈 위치는 C1 에서 정한 값이다.

/stereo/left:                    # must equal namespace + name in camera.launch.py
  ros__parameters:
    camera: 0                    # camera index (CAM0 connector = left)
    width: 640
    height: 480
    format: "RGB888"             # ROS encoding becomes bgr8 (section 2-3)
    sensor_mode: "2304:1296"     # full field of view, 56 fps limit (C1 section 2-2)
    frame_id: "stereo_left_optical_link"
    camera_info_url: ""          # filled in C3
    jpeg_quality: 80             # /stereo/left/image_raw/compressed for Foxglove over Wi-Fi

    # libcamera controls are parameters with the same names
    AfMode: 0                    # 0 = manual focus (C1 section 2-3)
    LensPosition: 0.5            # dioptres: focus at 2 m
    AeEnable: true
    AwbEnable: true
    FrameDurationLimits: [33333, 33333]   # fixed 30 fps (microseconds per frame)

3-6. 빌드 · 실행 · 확인 컨테이너 Mac

cd /ros2_ws
colcon build --symlink-install --packages-select rpi5_vision
source install/setup.bash
ros2 launch rpi5_vision camera.launch.py

기동 로그를 읽는다. 카메라 목록, 형식 목록, 그리고 libcamera 의 Selected sensor format: 2304x1296-... 줄이 보여야 한다. 다른 터미널에서 컨테이너에 하나 더 들어가(docker compose run --rm dev) 확인한다.

ros2 topic list | grep stereo
#   /stereo/left/camera_info   /stereo/left/image_raw   /stereo/left/image_raw/compressed
ros2 topic hz /stereo/left/image_raw                                   # average rate: 30.0 근처
ros2 topic echo /stereo/left/image_raw --field encoding --once         # bgr8
ros2 topic echo /stereo/left/image_raw --field header.frame_id --once  # stereo_left_optical_link
ros2 topic bw /stereo/left/image_raw                                   # 약 27 MB/s
ros2 param get /stereo/left AfMode                                # Integer value is: 0
ros2 param get /stereo/left LensPosition                          # Double value is: 0.5
ros2 param get /stereo/left sensor_mode                           # String value is: 2304:1296

Mac 의 Foxglove 에서 Image 패널을 추가하고 토픽을 /stereo/left/image_raw/compressed 로 고른다. 패널 설정의 전송 품질(QoS)을 Best Effort 로 둔다. 카메라 앞에서 손을 흔들어 영상이 움직이는지 본다.

카메라 노드는 이 뒤의 모든 쪽에서 이 명령으로 띄운다

ros2 launch rpi5_vision camera.launch.py — C3 이후 쪽은 이 노드가 떠 있다고 전제한다. 카메라는 한 프로세스만 열 수 있으므로 호스트의 rpicam 명령을 쓸 때는 이 노드를 먼저 끝낸다(Ctrl-C).

3-7. (선택) 좌표 트리에 연결되는가 컨테이너

학습 단계 05 를 끝냈으면 로봇 형상(URDF)을 발행하는 런치를 함께 띄워, 프레임 id 가 좌표 트리에 이어지는지 본다. 이 가이드의 나머지 쪽은 이 확인 없이 진행된다.

ros2 launch rpi5_description description.launch.py use_fake_joints:=true   # 다른 터미널
ros2 run tf2_ros tf2_echo base_link stereo_left_optical_link                     # 값이 나오면 트리에 이어진 것

평행이동 값은 아직 뜻이 없다. 카메라가 차체에 달려 있지 않기 때문이다. 여기서 보는 것은 이름이 맞아 트리에 이어졌는가 하나다.

🤔 이해 확인

이 쪽에서 설명한 내용만으로 답할 수 있다. 답을 펼치기 전에 먼저 말로 답해 본다.

1. 호스트에서는 카메라가 보이는데 컨테이너에서만 안 열린다. 가장 먼저 의심할 것은 무엇인가.

/dev/dma_heap 이 컨테이너에 전달되지 않은 것이다. Pi 5 는 카메라 버퍼를 이 장치로 할당한다. major 번호가 부팅 때 배정되므로 compose 의 장치 규칙이 이번 부팅의 값(.env 의 DMA_HEAP_MAJOR)을 써야 한다.

2. 설정에 format: RGB888 을 줬는데 인코딩이 bgr8 로 나온다. 버그인가.

아니다. libcamera 는 32비트 값 안의 순서로, ROS 와 OpenCV 는 메모리의 바이트 순서로 이름을 짓는다. 같은 데이터가 메모리에서는 B, G, R 순서라 bgr8 이 맞다. OpenCV 의 기본 순서와 같아서 C4 에서 변환 없이 쓴다.

3. 노드를 네임스페이스 stereo, 이름 left 로 두는 이유는 무엇이고, 설정 파일에는 어떤 영향이 있는가.

camera_ros 는 노드의 전체 이름을 접두어로 토픽을 발행하므로 stereo · left 여야 /stereo/left/image_raw 가 된다 — 스테레오 한 쌍의 왼쪽이라는 구조가 이름에 드러난다. 파라미터 YAML 은 맨 위 키를 노드의 전체 이름과 맞춰 적용하므로 키도 /stereo/left: 여야 한다. 어긋나면 오류 표시 없이 무시된다.

4. Mac 의 Foxglove 가 압축 없는 영상을 받으면 왜 끊기는가. 해법은 무엇인가.

640 × 480 × 3 바이트 × 30 장 = 초당 약 27 MB 라 Wi-Fi 의 전송량을 넘는다. 노드가 직접 발행하는 /stereo/left/image_raw/compressed(JPEG)를 보면 10 ~ 20 배 줄어든다. Pi 안의 노드는 압축 없는 토픽을 그대로 쓴다.
