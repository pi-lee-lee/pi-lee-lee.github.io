C++ 로 ROS 2 노드를 쓰는 패턴 모음

04·06·07·08a·08b·10 단계에서 반복해서 쓰는 rclcpp 패턴을 한 곳에 모았다. 각 패턴은 그대로 복사해서 쓸 수 있는 형태이고, 그 아래 한두 줄로 왜 그렇게 쓰는지를 붙였다. 단계 페이지에서 "부록 A 참조"라고 나오면 여기다. 처음부터 끝까지 읽는 문서가 아니라 필요한 절을 찾아 보는 문서다.

이 부록의 쓰임

ROS 2 Humble(rclcpp 16.x, Ubuntu 22.04 컨테이너) 기준이다. Jazzy 이후에는 일부 헤더 확장자(.h → .hpp)와 멤버 함수가 달라진다. 이 문서의 코드는 04 단계의 rpi5_hello_cpp 처럼 ament_cmake 패키지 안에서 빌드하는 것을 전제로 한다. C++ 문법 자체는 ROS 에 필요한 만큼만 다룬다(§1).

1. ROS 를 위한 C++ 최소 문법

rclcpp 코드가 낯설게 보이는 이유의 대부분은 ROS 가 아니라 현대 C++ 관용구 때문이다. 아래 열 가지만 알면 단계 페이지의 코드를 전부 읽을 수 있다.

1-1. std::shared_ptr 와 ::SharedPtr 관례

#include <memory>

auto node = std::make_shared<MyNode>();            // 힙에 만들고 참조 카운트로 수명 관리
rclcpp::Publisher<std_msgs::msg::String>::SharedPtr pub_;   // = std::shared_ptr<Publisher<...>>
sensor_msgs::msg::Image::ConstSharedPtr msg;        // = std::shared_ptr<const Image>
std_msgs::msg::String::UniquePtr m;                 // = std::unique_ptr<String> (소유권 이전)

ROS 2 의 거의 모든 타입은 T::SharedPtr, T::ConstSharedPtr, T::UniquePtr 별칭을 갖는다. 참조 카운트가 0 이 되면 객체가 소멸하므로, 발행자·구독자·타이머는 반드시 멤버 변수로 잡아 둔다(지역 변수면 생성자가 끝나는 순간 사라진다 — 04 단계 이해 확인 2번).

1-2. std::bind 와 람다

// std::bind — 멤버 함수를 콜백으로
timer_ = create_wall_timer(
  1s, std::bind(&MyNode::on_timer, this));

sub_ = create_subscription<std_msgs::msg::String>(
  "hello", 10,
  std::bind(&MyNode::on_msg, this,
            std::placeholders::_1));
// 람다 — 권장. 인자 개수를 틀릴 수 없고 짧다
timer_ = create_wall_timer(
  1s, [this]() { on_timer(); });

sub_ = create_subscription<std_msgs::msg::String>(
  "hello", 10,
  [this](const std_msgs::msg::String & msg) {
    on_msg(msg);
  });

[this] 는 "이 노드 객체를 캡처한다"는 뜻이다. 콜백 안에서 멤버(pub_, get_logger())를 쓰려면 필요하다. std::bind 는 _1 개수를 틀리면 컴파일 에러 메시지가 수백 줄이라 초보에게 불친절하다. 이 가이드는 람다를 기본으로 쓴다.

2. 노드 해부

#include <chrono>
#include <memory>
#include "rclcpp/rclcpp.hpp"

using namespace std::chrono_literals;

class MyNode : public rclcpp::Node
{
public:
  MyNode()
  : Node("my_node")                        // ① 노드 이름 — YAML 파라미터 키와 매칭된다
  {
    // ② 파라미터 선언 → ③ 인터페이스 생성(발행/구독/서비스/타이머) → ④ 초기 로그
    declare_parameter<double>("rate_hz", 10.0);
    timer_ = create_wall_timer(
      std::chrono::duration<double>(1.0 / get_parameter("rate_hz").as_double()),
      [this]() { on_timer(); });
    RCLCPP_INFO(get_logger(), "my_node started");
  }

  ~MyNode() override
  {
    // ⑤ 정리: 모터 정지 프레임 전송, 스레드 join, 파일 닫기 (RAII)
  }

private:
  void on_timer() { /* 주기 작업 */ }

  rclcpp::TimerBase::SharedPtr timer_;    // ⑥ 인터페이스는 멤버로 유지
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);                // --ros-args 를 여기서 파싱한다
  auto node = std::make_shared<MyNode>();
  rclcpp::on_shutdown([node]() { /* Ctrl+C 시 한 번 호출 — 정지 명령 등 */ });
  rclcpp::spin(node);                      // 콜백 루프 (블로킹)
  rclcpp::shutdown();
  return 0;
}

런타임 변경 받기 — add_on_set_parameters_callback

#include "rcl_interfaces/msg/set_parameters_result.hpp"

// 멤버: 핸들을 잡고 있어야 콜백이 유지된다
rclcpp::node_interfaces::OnSetParametersCallbackHandle::SharedPtr param_cb_;

// 생성자 안
param_cb_ = add_on_set_parameters_callback(
  [this](const std::vector<rclcpp::Parameter> & params) {
    rcl_interfaces::msg::SetParametersResult result;
    result.successful = true;
    for (const auto & p : params) {
      if (p.get_name() == "conf_threshold") {
        const double v = p.as_double();
        if (v < 0.0 || v > 1.0) { result.successful = false; result.reason = "0~1"; }
        else { conf_threshold_ = v; }              // ros2 param set 이 여기로 들어온다
      }
    }
    return result;
  });

콜백을 등록하지 않으면 ros2 param set 은 값을 바꾸지만 노드는 생성자에서 읽어 둔 옛 값을 계속 쓴다. 매 콜백에서 get_parameter() 를 다시 읽는 방법(단순, 약간의 비용)도 있다 — 08a 가 그 방식이다.

--params-file 은 노드 이름으로 매칭한다

YAML 의 최상위 키(mcu_bridge:)와 실행 중인 노드 이름이 다르면 에러 없이 통째로 무시되고 기본값이 쓰인다. 런치의 name=, -r __node:=, 생성자의 Node("…") 세 곳 중 무엇이 최종 이름인지 ros2 node list 로 확인한다. 07 단계의 함정 ②가 이것이다.

using GoalHandle = rclcpp_action::ClientGoalHandle<NavigateToPose>;

rclcpp_action::Client<NavigateToPose>::SharedPtr nav_client_;
GoalHandle::SharedPtr goal_handle_;

// 생성자
nav_client_ = rclcpp_action::create_client<NavigateToPose>(this, "navigate_to_pose");

void send_goal(double x, double y, double yaw)
{
  if (!nav_client_->wait_for_action_server(std::chrono::seconds(5))) {
    RCLCPP_ERROR(get_logger(), "Nav2 action server not available — lifecycle active 인가? (09)");
    return;
  }
  NavigateToPose::Goal goal;
  goal.pose.header.frame_id = "map";
  goal.pose.header.stamp = now();
  goal.pose.pose.position.x = x;
  goal.pose.pose.position.y = y;
  tf2::Quaternion q;
  q.setRPY(0.0, 0.0, yaw);
  goal.pose.pose.orientation = tf2::toMsg(q);

  auto options = rclcpp_action::Client<NavigateToPose>::SendGoalOptions();

  options.goal_response_callback = [this](GoalHandle::SharedPtr handle) {
    if (!handle) { RCLCPP_ERROR(get_logger(), "goal rejected"); return; }
    goal_handle_ = handle;                                       // 취소할 때 필요
  };

  options.feedback_callback =
    [this](GoalHandle::SharedPtr, const std::shared_ptr<const NavigateToPose::Feedback> fb) {
      // ⑤ "계획 대비 수행 정도" 가 여기로 들어온다
      RCLCPP_INFO_THROTTLE(get_logger(), *get_clock(), 1000,
        "remaining %.2f m, recoveries %d, t=%.1f s",
        fb->distance_remaining, fb->number_of_recoveries,
        rclcpp::Duration(fb->navigation_time).seconds());
    };

  options.result_callback = [this](const GoalHandle::WrappedResult & result) {
    goal_handle_.reset();
    switch (result.code) {
      case rclcpp_action::ResultCode::SUCCEEDED: RCLCPP_INFO(get_logger(), "arrived"); break;
      case rclcpp_action::ResultCode::ABORTED:   RCLCPP_WARN(get_logger(), "aborted by Nav2"); break;
      case rclcpp_action::ResultCode::CANCELED:  RCLCPP_WARN(get_logger(), "canceled"); break;
      default:                                    RCLCPP_ERROR(get_logger(), "unknown result"); break;
    }
  };

  nav_client_->async_send_goal(goal, options);
}

void cancel_goal()
{
  if (goal_handle_) { nav_client_->async_cancel_goal(goal_handle_); }
}

10. 실행기와 콜백 그룹

  SingleThreadedExecutor (rclcpp::spin 의 기본)
    큐: [scan 콜백][timer][image 콜백(300 ms 추론)][param 서비스] …  ← 한 스레드가 순서대로

① 콜백 그룹 + MultiThreadedExecutor② 워커 스레드 + 최신 프레임 슬롯
구조ROS 가 스레드를 준다. 코드 변경 최소내가 std::thread 를 만들고 콜백은 슬롯에 넣기만
프레임 드롭큐 깊이 1 + busy_ 플래그로 직접슬롯이 하나라 자연스럽게 최신만 남는다
공유 데이터다른 그룹 콜백과 동시에 돌 수 있다 → mutex/atomic 필요슬롯 접근만 mutex
종료실행기가 처리소멸자에서 running_=false; join()
적합대부분의 경우. 08b 의 1단계추론 라이브러리가 자체 스레드를 요구하거나 주기와 무관할 때
 
// ② 워커 스레드 패턴의 핵심
std::mutex mtx_;
sensor_msgs::msg::Image::ConstSharedPtr latest_;
std::thread worker_;
std::atomic<bool> running_{true};

// 구독 콜백: 넣기만 한다 (수 μs)
void on_image(sensor_msgs::msg::Image::ConstSharedPtr msg)
{
  std::lock_guard<std::mutex> lk(mtx_);
  latest_ = msg;                                   // 이전 프레임은 버려진다
}

// 워커: 꺼내서 처리
void worker_loop()
{
  while (running_ && rclcpp::ok()) {
    sensor_msgs::msg::Image::ConstSharedPtr frame;
    { std::lock_guard<std::mutex> lk(mtx_); frame.swap(latest_); }
    if (!frame) { std::this_thread::sleep_for(5ms); continue; }
    process(frame);                                // 여기서 publish 해도 된다 (publisher 는 스레드 안전)
  }
}
// 생성자 끝: worker_ = std::thread([this]() { worker_loop(); });
// 소멸자:    running_ = false; if (worker_.joinable()) worker_.join();
언제 락이 필요해지는가

단일 스레드 실행기에서는 콜백이 겹치지 않으므로 멤버 변수를 그냥 써도 된다(06 의 C++ 브리지에 Python 판의 Lock 이 없는 이유). 스레드가 둘 이상이 되는 순간(MultiThreaded 실행기, 워커 스레드, Reentrant 그룹) 같은 변수를 두 곳에서 읽고 쓰면 데이터 경쟁이다. 플래그 하나면 std::atomic, 구조체·포인터·컨테이너면 std::mutex + lock_guard. 락을 잡은 채로 publish 나 추론처럼 오래 걸리는 일을 하지 않는다.

이 프로젝트에서 쓰는 곳: 04(spin 의 원리), 08a(단일 스레드 캐시), 08b(추론 분리).

11. 라이프사이클 노드와 컴포넌트 (개요)

  unconfigured ──configure──► inactive ──activate──► active ──deactivate──► inactive
        ▲                                                │
        └──────────── cleanup ◄──────────────────────────┘        (어느 상태에서든 shutdown → finalized)

Nav2 의 서버들(controller_server, planner_server, bt_navigator…)은 rclcpp_lifecycle::LifecycleNode 다. 파라미터 로드(configure)와 실제 동작(activate)을 분리해서, 시스템 전체를 정해진 순서로 켜고 끌 수 있게 한다. lifecycle_manager 가 그 순서를 지휘하고 autostart 가 자동으로 activate 까지 올린다. "노드는 떠 있는데 아무것도 안 한다"는 대개 inactive 상태다(09 단계).

ros2 lifecycle list /controller_server        # 가능한 전이
ros2 lifecycle get  /controller_server        # 현재 상태
ros2 lifecycle set  /controller_server activate

컴포넌트는 노드를 공유 라이브러리로 만들어 한 프로세스에 여러 노드를 적재하는 방식이다(프로세스 내 통신으로 이미지 복사를 없앤다). CMake 에 rclcpp_components_register_node(my_lib PLUGIN "ns::MyNode" EXECUTABLE my_node) 한 줄이 추가된다. 이 가이드에서는 쓰지 않는다 — 노드가 프로세스 하나씩일 때 ros2 node list·로그·크래시 격리가 단순해서 학습에 유리하기 때문이다. 10 단계 이후의 최적화 항목이다.
