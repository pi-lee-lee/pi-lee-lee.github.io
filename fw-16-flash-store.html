F16 · 플래시 저장 — 제거됨

이 쪽은 제거됐다 — 하지 않는다

값을 보드의 플래시에 저장하는 기능은 이 로봇에 두지 않는다. 모든 값은 robot_params.h 에 적고 다시 굽는다.

제거됨

F16(내장 플래시 저장)은 쓰지 않는 쪽이다. 번호만 남겨 두었다 — 뒤 쪽의 번호(F17 ~ F20)를 바꾸지 않기 위해서다.

  • 결정: 2026-11-04, 결정 bd
  • 이 쪽에서 만들 코드(nvstore.h · nvstore.c)와 링커의 저장 섹터 예약은 만들지 않는다.
  • 체크 항목이 없다. 진행 현황에서도 세지 않는다.
  • 이전/다음 버튼은 이 쪽을 건너뛴다(F15 → F17).

1. 무엇이었나

PID 게인 셋을 칩 안 플래시의 섹터 7 에 덧쓰기로 저장하고, 부팅 때 되읽는 기능이었다. pid set 으로 바꾼 RAM 값을 리셋 뒤에도 남기는 것이 목적이었다.

2. 왜 제거했나

플래시 저장이 꼭 필요한 경우는 셋이다. 이 로봇은 어느 것에도 해당하지 않는다.

꼭 필요한 경우헤더로 안 되는 이유이 로봇
① 펌웨어가 실행 중에 스스로 만드는 개체별 값(자동 보정 결과 등)빌드할 때 값을 모른다없다 — WT901 보정은 모듈 안에 저장된다(fw-14 의 wt save)
② 리셋 · 전원 끄기를 넘어 남아야 하는 기록(고장 로그 · 리셋 이력)일어나는 순간을 빌드할 때 모른다없다 — 이 쪽은 그 기능이 아니었다
③ 빌드 환경 없이, 같은 바이너리의 여러 대에 다른 값다시 구울 수단이 없다없다 — 한 대이고, Pi 에서 다시 굽는다

남는 것은 편의뿐이었다. 그 편의에 비해 대가가 컸다.

  • 섹터 지우기 한 번이 1 ~ 4 s 걸리고, 그동안 1 kHz 루프가 멈춘다.
  • 그래서 IWDG 와 공존시키는 장치, 안전 규칙 S13(EN 네 핀이 모두 LOW 일 때만 저장), 찢어진 쓰기 대비(레코드 · CRC · 훑기)가 따라왔다.
  • 워치독 예산표에서 가장 긴 행이 이 지우기였다.
  • 게인의 원천이 헤더와 플래시 둘이 되어, 소스를 고쳐 구워도 옛 값이 나오는 경우가 생겼다.

3. 대신 쓰는 방법

  • 시험: 후보 게인은 pid set 으로 RAM 만 바꿔 본다(fw-13). 재플래시가 필요 없다. 리셋하면 지워지므로 시험한 값은 노트에 적는다.
  • 확정: 정한 값은 robot_params.h 에 적고 다시 굽는다. Mac 에서 빌드 → firmware/tools/deploy_pi.sh → Pi 의 ~/firmware/flash.sh.
  • 모든 값(게인 · 보호 문턱 · 안전 임계값)의 원천은 robot_params.h 하나다.

4. 함께 바뀐 곳

  • 워치독 예산표: "섹터 지우기" 행이 없어졌다. 최종판은 fw-19 §3-2 의 (다)에서 확정한다.
  • 안전 규칙 S13: 폐기. 번호는 다시 쓰지 않는다(fw-00 의 규칙 표).
  • DoD-Bench B16: 제거됨. 뒤 행 번호는 그대로다(fw-19).
  • 조립 뒤 튜닝: pid set → 헤더 → 다시 굽기(fw-20).
