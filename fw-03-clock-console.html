Morpho 의 CN12-10(PD8) · CN11-69(PD9) 에도 같은 신호가 나와 있을 수 있다 — UM 의 표 10 과 표 14 가 SB81 · SB82 의 기본 상태를 다르게 적었다(미결). 그래서 그 두 핀에도 선을 꽂지 않는다. 이 쪽의 에코 확인은 점퍼가 아니라 Mac 터미널로 한다.

2. 원리 — 왜 520 인가, 그리고 왜 보드가 제 상태를 출력해야 하는가

  • VOS0 은 펌웨어가 부팅 때마다 설정한다(전압 먼저 → VOSRDY 대기 → 주파수). 전원을 끄면 사라진다. 520 도 VOS0 에서만 된다(VOS1 상한 400).
  • CPU_FREQ_BOOST 는 옵션 바이트다. 도구로 한 번 쓰면 남는다. 공장 기본값은 0 이다(RM0468 Rev 3 표 18). 이 프로젝트는 쓰지 않고 읽기만 한다.
  • 이름이 문서마다 다르다 — 데이터시트 · SYSCFG_UR18 · STM32CubeProgrammer 는 CPU_FREQ_BOOST, 플래시 레지스터와 HAL 은 CPUFREQ_BOOST. 같은 비트다. 이 쪽은 도구 명령에서는 앞의 것, C 코드에서는 뒤의 것을 쓴다.
  • VOS0 에서는 접합 온도 상한이 105 °C 로 내려간다(VOS1~3 은 125 °C — DS 표 13). 책상 위 실온에서는 그 상한까지 여유가 크지만, 조립 뒤 밀폐된 곳에 넣을 때 다시 볼 숫자다.

2-2. 부스트의 대가 — TCM 의 ECC 가 꺼진다

RM0468 은 같은 문장을 세 군데서 되풀이한다 — §2.4(140쪽) "The ECC is always active except when the CPU frequency boost feature is used. In that case the ECC is no more active on TCM RAMs", §4.9.24(FLASH_OPTSR2_CUR bit 2), §12.4.26(SYSCFG_UR18 bit 0 — "no more ECC on I/DTCM"). STM32CubeProgrammer 의 옵션 바이트 설명문도 같은 내용이다.

이것이 이 프로젝트에 해당하는 까닭은 링커 스크립트에 있다. CubeMX 가 만들어 주는 기본 링커 스크립트(STM32H723xG_flash.ld)는 .data · .bss · 힙 · 스택을 전부 DTCMRAM(0x2000 0000, 128 K)에 둔다. 즉 부스트를 켜면 내 변수와 스택이 놓인 바로 그 메모리에서 한 비트 오류를 고쳐 주던 장치가 빠진다. AXI-SRAM · SRAM1/2/4 의 ECC 는 영향이 없다고 읽히지만(문장이 TCM 만 지목한다) 그렇게 명시한 문장은 없다 — 추정.

실수로 들어간 550 은 오류를 내지 않으므로 코드가 아니라 숫자로 확인한다. 굽기 전에는 .ioc 의 RCC.SYSCLKFreq_VALUE=520000000(§3-2-1 ③)을, 구운 뒤에는 배너의 SYSCLK 520000000(§3-2-4)을 본다. 둘 중 하나라도 550000000 이면 고칠 곳은 증상 ↔ 원인 표에 있다.

펌웨어가 부스트 비트를 읽을 이유는 없다 — 비트를 보고 갈라질 코드가 없기 때문이다. 비트의 확인은 실습 A 의 -ob displ 기록으로 한다. 그래서 배너에도 비트 값을 싣지 않는다.

550 이 실수로 들어가면 CPU 만이 아니라 타이머 클럭이 275 MHz 가 되어 뒤 쪽의 분주값(1 kHz(주기 1 ms) 박자, 20 kHz PWM)이 전부 +5.8 % 빨라진다(§2-6). 보드레이트만은 맞는다 — HAL 이 BRR 을 그때의 PCLK1 에서 계산하기 때문이다(§2-7). 그래서 글자가 읽힌다는 것은 클럭이 520 이라는 증거가 되지 않는다.

2-9. 옵션 바이트 — 이 쪽은 읽기만 한다. 같은 구역에 되돌릴 수 없는 비트가 있다

이 프로젝트는 부스트를 쓰지 않으므로 옵션 바이트를 쓸 일이 없다. 쓰는 경우는 하나 — 실습 A 에서 CPU_FREQ_BOOST 가 1 로 읽혀 0 으로 되돌릴 때뿐이다(§3-1-4 의 상자). CPU_FREQ_BOOST 자체는 되돌릴 수 있는 비트다 — TCM ECC 가 꺼지는 것 말고 부작용 서술이 없고, 같은 절차로 0 으로 되돌릴 수 있다(RM0468 §4.9.25).

조심할 것은 그 이웃이다. 옵션 바이트는 _PRG 레지스터들에 새 값을 쓰고 OPTSTART 를 1 로 설정하면 플래시가 현재값(_CUR)과 견주어 다른 것을 한꺼번에 기록하는 구조다(RM0468 §4.4.3). 그래서 _PRG 에 실수로 들어간 이웃 값도 같이 기록된다. 그 이웃에 이런 비트가 있다.

  • ② 쓴 비트가 언제 하드웨어에 적용되는가. RM 은 옵션 바이트 쓰기가 끝나면 _CUR 레지스터로 자동 재적재된다는 것까지만 적었다 → 쓴 뒤(NRST 로 리셋)와 전원을 뺐다 넣은 뒤 두 번 읽어 기록한다.
  • ③ STM32_Programmer_CLI 가 끝난 뒤 코어가 다시 도는가, 멈춘 채인가. 도움말은 연결이 리셋을 일으킨다는 것(NORMAL · SWrst)과 -rst · -run · -halt 가 따로 있다는 것까지만 적었다 → §3-1-4 에서 LD1 을 보고 적는다. 멈춘 채면 NRST 로 복구한다.

옵션 바이트 구역의 쓰기 수명도 DS · RM 에서 찾지 못했다 — 그래서 더욱 쓰기는 "한 번"으로 제한한다.

2-10. reset cause — 플래그는 여럿이 같이 1 이 되고, 지우지 않으면 남는다

배너 셋째 줄의 reset <원인> 은 지금은 참고 정보일 뿐이지만 fw-06 에서 "워치독이 정말 리셋시켰는가"의 유일한 증거가 된다. 원천은 RCC_RSR 레지스터다(RM0468 §8.7.38). 함정이 둘 있다.

하나 — 플래그는 하나만 1 이 되지 않는다. RM0468 표 52(Reset source identification)에서 이 쪽에 필요한 행만 옮기면:

PINRSTF 는 거의 모든 리셋에 같이 1 이 된다(리셋 회로가 NRST 선을 함께 당기기 때문이다 — RM 이 표 위에서 IWDG 를 예로 든다). 그래서 "PINRSTF 가 1 이면 버튼 리셋"이라고 읽으면 전부 버튼 리셋이 된다. 판독은 가장 구체적인 플래그부터 보고 PIN · CPU 를 맨 나중에 본다.

둘 — 플래그는 지우기 전까지 남는다. 전원 인가가 아닌 리셋은 RCC_RSR 을 지우지 않는다. USB 를 꽂아 켠 뒤(POR) 버튼을 누르면 POR 플래그가 그대로 남은 채 PIN 이 추가로 1 이 된다 → 위의 순서로 읽으면 또 POR 이다. 그래서 부팅 때 한 번 읽어 변수에 저장해 두고 곧바로 지운다(RMVF 비트 — HAL 매크로 __HAL_RCC_CLEAR_RESET_FLAGS(), stm32h7xx_hal_rcc.h:7854). 읽고 지우는 곳은 펌웨어 전체에서 한 곳(console_init())이어야 한다 — 두 곳이면 나중에 읽는 쪽은 늘 지워진 레지스터를 읽는다.

이 판독 표는 §3-2-2 에서 전량으로 준다. 레지스터 비트 표이기 때문이다 — 여기가 틀리면 이후 모든 쪽의 "리셋 원인" 판정이 거짓이 된다. 대신 표의 행을 그대로 옮긴 호스트 시험이 같이 있어, 맞는지는 Mac 에서 직접 확인한다.

3. 실습

실습은 둘이다: A 옵션 바이트 읽기만 → B 클럭 트리 · 콘솔 · 배너. 끝자리 번호의 뜻은 전 쪽 공통이다(1 = CubeMX, 2 = 골격, 3 = 채우기, 4 = 굽고 보기) — 해당 없는 걸음은 번호째 건너뛴다. 명령의 경로는 ~/ros2_rpi5/ 부터 적었다 — 어느 디렉터리에서 쳐도 같은 곳을 가리킨다. 이 쪽의 명령은 전부 Mac 에서 돈다.

채울 자리마다 힌트 카드가 있다 — 읽는 순서

골격의 채울 자리에는 TODO(you) [T1] 처럼 번호가 붙어 있고(이 쪽은 T1 ~ T5), 그 주석 안에 번호 걸음이 있다. 먼저 걸음을 보고 직접 써 본다. 막히면 "직접 채우기" 절(§3-2-3)에서 같은 번호의 힌트 카드를 연다. 카드에는 그 자리의 완결 코드와, 그 코드를 줄마다 풀어 쓴 설명이 있다. 칸은 언제나 같다: 할 일 · 완결 코드 · 코드 설명 · 쓰는 API · 흔한 실수 · 확인.

완결 코드는 이 프로젝트의 펌웨어 빌드(링크까지, User/ 경고 0 — fw-05 ~ fw-07 의 완결 코드와 함께, 2026-10-04)를 통과한 코드다. 로그 매크로(T3)의 출력 꼴은 Mac 에서 LOG_NOW_MS() 만 가짜 값으로 바꿔 찍어 확인했다([1234] I app: init done). "흔한 실수" 표의 컴파일러 메시지는 틀린 코드를 같은 툴체인(arm-none-eabi-gcc 14.3.1, -Wall)으로 실제로 컴파일해 받은 글자다. 보드에서 도는 것 — 배너 석 줄 · PIN / POR · LD3 — 은 "굽고 보기"에서 내가 확인한다.

T5 의 ____ 는 카드에도 비어 있다 — 내가 적기 전에는 빌드가 멈춘다(의도된 것). 붙여 넣는 것으로 끝내지 않는다 — 설명을 읽고 줄마다 "왜 이 줄이 여기 있는가"를 말할 수 있게 된 뒤, 카드를 접고 직접 친다.

/* User/Inc/Tools/reset_cause.h - RCC_RSR 을 낱말 하나로 푼다.
 * 순수 로직: HAL 헤더가 없어서 host_tests/ 가 Mac 의 cc 로 빌드할 수 있다. */
#ifndef RESET_CAUSE_H
#define RESET_CAUSE_H

#include <stdint.h>

/* RCC_RSR 플래그 마스크. 비트 위치: RM0468 Rev 3, 8.7.38. 어느 원인이 어느 플래그를
 * 1 로 설정하는가: 표 52. console.c 가 컴파일 때 CMSIS 이름과 같음을 증명한다. */
#define RESET_RSR_CPURSTF    (1UL << 17)
#define RESET_RSR_D1RSTF     (1UL << 19)
#define RESET_RSR_D2RSTF     (1UL << 20)
#define RESET_RSR_BORRSTF    (1UL << 21)
#define RESET_RSR_PINRSTF    (1UL << 22)
#define RESET_RSR_PORRSTF    (1UL << 23)
#define RESET_RSR_SFTRSTF    (1UL << 24)
#define RESET_RSR_IWDG1RSTF  (1UL << 26)
#define RESET_RSR_WWDG1RSTF  (1UL << 28)
#define RESET_RSR_LPWRRSTF   (1UL << 30)

/* rsr   : 부팅 때 플래그를 지우기 전에 한 번 잡아 둔 RCC->RSR 원값
 * 반환  : 정적 문자열 - POR BOR IWDG WWDG LPWR SFT PIN CPU OTHER NONE */
const char *reset_cause_name(uint32_t rsr);

#endif /* RESET_CAUSE_H */

/* User/Src/Tools/reset_cause.c - 순수 로직(HAL 헤더 없음). */
#include "Tools/reset_cause.h"

const char *reset_cause_name(uint32_t rsr)
{
  /* 순서가 중요하다: PINRSTF 는 거의 모든 원인에, CPURSTF 는 모든 원인에 같이 1 이 된다
   * (표 52). 그래서 가장 구체적인 플래그부터 보고 PIN / CPU 는 맨 나중에 본다. */
  if (rsr & RESET_RSR_PORRSTF)   { return "POR";  }
  if (rsr & RESET_RSR_BORRSTF)   { return "BOR";  }
  if (rsr & RESET_RSR_IWDG1RSTF) { return "IWDG"; }
  if (rsr & RESET_RSR_WWDG1RSTF) { return "WWDG"; }
  if (rsr & RESET_RSR_LPWRRSTF)  { return "LPWR"; }
  if (rsr & RESET_RSR_SFTRSTF)   { return "SFT";  }
  if (rsr & RESET_RSR_PINRSTF)   { return "PIN";  }
  if (rsr & RESET_RSR_CPURSTF)   { return "CPU";  }
  if (rsr != 0UL)                { return "OTHER"; }
  return "NONE";
}

/* host_tests/test_reset_cause.c - 벡터는 RM0468 Rev 3 표 52
 * "Reset source identification (RCC_RSR)" 의 행이다. 비트 위치는 8.7.38.
 * 값은 python3 로 계산했다. 예: 1행:
 *   python3 -c "print(hex(sum(1<<b for b in (23,22,21,20,19,17))))"   -> 0xfa0000 */
#include <assert.h>
#include <stdio.h>
#include <string.h>
#include "Tools/reset_cause.h"

static int n_cases;

static void expect(uint32_t rsr, const char *want)
{
  const char *got = reset_cause_name(rsr);
  if (strcmp(got, want) != 0) {
    printf("FAIL rsr=0x%08lx want=%s got=%s\n", (unsigned long)rsr, want, got);
    assert(0);
  }
  n_cases++;
}

int main(void)
{
  expect(0x00FA0000UL, "POR");   /* 1행  전원 인가   : POR PIN BOR D2 D1 CPU */
  expect(0x00420000UL, "PIN");   /* 2행  NRST 핀     : PIN CPU               */
  expect(0x00620000UL, "BOR");   /* 3행  브라운아웃  : PIN BOR CPU           */
  expect(0x01420000UL, "SFT");   /* 4행  SYSRESETREQ : SFT PIN CPU           */
  expect(0x00020000UL, "CPU");   /* 5행  CPURST      : CPU 만                */
  expect(0x10420000UL, "WWDG");  /* 6행  WWDG1       : WWDG1 PIN CPU         */
  expect(0x04420000UL, "IWDG");  /* 8행  IWDG1       : IWDG1 PIN CPU         */
  expect(0x40420000UL, "LPWR");  /* 12행 저전력 가드 : LPWR PIN CPU          */
  expect(0x00080000UL, "OTHER"); /* 10행 D1 의 DStandby 탈출 : D1 만         */
  expect(0x00000000UL, "NONE");  /* 플래그를 지웠고 새로 일어난 일은 없다    */
  /* 끈적한 플래그: 전원 인가 뒤 NRST, 그 사이 아무도 RMVF 로 지우지 않았다.
   * 0x00FA0000 | 0x00420000 == 0x00FA0000 -> 여전히 POR 로 읽힌다. */
  expect(0x00FA0000UL | 0x00420000UL, "POR");
  printf("PASS reset_cause %d cases\n", n_cases);
  return 0;
}

3-2-3. 직접 채우기

  1. 호스트 시험을 먼저 돌린다 — 보드가 없어도 된다. 
    cd ~/ros2_rpi5/firmware
cc -std=c11 -Wall -Wextra -Ih723zg/User/Inc host_tests/test_reset_cause.c h723zg/User/Src/Tools/reset_cause.c -o /tmp/test_reset_cause && /tmp/test_reset_cause
    PASS reset_cause 11 cases 가 나와야 한다. 그 뒤에 일부러 reset_cause.c 의 PIN 줄을 맨 위로 올려 다시 돌려 본다 — 첫 벡터에서 want=POR got=PIN 으로 멈춘다. 이것이 §2-10 의 "하나"다. 되돌려 놓는다.
  2. _write() — 막히면: HAL 의 블로킹 송신은 HAL_UART_Transmit() 이고 넷째 인자가 타임아웃 [ms] 다. 정할 것은 둘이다. ① 타임아웃: 배너 한 줄 80 B 남짓이 460800 8N1 에서 걸리는 시간을 §2-7 의 식으로 계산해 그보다 넉넉히 둔다. ② 실패했을 때 돌려줄 값: len 을 돌려주면 "보냈다"고 거짓으로 답하는 것이고(글자를 버린다), −1 을 돌려주면 C 라이브러리가 stdout 에 오류 표시를 남긴다. 콘솔이 멈췄을 때 나머지 펌웨어가 멈추지 않는 쪽이 어느 것인지로 정한다.
  3. 배너 — printf() 세 번. 클럭 숫자는 상수가 아니라 HAL 의 읽기 함수에서 가져온다. HAL_RCC_GetSysClockFreq() 는 PLL 레지스터를 되읽어 HSE_VALUE 와 곱한다(stm32h7xx_hal_rcc.c:1388 부터). 즉 배너의 숫자는 "레지스터에 실제로 들어간 분주값 × 내가 HAL 에 알려 준 입력 주파수"다. 주파수를 재는 것은 아니다(이해 확인 7번).
  4. stdout 버퍼링 — 생성물의 _isatty() 가 1 을 돌려주므로 newlib 은 stdout 을 줄 단위로 모았다 내보낸다(추정 — 확인법: 줄바꿈 없는 printf("abc") 가 곧바로 보이는가). fw-05 의 프롬프트 > 처럼 줄바꿈 없는 글자를 바로 내보내려면 setvbuf() 로 버퍼링을 끈다. 어디서 부를지는 내가 정한다.
  5. LOG_* 네 매크로와 FW_ASSERT — 다 채운 뒤 app_init() 끝에 LOG_INF("app", "init done"); 한 줄을 넣는다. 출력 모양([<tick_ms>] I app: init done)을 터미널에서 확인한다.
  6. app.c 의 주기 배너 — BANNER_PERIOD_MS 의 ____ 에 초를 정해 적고, app_loop() 에 시각 차 비교 블록을 넣는다(HAL_Delay 없이 — LD1 점멸이 멈추면 안 된다). 임시 장치다 — fw-05 가 ver 명령으로 바꾸면 지운다.
  7. 굽기 전에 한 번 더 — §3-2-1 ③ 의 RCC.SYSCLKFreq_VALUE 가 520000000 인가. 그다음 굽는다(§3-2-4).

힌트 T1 — _write() · 블로킹 HAL 송신으로 len 바이트를 보낸다

할 일 — 부르는 쪽은 내 코드가 아니라 C 라이브러리(newlib)다: printf() 가 모은 글자를 내보낼 때(줄 끝 \n 에서, 또는 fflush() 때) 이 함수를 부른다. 입력: 바이트 묶음의 주소 ptr 와 길이 len(끝에 0 이 없다 — 문자열이 아니라 바이트열이다). 출력: 받아들인 바이트 수. 끝났을 때 참이어야 하는 것: len 바이트가 USART3 으로 나갔거나, 타임아웃 안에 못 나갔으면 버려졌고 — 어느 쪽이든 주 루프는 계속 돈다.

완결 코드

/* 완결 코드 T1 - User/Src/Tools/console.c */
#define CONSOLE_TX_TIMEOUT_MS  100U   /* [ms] 1 kB 를 한꺼번에 보내도 460800 8N1 에서 약 22 ms. 값은 내가 정한다 */

int _write(int file, char *ptr, int len)
{
  (void)file;                        /* stdout 과 stderr 를 가르지 않는다: 둘 다 VCP 로 간다 */
  if (len <= 0) {
    return 0;                        /* 보낼 것이 없다 - HAL 을 부르지 않는다 */
  }
  /* 타임아웃이 있는 블로킹 송신. 실패하면 글자를 일부러 버리고 그래도 len 을
   * 돌려준다: 동작하지 않는 콘솔이 나머지 펌웨어를 멈추게 하면 안 된다. */
  (void)HAL_UART_Transmit(&huart3, (const uint8_t *)ptr, (uint16_t)len, CONSOLE_TX_TIMEOUT_MS);
  return len;
}

코드 설명

  • #define CONSOLE_TX_TIMEOUT_MS 100U — 함수 위에 이름 붙인 상수로 둔다. 100 은 예시 값이다(아래 "다르게 써도 되는 곳"). U 접미는 "부호 없는 정수" — 넷째 인자의 형 uint32_t 와 맞춘다. 이 이름은 fw-07 의 mem 명령이 그대로 가져다 쓴다.
  • (void)file; — "이 인자는 일부러 안 쓴다"고 컴파일러에게 알리는 관용구(-Wextra 의 unused parameter 경고를 막는다). stdout(1)과 stderr(2)를 가르지 않고 둘 다 같은 VCP 로 보낸다.
  • if (len <= 0) { return 0; } — 보낼 것이 없으면 HAL 을 부르지 않는다. HAL_UART_Transmit() 은 Size 가 0 이면 HAL_ERROR 를 돌려준다(stm32h7xx_hal_uart.c:1128 의 검사) — 그 경우를 미리 막는다.
  • (const uint8_t *)ptr — newlib 은 char * 를 주고 HAL 은 const uint8_t * 를 받는다. 같은 바이트지만 형이 달라서 캐스트 없이 넘기면 경고가 난다(아래 표). (uint16_t)len 도 같은 이유(int → uint16_t). 캐스트 = "이 값을 이 형으로 보라".
  • (void)HAL_UART_Transmit(…) — 반환값(HAL_StatusTypeDef)을 일부러 버린다. 실패해도 len 을 돌려주는 것이 이 코드의 결정이다: 터미널이 안 열려 있어도, USART 가 멈춰도, printf() 를 부른 코드는 모른 채 계속 간다. 동작하지 않는 콘솔이 나머지 펌웨어를 멈추게 하면 안 된다.
  • return len; — "다 받아들였다". 골격의 (void)ptr; 는 지웠다(이제 ptr 를 쓴다).

완결 코드

/* 완결 코드 T3 - User/Inc/Tools/log.h */
#define LOG_ERR(tag, fmt, ...)   printf("[%lu] E " tag ": " fmt "\r\n", LOG_NOW_MS(), ##__VA_ARGS__)
#define LOG_WRN(tag, fmt, ...)   printf("[%lu] W " tag ": " fmt "\r\n", LOG_NOW_MS(), ##__VA_ARGS__)
#define LOG_INF(tag, fmt, ...)   printf("[%lu] I " tag ": " fmt "\r\n", LOG_NOW_MS(), ##__VA_ARGS__)
#define LOG_DBG(tag, fmt, ...)   printf("[%lu] D " tag ": " fmt "\r\n", LOG_NOW_MS(), ##__VA_ARGS__)

코드 설명

  • #define LOG_ERR(tag, fmt, ...) — 인자 목록 끝의 ... 가 "그 뒤 인자는 몇 개든"(가변 인자 매크로). 매크로 몸에서 그 인자들은 __VA_ARGS__ 라는 이름으로 나온다.
  • "[%lu] E " tag ": " fmt "\r\n" — 문자열 리터럴 다섯 조각을 나란히 놓았다. C 는 나란히 놓인 문자열 리터럴을 컴파일 때 하나로 잇는다("ab" "cd" 는 "abcd"). tag 와 fmt 자리에 호출자의 리터럴이 글자 그대로 들어오므로 LOG_INF("app", "n=%lu", x) 는 "[%lu] I " "app" ": " "n=%lu" "\r\n" → "[%lu] I app: n=%lu\r\n" 이 된다. printf 는 서식 문자열 하나를 받는다. 그래서 tag 는 반드시 문자열 리터럴이어야 한다(변수를 넣으면 아래 표의 오류).
  • LOG_NOW_MS() — 첫 %lu 에 들어가는 시각. log.h 위쪽에서 이미 (unsigned long) 으로 바꿔 두었다. 이 이름을 거치기 때문에 fw-06 이 시각 원천을 바꿀 때 한 줄만 고친다.
  • , ##__VA_ARGS__ — 핵심 한 줄. 가변 인자가 하나도 없으면 앞의 쉼표를 지우라는 GNU C 확장이다(gcc · clang 둘 다 받는다. 이 프로젝트는 -std=gnu11). 이것이 없으면 LOG_INF("app", "init done") 이 printf("…", LOG_NOW_MS(), ) 로 펼쳐져 쉼표 뒤가 비어 오류다(표). 표준만 쓰는 빌드(-std=c11 -pedantic)는 token pasting of ',' and __VA_ARGS__ is a GNU extension 경고를 낸다 — Mac 의 cc 에서 확인. 이 헤더는 main.h 를 포함하므로 호스트 시험으로는 가지 않는다.
  • 네 줄은 등급 글자(E W I D) 한 글자만 다르다. 골격의 ((void)0) 자리표시는 지웠다 — 그 자리표시는 "아무 일도 안 하는 식"이었다(네 매크로를 쓴 코드가 빌드되게 하려고).

코드 설명

  • 줄 끝의 \ — 매크로는 한 줄이어야 해서, 줄을 바꿀 때마다 \ 로 "다음 줄도 이어진다"고 적는다. \ 뒤에 공백이 있으면 안 된다(표 — 편집기가 끝 공백을 보여 주게 해 둔다). 마지막 줄에는 \ 가 없다.
  • if (!(cond)) — cond 를 괄호로 감싼다. 매크로 인자는 글자 그대로 들어오므로 FW_ASSERT(a == b) 가 !a == b 로 펼쳐지지 않게 한다 — ! 가 == 보다 먼저 묶인다(표).
  • printf("[%lu] E assert: %s:%d\r\n", LOG_NOW_MS(), __FILE__, __LINE__); — 로그 줄 꼴을 따랐다(등급 E, tag assert). __FILE__ 은 이 매크로가 펼쳐진 자리의 파일 이름 문자열, __LINE__ 은 그 줄 번호(int → %d). 그래서 매크로여야 한다 — 함수였다면 늘 log.h 의 줄이 찍힌다. 이 프로젝트의 CMake 는 소스를 절대 경로로 넘기므로 __FILE__ 은 /Users/…/User/Src/app.c 처럼 길다 — 멈춘 상태에서 읽는 줄이라 그대로 둔다.
  • HAL_GPIO_WritePin(LD3_GPIO_Port, LD3_Pin, GPIO_PIN_SET); — LD3_* 두 이름은 CubeMX 의 User Label 에서 main.h 에 생성된다. 이 프로젝트의 생성물에서는 LD3_Pin GPIO_PIN_14 · LD3_GPIO_Port GPIOB 다. log.h 가 main.h 를 포함하므로 보인다.
  • for (;;) { } — 조건이 없는 for 는 끝없는 루프. while (1) { } 과 같다(동일). IWDG 가 없는 지금은 여기서 NRST 를 기다린다. 골격의 ((void)(cond)) 자리표시는 지웠다 — 그 자리표시는 "cond 를 평가만 하고 버린다"였다.
  • 다르게 써도 되는 곳 — ① 찍는 꼴: 파일:줄 만 있으면 된다. 조건식 글자까지 보고 싶으면 #cond(인자를 문자열로 바꾸는 # 연산자)를 %s 로 더한다. 긴 경로를 줄이려면 __FILE_NAME__(경로를 뗀 이름만 주는 GCC 12 이상의 매크로 — 이 툴체인 14.3.1 에서 컴파일되는 것을 확인했다. 출력은 보드에서 본다). ② 순서: LED 를 먼저 켜고 찍어도 된다 — 콘솔이 멈춰 printf() 가 타임아웃까지 걸리는 경우에는 그쪽이 LED 가 빨리 켜진다. ③ 멈추지 않고 돌아오는 ASSERT 는 이 가이드의 뜻이 아니다 — "조건을 한 번 평가하고 늘 켜져 있다"는 성질에 뒤 쪽이 의존한다(fw-15 는 등록 호출 그 자체를 인자로 넣는다).

힌트 T5 — app_loop() · ____ s 마다 배너를 다시 찍는다

할 일 — USB 를 다시 꽂으면 첫 배너를 놓치는 문제(§3-2-2 끝)의 임시 대책. 주 루프가 돌 때마다 "마지막으로 찍은 뒤 ____ s 가 지났는가"를 보고, 지났으면 console_print_banner(). 불변식: 빨리 돌아온다(HAL_Delay() 없음) — LD1 점멸이 멈추지 않는다. fw-05 가 ver 명령을 만들면 이 블록 전체를 지운다.

완결 코드

/* 완결 코드 T5 - User/Src/app.c 의 app_loop() 안 */
#define BANNER_PERIOD_MS   (____ * 1000u)   /* [ms] ____ 에 내가 정한 초를 적는다. 임시 - fw-05 가 지운다 */

void app_loop(void)
{
  /* ... fw-02 의 LD1 점멸은 그대로 둔다 ... */
  static uint32_t banner_last_ms;                        /* 마지막으로 배너를 찍은 시각 [ms], 부팅 때 0 */
  uint32_t banner_now_ms = HAL_GetTick();

  if ((uint32_t)(banner_now_ms - banner_last_ms) >= BANNER_PERIOD_MS) {   /* 부호 없는 차: 한 바퀴 돌아도 맞다 */
    banner_last_ms = banner_now_ms;
    console_print_banner();
  }
}

코드 설명

  • #define BANNER_PERIOD_MS (____ * 1000u) — 주기를 이름으로 둔다. ____ 에 내가 정한 초를 적는다 — 비워 두면 error: '____' undeclared 로 빌드가 멈춘다. 의도된 것이다: 숫자는 가이드가 아니라 내가 정한다.

    값의 기준: 눈으로 배너를 셀 수 있고 터미널을 다시 열 시간이 되면 된다. 배너 석 줄 100 B 남짓은 460800 에서 2 ms 라 주 루프를 거의 멈추게 하지 않는다.

    함수 밖, 파일 위쪽의 #include 들 다음에 둔다. 1000u 의 u 는 부호 없는 곱셈 — uint32_t 와의 비교에 맞춘다.

  • static uint32_t banner_last_ms; — 함수 안의 static 변수는 함수가 끝나도 값을 기억한다(보통의 지역 변수는 돌아올 때 사라진다). 처음 값은 0. fw-02 의 last_ms 와 같은 꼴.
  • uint32_t banner_now_ms = HAL_GetTick(); — 지금 시각 [ms]. fw-02 의 점멸 코드에 이미 now_ms 가 있으면 그 변수를 그대로 써도 된다(동일) — 같은 이름을 한 함수에서 두 번 선언하면 오류라(표) 다른 이름으로 썼다.
  • (uint32_t)(banner_now_ms - banner_last_ms) >= BANNER_PERIOD_MS — 부호 없는 뺄셈이다. 49.7 일에 한 번 카운터가 한 바퀴 돌아도 차는 맞다(fw-02 와 같은 설명). >= 라 정확히 주기에 걸리지 않아도 다음 바퀴에 찍는다.
  • banner_last_ms = banner_now_ms; 다음 console_print_banner(); — 둘의 순서는 어느 쪽이든 된다(배너가 수 ms 라). 갱신 방식은 fw-02 의 완결 코드와 같은 선택이다.
  • 다르게 써도 되는 곳 — ① banner_last_ms += BANNER_PERIOD_MS 로 갱신하면 평균 주기를 지키는 대신, 오래 멈췄다 돌아오면 밀린 만큼 연달아 찍는다. fw-02 와 같은 선택이고, 여기서는 어느 쪽이든 된다. ② 부팅 직후에는 찍지 않는다(app_init() 이 이미 찍었다) — 첫 주기까지 기다리는 것이 이 코드의 동작이다.

쓰는 API — HAL_GetTick(): stm32h7xx_hal.h:1081, __weak uint32_t HAL_GetTick(void) 는 stm32h7xx_hal.c:338. 인자 없음, 반환 [ms] — SysTick 인터럽트가 1 ms 마다 1 올리는 카운터. 어디서든 읽을 수 있다. (HAL_Delay() 는 이 값을 기다리며 도는 함수라 주 루프의 불변식을 깬다.)

2. "H723 은 550 MHz 다"라는 문장에 빠진 것은 무엇이고, 550 을 얻는 대가는 무엇인가?
조건이 둘이다 — 전압 스케일 VOS0 그리고 옵션 바이트 CPU_FREQ_BOOST = 1. VOS0 만으로는 520 MHz 가 상한이다(DS13313 표 12). VOS0 은 펌웨어가 부팅마다 설정하고, 부스트 비트는 도구로 한 번 써 두는 비휘발 설정이다(공장 기본 0). 대가는 ITCM · DTCM 의 ECC 가 꺼지는 것이고, 기본 링커 스크립트에서는 그 DTCM 이 내 변수와 스택이 놓이는 곳이다. 얻는 것은 CPU 와 타이머 분해능 각 +5.8 %. 이 프로젝트는 그 교환을 하지 않는다 — 부스트 0(공장 기본값)을 유지하고 520 MHz 로 돈다(결정 9 개정, 2026-09-29). 판단의 이유로 적힌 것은 "얻는 이득이 없다"이다 — +5.8 % 가 이 MCU 의 부하에서 필요하지 않다는 판단이고, 측정으로 확인한 것이 아니라 결정의 이유다.
3. Clock Configuration 화면의 안내대로 CPU 를 550 MHz 로 올려 생성한 코드를 부스트 0 인 칩에 구우면 누가 막아 주는가? 이 쪽은 그 실수를 어디서 잡는가?
확인한 범위에서는 어느 층도 막지 않는다. 화면은 상한을 550 으로 안내하고 부스트 비트는 표시하지 않는다(사용자 실측). HAL 은 헤더 주석으로만 경고하고(stm32h7xx_hal_rcc.h:7529), LL 의 검사는 "VOS0 이면 550 이하"까지만 본다. 보드 프리셋(…_Board_AllConfig.ioc)은 처음부터 550 을 담고 있다. 하드웨어가 거부한다는 서술도 찾지 못했다 — 오류 없이 규격 밖으로 돈다. 그래서 이 쪽은 숫자를 두 번 되읽는다: 굽기 전에 .ioc 의 RCC.SYSCLKFreq_VALUE=520000000(§3-2-1 ③), 구운 뒤에 배너의 SYSCLK 520000000(§3-2-4). 550000000 이 보이면 굽지 않거나 곧바로 고친다 — 고칠 곳은 증상 ↔ 원인 표.
4. HSI 로도 460800 통신은 되는데 왜 굳이 HSE(BYPASS)인가? BRR 양자화 오차 +0.042 % 는 걱정할 크기인가?
HSI 의 최악 오차(약 ±1.5 %, DS13313 표 36 의 단순 합)는 보드레이트뿐 아니라 클럭에서 파생되는 모든 시간에 들어간다. 1 kHz 루프의 dt, 속도 추정(±1.5 % 배율), MCU 시각(최대 0.9 s/분)이 그 예다. 수신 허용 한계 3.33 %(RM0468 표 421)는 내 오차 + 상대편 오차 + 선로의 합에 대한 것이라 HSI 면 그 절반을 MCU 혼자 쓴다. 양자화 0.042 % 는 그 앞에서 작다 — 지배항은 클럭 소스다. BYPASS 인 이유는 보드에 수정이 실장돼 있지 않고 ST-LINK 의 MCO 8 MHz 가 PH0 로 들어오기 때문이다. 대가는 ST-LINK 부와 SB45 에 의존한다는 것이다.
5. 520 에서 HPRE 를 ÷1 로, 또는 APB 를 ÷1 로 두면 각각 무엇이 규격을 넘는가? 그리고 APB 가 130 MHz 인데 타이머는 왜 260 MHz 인가?
HPRE ÷1 이면 AXI · AHB 가 520 MHz(상한 275), APB ÷1 이면 APB 가 260 MHz(상한 137.5)다. 상한 안에서 가장 빠른 조합은 ÷1 · ÷2 · ÷2 하나뿐이다(더 나누면 규격 안이지만 느려질 뿐이다). 여유가 0 인 것은 CPU 한 줄(520 / 520)이고, 버스 · APB · 타이머는 상한 아래(15 · 7.5 · 15 MHz)다. 타이머는 APB 분주가 ÷2 이상이면 버스 클럭의 두 배를 받는다(RM0468 표 53) → 130 × 2 = 260 MHz. fw-06 의 TIM6 분주(PSC 259 · ARR 999)와 fw-08 의 ARR 6500 이 이 값에서 나온다. 실수로 550 이 들어가면 타이머가 275 MHz 가 되어 그 분주값들이 전부 +5.8 % 빨라진다 — 배너의 숫자를 되읽는 이유 하나다.
6. (실습 A 에서 1 이 나와 되돌려야 할 때) 옵션 바이트를 쓰기 전에 displ 을 파일로 남기고, 한 번에 한 비트만 쓰고, 다시 diff 하는 이유는? 같은 일을 펌웨어가 부팅 때 하게 하면 왜 안 되는가?
같은 구역에 되돌릴 수 없는 비트가 있기 때문이다 — RDP Level 2 는 비가역이고 Level 1 → 0 은 플래시 전체를 지운다. 기록은 _PRG 와 _CUR 가 다른 것을 한꺼번에 쓰는 구조라, 실수로 들어간 이웃 값도 같이 기록된다. 파일은 복구의 기준점이고 diff 는 "그 비트만 바뀌었다"의 증거다. 펌웨어에 넣으면 그 코드의 버그가 매 부팅마다 옵션 바이트를 잘못 쓰는 원인이 된다. 게다가 이 HAL 의 HAL_FLASHEx_OBGetConfig() 는 OptionType 에 RDP 를 포함해 채운다(stm32h7xx_hal_flash_ex.c:579-582). 읽은 구조체를 그대로 되쓰면 RDP 까지 다시 쓴다.
7. (일부러 틀리면) ① console_init() 에서 플래그를 지우는 줄을 빼면 ② HSE_VALUE 를 25000000 으로 두면 — 각각 무엇이 보이는가? 배너의 SYSCLK 520000000 은 주파수를 "잰" 값인가?
① 전원을 넣은 뒤로는 어떤 리셋을 해도 POR 이 찍힌다. 전원 인가가 아닌 리셋은 RCC_RSR 을 지우지 않아 POR 플래그가 남고, 판독은 구체적인 플래그부터 보기 때문이다(호스트 시험의 마지막 벡터가 이 상황이다). ② HAL 은 PCLK1 을 실제의 25 ÷ 8 배로 간주하고 BRR 을 계산한다 → 실제 보드레이트가 그만큼 느려져 터미널에 깨진 글자가 나온다. 배너가 읽힌다면 숫자도 그 배율만큼 커져 있을 것이다. 배너의 숫자는 잰 값이 아니다 — PLL 레지스터를 되읽어 HSE_VALUE 와 곱한 계산값이다. 그래도 쓸모가 있는 까닭: 분주값이 의도대로 들어갔는지를 보여 주고, 글자가 460800 에서 정상으로 읽힌다는 사실이 "HAL 이 가정하는 PCLK1 과 실제가 수 % 안에서 같다"는 독립된 증거가 된다. 시간축의 ppm 급 확인은 Pi 의 시계와 견주는 뒤 쪽의 일이다.
