내가 돌았나, 세상이 돌았나

l-13 의 차분은 센서가 가만히 있을 때만 뜻을 갖는다. 센서를 5 cm 밀면 미는 쪽을 마주 본 면이 "움직인 것"이 되고(l-13 §2-4), 도구는 무엇이 움직였는지 구별하지 못한다. 이 쪽에서 만드는 것은 헤더 align.hpp 와 도구 lab_align 이다. 헤더의 함수는 넷이다. correspond() 는 두 장의 점을 짝짓는다. estimate() 는 그 짝에서 얼마나 옮기고 돌리면 포개지는가를 낸다. icp() 는 그 둘을 되풀이하고, rms() 는 포개진 정도를 수 하나로 낸다. 여기서 나오는 수 세 개(dx, dy, dθ)가 09 의 스캔 매칭이 내는 것과 같은 양이고, 09 의 파라미터가 왜 그런 값인지도 이 쪽에서 설명된다. 09 는 본편(로봇 전체를 순서대로 만드는 가이드)의 SLAM · Nav2 쪽이다. 1. 개요 — 두 장을 포개면 내 움직임이 나온다

l-08 부터 l-12 까지는 전부 한 장 안의 일이었다. 점을 방으로 옮기고(l-08), 없는 곳을 칠하고(l-09), 덩어리로 묶고(l-10), 선분으로 줄이고(l-11), 지나갈 수 있는지 판정했다(l-12). l-13 에서 처음으로 두 장을 맞대었고, 그 차분에는 한계가 있었다 — 같은 각도의 거리를 빼는 것은 센서가 그 자리에 그대로 있었을 때만 뜻이 있다.

이 쪽이 하는 일은 하나다. 두 장을 포개는 데 필요한 (옮김, 돌림)을 구한다. 그 수가 나오면 두 가지가 한꺼번에 풀린다 — 센서가 움직여도 차분을 할 수 있고, 그 수 자체가 "내가 얼마나 움직였는가"가 된다. 09 의 스캔 매칭이 하는 일이 정확히 이것이다.

2. 원리 — 왜 세 걸음이고, 왜 되풀이하고, 왜 수렴이 정답이 아닌가

2-1. l-13 이 남긴 물음 — 센서가 움직이면 모든 각도가 바뀐다

차분은 단순하다. 같은 각도의 거리가 줄었으면 무언가 앞으로 온 것이다. 이 판단이 성립하는 조건은 하나다 — "같은 각도"가 같은 방향을 가리켜야 한다는 것이고, 이 조건은 센서가 움직이지 않았을 때만 참이다.

센서를 20 cm 앞으로 밀면 앞 벽까지의 거리가 20 cm 줄고, 뒤 벽까지의 거리는 20 cm 늘고, 옆 벽은 거리도 각도도 함께 바뀐다. 차분 도구는 이 변화 중 가까워진 쪽(미는 쪽을 마주 본 면)을 "움직였다"고 보고한다(l-13 §2-4) — 틀린 출력은 아니다. 센서가 보는 좌표계에서는 실제로 온 방이 움직였다. 도구가 구별하지 못하는 것은 움직인 것이 방인지 센서인지다.

라이다 한 대만으로는 그 둘을 구별할 수 없다. 대신 할 수 있는 일이 있다 — "온 방이 똑같은 방식으로 움직였다면 움직인 것은 나다" 라고 정하는 것이다. "똑같은 방식"이 바로 강체 운동 하나(옮김 + 돌림)이고, 그 강체 운동을 찾는 것이 이 쪽의 일이다. 그리고 이 정의에는 대가가 있다 — 방 전체가 아니라 일부만 움직였을 때(사람이 지나갈 때) 그 사람의 점도 추정에 들어간다. §2-4 의 "이상치"가 이 경우를 다룬다.

2-2-1. 왜 되풀이하는가 — 한 번으로는 40 %밖에 못 간다

되풀이하는 이유를 한 줄로 쓰면 이렇다: 대응이 틀려서 변환이 틀리고, 변환이 나아지면 대응도 나아진다. 말로는 그럴듯한데 얼마나 나아지는지는 재 봐야 안다.

집필자가 정답을 아는 합성 장면으로 재 보았다. 장면은 4 m × 3 m 방 안에서 센서를 정확히 0.20 m 앞으로 옮긴 두 장이다. 두 장은 room(2.0, 1.5, 0.0, 360)(방 한가운데)과 room(2.2, 1.5, 0.0, 360) 이고, 한 장에 360 점이다. room() 은 §3-6-2 의 tests/align_fixtures.hpp 에 있다. 반복마다 누적 dx 를 찍으면 이렇다.

iteration  3   dx =  -0.15786 m   (this step  -0.02997 m)

읽을 것이 셋 있다.

  1. 이 장면에서 한 번의 추정은 답의 40 %였다. 0.0797 / 0.20 ≈ 0.40. 대응이 틀렸기 때문이고, 틀린 만큼 덜 움직이는 쪽으로 틀린다 — 가장 가까운 점을 고르면 진짜 짝보다 가까운 점이 뽑히기 쉽기 때문이다. 비율은 방과 움직인 양에 따라 달라지지만 덜 나오는 방향은 같다. 정합이 한 번에 안 끝나는 이유는 이 한 줄이다.
  2. 걸음 폭이 줄어든다. 0.0797 → 0.0482 → 0.0300 → … 매번 남은 거리의 비슷한 비율만큼 간다. 그래서 10 번으로 98 %까지 가지만 마지막 몇 % 를 채우는 데 그만큼의 반복이 또 든다. 어디서 멈출지는 내가 정한다(§3-2-3).
  3. 멈춘 자리가 -0.20100 이지 -0.20000 이 아니다. 0.5 % 가 남는다. 이것은 버그가 아니라 같은 벽을 다른 자리에서 다시 찍었기 때문이다 — 센서가 옮겨 가면 광선이 벽의 다른 점에 닿는다. 합성 장면인데도 남는 이 차가, 실물에서 줄자와 딱 맞지 않는 이유의 아래 한계다.

2-2-2. 무엇을 최소화하는가 — 그리고 한 번의 추정은 닫힌 식이다

짝 목록이 손에 있다고 하자. "가장 잘 포갠다"는 말을 수로 바꾸면 하나뿐이다 — 짝지어진 두 점 사이 거리의 제곱을 모두 더한 값을 가장 작게 만든다.

E(dx, dy, dtheta) = 짝마다  | R p + t - q |^2  을 모두 더한 것
      p = a 의 점,  q = b 의 점,  R = dtheta 만큼의 회전,  t = (dx, dy)

미지수가 셋이고 식은 제곱합이라 미분해서 0 이 되는 자리를 그냥 풀 수 있다. 반복도 근사도 필요 없다. 그 결과가 아래 세 걸음이고, 이 셋이 이 쪽이 요구하는 수학의 전부다.

걸음 1  두 집합의 중심을 각각 원점으로 옮긴다
        u = p - p_mean          v = q - q_mean
        -> 옮기고 나면 t 가 식에서 사라지고, 남는 미지수는 dtheta 하나다

걸음 2  합 둘을 만들고 각을 한 번에 구한다
        S = sum( u_x * v_y - u_y * v_x )      (짝마다 교차곱, 그 합)
        C = sum( u_x * v_x + u_y * v_y )      (짝마다 내적,   그 합)
        dtheta = atan2(S, C)

걸음 3  옮겼던 중심을 되돌려 t 를 얻는다
        (dx, dy) = q_mean - R(dtheta) 를 p_mean 에 적용한 것

왜 중심부터 옮기는가가 이 절의 핵심이다. 회전은 원점을 기준으로 도는 연산이라, 두 집합이 원점에서 멀리 떨어져 있으면 "돌리기"와 "옮기기"가 서로 섞여 들어간다. 중심을 원점에 놓으면 그 섞임이 사라져 각 하나만 남고, 각이 정해지면 옮김은 뺄셈 한 번이다. 순서를 바꾸면 — 중심을 안 옮기고 바로 S·C 를 만들면 — 오류 없이 틀린 값이 나온다. §3-6-4 의 첫 줄이 이 실수를 실제로 검출하는 출력이다.

atan2(S, C) 를 쓰는 이유도 하나다. S 와 C 는 각각 sin·cos 에 비례하는 양이고, 둘의 부호를 함께 봐야 네 사분면이 구별된다. atan(S/C) 로 쓰면 180° 어긋난 답이 같은 값이 되어 벽을 정면으로 보는 것과 등지는 것이 구별되지 않는다.

점 수가 2 배가 되면 시간은 약 4 배가 된다(360 → 720 에서 3.6 배, 720 → 1 450 에서 3.8 배). 짝의 수가 점 수의 제곱이기 때문이고, 이것은 기계가 바뀌어도 변하지 않는다. 배수는 컴파일러마다 조금 다르다(각주 2 — clang 빌드는 4.1 배였다). 1 450 점이면 이 Mac 에서 반복 한 번에 약 1 ms 다 — 서른 번 반복해도 약 32 ms 다. 회전수를 아직 재지 않아 데이터시트(제조사가 낸 RPLIDAR A1 사양 문서)의 5.5 Hz(주기 약 182 ms)를 대신 놓으면 그보다 짧다 — 그 조건에서 집필자의 결과는 "예산 안"이다. 내 Pi 의 값은 재 봐야 안다(§3-5, 확인 과제). 확인 과제는 집필자가 확인하지 못해 내가 내 장치로 확인할 항목이다.

⚠ 예산 안이라고 "전수 탐색이면 된다"로 읽지 않는다. 시간은 점 수의 제곱으로 늘고, 반복 횟수만큼 곱해진다 — 점이 두 배면 네 배다. 실제 구현이 쓰는 방법은 셋이고, 셋 다 ①번 걸음을 고친다.

  • k-d 트리(가장 가까운 점을 전부 훑지 않고 찾는다)
  • 격자로 미리 나누기(l-09 의 격자가 그 재료다)
  • 점을 솎기(l-10 의 downsample(s, k))

② 는 닫힌 식이라 고칠 것이 없다. ③ 은 ①·② 를 되풀이하는 걸음이라, 반복 한 번의 시간은 대부분 ① 이 쓴다. 어느 걸음이 시간을 많이 쓰는지 내 손으로 재 본 사람만 그 선택을 이해할 수 있다. §3-5 를 실습으로 둔 이유가 이것이다.

예산이 되는 수는 내 한 바퀴 주기이고, 그 값은 l-04 §3-2 에서 잰 내 회전수에서 나온다(주기 ms = 1000 / 내 회전수). ⚠ 데이터시트의 5.5 Hz(주기 약 182 ms)를 내 주기로 쓰지 않는다. 5.5 Hz 는 데이터시트 성능 표의 typical 값이고, 같은 표에 360 samples per scan 이라는 조건이 함께 붙어 있다.3 내 값이 5.5 Hz 와 많이 다르면 그 차이 자체가 기록할 일이다.

3. 실습

여섯 걸음이고, 장비가 필요한 것은 B 와 C 의 마지막 걸음 둘뿐이다. 나머지는 기록 파일이나 합성 장면으로 끝난다. 이 쪽이 scripts/lidar_lab/ 에 더하는 것은 헤더 align.hpp(채울 자리 넷)와 시험, 그리고 도구 셋이다. 도구 셋(lab_align · lab_align_room · lab_align_time)은 전량이다. 빌드와 실행은 Pi 에서 한다. 명령 앞의 pi$ 는 Pi 의 셸에서 친다는 표시다. Mac 에서는 시험 test_align 만 연습할 수 있다(결정 L3).

⚠ 순서를 지킨다. A 는 골격을 열기 전에 하는 걸음이다. 함수 이름 셋(correspond · estimate · icp)이 이미 답의 절반을 드러낸다. 그래서 골격을 보기 전에 내 말로 먼저 써 두면 뒤에서 무엇을 새로 알았는지가 기록으로 남는다.

이 쪽의 도구는 모터를 부르지 않는다

이 쪽의 도구(lab_align · lab_align_room · lab_align_time · peek.py)는 포트를 열지 않고 모터를 부르지 않는다 — 라이다가 꽂혀 있고 머리가 돌고 있었다면 그대로 돈다. 돈다고 간주한다. 기록은 l-04 의 lab_turn 으로 한다. 그 도구는 끝에 motor(fd, false) 로 머리를 멈춘다 — 끝난 뒤에도 돌면 USB 케이블을 뽑는다(l-01 의 L2 — 도는 머리 규칙). 레이저 규칙 L1 도 l-01 이 소유한다. L1 은 이렇다 — 광원은 눈에 보이지 않는 785 nm 적외선이므로, 스캔 창을 렌즈 높이에서 정면으로 들여다보지 않는다.

// (point of a, point of b): a GUESSED partner, not a known one (2-2).
using Pair = std::pair<Point, Point>;

// A rigid motion in the plane: turn by dtheta (RADIANS) about the ORIGIN, then shift by
// (dx, dy) (METRES). estimate() and icp() report the motion that takes the points of a onto
// the points of b -- the POINTS' motion, not the sensor's (2-3).
struct Pose2 {
  double dx, dy, dtheta;
};

// Move every point of pts by tf: turn about the origin, then shift. A hole (an EMPTY
// optional, a no-return of to_xy()) stays a hole at the same index, so the result is as long
// as pts. Given in full: icp(), lab_align and lab_align_room use it.
inline std::vector<std::optional<Point>> apply_pose(
    const Pose2& tf, const std::vector<std::optional<Point>>& pts) {
  const double c = std::cos(tf.dtheta), s = std::sin(tf.dtheta);
  std::vector<std::optional<Point>> out(pts.size());
  for (std::size_t i = 0; i < pts.size(); ++i) {
    if (!pts[i]) continue;
    const double x = pts[i]->first, y = pts[i]->second;
    out[i] = Point{c * x - s * y + tf.dx, s * x + c * y + tf.dy};
  }
  return out;
}

}  // namespace lidar_lab

//          default would decide how long to keep going for you, without saying so.
// Invariants -- each one is graded by a vector in tests/test_align.cpp:
//   1. iters <= 0 -> {0, 0, 0}: nothing was done, so nothing moved (vector 14).
//   2. The total is the COMPOSITION of the steps, not their sum. Applying step 1 then step 2
//      gives

//          (dx, dy) = R(t2) applied to (dx1, dy1), then plus (dx2, dy2)
//      -- the earlier shift gets TURNED by the later rotation. Adding the three numbers
//      instead is the classic bug, and vector 16 catches it.
//   3. Each round works on the points as they are NOW: move your working copy by the step
//      you just estimated (apply_pose(), above) before you correspond again.
//   4. One round is enough when the motion is small next to the point spacing (vector 15) --

  (void)b;

/* 완결 코드 T1 - scripts/lidar_lab/include/lidar_lab/align.hpp (correspond) */
inline std::vector<Pair> correspond(const std::vector<std::optional<Point>>& a,
                                    const std::vector<std::optional<Point>>& b) {
  std::vector<Point> cand;  // b's measured points, gathered ONCE, before the loop
  for (const std::optional<Point>& q : b) {
    if (q) cand.push_back(*q);
  }
  std::vector<Pair> out;
  if (cand.empty()) return out;
  for (const std::optional<Point>& p : a) {
    if (!p) continue;
    std::size_t best = 0;
    double best_d2 = 0.0;
    for (std::size_t j = 0; j < cand.size(); ++j) {
      const double ex = cand[j].first - p->first, ey = cand[j].second - p->second;
      const double d2 = ex * ex + ey * ey;  // squared: sqrt keeps the order, so skip it
      if (j == 0 || d2 < best_d2) {
        best = j;
        best_d2 = d2;
      }
    }
    out.emplace_back(*p, cand[best]);
  }
  return out;
}

코드 설명

  • std::vector<Point> cand; 와 그 아래 세 줄 — b 의 측정점을 루프 밖에서 한 번 모은다(불변식 2). 루프 안에서 거르면 같은 일을 a 의 점 수만큼 되풀이한다.
  • if (cand.empty()) return out; — 맞댈 것이 없으면 빈 목록이다(불변식 4, 벡터 13). 아래의 cand[best] 가 빈 목록을 읽지 않게 지키는 줄이기도 하다.
  • if (!p) continue; — a 의 빈 값은 건너뛴다(불변식 1, 벡터 10). 그래서 결과가 a 보다 짧을 수 있다.
  • const double d2 = ex * ex + ey * ey; — 거리의 제곱으로 비교한다. 제곱근은 크기 순서를 바꾸지 않으므로 고르는 점이 같고, 후보마다 제곱근 한 번을 아낀다.
  • if (j == 0 || d2 < best_d2) — 첫 후보로 시작하고 더 작을 때만 바꾼다. 같은 거리면 앞의 후보가 남는다(불변식 5, 13b).
  • out.emplace_back(*p, cand[best]); — 짝 하나를 더한다. 같은 cand[best] 가 여러 번 나와도 된다(불변식 3, 벡터 12).
  • 골격의 자리표시 셋((void)a; · (void)b; · return {};)은 지웠다.

  • 다르게 써도 되는 곳 — 둘이다.7

    제곱 대신 std::hypot(ex, ey) 로 비교해도, b 의 빈 값을 루프 안에서 건너뛰어도 23 개를 통과한다. 달라지는 것은 속도뿐이다(§3-5 에서 잰다).

/* 완결 코드 T2 - scripts/lidar_lab/include/lidar_lab/align.hpp (estimate) */
inline Pose2 estimate(const std::vector<Pair>& pairs) {
  if (pairs.empty()) return Pose2{0.0, 0.0, 0.0};
  const double n = static_cast<double>(pairs.size());
  double pxm = 0.0, pym = 0.0, qxm = 0.0, qym = 0.0;  // step 1: the two centres, kept
  for (const Pair& pq : pairs) {
    pxm += pq.first.first;
    pym += pq.first.second;
    qxm += pq.second.first;
    qym += pq.second.second;
  }
  pxm /= n;
  pym /= n;
  qxm /= n;
  qym /= n;
  double S = 0.0, C = 0.0;  // step 2: cross and dot of the centred points, summed
  for (const Pair& pq : pairs) {
    const double ux = pq.first.first - pxm, uy = pq.first.second - pym;
    const double vx = pq.second.first - qxm, vy = pq.second.second - qym;
    S += ux * vy - uy * vx;
    C += ux * vx + uy * vy;
  }
  const double th = std::atan2(S, C);
  const double c = std::cos(th), s = std::sin(th);
  return Pose2{qxm - (c * pxm - s * pym), qym - (s * pxm + c * pym), th};  // step 3
}

코드 설명

  • 첫 루프와 네 번의 나눗셈 — 걸음 1. 첫 점들의 중심 (pxm, pym) 과 둘째 점들의 중심 (qxm, qym) 을 변수에 남긴다 — 걸음 3 에서 다시 쓴다.
  • 둘째 루프 — 걸음 2. 중심을 뺀 u · v 로 교차곱 S 와 내적 C 를 모은다. 중심을 빼는 것이 각 하나만 남기는 이유다(§2-2-2, 이해 확인 3).
  • std::atan2(S, C) — 두 합의 부호를 같이 봐 네 사분면을 가른다. 결과는 [-π, +π] 다(벡터 8: 200° 가 −160° 로). 짝이 하나뿐이거나 모두 한 자리면 두 합이 +0.0 이고, C 라이브러리의 규칙으로 atan2(+0.0, +0.0) 은 +0.0 이다(불변식 2 · 3).4 둘째 인자가 -0.0 이면 π 가 나온다 — 두 합이 +0.0 인 것은 덧셈과 곱셈의 규칙 덕이다.
  • 마지막 줄 — 걸음 3. 둘째 중심에서 돌린 첫 중심을 뺀다. 돌리지 않고 qxm - pxm 만 쓰면 회전이 있는 벡터(5 ~ 7)가 틀린다.

  • 다르게 써도 되는 곳 — 변수 이름과 루프 수다. 세 걸음의 순서만 지키면 된다. 집필자가 따로 잰 다른 꼴은 없다.

/* 완결 코드 T3 - scripts/lidar_lab/include/lidar_lab/align.hpp (icp) */
inline Pose2 icp(const std::vector<std::optional<Point>>& a,
                 const std::vector<std::optional<Point>>& b, int iters) {
  Pose2 total{0.0, 0.0, 0.0};
  std::vector<std::optional<Point>> cur = a;  // the working copy, moved round by round
  for (int k = 0; k < iters; ++k) {
    const Pose2 step = estimate(correspond(cur, b));
    const double c = std::cos(step.dtheta), s = std::sin(step.dtheta);
    total = Pose2{c * total.dx - s * total.dy + step.dx,  // invariant 2: the earlier shift
                  s * total.dx + c * total.dy + step.dy,  // is TURNED by the later rotation
                  normalize(total.dtheta + step.dtheta)};
    cur = apply_pose(step, cur);  // invariant 3: the next round sees the moved points
  }
  return total;
}

코드 설명

  • Pose2 total{0.0, 0.0, 0.0}; 와 cur = a — 되풀이 사이에 남기는 것 둘이다. iters 가 0 이면 루프를 한 번도 반복하지 않고 시작값을 돌려준다(불변식 1, 벡터 14).
  • estimate(correspond(cur, b)) — 이번 걸음. 지금 자리의 점으로 짝을 다시 짓는다(불변식 3).
  • total = Pose2{c * total.dx - s * total.dy + step.dx, …} — 합성(불변식 2). 앞의 옮김 (total.dx, total.dy) 를 이번 걸음의 각으로 돌린 뒤 이번 옮김을 더한다. 각은 더하고 normalize() 로 접는다.
  • cur = apply_pose(step, cur); — 작업 사본을 이번 걸음만큼 옮긴다. cur 는 이미 앞의 걸음들로 옮겨져 있다. 빈 값은 같은 자리에 빈 값으로 남는다(15b).
  • 골격의 자리표시 넷((void)a; · (void)b; · (void)iters; · return Pose2{0.0, 0.0, 0.0};)은 지웠다.

  • 다르게 써도 되는 곳 — 셋이다.7 어느 쪽이 맞고 틀린 문제가 아니다.

    ① 매번 원본을 누적 운동으로 옮긴다(cur = apply_pose(total, a);) — 23 개를 통과한다. 부동소수 오차가 쌓이지 않는 대신 매번 전체를 다시 계산한다. 한 번의 대응이 훨씬 오래 걸리므로 성능 차이는 없다(§2-7).

    ② 각을 normalize() 로 접지 않는다 — 23 개가 그대로 통과한다(§3-6-4). 여러 바퀴를 이어 붙일 때만 차이가 나므로, 빼는 것도 선택이다 — 다만 뺐다면 그 사실을 주석에 적는다.

    ③ 합성을 작은 함수로 뗀다 — 읽기 쉽고 따로 시험할 수 있다. 다만 공개 이름이 하나 늘고, 시험은 icp() 만 부른다. 여섯 줄짜리 함수를 이름으로 만들 가치가 있는지는 내가 정한다.

    조기 종료(걸음이 작으면 그만)는 icp() 안에 두지 않았다. 멈춘 것이 수렴인지 포기인지 바깥에서 알 수 없게 되기 때문이다 — lab_align 의 셋째 줄이 그 판단 재료를 준다(§3-2-3 의 표).

완결 코드

/* 완결 코드 T4 - scripts/lidar_lab/include/lidar_lab/align.hpp (rms) */
inline std::optional<double> rms(const std::vector<Pair>& pairs) {
  if (pairs.empty()) return std::nullopt;
  double sum = 0.0;
  for (const Pair& pq : pairs) {
    const double ex = pq.second.first - pq.first.first;
    const double ey = pq.second.second - pq.first.second;
    sum += ex * ex + ey * ey;
  }
  return std::sqrt(sum / static_cast<double>(pairs.size()));
}

코드 설명

  • if (pairs.empty()) return std::nullopt; — 짝이 없으면 빈 값이다(불변식 1, 17a). 0.0 은 "완벽하게 포개졌다"는 뜻이 되므로 쓰지 않는다 — 비교한 것이 없는 것과 다르다.
  • sum += ex * ex + ey * ey; — 거리의 제곱을 모은다. 제곱근은 아직 취하지 않는다.
  • std::sqrt(sum / …) — 짝 수로 나눈 뒤 한 번 제곱근(불변식 2). 거리의 평균(17c 의 2.0)과 다르고, 합의 제곱근(17d)과도 다르다. 큰 차이 하나가 결과를 크게 끌어올리는 것이 이 수의 성질이다 — §2-4 의 "멀리 틀린 짝일수록 영향이 크다"와 같은 이유다.
  • 골격의 자리표시((void)pairs; · return std::nullopt;)는 지웠다.

  • 다르게 써도 되는 곳 — 제곱을 std::hypot(ex, ey) 의 제곱으로 써도 23 개를 통과한다.7

3-3-1. 확인 — "제자리"를 무엇으로 정할 것인가

제자리 회전은 만들기가 어렵다. 손으로 돌리면 대개 중심도 같이 옮겨진다. 옮긴 만큼이 (dx, dy) 로 나오고, 그러면 "회전만 추정하는 특수한 경우"(§2-5)가 아니게 된다.

  1. 센서 바닥의 한 점을 회전 중심으로 정하고 책상에 표시한다. 몸체 중심이 아니라 스캔 머리의 축에 가까운 점이 좋다 — 축이 제자리면 점들도 제자리에서 돈다.
  2. 그 점을 지나는 기준선을 하나 긋고, 각도기(또는 접은 종이)로 30° 선을 하나 더 긋는다. 두 선 사이가 내가 만들 각이다.
  3. 몸체의 어느 면을 선에 맞출지 정한다. 매번 다른 면에 맞추면 각이 달라진다.

⚠ 30° 는 예시다. 각도기가 45°만 만들 수 있으면 45°로 하고 표에 그렇게 적는다. 각이 커질수록 §2-6 의 문제가 커진다는 것을 이 실습이 직접 보여 줄 것이다.

3-4. 실습 D — 수렴했는데 틀린 자리를 내 손으로 만든다 기록 파일

이 실습은 라이다도 기록 파일도 필요 없다. 정답을 아는 합성 장면을 쓰기 때문이고, 합성 장면을 쓰는 것이 이 실습의 요점이다. 실물에서는 "틀렸다"는 것을 알 방법이 없다. 정답을 아는 곳에서 한 번 봐 두어야 실물에서 같은 증상을 알아챌 수 있다.

3-4-1. 확인 — 장면을 만드는 함수는 이미 손에 있다

§3-6-2 의 tests/align_fixtures.hpp 에 room(cx, cy, deg0, n, w, h) 가 들어 있다. 정사각형 방 한가운데에 센서를 놓고 제자리에서 45° 돌린 장면을 room() 으로 만든다. 광선을 쏘아 벽에 닿은 자리를 점으로 주는 함수라, 센서가 옮겨 가면 점도 제대로 다른 자리에 찍힌다 — 점집합을 그냥 회전시킨 것과 다르다.

// scripts/lidar_lab/src/align_room.cpp -- the synthetic scenes of l-14, where the answer is
// known: run YOUR icp() on them and see where it stops.  (l-14, given in full)
//   pi$ scripts/lidar_lab/build/lab_align_room <scene>
//   square    3-4  a 3 m x 3 m room, the sensor turned 45 deg in place, at the centre and off
//                  it (0.9, 0.7): dtheta after 1, 5, 20, 100 rounds, and the residual where it
//                  stopped next to the residual of the true answer (2-6 is the same scene)
//   step      2-2-1  a 4 m x 3 m room, the sensor moved +0.20 m from the centre: the total dx
//                  after 1, 2, 3, 5, 10, 20, 30 rounds and how much the last round added
//   corridor  2-4  the same 4 m x 3 m room moved +1.00 m, a 10 m x 1.2 m corridor moved
//                  +1.00 m along and +0.30 m across, 100 rounds each (20 too, for the first)
//   turn      3-3-3  the 4 m x 3 m room, the sensor turned +30 deg in place at the centre:
//                  dtheta after 5, 10, 20, 30, 100 rounds and the two residuals
// Every scene is room() of tests/align_fixtures.hpp, 360 points a revolution, no noise -- so
// the output must be the same on every machine, and the same as the page's. If yours differs,
// your icp() differs (3-4-3).
// The numbers are YOUR icp() and YOUR rms(); the scene is not yours.
// No port, no file, no clock, no motor.
// Exit code: 0 = done; 2 = usage.
#include <cstddef>
#include <cstdio>
#include <cstring>
#include <optional>

#include "lidar_lab/angles.hpp"

#include "../tests/align_fixtures.hpp"

using namespace lidar_lab;

namespace {

using Pts = std::vector<std::optional<Point>>;

// The residual of the pairs a motion leaves: move a by tf, guess the partners, rms().
void print_rms(const char* label, const Pts& a, const Pts& b, const Pose2& tf) {
  const std::optional<double> r = rms(correspond(apply_pose(tf, a), b));
  if (r) {
    std::printf("  %s : %.6f m\n", label, *r);
  } else {
    std::printf("  %s : none\n", label);
  }
}

void square() {
  const double place[2][2] = {{1.5, 1.5}, {0.9, 0.7}};
  const char* name[2] = {"centre", "off-centre"};
  const int rounds[4] = {1, 5, 20, 100};
  for (int p = 0; p < 2; ++p) {
    const Pts a = room(place[p][0], place[p][1], 0.0, 360, 3.0, 3.0);
    const Pts b = room(place[p][0], place[p][1], 45.0, 360, 3.0, 3.0);
    Pose2 last{0.0, 0.0, 0.0};
    for (int it : rounds) {
      last = icp(a, b, it);
      std::printf("%-10s iters %3d -> dtheta = %8.4f deg\n", name[p], it, to_deg(last.dtheta));
    }
    print_rms("rms of the answer it found (iters 100)", a, b, last);
    print_rms("rms of the true answer (-45 deg)      ", a, b, Pose2{0.0, 0.0, to_rad(-45.0)});
  }
}

void step() {
  const Pts a = room(2.0, 1.5, 0.0, 360);
  const Pts b = room(2.2, 1.5, 0.0, 360);
  const int rounds[7] = {1, 2, 3, 5, 10, 20, 30};
  for (int it : rounds) {
    const Pose2 p = icp(a, b, it);
    const Pose2 q = icp(a, b, it - 1);  // one round fewer: the difference is round it alone
    std::printf("iteration %2d   dx = %9.5f m   (this step %9.5f m)\n", it, p.dx, p.dx - q.dx);
  }
}

void corridor() {
  const Pose2 r = icp(room(2.0, 1.5, 0.0, 360), room(3.0, 1.5, 0.0, 360), 100);
  std::printf("4 m x 3 m room,  sensor moved +1.00 m :  dx = %9.5f m   (iters 100)\n", r.dx);
  const Pts c0 = room(5.0, 0.6, 0.0, 360, 10.0, 1.2);
  const Pts c1 = room(6.0, 0.6, 0.0, 360, 10.0, 1.2);
  const Pose2 c20 = icp(c0, c1, 20);
  const Pose2 c100 = icp(c0, c1, 100);
  std::printf("10 m x 1.2 m corridor, same +1.00 m   :  dx = %9.5f m   (iters 20)\n", c20.dx);
  std::printf("10 m x 1.2 m corridor, same +1.00 m   :  dx = %9.5f m   (iters 100)\n", c100.dx);
  const Pose2 s = icp(c0, room(5.0, 0.9, 0.0, 360, 10.0, 1.2), 100);
  std::printf("10 m x 1.2 m corridor, sideways +0.30 :  dy = %9.5f m   (iters 100)\n", s.dy);
}

void turn() {
  const Pts a = room(2.0, 1.5, 0.0, 360);
  const Pts b = room(2.0, 1.5, 30.0, 360);
  const int rounds[5] = {5, 10, 20, 30, 100};
  Pose2 last{0.0, 0.0, 0.0};
  for (int it : rounds) {
    last = icp(a, b, it);
    std::printf("turned +30 deg in place, iters %3d -> dtheta = %8.4f deg\n", it,
                to_deg(last.dtheta));
  }
  print_rms("rms where it stopped (iters 100)", a, b, last);
  print_rms("rms at the true -30 deg         ", a, b, Pose2{0.0, 0.0, to_rad(-30.0)});
}

int usage() {
  std::printf("usage: lab_align_room square|step|corridor|turn\n");
  return 2;
}

}  // namespace

int main(int argc, char** argv) {
  if (argc != 2) return usage();
  if (std::strcmp(argv[1], "square") == 0) {
    square();
  } else if (std::strcmp(argv[1], "step") == 0) {
    step();
  } else if (std::strcmp(argv[1], "corridor") == 0) {
    corridor();
  } else if (std::strcmp(argv[1], "turn") == 0) {
    turn();
  } else {
    return usage();
  }
  return 0;
}

3-4-4. 보고 판정하기

두 줄을 나란히 놓고 읽는다.

  1. 한가운데: 첫 반복부터 0° 이고 100번을 반복해도 0° 다. 도구는 "아무것도 안 돌았다"는 답을 냈고, 각만 보면 그 답이 틀렸다는 신호가 없다 — 신호는 잔차(0.3 m) 하나다. 반복을 1000번으로 늘려도 같다1 — 이것이 "발산"보다 위험한 실패다. 발산은 눈에 띄지만 이 실패는 정상처럼 보이는 값으로 틀린다.
  2. 구석 쪽: 같은 도구가 -45.0000° 를 정확히 찾는다. 고친 것은 알고리즘이 아니라 장면이다. 정사각형 방을 한가운데서 보면 90° 돌려도 똑같이 보이는데, 센서를 비켜 놓는 순간 그 대칭이 깨진다.
  3. 구석 쪽도 20번에서는 -35° 다. 답이 있는 장면에서도 반복이 모자라면 틀린 값이 나온다. 20번에서 멈춘 사람은 -35° 가 중간값인지 최종값인지 알 수 없다. 걸음 폭이 줄었는지를 같이 보는 수밖에 없다(lab_align 의 셋째 줄 — §3-2-3 의 표).

3-5. 실습 E — 반복 한 번의 시간을 내 한 바퀴와 견준다 기록 파일

재는 도구 lab_align_time 은 전량이고, 재는 대상은 B 에서 채운 내 correspond() · estimate() 다. 그래서 골격 걸음이 없다. 확인할 것은 하나뿐이라 여기에 적는다 — 내 회전수가 l-04 §3-2 에 적혀 있는가. 이 실습의 판정은 그 값에서 나오고(주기 ms = 1000 / 내 회전수), 없으면 "반복 한 번이 몇 ms"까지만 나오고 판정이 나지 않는다. 그때는 ms 를 적어 두고 l-04 로 돌아가 회전수를 재 온 뒤 표의 나머지를 채운다.

3-5-1. 확인

시계는 순수 함수 밖에 둔다. correspond() 안에 시계를 넣으면 그 함수가 더 이상 순수하지 않아 시험 벡터가 시각에 의존하게 된다. 이 함수들을 부르는 노드를 만든다면 시간은 그 콜백 쪽에서 잰다. 재는 곳은 호출하는 쪽이다 — l-09 §3-4-3 의 lab_grid --time 이 같은 이유로 같은 자리를 골랐다.

3-5-3. 채우기

재는 도구는 lab_align_time 이다 — 전량이다. 기록의 이웃한 두 바퀴로 대응 한 번 + 추정 한 번(반복 1회분)을 다섯 번 재서 가장 짧은 값을 찍는다. --k 를 주면 l-10 의 downsample(s, k) 로 솎은 뒤 같은 것을 잰다. --room 은 기록 없이 §2-7 의 합성 장면을 잰다.

// scripts/lidar_lab/src/align_time.cpp -- how long ONE round of icp() takes: one correspond()
// plus one estimate(), timed from the OUTSIDE.  (l-14, given in full)
//   pi$ scripts/lidar_lab/build/lab_align_time <file.scan.jsonl> [--turn K] [--k N]...
//   pi$ scripts/lidar_lab/build/lab_align_time --room
//   --turn K  revolutions K and K+1 of the file (1 = the first; default 1). A file with one
//             revolution times it against itself -- the count of pairs is what matters
//   --k N     may be repeated: also thin both revolutions with l-10's downsample(s, N) first
//             (N >= 1; 1 = every point). Without --k: N = 1 only
//   --room    no file: room() of tests/align_fixtures.hpp at n = 90, 360, 720, 1450 points,
//             the sensor moved 0.20 m (2-7)
// Each line is the SHORTEST of 5 runs, in ms -- a slower run was slowed by something other
// than this code (the scheduler, another process), and the question is what THIS code costs.
// The clock stays OUT of align.hpp: the vectors must not depend on time, and a node that
// called these functions would time them in its callback.
// The time is measured with the build as it is (RelWithDebInfo, _GLIBCXX_ASSERTIONS on).
// Exit code: 0 = done; 1 = the loader refused the file, or there is no such revolution;
// 2 = usage.
#include <chrono>
#include <cmath>
#include <cstddef>
#include <cstdio>
#include <cstdlib>
#include <cstring>
#include <exception>
#include <optional>
#include <vector>

#include "lidar_lab/align.hpp"
#include "lidar_lab/cluster.hpp"
#include "lidar_lab/geom.hpp"
#include "lidar_lab/scan_io.hpp"
#include "../tests/align_fixtures.hpp"

using namespace lidar_lab;

namespace {

using Pts = std::vector<std::optional<Point>>;

// "4" -> 4, only lo .. hi.
bool parse_int(const char* text, long lo, long hi, long& v) {
  char* end = nullptr;
  v = std::strtol(text, &end, 10);
  return end != text && *end == '\0' && v >= lo && v <= hi;
}

std::size_t measured(const Pts& xy) {
  std::size_t m = 0;
  for (const std::optional<Point>& p : xy) m += p ? 1 : 0;
  return m;
}

// One round, 5 times -> the shortest, in ms. The answers are compared afterwards, so the
// optimiser cannot drop a call whose result nobody reads.
double one_round_ms(const Pts& a, const Pts& b) {
  double best_ms = 0.0;
  Pose2 first{0.0, 0.0, 0.0};
  bool agree = true;
  for (int k = 0; k < 5; ++k) {
    const auto t0 = std::chrono::steady_clock::now();
    const Pose2 p = estimate(correspond(a, b));
    const auto t1 = std::chrono::steady_clock::now();
    if (k == 0) first = p;
    agree = agree && p.dx == first.dx && p.dy == first.dy && p.dtheta == first.dtheta;
    const double ms = std::chrono::duration<double, std::milli>(t1 - t0).count();
    if (k == 0 || ms < best_ms) best_ms = ms;
  }
  if (!agree) std::printf("note: the 5 runs did not agree\n");
  return best_ms;
}

int usage() {
  std::printf("usage: lab_align_time <file.scan.jsonl> [--turn K] [--k N]...\n"
              "       lab_align_time --room\n");
  return 2;
}

}  // namespace

int main(int argc, char** argv) {
  std::vector<const char*> pos;
  std::vector<long> ks;
  long turn = 1;
  bool synthetic = false;
  for (int i = 1; i < argc; ++i) {
    if (std::strcmp(argv[i], "--room") == 0) {
      synthetic = true;
    } else if (std::strcmp(argv[i], "--turn") == 0 && i + 1 < argc) {
      if (!parse_int(argv[++i], 1, 100000, turn)) return usage();
    } else if (std::strcmp(argv[i], "--k") == 0 && i + 1 < argc) {
      long k = 0;
      if (!parse_int(argv[++i], 1, 1000, k)) return usage();
      ks.push_back(k);
    } else if (argv[i][0] == '-' && argv[i][1] == '-') {
      return usage();
    } else {
      pos.push_back(argv[i]);
    }
  }

  if (synthetic) {
    if (!pos.empty() || !ks.empty()) return usage();
    const int ns[4] = {90, 360, 720, 1450};
    for (int n : ns) {
      const Pts a = room(2.0, 1.5, 0.0, n);
      const Pts b = room(2.2, 1.5, 0.0, n);
      std::printf("n=%4d  %8zu pairs  one iteration  min %8.3f ms\n", n,
                  measured(a) * measured(b), one_round_ms(a, b));
    }
    return 0;
  }

  if (pos.size() != 1) return usage();
  if (ks.empty()) ks.push_back(1);
  try {
    const std::vector<Scan> scans = load_jsonl(pos[0]);
    if (static_cast<std::size_t>(turn) > scans.size()) {
      std::printf("no turn %ld: the file has %zu revolutions\n", turn, scans.size());
      return 1;
    }
    const std::size_t ia = static_cast<std::size_t>(turn) - 1;
    const std::size_t ib = ia + 1 < scans.size() ? ia + 1 : ia;
    if (ib == ia) std::printf("one revolution only: timing it against itself\n");
    for (long k : ks) {
      const Pts a = to_xy(downsample(scans[ia], static_cast<std::size_t>(k)));
      const Pts b = to_xy(downsample(scans[ib], static_cast<std::size_t>(k)));
      std::printf("k=%-3ld %5zu points (%zu measured), one iteration: min %.3f ms  (%zu pairs)\n",
                  k, a.size(), measured(a), one_round_ms(a, b), measured(a) * measured(b));
    }
  } catch (const std::exception& e) {
    std::printf("error: %s\n", e.what());
    return 1;
  }
  return 0;
}

// All three within 1e-9. nan never passes.
void near3(const std::string& name, const Pose2& got, double dx, double dy, double dtheta) {
  const bool ok = std::fabs(got.dx - dx) <= 1e-9 && std::fabs(got.dy - dy) <= 1e-9 &&
                  std::fabs(got.dtheta - dtheta) <= 1e-9;
  check(name, ok, pose(got), pose(Pose2{dx, dy, dtheta}));
}

// The perfect pairs (a[i], b[i]) of two lists made by moved(): its point i IS the partner.
std::vector<Pair> zip(const Pts& a, const Pts& b) {
  std::vector<Pair> out;
  for (std::size_t i = 0; i < a.size() && i < b.size(); ++i) {
    if (a[i] && b[i]) out.emplace_back(*a[i], *b[i]);
  }
  return out;
}

template <class T>

  check(name, got == want, str(got), str(want));
}

// Rigid motion of a point list: turn by deg about the ORIGIN, then shift by (dx, dy).
// The pairs are perfect, so a vector built with it grades the ARITHMETIC only. A hole stays
// a hole.
inline std::vector<std::optional<Point>> moved(const std::vector<std::optional<Point>>& pts,
                                               double dx, double dy, double deg) {
  const double th = to_rad(deg);
  const double c = std::cos(th), s = std::sin(th);
  std::vector<std::optional<Point>> out(pts.size());
  for (std::size_t i = 0; i < pts.size(); ++i) {
    if (!pts[i]) continue;
    const double x = pts[i]->first, y = pts[i]->second;
    out[i] = Point{c * x - s * y + dx, s * x + c * y + dy};
  }
  return out;
}

// Ray-cast a w x h rectangular room (walls x = 0, x = w, y = 0, y = h) from (cx, cy) with
// the sensor turned deg0 -> n points in the SENSOR frame, one every 360/n degrees, as to_xy()
// would give them. When the sensor moves, the rays hit OTHER spots of the same walls -- the
// pairs are not perfect, which is what 2-2-1 is about. Deterministic: same input, same
// doubles. (cx, cy) must be inside the room; a ray that hits nothing leaves a hole.
inline std::vector<std::optional<Point>> room(double cx, double cy, double deg0, int n,
                                              double w = 4.0, double h = 3.0) {
  std::vector<std::optional<Point>> out;
  for (int k = 0; k < n; ++k) {
    const double phi = 360.0 * k / n;
    const double th = to_rad(deg0 + phi);
    const double ux = std::cos(th), uy = std::sin(th);
    const double lim[4] = {0.0, w, 0.0, h};
    const double dir[4] = {ux, ux, uy, uy};
    const double from[4] = {cx, cx, cy, cy};
    std::optional<double> best;
    for (int j = 0; j < 4; ++j) {
      if (std::fabs(dir[j]) < 1e-12) continue;
      const double t = (lim[j] - from[j]) / dir[j];
      if (t <= 1e-9) continue;
      const double hx = cx + t * ux, hy = cy + t * uy;
      if (-1e-9 <= hx && hx <= w + 1e-9 && -1e-9 <= hy && hy <= h + 1e-9) {
        if (!best || t < *best) best = t;
      }
    }
    if (!best) {
      out.emplace_back();
      continue;
    }
    const double r = to_rad(phi);
    out.emplace_back(Point{*best * std::cos(r), *best * std::sin(r)});
  }
  return out;
}

}  // namespace lidar_lab

2. 대응이 "가장 가까운 점"이라는 추측인데도 반복하면 답에 다가간다. 왜 한 번에는 못 가고, 왜 되풀이하면 나아지는가

가장 가까운 점을 고르면 진짜 짝보다 가까운 점이 뽑히기 쉽다. 진짜 짝은 더 멀리 있는데 그 사이에 다른 점이 끼어 있기 때문이다. 그래서 추정된 움직임은 실제보다 작게 나온다 — §2-2-1 에서 첫 반복이 답의 40 % 였던 것이 이 때문이다.

되풀이하면 나아지는 이유는 두 집합이 가까워질수록 "가장 가까운 점"이라는 추측이 실제로 맞을 확률이 올라가기 때문이다. 40 % 를 옮기고 나면 남은 어긋남이 60 % 로 줄고, 그 상태에서 다시 짝을 지으면 앞보다 나은 짝이 나온다. 대응이 나아지면 변환이 나아지고, 변환이 나아지면 대응이 나아진다.

그리고 그 성질에는 조건이 있다 — 처음부터 충분히 가까워야 한다. 멀리서 시작하면 "가장 가까운 점"이 아예 다른 벽의 점이 되고, 그러면 반복할수록 대응과 변환이 틀린 답 쪽으로 함께 수렴한다. §3-4 가 그 극단적인 경우다.

3. §2-2-2 의 dtheta = atan2(S, C) 는 어디서 나오는가 — 그리고 왜 중심을 먼저 옮기면 각 하나만 남는가

중심 먼저. 최소화하는 식에 t(옮김)가 들어 있는데, t 에 대해 미분해서 0 으로 놓으면 "두 집합의 중심이 서로 겹쳐야 한다"가 바로 나온다. 어떤 회전을 쓰든 최적의 옮김은 중심을 맞추는 것이라는 뜻이다. 그래서 중심을 각각 원점으로 보내 버리면 t 가 이미 최적이라 식에서 사라지고, 남은 미지수는 각 하나가 된다.

그 다음 각. 중심을 옮긴 점을 u·v 라 하면 최소화할 것은 sum |R u - v|^2 이고, 회전은 길이를 바꾸지 않으므로 |R u|^2 와 |v|^2 는 각과 무관한 상수다. 남는 것은 가운데 항 하나뿐이라, 식을 가장 작게 만드는 것은 sum (R u)·v 를 가장 크게 만드는 것과 같은 뜻이 된다.

그 합을 cos·sin 으로 펼치면 C·cos(theta) + S·sin(theta) 꼴이 된다(S·C 는 §2-2-2 의 두 합). 이 꼴이 가장 커지는 각은 (C, S) 가 가리키는 방향, 곧 atan2(S, C) 다. atan(S/C) 로 쓰면 가장 큰 자리와 가장 작은 자리(180° 반대)가 같은 값이 되어 벽을 등진 답이 섞여 들어온다.
