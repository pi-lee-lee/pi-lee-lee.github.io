11 · 다중 지도

층을 구역으로 나눠 그리고, 지도를 바꿔 가며 구역 사이를 다닌다

09b 는 구역 하나를 그렸다. 이 쪽의 구역 관리 노드 region_manager 는 한 층을 구역 단위로 탐사한다. 구역 하나를 다 그리면 출구 하나를 건너 다음 구역을 그린다. 건널 출구는 사용자에게 물을 수 있다. 건널 출구가 더 없으면 층 지도를 구역마다 잘라 저장하고 구역 그래프를 쓴다. 항법 모드에서는 목표가 있는 구역까지 출구를 차례로 지나며, 출구마다 지도를 바꾼다.

층은 지도를 따로 둔다. 층마다 SLAM 을 따로 실행해 층 지도를 만들고, 두 층은 엘리베이터 간선으로 잇는다. 엘리베이터를 타는 동작은 그 뒤 단계(작성 예정)에서 다루고, 이 쪽에서는 그 구간을 사람이 로봇을 옮겨 대신한다.

2. 원리 — 왜

2-1. 층마다 SLAM 하나 — 그리고 관리 노드를 따로 두는 이유

층과 층 사이에서는 SLAM 을 이어서 실행할 수 없다. 이유는 둘이다.

  • 엘리베이터 안에서 라이다는 카 내부만 보고, 카가 움직이는 동안 바퀴는 멈춰 있어 /odom 이 0 이다. 문이 열리면 같은 자세에서 다른 층이 보인다. SLAM 이 이 스캔을 원래 층 지도에 맞추려 하면 지도가 망가진다.
  • 2D 격자 지도에는 높이 축이 없다. 두 층은 같은 x-y 위에 겹쳐 있어서, 한 지도에 그리면 두 층의 벽이 같은 칸에 찍힌다.

그래서 층마다 SLAM 세션 하나, 좌표계 하나를 둔다. 같은 층 안에서는 출구를 걸어서 지나가므로 SLAM 이 이어진다 — 층 안의 구역 지도는 모두 같은 좌표계를 쓴다. 이 사실이 두 가지를 쉽게 만든다.

  • 층 안의 간선은 두 자세가 같은 좌표다(pose_to = pose_from).
  • 새 출구가 이미 탐사한 구역으로 이어지는지(고리)를 좌표로 판정할 수 있다. 출구마다 번호를 붙인 표식이 필요 없다(§2-3).

관리 노드를 따로 두는 이유는 09b 탐사 노드의 시작 조건에 있다. 09b 노드는 빈 출구 목록으로 시작한다. 그 노드로 구역 B 를 탐사하면 구역 A 의 다른 출구를 모르므로, 칠하기가 A 를 지나 그 출구 밖으로 퍼진다. region_manager 는 층의 출구 목록을 처음부터 끝까지 들고 있고, 모든 구역의 확정 출구를 벽으로 둔다. 구역 하나 안의 탐사 규칙은 09b 노드의 함수를 그대로 옮겨 쓰고, 09b 노드는 고치지 않는다.

2-2. 구역의 정의 — 입구에서, 출구를 모두 벽으로 두고 칠한 영역

구역은 칸 목록으로 저장하지 않는다. 입구 자세 하나로 저장하고, 필요할 때마다 다시 칠한다. 칠하기는 09b §2-3 과 같다 — 입구 칸에서 시작해 코스트맵의 0~98 칸만 지나고, 확정된 출구를 모두 가상 벽(09b §2-5-3)으로 둔다.

  • 첫 구역 r0 의 입구는 층을 탐사하기 시작한 자세다.
  • 새 구역의 입구는 출구를 건넌 직후의 자세다(§2-3).

칸 목록이 아니라 입구를 저장하는 이유는, 탐사 도중 출구가 확정될 때마다 구역의 모양이 바뀌기 때문이다. 벽이 늘면 구역은 줄어든다. 칸 목록을 저장해 두면 나중에 확정된 출구가 반영되지 않는다. 입구와 출구 목록만 들고 있다가 다시 칠하면, 늘 지금의 출구로 나뉜 구역이 나온다.

출구가 확정되지 않은 곳에서는 두 구역이 하나로 이어진다. 두 구역의 칠한 영역이 겹치면 region_index() 는 앞 번호의 구역을 돌려준다. 그래서 구역 나눔은 09b 실습 B 의 출구 판정이 동작해야 성립한다.

2-3. 출구의 두 옆 — 간선인가, 건널 곳인가

구역이 완성되면 확정된 출구마다 양쪽을 본다. 출구 중심에서 출구 선의 수직 방향(법선)으로 side_m 떨어진 두 점이 옆 점이다(T1). side_m 의 기본값은 2 · robot_radius 다. 출구 선 바로 옆은 부풀린 문설주의 99 칸일 수 있는데, 옆 점은 로봇 중심이 놓일 수 있는 칸이어야 구역 안으로 판정되기 때문이다.

두 옆 점판정하는 일
서로 다른 두 구역 안간선 둘방향마다 하나. 자세는 그 쪽 옆 점에서 출구 중심을 보는 자세이고, 같은 층이라 pose_to = pose_from 이다
한쪽만 구역 안건널 곳구역 안의 옆 점이 가까운 쪽, 다른 옆 점이 먼 쪽(아직 탐사하지 않은 공간)
두 점이 같은 구역 안무시구역을 나누지 않는 틈이다 — 틈 양쪽이 다른 경로로 이어져 있다
두 점 모두 구역 밖아직 판정 안 함멀리서 보인 출구다. 이웃 구역을 탐사한 뒤 다시 본다

고리도 이 표로 판정된다. 구역 C 의 새 출구 너머가 이미 탐사한 구역 A 이면, 먼 옆 점이 A 의 칠한 영역 안에 있다. 그러면 그 출구는 건널 곳이 아니라 간선이 된다. 층 안이 한 좌표계이므로 이 비교가 성립한다.

건너기는 두 걸음이다.

  1. 가까운 옆 점까지 간다 — 출구 중심을 보는 자세로.
  2. 먼 옆 점까지 간다 — 출구를 등지는 자세로. 먼 옆 점은 아직 모르는 칸일 수 있다. allow_unknown: true(09b §2-2)가 그 경로를 허용한다.

도착한 자세가 새 구역의 입구가 된다. 두 걸음 중 하나가 max_failures 번 넘게 실패하면 그 출구를 제쳐 두고 다시 판정한다. 다른 출구가 아직 탐사하지 않은 공간으로 이어질 수 있기 때문이다.

2-4. 구역 지도 자르기 — 겹침 띠와 map_saver

구역의 칠한 영역은 로봇 중심이 닿는 칸이다. 그 칸만 잘라 내면 벽이 빠진다 — 벽은 99 · 100 띠 너머에 있기 때문이다. 그래서 둘레를 더 남긴다.

  1. 칠한 영역의 칸에서 band_m 안에 있는 /map 칸을 모두 남긴다(T2). 8-이웃 걸음으로 세므로 남는 모양은 정사각형이다.
  2. 남기지 않는 칸은 -1(모름)로 바꾸고, 남긴 칸의 경계 상자로 자른 뒤 원점을 그 상자의 왼쪽 아래 모서리로 옮긴다(T3).

겹침 띠가 필요한 이유는 둘이다.

  • 벽이 지도에 들어가야 AMCL 이 스캔을 맞춘다.
  • 지도를 바꾸는 자리(출구의 옆 점)가 두 구역 지도 모두에 들어가야 한다. 바꾸기 직전의 위치가 새 지도 안에 있어야 그 지도에서 초기 위치를 줄 수 있다. 그래서 band_m 은 side_m 보다 넉넉히 크게 정한다(내가 정하는 값, 출발값 1.0 m).

저장은 Nav2 의 map_saver 가 한다. 자른 격자를 regions/region_map 토픽에 TRANSIENT_LOCAL 로 내고, /map_saver/save_map 서비스(Humble SaveMap.srv)에 그 토픽을 저장하게 한다. 요청의 필드는 map_topic · map_url · image_format · map_mode · free_thresh · occupied_thresh 이고, 응답은 result(bool) 하나다. 09 의 map_saver_cli 와 같은 저장 코드를 쓰므로 .pgm · .yaml 의 형식과 문턱(0.25 · 0.65)이 09 §3-5 와 같다.

map_saver_server 는 lifecycle 노드다. lifecycle_manager 가 active 로 올려야 서비스가 응답한다. Humble nav2_bringup 의 slam_launch.py 도 같은 구성(map_saver_server + node_names: ['map_saver'] 인 lifecycle_manager)을 쓴다.

2-5. 지도 사이 이동 — load_map 과 /initialpose

목표가 다른 구역에 있으면 구역 그래프에서 간선 수가 가장 적은 경로를 찾는다(너비 우선 탐색, T4). 간선에는 방향이 있다 — 출구 하나에서 간선이 둘 나오는 이유다. 간선 하나를 지나는 순서는 다음과 같다.

  1. Nav2 로 간선의 pose_from 까지 간다 — 지금 지도의 좌표다.
  2. /map_server/load_map 서비스(Humble LoadMap.srv)로 다음 구역의 지도를 올린다. 요청은 map_url, 응답의 result 가 0(RESULT_SUCCESS)이면 성공이다.
  3. /initialpose 로 간선의 pose_to 를 공분산과 함께 준다(09b §2-7).
  4. relocalize_s 동안 기다린 뒤 다음 간선이나 목표로 간다.

3 이 필요한 이유는 AMCL 의 동작에 있다. Humble 의 amcl_node.cpp 는 새 지도를 받아도 파티클을 다시 초기화하지 않는다. 같은 층이면 좌표가 같아서 파티클이 그대로 맞지만, 층이 바뀌면 옛 층의 좌표를 그대로 들고 있게 된다. 그래서 같은 층에서도 늘 다시 준다 — 층 사이와 같은 절차를 한 가지로 쓰기 위해서다.

global_costmap 의 static_layer 도 새 /map 을 받아 격자 크기를 바꾼다. 그래서 지도는 진행 중인 목표가 없을 때, 로봇이 멈춰 있는 동안 바꾼다.

엘리베이터 간선은 pose_from(층 1 지도)과 pose_to(층 B1 지도)가 서로 다른 좌표계에 있다. 절차는 같고, 1 과 2 사이에 상태 AWAIT_ELEVATOR 가 들어간다. 지금은 사람이 로봇을 다른 층의 엘리베이터 앞으로 옮긴 뒤 arrived 를 보낸다. 그 뒤 단계에서는 이 자리에 층 판별이 들어간다 — 카 안에서 위를 보는 카메라로 층 표시를 읽고, 내린 뒤 주변을 촬영해 층을 확인하고, 틀리면 다시 타는 순서다.

2-6. 사용자에게 묻기 — 구역이 끝날 때마다

ask_user 가 참이면 구역이 끝날 때 상태가 AWAIT_USER 가 된다. 이때 사용자에게 두 가지를 보인다.

  • /regions/state 의 options=0:f1/r0->?,1:… — 건널 곳의 번호와 그 출구가 있는 구역
  • /regions/crossings — 건널 곳마다 가까운 옆 점 위에 go k 글자 마커. Foxglove 3D 에서 어느 출구가 몇 번인지 본다

사용자는 regions/command 에 go <k>(그 출구를 건넌다) 또는 finish(층 탐사를 끝낸다)를 보낸다. 묻는 이유는 탐사 범위를 사람이 정하게 하기 위해서다 — 계단 쪽 출구나 들어가면 안 되는 방을 건너지 않게 할 수 있다. ask_user 가 거짓이면 가장 가까운 건널 곳을 고른다. 고르는 규칙은 09b 의 목표 고르기와 같은 질문이라 TODO(you) 로 남겼다.

// Index of the first region whose mask (one byte per costmap cell) contains the costmap cell of p.
// -1 if p is outside the costmap or in no region.
inline int region_index(const Grid & cost, const std::vector<std::vector<uint8_t>> & masks, Point p)
{
  Cell c;
  if (!cell_of(cost, p, c)) { return -1; }
  const std::size_t k = cost.index(c.x, c.y);
  for (std::size_t i = 0; i < masks.size(); ++i) {
    if (masks[i].size() == cost.data.size() && masks[i][k]) { return static_cast<int>(i); }
  }
  return -1;
}

힌트 T1 — side_points() · 출구 중심에서 법선 방향으로 ± d

할 일 — 출구(끝점 a · b)와 거리 d 를 받아, 중심에서 a → b 의 왼쪽 법선 방향으로 d 떨어진 점(left)과 반대쪽 점(right)을 출력 인자로 돌려준다. a 와 b 가 같으면 방향이 없으므로 false.

완결 코드

/* 완결 코드 T1 - ros2_ws/src/rpi5_explore/include/rpi5_explore/region_core.hpp */
inline bool side_points(const Exit & e, double d, Point & left, Point & right)
{
  const double len = distance(e.a, e.b);
  if (len == 0.0) { return false; }
  const double nx = -(e.b.y - e.a.y) / len;
  const double ny = (e.b.x - e.a.x) / len;
  const Point c{(e.a.x + e.b.x) / 2.0, (e.a.y + e.b.y) / 2.0};
  left = {c.x + d * nx, c.y + d * ny};
  right = {c.x - d * nx, c.y - d * ny};
  return true;
}

코드 설명

  • len 으로 나누는 것은 방향을 길이 1 로 만드는 것이다. 나누지 않으면 출구가 넓을수록 옆 점이 멀어진다.
  • (-dy, dx) — 벡터 (dx, dy) 를 왼쪽으로 90° 돌린 것이다. 오른쪽은 부호를 바꾼 (dy, -dx) 이고, 코드는 중심에서 빼는 것으로 대신한다.
  • Point & left 는 출력 인자다 — 함수 안에서 대입한 값이 부른 쪽의 변수에 남는다.
  • 다르게 써도 되는 곳 — 어느 쪽을 left 로 부르든 판정(§2-3)에는 상관없다. 다만 시험은 "a → b 의 왼쪽"을 left 로 채점한다.

/* 완결 코드 T2 - ros2_ws/src/rpi5_explore/include/rpi5_explore/region_core.hpp */
inline std::vector<uint8_t> band_mask(
  const Grid & map, const Grid & cost, const std::vector<uint8_t> & reach, int band_cells)
{
  std::vector<uint8_t> keep(map.data.size(), 0);
  if (reach.size() != cost.data.size() || band_cells < 0) { return keep; }
  std::vector<int> dist(map.data.size(), -1);
  std::queue<Cell> todo;
  for (int y = 0; y < map.height; ++y) {
    for (int x = 0; x < map.width; ++x) {
      Cell c;
      if (!cell_of(cost, cell_center(map, {x, y}), c) || !reach[cost.index(c.x, c.y)]) { continue; }
      dist[map.index(x, y)] = 0;
      keep[map.index(x, y)] = 1;
      todo.push({x, y});
    }
  }
  while (!todo.empty()) {
    const Cell c = todo.front();
    todo.pop();
    const int d = dist[map.index(c.x, c.y)];
    if (d == band_cells) { continue; }
    for (int dy = -1; dy <= 1; ++dy) {
      for (int dx = -1; dx <= 1; ++dx) {
        const int nx = c.x + dx;
        const int ny = c.y + dy;
        if ((dx == 0 && dy == 0) || !map.inside(nx, ny) || dist[map.index(nx, ny)] >= 0) { continue; }
        dist[map.index(nx, ny)] = d + 1;
        keep[map.index(nx, ny)] = 1;
        todo.push({nx, ny});
      }
    }
  }
  return keep;
}

코드 설명

  • dist — 칸마다 시작점에서 몇 걸음인지. -1 은 아직 닿지 않았다는 뜻이고, 한 칸을 두 번 넣지 않는 표시를 겸한다(09b 힌트 T2 의 mask 와 같은 역할).
  • 시작점을 모두 먼저 큐에 넣는다. 그래야 너비 우선 탐색이 "가장 가까운 시작점까지의 걸음 수"를 센다. 시작점을 하나씩 따로 칠하면 같은 결과를 내지만 칸마다 여러 번 계산한다.
  • if (d == band_cells) { continue; } — 한계 걸음에 닿은 칸은 남기되 이웃으로 넓히지 않는다. 그래서 정확히 band_cells 걸음까지 남는다.
  • 코스트맵과 /map 의 해상도가 달라도 cell_center() → cell_of() 로 세계 좌표를 거쳐 맞춘다(09b 힌트 T3 의 reachable 과 같다).

/* 완결 코드 T3 - ros2_ws/src/rpi5_explore/include/rpi5_explore/region_core.hpp */
inline Grid crop(const Grid & map, const std::vector<uint8_t> & keep)
{
  Grid out;
  out.resolution = map.resolution;
  out.width = 0;
  if (keep.size() != map.data.size()) { return out; }
  int x0 = map.width, y0 = map.height, x1 = -1, y1 = -1;
  for (int y = 0; y < map.height; ++y) {
    for (int x = 0; x < map.width; ++x) {
      if (!keep[map.index(x, y)]) { continue; }
      x0 = std::min(x0, x); y0 = std::min(y0, y);
      x1 = std::max(x1, x); y1 = std::max(y1, y);
    }
  }
  if (x1 < 0) { return out; }
  out.width = x1 - x0 + 1;
  out.height = y1 - y0 + 1;
  out.origin_x = map.origin_x + x0 * map.resolution;
  out.origin_y = map.origin_y + y0 * map.resolution;
  out.data.assign(static_cast<std::size_t>(out.width) * out.height, -1);
  for (int y = y0; y <= y1; ++y) {
    for (int x = x0; x <= x1; ++x) {
      if (keep[map.index(x, y)]) { out.data[out.index(x - x0, y - y0)] = map.at(x, y); }
    }
  }
  return out;
}

코드 설명

  • x0 = map.width · x1 = -1 로 시작하면 첫 남긴 칸에서 둘 다 그 칸으로 바뀐다. 끝까지 x1 < 0 이면 남긴 칸이 없다는 뜻이다.
  • 원점 — 칸 (x0, y0) 의 모서리는 세계 좌표로 origin + x0 · resolution 이다. 원점을 옮기지 않으면 지도가 그만큼 어긋난 자리에 놓인다(map_server 가 읽는 origin, 09 §3-5).
  • 상자 안이라도 남기지 않은 칸은 -1 로 둔다 — 이웃 구역의 안쪽까지 지도에 들어가지 않게 하려는 것이다. 겹침 띠만큼만 이웃이 들어간다.

/* 완결 코드 T4 - ros2_ws/src/rpi5_explore/include/rpi5_explore/region_core.hpp */
inline std::vector<int> region_path(int n_regions, const std::vector<Edge> & edges, int from, int to)
{
  std::vector<int> path;
  if (from == to || from < 0 || to < 0 || from >= n_regions || to >= n_regions) { return path; }
  std::vector<int> via(n_regions, -1);         // edge used to reach each region
  std::vector<uint8_t> seen(n_regions, 0);
  std::queue<int> todo;
  seen[from] = 1;
  todo.push(from);
  while (!todo.empty()) {
    const int r = todo.front();
    todo.pop();
    for (std::size_t k = 0; k < edges.size(); ++k) {
      const Edge & e = edges[k];
      if (e.from != r || e.to < 0 || e.to >= n_regions || seen[e.to]) { continue; }
      seen[e.to] = 1;
      via[e.to] = static_cast<int>(k);
      if (e.to == to) {
        for (int at = to; at != from; at = edges[via[at]].from) { path.push_back(via[at]); }
        std::reverse(path.begin(), path.end());
        return path;
      }
      todo.push(e.to);
    }
  }
  return path;
}

코드 설명

  • 너비 우선 탐색은 간선 수가 적은 구역부터 꺼낸다. 그래서 처음 닿은 경로가 간선 수가 가장 적은 경로다 — 시험의 "긴 경로 0 → 4 → 5 → 2" 가 뽑히지 않는 이유다.
  • via[r] — 구역 r 에 처음 닿게 한 간선. 도착하면 via 를 따라 출발점까지 거꾸로 걸어가고, std::reverse 로 순서를 뒤집는다.
  • seen — 이미 닿은 구역에는 다시 가지 않는다. 출구마다 간선이 양방향으로 있으므로, 이것이 없으면 0 → 1 → 0 → 1 … 을 끝없이 반복한다.
  • 다르게 써도 되는 곳 — 간선마다 거리를 두고 짧은 거리 순(데이크스트라)으로 찾을 수도 있다. 이 쪽은 지도를 바꾸는 횟수를 줄이는 쪽을 골랐다.

  m.data.assign(g.data.begin(), g.data.end());
  return m;
}

static std::string pose_str(const Pose2D & p)
{
  char b[96];
  std::snprintf(b, sizeof(b), "[%.3f, %.3f, %.3f]", p.x, p.y, p.yaw);
  return b;
}

static Pose2D pose_of(const YAML::Node & n)       // [x, y, yaw]
{
  return {n[0].as<double>(), n[1].as<double>(), n[2].as<double>()};
}

static Pose2D facing(core::Point p, core::Point target)   // stand at p, look at target
{
  return {p.x, p.y, std::atan2(target.y - p.y, target.x - p.x)};
}

static Pose2D away(core::Point p, core::Point from)       // stand at p, look away from `from`
{
  return {p.x, p.y, std::atan2(p.y - from.y, p.x - from.x)};
}

  // One reachable mask per region: flood fill from the region's entry with every confirmed exit
  // as a wall (09b §2-5-3). A region is "what the robot can reach from its entry without crossing an exit".
  std::vector<std::vector<uint8_t>> region_masks() const
  {
    std::vector<std::vector<uint8_t>> masks;
    const std::vector<core::Cell> walls = exit_walls();
    for (const RegionRec & g : regions_) {
      core::Cell c;
      if (core::cell_of(cost_, {g.entry.x, g.entry.y}, c)) { masks.push_back(core::reachable_mask(cost_, c, walls)); }
      else { masks.emplace_back(cost_.data.size(), 0); }
    }
    return masks;
  }

  bool failed(std::size_t i) const
  {
    return std::find(failed_exits_.begin(), failed_exits_.end(), static_cast<int>(i)) != failed_exits_.end();
  }

  // Look at both sides of every confirmed exit (§2-3):
  //   both sides in two different regions -> two directed edges (the map switch happens on each side)
  //   one side in a region, the other in none -> a crossing to unexplored space
  //   same region on both sides, or no region on either side -> not a region boundary (yet); ignored
  void classify_exits()
  {
    masks_ = region_masks();
    crossings_.clear();
    edges_.clear();
    for (std::size_t i = 0; i < exits_.size(); ++i) {
      const core::Exit & e = exits_[i];
      core::Point l, r;
      if (e.hits < min_hits_ || failed(i) || !core::side_points(e, side_m_, l, r)) { continue; }
      const int il = core::region_index(cost_, masks_, l);
      const int ir = core::region_index(cost_, masks_, r);
      const core::Point c{(e.a.x + e.b.x) / 2.0, (e.a.y + e.b.y) / 2.0};
      if (il >= 0 && ir >= 0 && il != ir) {
        edges_.push_back({il, ir, "exit", facing(l, c), facing(l, c)});   // same frame: pose_to = pose_from
        edges_.push_back({ir, il, "exit", facing(r, c), facing(r, c)});
      } else if (il >= 0 && ir < 0) {
        crossings_.push_back({static_cast<int>(i), il, facing(l, c), away(r, c)});
      } else if (ir >= 0 && il < 0) {
        crossings_.push_back({static_cast<int>(i), ir, facing(r, c), away(l, c)});
      }
    }
  }

    q.setRPY(0.0, 0.0, p.yaw);
    m.pose.pose.orientation = tf2::toMsg(q);
    m.pose.covariance[0] = sigma_xy_ * sigma_xy_;
    m.pose.covariance[7] = sigma_xy_ * sigma_xy_;
    m.pose.covariance[35] = sigma_yaw_ * sigma_yaw_;
    pub_initialpose_->publish(m);
    return true;
  }

  {

⑭ 경로 시작 · 간선 도착 — 엘리베이터 간선이면 AWAIT_ELEVATOR 에서 멈춘다(§2-5).

  void start_route(const std::string & region, const Pose2D & goal)
  {
    if (state_ != State::IDLE) { RCLCPP_WARN(get_logger(), "busy - goto ignored"); return; }
    const int to = region_named(region);
    if (to < 0) { RCLCPP_WARN(get_logger(), "unknown region %s", region.c_str()); return; }
    std::vector<core::Edge> plain;
    for (const EdgeRec & e : edges_) { plain.push_back({e.from, e.to}); }
    path_ = core::region_path(static_cast<int>(regions_.size()), plain, cur_, to);
    if (to != cur_ && path_.empty()) { RCLCPP_WARN(get_logger(), "no route to %s", region.c_str()); return; }
    goal_pose_ = goal;
    path_pos_ = 0;
    leg_failures_ = 0;
    next_leg();
  }

  void next_leg()
  {
    if (path_pos_ < path_.size()) { start_leg(State::TO_EDGE, edges_[path_[path_pos_]].pose_from); }
    else { start_leg(State::TO_GOAL, goal_pose_); }
  }

  void arrive_at_edge()
  {
    leg_failures_ = 0;
    const EdgeRec & e = edges_[path_[path_pos_]];
    if (e.type == "elevator") {                                // the ride itself is a later stage
      state_ = State::AWAIT_ELEVATOR;
      RCLCPP_WARN(get_logger(), "elevator to %s: take the robot there, then send \"arrived\"", regions_[e.to].name.c_str());
      return;
    }
    state_ = State::SWITCHING;
    switch_step_ = 0;
  }

⑮ 지도 바꾸기 — §2-5 의 2 ~ 4. switch_step_ 이 네 단계를 가른다 — 0 요청 전, 1 응답 대기, 2 초기 위치 보낼 차례, 3 다시 맞추는 시간 대기.

  // Map switch at an edge (§2-5): load the next region's map, then re-seed AMCL in that map - AMCL keeps
  // its particles when a new map arrives (09b §2-7), so the pose must be given again.
  void switch_tick(const rclcpp::Time & t)
  {
    const EdgeRec & e = edges_[path_[path_pos_]];
    if (switch_step_ == 0) {
      if (!load_client_->service_is_ready()) { return; }
      auto req = std::make_shared<nav2_msgs::srv::LoadMap::Request>();
      req->map_url = regions_[e.to].map_file;
      switch_step_ = 1;                                        // 1 = waiting for the response
      load_client_->async_send_request(
        req, [this](rclcpp::Client<nav2_msgs::srv::LoadMap>::SharedFuture f) {
          if (f.get()->result != nav2_msgs::srv::LoadMap::Response::RESULT_SUCCESS) { abort_route("load_map failed"); return; }
          switch_step_ = 2;
        });
    } else if (switch_step_ == 2) {
      if (!send_pose(e.pose_to)) { return; }
      switch_since_ = t;
      switch_step_ = 3;
    } else if (switch_step_ == 3 && (t - switch_since_).seconds() >= relocalize_s_) {
      cur_ = e.to;
      ++path_pos_;
      next_leg();
    }
  }

  void abort_route(const std::string & why)
  {
    if (goal_active_ && !cancel_pending_) { cancel_goal(false); }
    state_ = State::IDLE;
    RCLCPP_ERROR(get_logger(), "route stopped in %s: %s", regions_[cur_].name.c_str(), why.c_str());
  }

  void on_result(const GoalHandle::WrappedResult & res)
  {
    goal_active_ = false;
    goal_handle_.reset();
    const bool ok = (res.code == rclcpp_action::ResultCode::SUCCEEDED);
    const bool bad = (res.code == rclcpp_action::ResultCode::ABORTED) ||
                     (res.code == rclcpp_action::ResultCode::CANCELED && cancel_counts_);
    switch (state_) {
      case State::EXPLORING:
        if (bad) { note_failure(target_); }                   // the 09b rule
        break;
      case State::TO_EXIT:
        if (ok) { leg_failures_ = 0; start_leg(State::CROSSING, crossings_[chosen_].far); }
        else if (bad) { leg_failed(); }
        break;
      case State::CROSSING:
        if (ok) { enter_new_region(); }
        else if (bad) { leg_failed(); }
        break;
      case State::RETURNING:
        if (ok) { state_ = State::SETTLING; settle_since_ = now(); }
        else if (bad && ++leg_failures_ > max_failures_) { finish(State::ABORTED, 3, "could not return to the floor start"); }
        break;
      case State::TO_EDGE:
        if (ok) { arrive_at_edge(); }
        else if (bad && ++leg_failures_ > max_failures_) { abort_route("could not reach the exit"); }
        break;
      case State::TO_GOAL:
        if (ok) { state_ = State::IDLE; RCLCPP_INFO(get_logger(), "arrived (%s)", regions_[cur_].name.c_str()); }
        else if (bad && ++leg_failures_ > max_failures_) { abort_route("could not reach the goal"); }
        break;
      default:
        break;
    }
    cancel_pending_ = false;
    maybe_shutdown();
  }

  void on_command(const std::string & c)
  {
    std::istringstream in(c);
    std::string word;
    in >> word;
    if (word == "start") {
      start_requested_ = true;
    } else if (word == "stop") {
      finish(State::ABORTED, 4, "stopped by command");       // finish() cancels an active goal
    } else if (word == "go" && state_ == State::AWAIT_USER) {
      std::size_t k = 0;
      if (in >> k && k < crossings_.size()) { start_crossing(k); }
      else { RCLCPP_WARN(get_logger(), "go <k>: k must be one of the options in regions/state"); }
    } else if (word == "finish" && state_ == State::AWAIT_USER) {
      finish_floor();
    } else if (word == "goto") {
      std::string region;
      Pose2D g;
      if (in >> region >> g.x >> g.y >> g.yaw) { start_route(region, g); }
      else { RCLCPP_WARN(get_logger(), "goto <region> <x> <y> <yaw>"); }
    } else if (word == "arrived" && state_ == State::AWAIT_ELEVATOR) {
      state_ = State::SWITCHING;
      switch_step_ = 0;
    } else {
      RCLCPP_WARN(get_logger(), "not accepted in this state: %s", c.c_str());
    }
  }
  void tick()
  {
    const rclcpp::Time t = now();
    switch (state_) {
      case State::WAIT_DATA: {
        Pose2D r;
        if (robot_radius_ <= 0.0 || !have_map_ || !have_cost_ || !robot_pose(r)) { break; }
        if (!autostart_ && !start_requested_) { break; }
        regions_.push_back({floor_ + "/r0", r, ""});           // the floor start is region 0's entry
        cur_ = 0;
        t_start_ = t;
        state_ = State::EXPLORING;
        RCLCPP_INFO(get_logger(), "exploring %s from (%.2f, %.2f)", regions_[0].name.c_str(), r.x, r.y);
        break;
      }
      case State::EXPLORING: explore_tick(t); break;
      case State::TO_EXIT:
      case State::CROSSING:
      case State::RETURNING:
      case State::TO_EDGE:
      case State::TO_GOAL:
        if (!goal_active_ && !cancel_pending_) { send_goal(leg_); }   // retry a failed leg (on_result counts)
        break;
      case State::SETTLING:
        if ((t - settle_since_).seconds() >= settle_s_) { start_saving(); }
        break;
      case State::SAVING: save_tick(); break;
      case State::LOCALIZING: localize_tick(); break;
      case State::SWITCHING: switch_tick(t); break;
      case State::AWAIT_USER:                                  // waits for go <k> / finish
      case State::AWAIT_ELEVATOR:                              // waits for arrived
      case State::IDLE:                                        // waits for goto
      case State::DONE:
      case State::ABORTED:
        break;
    }
    if (!rclcpp::ok()) { return; }                             // finish() may have shut the context down
    publish_state();
    publish_markers();
    publish_crossings();
  }

3-8. 실습 D — 두 번째 층 등록과 엘리베이터 간선 조립 후

엘리베이터가 없어도 서로 떨어진 방 둘로 절차를 확인할 수 있다. 방 2 를 층 b1 로 다룬다. 엘리베이터를 타는 대신 사람이 로봇을 옮긴다.

  1. 층 b1 을 탐사한다 — 로봇을 방 2 로 옮기고, SLAM 과 Nav2 를 새로 실행한다(새 SLAM 세션 = 새 좌표계). 실습 A 와 같은 명령에 -p floor:=b1 을 더한다. /maps/b1/graph.yaml 이 생긴다.
  2. "엘리베이터 앞" 자세를 잰다 — 방마다 한 자리를 엘리베이터 앞으로 정한다. 그 층의 항법 구성에서 로봇을 그 자리에 두고 ros2 run tf2_ros tf2_echo map base_footprint 로 x · y · yaw(라디안)를 읽는다. 층 f1 과 층 b1 에서 각각 한다.
  3. 건물 파일을 쓴다 — 아래 꼴로 /maps/building.yaml. 간선은 방향마다 하나씩 둘이다.
  4. 층 사이로 보낸다 — 층 f1 의 항법 구성에서 -p graph_file:=/maps/building.yaml 로 구역 관리 노드를 실행하고 goto b1/r0 <x> <y> <yaw> 를 보낸다. 좌표는 /maps/b1/graph.yaml 에 있는 b1/r0 의 entry 자세다.
  5. 엘리베이터 구간 — 로봇이 층 f1 의 엘리베이터 앞에서 AWAIT_ELEVATOR 로 멈춘다. 로봇을 방 2 의 엘리베이터 앞에 같은 방향으로 옮기고 {data: arrived} 를 보낸다. b1 지도가 올라오고 초기 위치가 주어진 뒤 목표로 간다.
# /maps/building.yaml - written by hand
graphs: [/maps/f1/graph.yaml, /maps/b1/graph.yaml]
edges:
  - from: f1/r1                 # the region of f1 that has the elevator door
    to: b1/r0
    type: elevator
    pose_from: [0.0, 0.0, 0.0]  # ____ in f1's map frame: in front of the elevator (tf2_echo on f1)
    pose_to: [0.0, 0.0, 0.0]    # ____ in b1's map frame: in front of the elevator (tf2_echo on b1)
  - from: b1/r0
    to: f1/r1
    type: elevator
    pose_from: [0.0, 0.0, 0.0]  # ____ b1 side
    pose_to: [0.0, 0.0, 0.0]    # ____ f1 side

항법 모드는 start_region 이 비어 있으면 첫 그래프(graphs 의 첫 줄)의 end_region · end_pose 에서 시작한다. 다른 자리에서 시작하려면 -p start_region:=b1/r0 -p initial_pose:="[x, y, yaw]" 를 준다.

🤔 이해 확인

1. 층마다 지도를 따로 두는 이유 둘은?

① 엘리베이터 안에서는 라이다가 카 내부만 보고 /odom 이 0 이며, 문이 열리면 같은 자세에서 다른 층이 보이므로 SLAM 을 이어 갈 수 없다. ② 2D 격자에는 높이 축이 없어 두 층의 벽이 같은 칸에 겹친다(§2-1).

2. 09b 탐사 노드를 구역마다 다시 실행하면 무엇이 문제인가?

09b 노드는 빈 출구 목록으로 시작한다. 구역 B 를 탐사할 때 구역 A 의 다른 출구를 모르므로, 칠하기가 A 를 지나 그 출구 밖까지 퍼진다. 그래서 층의 출구 목록을 처음부터 끝까지 들고 있는 관리 노드를 따로 둔다(§2-1).

3. 구역을 칸 목록이 아니라 입구 자세로 저장하는 이유는?

탐사 도중 출구가 확정될 때마다 벽이 늘어 구역의 모양이 바뀐다. 칸 목록은 나중에 확정된 출구를 반영하지 못한다. 입구와 출구 목록으로 필요할 때 다시 칠하면 늘 지금의 출구로 나뉜 구역이 나온다(§2-2).

4. 새 출구가 이미 탐사한 구역으로 이어지는지(고리)를 표식 번호 없이 판정할 수 있는 이유는?

한 층은 SLAM 하나라서 모든 구역이 같은 좌표계에 있다. 출구의 먼 옆 점이 이미 탐사한 구역의 칠한 영역 안에 있는지를 좌표로 비교하면 된다. 들어 있으면 그 출구는 건널 곳이 아니라 간선이다(§2-1 · §2-3).

5. 구역 지도에 겹침 띠를 남기는 이유 둘은? band_m 은 side_m 과 비교해 어떻게 정하는가?

① 칠한 영역은 로봇 중심이 닿는 칸이라 벽이 빠진다 — 벽이 있어야 AMCL 이 스캔을 맞춘다. ② 지도를 바꾸는 자리(출구의 옆 점)가 새 지도 안에 있어야 그 지도에서 초기 위치를 줄 수 있다. 그래서 band_m 은 side_m 보다 넉넉히 크게 정한다(§2-4).

6. 같은 층에서 지도를 바꾼 뒤에도 /initialpose 를 다시 주는 이유는?

AMCL 은 새 지도를 받아도 파티클을 다시 초기화하지 않는다. 같은 층이면 좌표가 같아 파티클이 맞지만, 층이 바뀌면 옛 층의 좌표를 들고 있게 된다. 절차를 하나로 쓰기 위해 같은 층에서도 늘 다시 준다(§2-5).

7. 출구 하나에서 간선이 둘 나오는 이유는?

간선에는 방향이 있다. 지도를 바꾸는 자세(pose_from)가 출발하는 쪽 옆 점이므로, A → B 와 B → A 의 자세가 다르다. 그래서 방향마다 간선을 하나씩 둔다(§2-3 · §2-5).

8. (일부러 틀려 보기) T4 에서 seen 검사를 빼면 어떻게 되는가?

출구마다 간선이 양방향으로 있어서 탐색이 0 → 1 → 0 → 1 … 을 끝없이 반복한다. 시험은 아무 줄도 출력하지 않고 끝나지 않는다(힌트 T4 의 흔한 실수).
