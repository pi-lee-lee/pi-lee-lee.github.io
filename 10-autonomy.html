2. 원리 — 왜

2-1. 런치 계층화는 디버깅 전략이다

노드가 15개를 넘어가면 하나의 런치파일로는 관리가 안 된다. 15개 노드가 동시에 뜨면 로그가 뒤섞여 어느 노드가 실패했는지 찾을 수 없다. 계층별로 따로 띄울 수 있어야 문제가 생겼을 때 "어느 계층인가"를 좁힐 수 있다.

rpi5_bringup/launch/
├── robot.launch.py         ← 하드웨어 계층 (센서 + 구동 + TF)          [제공됨]
├── perception.launch.py    ← 인지 계층 (SLAM / 검출기 선택)             [★ 직접 작성]
├── navigation.launch.py    ← Nav2                                    [★ 직접 작성]
└── autonomy.launch.py      ← 위 셋 + 감독 노드를 포함하는 최상위          [★ 직접 작성]

★ 표시된 세 개는 저장소에 아직 없다. 04 단계에서 배운 런치 문법과 ros2_ws/src/rpi5_bringup/launch/robot.launch.py 를 본보기로 삼는다. 이것을 직접 짜는 것이 이 단계의 첫 실습이다 — 시스템의 구조를 스스로 표현할 수 있는지가 여기서 드러난다.

2-2. 안전은 기능이 아니라 요구사항이다 — 3단 방어

   ① MCU 워치독 (하드웨어)     N ms 무명령 → 즉시 정지
      ↑ Pi 가 죽어도 동작. 최후의 보루                       (06a·06 에서 펌웨어에 넣었다)

   ② mcu_bridge 워치독 (ROS)   cmd_timeout_s 초과 → 0 발행
      ↑ 상위 노드가 죽거나 멈췄을 때                          (06 의 C++ 브리지)

   ③ 속도 제한 (파라미터)       max_linear_vel / max_angular_vel
      ↑ Nav2 튜닝 실수로 큰 값이 와도 하드웨어 보호            (robot_params.yaml)

세 가지가 독립적으로 동작해야 한다. 하나가 죽어도 나머지가 남는다. 감독 노드의 "사람 앞에서 멈춤"은 이 세 겹 위에 얹는 네 번째 층이지, 아래 세 층을 대신하지 않는다. 그리고 물리 E-stop 버튼(모터 전원 차단)은 이 모든 소프트웨어와 무관하게 있어야 한다.

2-3. 감독(supervision)이란 무엇인가 — Nav2 가 이미 하는 것과 하지 않는 것

Nav2 의 bt_navigator 는 행동 트리(BT)로 "경로를 못 찾으면 재계획, 막히면 제자리 회전·후진·대기"까지 스스로 복구한다. 그런데 그것은 하나의 목표 안에서의 일이다. 다음은 Nav2 가 모르는 것이다.

이 규칙에는 함정이 있다 — 3-3 의 TODO 가 그것이다

① 목표 근처에서 최종 yaw 를 맞추느라 제자리 회전하는 동안 distance_remaining 은 줄지 않는다. ② Nav2 의 복구 행동(후진·회전) 중에는 거리가 잠시 늘어난다. ③ 재계획으로 경로가 길어지면 값이 튀어오른다. 이런 순간을 정체로 오판하면 로봇은 도착 직전에 취소당한다. number_of_recoveries, 목표 허용 오차, 시간 창을 어떻게 조합할지는 당신이 정한다.

2-4. 왜 감독 노드가 /cmd_vel 을 직접 쏘지 않는가

"사람이 보이면 속도 0 을 발행하면 되지 않나?" — Nav2 의 controller_server 도 같은 토픽에 10 Hz 로 발행하고 있다. 같은 토픽에 발행자가 둘이면 mcu_bridge 는 마지막에 도착한 값을 따른다. 0 과 0.25 가 번갈아 들어가 로봇이 덜컥거리며 전진한다. 05 단계의 "하나의 좌표계에는 부모가 하나"와 같은 종류의 문제다.

그래서 멈추는 수단은 목표 취소(goal cancel) 뿐이다. 취소하면 Nav2 가 스스로 0 을 내고 멈춘다. 발행자는 여전히 하나다. 정말로 여러 소스(조이스틱, 감독, Nav2)의 속도를 중재해야 한다면 그 일을 전담하는 노드(twist_mux, 우선순위 기반)를 따로 둔다 — §3-8 확장 항목이다.

2-6. systemd 자동 기동 — 개발 중에는 켜지 않는다

전원을 넣으면 로봇이 뜨게 하는 것은 한 줄이다. 그러나 개발 중에 enable 하면 부팅 때마다 로봇이 떠서, 당신이 개발용으로 띄운 노드와 같은 이름·같은 토픽으로 충돌한다. 두 개의 mcu_bridge 가 같은 시리얼 포트를 열려고 싸우는 상황이다. 시스템이 안정된 뒤에 켠다.

perception.launch.py — 인지 계층

"""인지 계층: 지도 작성(SLAM) 또는 검출기.

    ros2 launch rpi5_bringup perception.launch.py mode:=mapping detector:=none
    ros2 launch rpi5_bringup perception.launch.py mode:=navigation detector:=yolo

mode:=navigation 일 때 위치추정(AMCL)과 map_server 는 Nav2 의 bringup_launch.py 가
띄우므로 여기서는 검출기만 띄운다. (09 단계 §3-7 참조)
"""
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, IncludeLaunchDescription
from launch.conditions import IfCondition
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import LaunchConfiguration, PathJoinSubstitution, PythonExpression
from launch_ros.actions import Node
from launch_ros.substitutions import FindPackageShare


def generate_launch_description():
    mode = LaunchConfiguration('mode')
    detector = LaunchConfiguration('detector')
    bringup_share = FindPackageShare('rpi5_bringup')

    # ── SLAM (mapping 모드에서만) ─────────────────────────────────────────
    #   ★ slam_toolbox 런치의 use_sim_time 기본값은 'true' 다. 실제 로봇에서는 반드시 false.
    slam = IncludeLaunchDescription(
        PythonLaunchDescriptionSource([PathJoinSubstitution([
            FindPackageShare('slam_toolbox'), 'launch', 'online_async_launch.py'])]),
        launch_arguments={
            'use_sim_time': 'false',
            'slam_params_file': PathJoinSubstitution([bringup_share, 'config', 'slam_params.yaml']),
        }.items(),
        condition=IfCondition(PythonExpression(["'", mode, "' == 'mapping'"])),
    )

    # ── 검출기: 같은 /detections 를 내는 두 구현 중 하나 ─────────────────
    yolo = Node(
        package='rpi5_vision', executable='yolo_detector', name='yolo_detector',
        output='screen',
        parameters=[PathJoinSubstitution([bringup_share, 'config', 'robot_params.yaml'])],
        condition=IfCondition(PythonExpression(["'", detector, "' == 'yolo'"])),
    )
    hailo = Node(
        package='rpi5_hailo_detect', executable='hailo_detect', name='hailo_detect',
        output='screen', emulate_tty=True,
        parameters=[PathJoinSubstitution([bringup_share, 'config', 'robot_params.yaml'])],
        condition=IfCondition(PythonExpression(["'", detector, "' == 'hailo'"])),
    )

    # ★ TODO(you): 08a 의 detection_overlay 를 detector != none 일 때 함께 띄운다.
    #   08d 의 object_tracker · object_localizer · hailo_depth(depth_rate_hz) 도 같은 조건으로 — localizer 의 target_frame 은 mode 에 따라 base_link(mapping) / map(navigation)
    # ★ TODO(you): 07 의 scan_watch(/scan_front_min) 를 여기 또는 robot.launch.py 에 둔다 — 어느 계층이 맞는가?

    return LaunchDescription([
        DeclareLaunchArgument('mode', default_value='mapping', description='mapping | navigation'),
        DeclareLaunchArgument('detector', default_value='none', description='none | yolo | hailo'),
        slam, yolo, hailo,
    ])

navigation.launch.py — 계획·제어 계층

"""계획·제어 계층: Nav2 (AMCL + map_server + planner + controller + BT).

    ros2 launch rpi5_bringup navigation.launch.py map:=/maps/my_room.yaml
"""
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument, IncludeLaunchDescription
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import LaunchConfiguration, PathJoinSubstitution
from launch_ros.substitutions import FindPackageShare


def generate_launch_description():
    nav2 = IncludeLaunchDescription(
        PythonLaunchDescriptionSource([PathJoinSubstitution([
            FindPackageShare('nav2_bringup'), 'launch', 'bringup_launch.py'])]),
        launch_arguments={
            'use_sim_time': 'false',
            'map': LaunchConfiguration('map'),
            'params_file': PathJoinSubstitution([
                FindPackageShare('rpi5_bringup'), 'config', 'nav2_params.yaml']),
            # autostart: lifecycle_manager 가 노드들을 configure → activate 까지 자동으로 올린다.
            # false 면 노드가 'unconfigured' 로 떠 있기만 하고 아무 일도 안 한다 (09 단계 §2-7).
            'autostart': 'true',
        }.items(),
    )
    return LaunchDescription([
        DeclareLaunchArgument('map', description='map_saver 로 저장한 지도 YAML 의 절대 경로'),
        nav2,
    ])

// =============================================================================
//  mission_supervisor.cpp — 임무 수준 감독 노드 (10단계)
//
//  [ 이 노드의 자리 ]
//    Nav2 는 "저 점까지 가라"를 수행한다. 이 노드는 그 위에서
//      · 목표를 순서대로 준다            (waypoints)
//      · 수행 정도를 계속 판정한다       (액션 피드백: distance_remaining, number_of_recoveries)
//      · 정체·실패 시 정책을 적용한다    (재시도, 건너뛰기, 임무 실패)
//      · 안전 조건에 즉시 반응한다       (사람 근접 / 전방 장애물 → 일시정지, 해제되면 재개)
//      · 상태를 밖으로 알린다            (/mission/state)
//
//  [ 설계 원칙 ]
//    · /cmd_vel 을 직접 쏘지 않는다. 멈추는 수단은 오직 goal cancel 이다.
//    · 콜백은 전부 기본(단일 스레드) 실행기에서 순서대로 돈다 → 뮤텍스가 필요 없다.
//    · 정책 값은 전부 파라미터다. 코드를 고치지 않고 현장에서 조절한다.
// =============================================================================
#include <algorithm>
#include <chrono>
#include <cmath>
#include <cstdio>
#include <limits>
#include <memory>
#include <string>
#include <vector>

#include "rclcpp/rclcpp.hpp"
#include "rclcpp_action/rclcpp_action.hpp"
#include "nav2_msgs/action/navigate_to_pose.hpp"
#include "geometry_msgs/msg/pose_stamped.hpp"
#include "std_msgs/msg/float32.hpp"
#include "std_msgs/msg/string.hpp"
#include "vision_msgs/msg/detection2_d_array.hpp"     // 파일명은 snake_case: Detection2DArray → detection2_d_array
#include "tf2/LinearMath/Quaternion.h"
#include "tf2_geometry_msgs/tf2_geometry_msgs.hpp"

using namespace std::chrono_literals;
using NavigateToPose = nav2_msgs::action::NavigateToPose;
using GoalHandle = rclcpp_action::ClientGoalHandle<NavigateToPose>;

class MissionSupervisor : public rclcpp::Node
{
public:
  enum class State { IDLE, NAVIGATING, PAUSED, SUCCEEDED, FAILED };

  MissionSupervisor()
  : Node("mission_supervisor")
  {
    // ── 1. 파라미터: 정책은 전부 여기 ─────────────────────────────────────
    //   waypoints 는 [x0, y0, yaw0, x1, y1, yaw1, ...] 평탄 배열. ROS 2 파라미터에 중첩 배열은 없다.
    //   ★ 정수로만 쓰면([1, 0, 0]) 정수 배열로 파싱되어 타입 예외가 난다. 1.0 처럼 소수점을 붙인다.
    declare_parameter<std::vector<double>>("waypoints", std::vector<double>{});
    declare_parameter<std::string>("frame_id", "map");
    declare_parameter<bool>("autostart", false);            // true 면 뜨자마자 출발 — 받침대 위가 아니면 위험
    declare_parameter<double>("stall_timeout_s", 10.0);     // 이 시간 동안 진전이 없으면 정체
    declare_parameter<double>("stall_epsilon_m", 0.10);     // 이만큼 가까워져야 '진전'
    declare_parameter<int>("max_retries", 2);
    declare_parameter<bool>("person_pause", true);
    declare_parameter<std::string>("person_class_id", "person");  // 08b/08c 검출기가 내는 class_id 문자열과 맞춘다
    declare_parameter<double>("person_min_bbox_px", 120.0);  // 박스 높이가 이보다 크면 "가깝다"
    declare_parameter<double>("front_stop_m", 0.25);         // /scan_front_min 이 이보다 작으면 정지
    declare_parameter<double>("resume_hold_s", 2.0);         // 조건 해제가 이만큼 유지되면 재개

    waypoints_ = get_parameter("waypoints").as_double_array();
    frame_id_ = get_parameter("frame_id").as_string();
    autostart_ = get_parameter("autostart").as_bool();
    stall_timeout_s_ = get_parameter("stall_timeout_s").as_double();
    stall_epsilon_m_ = get_parameter("stall_epsilon_m").as_double();
    max_retries_ = static_cast<int>(get_parameter("max_retries").as_int());
    person_pause_ = get_parameter("person_pause").as_bool();
    person_class_id_ = get_parameter("person_class_id").as_string();
    person_min_bbox_px_ = get_parameter("person_min_bbox_px").as_double();
    front_stop_m_ = get_parameter("front_stop_m").as_double();
    resume_hold_s_ = get_parameter("resume_hold_s").as_double();

    if (waypoints_.size() % 3 != 0) {
      RCLCPP_ERROR(get_logger(), "waypoints 는 [x, y, yaw] 의 배수여야 합니다 (현재 %zu 개) — 무시합니다",
                   waypoints_.size());
      waypoints_.clear();
    }

    // 시각 변수는 반드시 now() 로 초기화한다. 기본 생성된 rclcpp::Time 은 SYSTEM_TIME 이라
    // ROS_TIME 인 now() 와 빼면 "different time sources" 예외가 난다.
    last_progress_time_ = clear_since_ = person_stamp_ = front_stamp_ = now();

    // ── 2. 인터페이스 ─────────────────────────────────────────────────────
    client_ = rclcpp_action::create_client<NavigateToPose>(this, "navigate_to_pose");

    // 센서 파생 토픽은 BEST_EFFORT 로 구독한다: 발행자가 RELIABLE 이든 BEST_EFFORT 이든 붙는다 (03 §2-7).
    auto sensor_qos = rclcpp::QoS(1).best_effort();
    sub_det_ = create_subscription<vision_msgs::msg::Detection2DArray>(
      "detections", sensor_qos,
      std::bind(&MissionSupervisor::on_detections, this, std::placeholders::_1));
    sub_front_ = create_subscription<std_msgs::msg::Float32>(
      "scan_front_min", sensor_qos,
      [this](const std_msgs::msg::Float32 & msg) { front_min_m_ = msg.data; front_stamp_ = now(); });
    sub_cmd_ = create_subscription<std_msgs::msg::String>(
      "mission/command", 10,
      std::bind(&MissionSupervisor::on_command, this, std::placeholders::_1));

    pub_state_ = create_publisher<std_msgs::msg::String>("mission/state", 10);

    tick_timer_ = create_wall_timer(500ms, std::bind(&MissionSupervisor::tick, this));      // 상태기계 2 Hz
    state_timer_ = create_wall_timer(1s, std::bind(&MissionSupervisor::publish_state, this)); // 상태 보고 1 Hz

    RCLCPP_INFO(get_logger(), "mission_supervisor 시작: waypoint %zu 개, autostart=%d  ('start' 명령으로 출발)",
                waypoints_.size() / 3, autostart_ ? 1 : 0);
  }

private:
  // ── 목표 전송 ──────────────────────────────────────────────────────────
  void send_goal(size_t idx)
  {
    if (idx * 3 + 2 >= waypoints_.size()) {
      // 마지막 목표까지 끝났다. TODO(you): 건너뛴 목표가 있으면 성공인가 실패인가 — 임무의 정의에 달렸다.
      state_ = (skipped_ == 0) ? State::SUCCEEDED : State::FAILED;
      RCLCPP_INFO(get_logger(), "임무 종료: %s (건너뜀 %zu)", state_name(state_), skipped_);
      return;
    }
    if (!client_->wait_for_action_server(5s)) {
      RCLCPP_ERROR(get_logger(), "navigate_to_pose 액션 서버가 없습니다 — Nav2 가 active 인가? (ros2 lifecycle get /bt_navigator)");
      state_ = State::FAILED;
      return;
    }

    NavigateToPose::Goal goal;
    goal.pose.header.frame_id = frame_id_;
    goal.pose.header.stamp = now();
    goal.pose.pose.position.x = waypoints_[idx * 3];
    goal.pose.pose.position.y = waypoints_[idx * 3 + 1];
    tf2::Quaternion q;
    q.setRPY(0.0, 0.0, waypoints_[idx * 3 + 2]);       // 평면 로봇: yaw 만
    goal.pose.pose.orientation = tf2::toMsg(q);

    auto options = rclcpp_action::Client<NavigateToPose>::SendGoalOptions();
    options.goal_response_callback =
      std::bind(&MissionSupervisor::on_goal_response, this, std::placeholders::_1);
    options.feedback_callback =
      std::bind(&MissionSupervisor::on_feedback, this, std::placeholders::_1, std::placeholders::_2);
    options.result_callback =
      std::bind(&MissionSupervisor::on_result, this, std::placeholders::_1);

    best_distance_m_ = std::numeric_limits<double>::infinity();
    last_progress_time_ = now();
    cancel_pending_ = false;
    client_->async_send_goal(goal, options);
    state_ = State::NAVIGATING;
    pause_reason_.clear();
    RCLCPP_INFO(get_logger(), "goal %zu/%zu 전송: (%.2f, %.2f, yaw %.2f)",
                idx + 1, waypoints_.size() / 3, goal.pose.pose.position.x, goal.pose.pose.position.y,
                waypoints_[idx * 3 + 2]);
  }

  void on_goal_response(GoalHandle::SharedPtr handle)
  {
    if (!handle) {
      RCLCPP_ERROR(get_logger(), "goal 이 거부되었습니다 (Nav2 미준비 또는 목표가 유효하지 않음)");
      state_ = State::FAILED;
      return;
    }
    goal_handle_ = handle;
    if (cancel_pending_) { client_->async_cancel_goal(goal_handle_); }   // 응답보다 먼저 취소가 결정된 경우
  }

  // 피드백: 여기서 "진전"을 기록한다. 판정은 tick() 에서 한다 (피드백 주기에 판정을 묶지 않는다).
  void on_feedback(GoalHandle::SharedPtr, const std::shared_ptr<const NavigateToPose::Feedback> fb)
  {
    last_distance_m_ = fb->distance_remaining;
    recoveries_ = fb->number_of_recoveries;
    // '진전' = 지금까지의 최소 거리보다 epsilon 이상 더 가까워졌다.
    // (직전 값과만 비교하면 느리지만 꾸준한 전진이 전부 '정체'로 보인다)
    if (best_distance_m_ - fb->distance_remaining >= stall_epsilon_m_) {
      best_distance_m_ = fb->distance_remaining;
      last_progress_time_ = now();
    }
  }

  void on_result(const GoalHandle::WrappedResult & result)
  {
    goal_handle_.reset();
    cancel_pending_ = false;
    switch (result.code) {
      case rclcpp_action::ResultCode::SUCCEEDED:
        RCLCPP_INFO(get_logger(), "waypoint %zu 도착", idx_ + 1);
        idx_++;
        retries_ = 0;
        send_goal(idx_);                       // 마지막이면 send_goal 이 종료 상태로 보낸다
        break;

      case rclcpp_action::ResultCode::ABORTED:
        // Nav2 가 복구 행동까지 다 해 보고 포기한 것. 한도 안이면 같은 목표를 다시 준다(재계획 강제).
        if (++retries_ <= max_retries_) {
          RCLCPP_WARN(get_logger(), "ABORTED — 재시도 %d/%d", retries_, max_retries_);
          send_goal(idx_);
        } else {
          RCLCPP_ERROR(get_logger(), "waypoint %zu 실패 — 재시도 한도 초과", idx_ + 1);
          state_ = State::FAILED;
        }
        break;

      case rclcpp_action::ResultCode::CANCELED:
        // 우리가 취소한 것(PAUSED)이면 그대로 둔다. 남이 취소했으면 IDLE 로 돌아간다.
        if (state_ != State::PAUSED) {
          RCLCPP_WARN(get_logger(), "goal 이 외부에서 취소되었습니다");
          state_ = State::IDLE;
        }
        break;

      default:
        RCLCPP_ERROR(get_logger(), "알 수 없는 결과 코드");
        state_ = State::FAILED;
    }
  }

  // ── 안전 조건 ──────────────────────────────────────────────────────────
  bool person_near() const
  {
    // 검출 메시지가 1초 이상 오래되면 무시한다 — 검출기가 죽었을 때 영원히 멈춰 있지 않도록.
    return person_pause_ && person_near_ &&
           (now() - person_stamp_) < rclcpp::Duration::from_seconds(1.0);
  }

  bool front_blocked() const
  {
    return std::isfinite(front_min_m_) && front_min_m_ < front_stop_m_ &&
           (now() - front_stamp_) < rclcpp::Duration::from_seconds(1.0);
  }

  void on_detections(const vision_msgs::msg::Detection2DArray & msg)
  {
    bool near = false;
    for (const auto & det : msg.detections) {
      if (det.results.empty()) { continue; }
      const auto & hyp = det.results[0].hypothesis;      // 가장 높은 가설 하나만 본다
      if (hyp.class_id == person_class_id_ && det.bbox.size_y >= person_min_bbox_px_) {
        near = true;
        break;
      }
    }
    person_near_ = near;
    person_stamp_ = now();
  }

  // ── 외부 명령: start / pause / resume / abort ─────────────────────────
  void on_command(const std_msgs::msg::String & msg)
  {
    if (msg.data == "start") {
      if (state_ == State::IDLE || state_ == State::SUCCEEDED || state_ == State::FAILED) {
        idx_ = 0; retries_ = 0; skipped_ = 0; manual_pause_ = false;
        send_goal(0);
      }
    } else if (msg.data == "pause") {
      manual_pause_ = true;
      cancel_and_pause("manual");
    } else if (msg.data == "resume") {
      manual_pause_ = false;
    } else if (msg.data == "abort") {
      manual_pause_ = false;
      cancel_current();
      state_ = State::FAILED;
      pause_reason_ = "abort";
    }
  }

  void cancel_current()
  {
    cancel_pending_ = true;
    if (goal_handle_) { client_->async_cancel_goal(goal_handle_); }
  }

  void cancel_and_pause(const std::string & reason)
  {
    if (state_ != State::NAVIGATING) { return; }
    cancel_current();
    state_ = State::PAUSED;
    pause_reason_ = reason;
    clear_since_ = now();
    RCLCPP_WARN(get_logger(), "PAUSED (%s)", reason.c_str());
  }

  // ── 상태기계: 2 Hz 로 평가 ────────────────────────────────────────────
  void tick()
  {
    const auto t = now();
    switch (state_) {
      case State::IDLE:
        if (autostart_ && !waypoints_.empty() && !started_) { started_ = true; send_goal(0); }
        break;

      case State::NAVIGATING: {
        // ① 안전: 사람 근접 / 전방 장애물 → 즉시 취소하고 PAUSED
        if (person_near())   { cancel_and_pause("person"); break; }
        if (front_blocked()) { cancel_and_pause("front_obstacle"); break; }

        // ② 정체(stall): stall_timeout_s 동안 '진전'이 없다
        //   TODO(you): 아래 규칙의 함정을 보완하라 —
        //     · 목표 근처에서 최종 yaw 정렬(제자리 회전) 중에는 distance_remaining 이 줄지 않는다
        //         → last_distance_m_ 가 nav2_params.yaml 의 xy_goal_tolerance 보다 작으면 정체로 보지 않는다
        //     · Nav2 의 복구 행동(spin/backup) 중에는 거리가 잠시 늘어난다
        //         → recoveries_ 가 증가하면 타이머를 리셋하거나 timeout 을 늘린다
        //     · 재계획으로 경로가 길어지면 distance_remaining 이 튀어오른다 → best_distance_m_ 를 완화
        const double since_progress = (t - last_progress_time_).seconds();
        if (since_progress > stall_timeout_s_) {
          retries_++;
          RCLCPP_WARN(get_logger(), "정체 %.0f s (남은 거리 %.2f m, 복구 %d회) — 취소 후 재시도 %d/%d",
                      since_progress, last_distance_m_, recoveries_, retries_, max_retries_);
          cancel_current();
          state_ = State::PAUSED;
          pause_reason_ = "stall";
          clear_since_ = t;
          if (retries_ > max_retries_) {
            // TODO(you): 정책 결정 — 이 waypoint 를 건너뛸 것인가, 임무를 실패로 끝낼 것인가
            RCLCPP_ERROR(get_logger(), "waypoint %zu 건너뜀 (정체 재시도 한도 초과)", idx_ + 1);
            idx_++; skipped_++; retries_ = 0;
          }
        }
        break;
      }

      case State::PAUSED: {
        // 멈춘 원인이 사라진 상태가 resume_hold_s 동안 유지되면 같은 목표를 다시 보낸다
        const bool blocked = person_near() || front_blocked() || manual_pause_;
        if (blocked) { clear_since_ = t; break; }
        if (goal_handle_) { break; }           // 아직 취소 결과가 안 왔다 — 두 goal 이 동시에 살지 않게 기다린다
        if ((t - clear_since_).seconds() >= resume_hold_s_) {
          RCLCPP_INFO(get_logger(), "재개 (%s 해제)", pause_reason_.c_str());
          send_goal(idx_);
        }
        break;
      }

      case State::SUCCEEDED:
      case State::FAILED:
        break;                                 // 종료 상태. 새 임무는 'start' 명령으로
    }
  }

  // ── 상태 보고 ─────────────────────────────────────────────────────────
  void publish_state()
  {
    const size_t total = waypoints_.size() / 3;
    char buf[192];
    std::snprintf(buf, sizeof(buf),
                  "%s wp=%zu/%zu dist=%.2f retries=%d recov=%d front=%.2f person=%d reason=%s",
                  state_name(state_), std::min(idx_ + 1, total), total,
                  last_distance_m_, retries_, recoveries_, static_cast<double>(front_min_m_),
                  person_near() ? 1 : 0, pause_reason_.empty() ? "-" : pause_reason_.c_str());
    std_msgs::msg::String msg;
    msg.data = buf;
    pub_state_->publish(msg);
  }

  static const char * state_name(State s)
  {
    switch (s) {
      case State::IDLE: return "IDLE";
      case State::NAVIGATING: return "NAVIGATING";
      case State::PAUSED: return "PAUSED";
      case State::SUCCEEDED: return "SUCCEEDED";
      case State::FAILED: return "FAILED";
    }
    return "?";
  }

  // ── 멤버 ─────────────────────────────────────────────────────────────
  rclcpp_action::Client<NavigateToPose>::SharedPtr client_;
  GoalHandle::SharedPtr goal_handle_;
  rclcpp::Subscription<vision_msgs::msg::Detection2DArray>::SharedPtr sub_det_;
  rclcpp::Subscription<std_msgs::msg::Float32>::SharedPtr sub_front_;
  rclcpp::Subscription<std_msgs::msg::String>::SharedPtr sub_cmd_;
  rclcpp::Publisher<std_msgs::msg::String>::SharedPtr pub_state_;
  rclcpp::TimerBase::SharedPtr tick_timer_, state_timer_;

  std::vector<double> waypoints_;
  std::string frame_id_, person_class_id_, pause_reason_;
  double stall_timeout_s_{10.0}, stall_epsilon_m_{0.1}, person_min_bbox_px_{120.0};
  double front_stop_m_{0.25}, resume_hold_s_{2.0};
  int max_retries_{2};
  bool autostart_{false}, started_{false}, person_pause_{true}, manual_pause_{false}, cancel_pending_{false};

  State state_{State::IDLE};
  size_t idx_{0}, skipped_{0};
  int retries_{0}, recoveries_{0};
  double last_distance_m_{0.0}, best_distance_m_{std::numeric_limits<double>::infinity()};
  rclcpp::Time last_progress_time_, clear_since_, person_stamp_, front_stamp_;
  bool person_near_{false};
  float front_min_m_{std::numeric_limits<float>::infinity()};
};

1. 라이다를 다른 모델로 바꾸면 어느 파일들을 고쳐야 하는가?
① 드라이버 패키지 교체(Dockerfile 의 apt 또는 .repos + 런치파일의 package/executable), ② robot_params.yaml 의 lidar_node 파라미터(보드레이트 등), ③ 장착 위치가 바뀌었다면 URDF 의 lidar_* 속성. SLAM, Nav2, mcu_bridge, 감독 노드는 건드리지 않는다. 이것이 노드 분리의 효과다.
2. map → odom → base_link 세 좌표계를 각각 누가 발행하며, 왜 나뉘어 있는가?
map→odom 은 SLAM/AMCL(불연속 보정), odom→base_link 는 mcu_bridge 또는 EKF(연속적, 누적오차 있음). 나눠 두면 제어기는 부드러운 odom 을 쓰고 경로계획은 정확한 map 을 쓸 수 있다. 합치면 위치 보정 때마다 로봇이 순간이동해 제어가 폭주한다.
3. Nav2 가 /cmd_vel 을 보냈는데 로봇이 안 움직인다. 어떤 순서로 확인하는가?
① ros2 topic hz /cmd_vel — 실제로 발행되는가 ② ros2 topic echo /cmd_vel — 값이 0 이 아닌가 ③ ros2 node info /mcu_bridge — 구독하고 있는가(토픽 이름/네임스페이스) ④ mcu_bridge 로그 — 워치독이 걸렸는가, 시리얼 오류인가 ⑤ MCU 원시 바이트 — 프레임이 나가는가. 그래프 → 데이터 → 하드웨어 순으로 좁힌다.
4. Hailo 추론을 켰더니 SLAM 지도가 깨지기 시작했다. 무엇을 의심하는가?
① CPU 포화로 SLAM 의 스캔 처리가 지연됨 → htop. 추론 전처리(리사이즈)가 CPU 를 먹고 있을 가능성이 크다. ② 전력 부족으로 라이다가 불안정 → vcgencmd get_throttled. ③ 발열로 스로틀링 → measure_temp. Hailo 자체가 아니라 주변 자원 경합이 원인인 경우가 많다.
5. 이 로봇에서 "노드를 분리한 것"이 실제로 어떤 이득을 주었는가? 하나만 들어 보십시오.
예: MCU 프로토콜이 확정되기 전에도 simulate:=true 로 ROS 쪽 전체 데이터 흐름(cmd_vel → 운동학 → odom → TF)을 검증할 수 있었다. 또는: 검출기를 YOLO(CPU)에서 Hailo 로 바꿨는데 감독 노드는 한 줄도 바꾸지 않았다 — 같은 /detections 계약 덕분이다.
6. 감독 노드가 사람을 보고 /cmd_vel 에 0 을 직접 발행하면 무엇이 문제인가?
Nav2 의 controller_server 도 같은 토픽에 10 Hz 로 발행한다. 발행자가 둘이면 mcu_bridge 는 마지막에 온 값을 따르므로 0 과 주행 속도가 번갈아 들어가 로봇이 덜컥이며 전진한다. 멈추는 수단은 goal cancel(Nav2 가 스스로 0 을 냄)이고, 정말 여러 소스를 섞어야 하면 twist_mux 같은 중재 노드를 따로 둔다.
7. distance_remaining 만으로 정체를 판정할 때의 함정은? 어떻게 보완하는가?
① 목표 근처에서 최종 yaw 정렬(제자리 회전) 중에는 거리가 줄지 않는다 → 목표 허용 오차 안이면 판정 제외. ② 복구 행동(후진·회전) 중에는 거리가 잠시 늘어난다 → number_of_recoveries 증가 시 타이머 리셋 또는 timeout 연장. ③ 재계획으로 경로가 길어지면 값이 튄다 → 최소값 기준을 완화. 공통 보완은 "충분히 긴 시간 창"과 "로봇 자세(current_pose)도 안 움직였는가"를 함께 보는 것이다.
8. 감독 노드의 상태를 로그가 아니라 토픽(/mission/state)으로 내는 이유는?
로그는 그 순간 그 터미널에만 보인다. 토픽은 Foxglove 에 그려지고 rosbag 에 다른 토픽과 같은 시간축으로 기록되어, "그때 감독 노드는 무엇을 판단했고 로봇은 무엇을 하고 있었는가"를 재생하며 대조할 수 있다. 판단 결과는 시스템의 일부이므로 시스템의 통신 방식(토픽)으로 낸다.
