C0 · 지도와 준비

카메라 가이드 — 지도와 준비

이 가이드(C0 ~ C8)는 카메라 영상이 ROS 2 토픽이 되고, OpenCV 로 가공되고, YOLO 가 물체를 찾고, 그 계산을 Hailo-8 가속기로 옮기는 데까지를 아홉 쪽으로 다룬다. 학습 단계 08 · 08a · 08b · 08c 와 같은 범위다. 차이는 둘이다. 코드는 빠진 곳 없이 전부 적혀 있고, 설명은 실행에 필요한 것만 적었다. 두 가이드 중 하나로 진행하면 된다.

이 쪽이 끝나면 보이는 것
  • 아홉 쪽이 각각 무엇을 만들고 어떤 순서로 이어지는지 안다.
  • Pi 호스트에서 확인 명령 다섯 개가 기대한 출력을 낸다 — 카메라 인식, Hailo 인식, 장치 파일, 컨테이너 이미지, 설치 버전.
  • Mac 의 Foxglove Studio 가 Pi 에 연결된다.
  • 값을 적을 자리(hardware/INVENTORY.md 4절 · 5절)를 확인했다.

필요한 것

  • Raspberry Pi 5, Camera Module 3 일반 모델 두 대(스테레오 한 쌍 — 왼쪽은 CAM/DISP 0, 오른쪽은 CAM/DISP 1 커넥터. C1 ~ C8 은 왼쪽 한 대로 진행한다), AI HAT+(Hailo-8, C7 부터 쓴다).
  • Mac — 코드 편집, 모델 내보내기(C5), 보정 계산(C3), Foxglove Studio 로 영상 보기.
  • 프린터로 뽑은 체커보드 한 장(C3). 종이는 판판한 판에 붙인다.

끝나 있어야 하는 것

  • 학습 단계 01 — OS 설치, hailo-all 설치, 호스트에서 카메라 인식.
  • 학습 단계 02 — 컨테이너 이미지 빌드, Foxglove 연결.
  • 학습 단계 04 와 05 는 권장이다. 04 는 C++ 패키지의 구조를, 05 는 카메라 좌표계 이름 stereo_left_optical_link 를 설명한다. 하지 않았어도 이 가이드의 코드는 그대로 동작한다.

1. 개요

1-1. 아홉 쪽의 흐름

한 쪽이 끝나면 토픽이나 파일이 하나 늘어난다. 뒤 쪽은 앞 쪽의 토픽을 입력으로 쓴다.

C6 와 C8 은 같은 토픽 이름, 같은 메시지, 같은 파라미터 이름을 쓴다. 그래서 박스를 그리는 노드와 뒤의 소비자는 어느 쪽이 발행하는지 구분하지 않는다. C8 은 새 기능이 아니라 C6 의 계산을 다른 장치로 옮기는 쪽이다.

1-2. 다른 가이드와의 관계

  • 학습 단계 08 ~ 08c 와 범위가 같다. 둘 다 할 필요는 없다. 학습 단계 쪽은 원리 설명이 길고 코드 일부를 직접 채운다. 이 가이드는 코드 전량과 짧은 설명이다.
  • 학습 단계 08d(물체 추적과 거리 추정)는 이 가이드의 끝(C8 의 /detections)에서 이어진다. 이 가이드는 08d 를 다루지 않는다.
  • 라이다 가이드(L) · MCU 펌웨어 가이드(F) 와는 장비가 겹치지 않는다. 서로 기다리지 않고 진행한다.

2. 전제 — 이 가이드 전체를 관통하는 사실 하나

카메라 드라이버(imx708)와 Hailo 드라이버(hailo_pci)는 호스트 커널에 있다. 그 드라이버를 쓰는 라이브러리 — 카메라는 libcamera, Hailo 는 HailoRT — 는 컨테이너에 있다. 컨테이너는 호스트와 커널만 공유하므로, 라이브러리는 컨테이너에 따로 넣어야 하고 호스트 드라이버와 같은 세대여야 한다.

  • libcamera 는 C2 에서 호스트와 같은 판으로 소스 빌드한다.
  • HailoRT 는 C7 에서 호스트와 정확히 같은 버전의 패키지를 컨테이너에 설치한다. 조금이라도 다르면 장치 파일이 보여도 "No Hailo device found" 가 난다.
  • 호스트를 apt full-upgrade 하면 호스트 쪽만 올라간다. 그 뒤에는 이 쪽의 확인 명령을 다시 실행하고, 값이 바뀌었으면 컨테이너 이미지를 다시 빌드한다.

3. 실습

3-1. Pi 호스트에서 확인 Pi 호스트

ssh pi5 로 접속한 셸에서 실행한다. 주석이 기대한 출력의 모양이다.

rpicam-hello --list-cameras
#   0 : imx708 [4608x2592 10-bit RGGB] (…/i2c@88000/imx708@1a)
#       Modes: 'SRGGB10_CSI2P' : 1536x864 [120.13 fps ...]  2304x1296 [56.03 fps ...]  4608x2592 [14.35 fps ...]
#   1 : imx708 [4608x2592 10-bit RGGB] (…)          ← 오른쪽. 모드 목록은 위와 같다

hailortcli fw-control identify
#   Firmware Version: 4.23.0 (release,app,extended context switch buffer)
#   Device Architecture: HAILO8          ← HAILO8L 이면 AI Kit(13 TOPS)다. 모델 파일이 다르다

ls -l /dev/dma_heap/system /dev/media0 /dev/hailo0
#   crw-rw---- 1 root video 252,   0 ...  /dev/dma_heap/system     ← 쉼표 앞 숫자가 major
#   crw-rw---- 1 root video 238,   0 ...  /dev/media0               ← 부팅마다 바뀔 수 있다
#   crw-rw-rw- 1 root root  510,   0 ...  /dev/hailo0
cd ~/ros2_rpi5/docker && ./majors.sh --check
#   ✓ .env 의 major 번호가 지금 값과 같다   ← compose 의 장치 규칙이 이 값을 쓴다 (학습 단계 02 §2-3)

docker image inspect rpi5-ros2:humble --format '{{.Id}}'
#   sha256:...                           ← 이미지가 있다. 없으면 학습 단계 02 §3-4 로

dpkg -l hailort libcamera0.7 rpicam-apps 2>/dev/null | awk '/^ii/{print $2, $3}'
#   hailort 4.23.0
#   libcamera0.7 0.7.2+rpt20260817-1
#   rpicam-apps 1.13.0-1

세 장치 파일의 major 번호는 부팅마다 바뀔 수 있어 노트에 적어 두지 않는다. compose 의 장치 규칙은 부팅 때 docker/majors.sh 가 docker/.env 에 적은 값을 쓴다. --check 가 다르다고 하면 ./majors.sh 를 실행한다. "같다" 가 나오지 않고 .env 에 값이 없다고 나오면 학습 단계 02 §3-4 의 설치를 하지 않은 것이다.

3-2. Mac 의 Foxglove 연결 Mac

Pi 에서 Foxglove 브리지를 띄우고, Mac 의 Foxglove Studio 에서 Open connection → Foxglove WebSocket 에 ws://<Pi 주소>:8765 를 넣는다. 학습 단계 02 에서 했던 것과 같다.

# Pi 호스트
cd ~/ros2_rpi5/docker && docker compose up -d foxglove
docker compose ps        # ros2_foxglove 가 running 이면 된다

연결되면 왼쪽 패널 목록에 토픽이 (아직 없으므로) 비어 있는 상태로 보인다. 연결 자체가 되는 것만 확인한다.

🤔 이해 확인

이 쪽에서 설명한 내용만으로 답할 수 있다. 답을 펼치기 전에 먼저 말로 답해 본다.

1. 카메라 드라이버와 libcamera 는 각각 어디에 있는가. 둘의 세대가 같아야 하는 이유는 무엇인가.

드라이버는 호스트 커널에, libcamera 는 컨테이너에 있다. 컨테이너는 커널만 호스트와 공유한다. libcamera 는 커널 드라이버가 내놓는 장치 구조를 그대로 읽으므로, 드라이버와 다른 세대의 libcamera 는 카메라를 열지 못한다. Hailo 도 같은 구조다 — 드라이버는 호스트, HailoRT 는 컨테이너.

2. 아홉 쪽 가운데 Mac 에서 하는 일은 무엇이고, 왜 Pi 가 아니라 Mac 인가.

C3 의 보정 계산과 C5 의 모델 준비(ultralytics 로 확인하고 ONNX 로 내보내기)다. ultralytics 는 PyTorch 를 함께 설치해 용량이 크고, Pi 의 CPU 에서는 느리다. 결과 파일(camera_info.yaml, yolov8n.onnx)만 Pi 로 보낸다.

3. C6 와 C8 이 같은 토픽 이름 /detections 를 쓰는 이유는 무엇인가.

박스를 그리는 노드와 뒤의 소비자가 검출기를 구분하지 않게 하기 위해서다. 토픽 이름 · 메시지 형식 · 파라미터 이름이 같으면 CPU 검출기를 Hailo 검출기로 바꿔도 다른 노드는 한 줄도 고치지 않는다.
