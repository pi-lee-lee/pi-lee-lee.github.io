펌웨어 21쪽의 지도 — 지금 끝낼 수 있는 쪽부터 짚는다

본편 06a 에서 정한 것은 두 가지였다 — MCU 가 제어와 안전의 전권을 갖는다는 것, 그리고 Pi 와는 계약 v2 로만 말한다는 것. 이 펌웨어 가이드(fw-00 ~ fw-20)는 그 MCU 쪽을 NUCLEO-H723ZG 위에 빈 프로젝트에서 시작해 내 손으로 쌓는 21쪽이다. 이 쪽은 코드를 한 줄도 쓰지 않는다. 대신 뒤의 20쪽이 전제하는 세 가지 — 도구가 설치된 Mac, "무엇이 있어야 어느 쪽이 열리는가"를 적은 부품표, 부품보다 먼저 읽어 둘 안전 규칙 — 을 한 장으로 만든다.

이 쪽이 끝나면 보이는 것

설치 확인 명령이 전부 OK 와 기대한 버전을 내고, 내 노트에 세 장의 표가 있다 — 무납땜 부품표(보유 / 미보유 / 막히는 쪽), 그 옆에 옮겨 적은 내 부품에 해당하는 안전 규칙, 그리고 자기 진단표(정독할 쪽 / 훑을 쪽). 부품 × 쪽 표(§1-3)에서 "지금 끝낼 수 있는 쪽"을 손가락으로 짚을 수 있다.

이 쪽에 필요한 것 — Mac 한 대. 보드도 부품도 없어도 된다(이 쪽은 보드를 꽂지 않는다). 없으면 — Mac 에 ST 도구가 아직 없으면 §3-1-3 의 "빈 Mac 이라면"에서 시작한다. 그 절은 절차가 빈칸이다(이 가이드를 쓴 Mac 에는 도구가 이미 설치돼 있어 설치 과정을 재현해 볼 수 없었다) — 내가 설치하면서 채운다.

1. 개요 — 21쪽이 놓인 모양

이 가이드가 주는 것은 완성 코드가 아니라 구조와 계약이다. 쪽마다 CubeMX 설정값의 근거, 함수의 경계(골격), 그리고 "내 코드가 맞는지"를 가르는 관찰 수단을 주고, 본문은 내가 채운다. 전 과정은 Pi 없이 Mac 과 Nucleo(그리고 책상 위 부품)로 진행하고 검증한다. 처음부터 끝까지 지키는 구조는 하나다 — 펌웨어를 제어·안전 모듈과 통신 모듈로 나눈다(06a §2-5).

이 쪽에서 처음 나오는 말을 한 줄씩 정해 둔다.

2-1. 왜 벤치와 조립을 갈랐는가 — 임시값은 어디서 터지는가

지금의 실물 상태는 이렇다 — 모터는 섀시에 고정돼 있고, 센서와 보드는 차체에서 떼어져 있다(hardware/INVENTORY.md 머리말, 2026-09-22). 이 상태에서 할 수 있는 일과 없는 일이 갈린다. 바퀴를 공중에 띄우고 하는 일(엔코더 카운트, 개루프 구동, 무부하 PID)은 지금 되고, 차체가 바닥에서 굴러야 하는 일(부하 PID, 유효 트랙 폭, 회전 부호, 안전 임계값의 확정)은 조립 뒤에만 된다. 그래서 가이드를 벤치(fw-00 ~ fw-19)와 조립 후(관문 09a 와 그 안의 fw-20)로 가르고, 완료 기준도 둘로 나눴다 — 벤치 완료 기준은 fw-19, 조립 완료 기준은 관문 09a.

2-2. 왜 글자 명령 창이 먼저이고 계약 v2 가 뒤인가

최종 제품에서 MCU 가 Pi 에 말하는 방법은 계약 v2 하나다. 그런데 그 계약의 상태 프레임(0x81)에 실리는 것은 이것뿐이다(06a §4-2): 좌·우 쪽당 평균 누적 틱 l_tick · r_tick, 배터리 전압, 전류, fault 비트, MCU 시각 — 표는 "바퀴별 값은 MCU 안에서만 쓴다"고 적었다.

벤치에서 내가 봐야 하는 것은 정확히 그 "MCU 안에서만 쓰는" 값들이다.

2-3. 왜 안전 규칙이 부품보다 먼저인가

1세대 기록에서 가장 비싼 줄은 코드가 한 줄도 없을 때 쓰였다. 2026-06-12, 6S LiPo 를 IBT-2 모듈에 직결하는 순간 모듈이 죽었다 — 구매 기록은 "4 사망", 결과 문서는 "5개 사망 + 3개 측정"으로 수량 표기가 어긋나지만 사고 자체는 같다(D/bts_stage1_results.md:6,65-83, H/BOM.md:28). 죽은 모듈 3장의 측정 결과는 같았다: B+ 와 한쪽 칩의 VS 사이 단선, M+ ↔ GND 0 Ω(하단 MOSFET 단락), 다른 칩의 상단 MOSFET 단락. 이 상태에서 주 릴레이를 넣으면 모터가 풀 역회전하고 신호로는 세울 수 없다 — 배터리 분리만이 정지 수단이었다.

등급 — 원인은 추정, 대책은 실측

원인 서술(전원 인가 순간 제어 입력이 떠 있었고, 내부저항이 낮은 배터리의 급한 dV/dt 가 게이트를 가짜로 켜 슛스루가 났다)은 1세대 문서가 "95 %+ 확정"이라 적었지만 파형을 잰 적은 없다 — 토폴로지 논증이다. 대책 쪽은 실측이다: 새 모듈 1장에 0 → 24 V 를 점진 인가했을 때 정·역·가감속이 정상이었고, 이후의 운용 규칙(배터리 직결 금지 = 사전충전 회로, 제어 입력 풀다운, GND 공통)으로 벤치와 주행까지 갔다.

이 사고에서 가져오는 것은 순서다. 안전 규칙은 "전원을 넣는 절"의 앞이 아니라 부품을 책상에 올리기 전에 읽는다 — 어긴 결과가 코드 버그가 아니라 부품 소손과 되돌릴 수 없는 작업이기 때문이다. 아래 15개가 이 가이드 전체의 안전 규칙이다. 여기서는 무엇을 · 왜만 소개하고, 절차와 판정법은 "상세" 열의 쪽이 다룬다(F0 ~ F20 이 전부 나와 있다 — 상세 열의 쪽으로 바로 갈 수 있다). 실습 B(§3-2)에서 내 부품에 해당하는 규칙을 부품표 옆에 옮겨 적는다.

2-4. 값의 세 상태와 관문 09a

앞 소절(§2-1)의 문제 — 임시값이 조용히 계산에 쓰인다 — 를 막는 장치는 단순하다. 모든 값 옆에 그 값의 상태를 적는다. 같은 규약을 hardware/INVENTORY.md(머리의 "값의 상태 표기"), Pi 쪽 파라미터 파일, 그리고 펌웨어의 헤더가 같이 쓴다(firmware/README.md 규칙 3).

펌웨어에서는 공용 상수 헤더 robot_params.h(fw-08 에서 빈 틀이 생기고 각 쪽이 키를 더한다)에 이 표기가 값과 같은 줄의 주석으로 들어간다. 꼴은 이렇다 — 둘째 · 셋째 줄은 같은 키의 실측 전 · 후 모습이고(한 파일에 함께 있지 않다), 셋째 줄의 숫자 자리는 자리표시다.

#define PWM_CMD_HOLD_MS   0          /* ____ 학습자가 정한다 [ms] */
#define ENCODER_CPR       94000L     /* NOMINAL(gen1-record): 500 PPR x 4 x 47 [바퀴 1회전당 카운트] */
#define ENCODER_CPR       <n>L       /* MEASURED(<날짜>, 손으로 <N>바퀴 돌린 평균) [바퀴 1회전당 카운트] */

첫 줄이 핵심이다. 자리표시 0 이 위험한 쪽으로 동작하는 키가 있다 — 최저 전압 0 mV 는 "절대 트립하지 않음"이다. 그래서 EMPTY 키를 쓰는 .c 는 첫머리에 _Static_assert 가드를 두어, 빈칸인 채로는 그 모듈의 빌드가 멈추게 한다. "모르는 값이 있으면 돌지 않는다"가 "모르는 값이 0 으로 돈다"보다 안전하다. 남은 빈칸과 임시값의 수는 눈으로 세지 않는다 — 저장소의 scripts/check_nominal.sh 가 센다(§3-1-4 에서 한 번 돌려 본다).

1세대 기록을 쓰는 법도 이 표기에서 나온다. 모터 · 엔코더 · IBT-2 · 전원/안전 부품은 1세대에서 쓰던 바로 그 개체다(INVENTORY 머리말, 사용자 확인 2026-09-22). 그래서:

  • 부품에 속한 값(엔코더 PPR, 기어비, 모듈 풀다운 30 kΩ, INA226 주소, 릴레이 동작 시간)은 NOMINAL(gen1-record) 로 쓴다 — 관문에서 다시 재서 MEASURED 로 바꾼다. 남이 잰 값이 아니라 "다른 조립 상태 · 다른 MCU 에서 잰 값"이다.
  • 벤치 제어 상수(PID 게인, 보호 문턱, 가감속 한도)는 값으로 쓰지 않는다. 인용할 때는 "1세대 무부하 튜닝값(기록)"이라는 꼬리표가 붙고, 합격선이 아니다. 1세대의 게인은 단위부터 다르다.
  • 가져오는 것은 사고 경위와 판정식의 구조다(§2-1 의 표가 그 예다). 1세대의 핀 번호 · 2칩 분담 · XIP 구성 · 외부 플래시는 가져오지 않는다.

합격 수치도 같은 원리로 빈칸이다. 이 가이드의 체크포인트에 "지터 ____ µs 이내" 같은 빈칸이 나오면 그것은 빠뜨린 것이 아니다 — 근거 없는 숫자를 합격선으로 앉히지 않으려는 것이다. 순서는 측정 → 기록 → 그 기록을 보고 내가 합격선을 정한다이다. 출처가 있는 값(데이터시트 한계, 계약의 200 ms)만 숫자로 적혀 있다.

3. 실습

이 쪽은 CubeMX 를 열어 설정하지 않고 코드도 쓰지 않는다(앱이 뜨는지만 본다). 그래서 다른 쪽의 네 걸음(CubeMX 설정 → 골격 → 직접 채우기 → 굽고 보기) 가운데 "채우기"와 "보기"만 있다. 실습은 셋이다 — A 설치 확인, B 무납땜 부품표, C 자기 진단표. 셋 다 Mac 과 노트만 있으면 된다. 보드는 꽂지 않는다.

1세대에서 해 봤다고 훑으면 안 되는 곳

1세대(다른 STM32 + ESP32 의 2칩 구성)에서 해 본 것 가운데 H723 에서는 다르게 생긴 것이 있다. 아래에 해당하면 "해 봤다"여도 정독으로 옮긴다.

  • DMA — H723 은 DMA1/DMA2 + DMAMUX 이고 순환 모드 비트가 따로 있다. 1세대의 DMA(채널 · 연결 리스트 방식)와 설정 화면도 HAL 의 동작도 다르다 → fw-07.
  • 부팅 구성 — H723 은 컨텍스트가 하나다. 1세대의 Boot/Appli 이중 컨텍스트 · 외부 플래시 실행(XIP)은 없다 → fw-02 · fw-03.
  • 설정 저장 — 외부 NOR 가 아니라 H723 내장 플래시다 → fw-16.
  • PWM · 엔코더 — ESP32 의 전용 주변장치가 아니라 H723 의 타이머로 새로 쓴다. 핀 번호 · 클럭 수치는 하나도 가져오지 않는다 → fw-08 · fw-09.

2. 왜 벤치와 조립을 갈랐는가 — 임시값은 어디서 터지는가

조립해야만 얻는 값(유효 트랙 폭, 부하 게인, 좌/우 묶음의 회전 부호, 안전 임계값)이 있기 때문이다. 벤치에서는 그 자리에 임시값을 둘 수밖에 없는데, 임시값은 에러를 내지 않고 계산에 그대로 쓰인다. 그래서 증상이 값을 적은 자리가 아니라 멀리서 난다 — 틀린 트랙 폭은 SLAM 지도가 휘는 것으로, 틀린 좌/우 묶음은 제자리 회전에서만의 과전류로 나타났다(1세대 기록). 관문은 그런 값을 한 곳에 모아 닫는 자리이고, 세 상태 표기는 그 사이에 "이 값은 아직 임시다"를 잊지 않게 하는 장치다. 벤치의 합격은 경로가 돈다는 뜻이지 숫자가 맞다는 뜻이 아니다.

3. 계약 v2 의 상태 프레임만으로는 "FL 엔코더의 부호가 맞는가"를 판정할 수 없다. 왜인가, 그리고 이 가이드는 그것을 어떻게 보는가

상태 프레임의 l_tick 은 왼쪽 앞뒤 두 바퀴의 평균이다. FL 의 부호만 뒤집혀 있으면 평균은 0 근처가 되고, FL 이 끊겨 있으면 절반이 된다 — 어느 바퀴가 어떻게 틀렸는지가 평균에서 사라진다. 계약에 바퀴별 필드를 더하는 길은 Pi 쪽 · probe · 펌웨어 세 구현을 함께 고치는 일이고 계약의 확장은 06a 의 일이다. 그래서 같은 VCP 를 LINK_MODE 로 갈라 TEXT 모드의 enc 명령으로 바퀴별 카운트 4개를 본다. 치르는 값은 최종 펌웨어에 두 모드가 남는다는 것, 그리고 V2 모드에는 명령 창이 없다는 것이다.

4. 1세대의 모듈 소손은 펌웨어가 한 줄도 없을 때 났다. 그 사실이 이 가이드의 쪽 순서와 안전 규칙의 자리에 어떻게 반영돼 있는가

사고의 조건은 "배터리 직결"과 "제어 입력이 떠 있음"이었다 — 둘 다 코드가 아니라 결선과 순서의 문제다. 그래서 안전 규칙은 전원 절의 앞이 아니라 부품표보다 앞(이 쪽)에 있고, 출력단은 모터 전원 없이 먼저 검증하며(fw-08: 리셋 중에도 EN 이 LOW 인가), 버스 전압을 읽는 수단(fw-10)이 선 뒤에야 첫 통전(fw-11)이 온다. 모터 전원을 넣는 절에는 STOP 리스트가 실습보다 앞에 온다(S1). 원인 서술 자체는 추정 등급이라는 점도 기억한다 — 파형을 잰 적은 없다. 실측으로 확인된 것은 대책 쪽이다.

5. robot_params.h 의 바퀴 반지름에 NOMINAL(gen1-record) 가 붙어 있다. 이 값으로 fw-13 을 진행해도 되는가? 본편 09(SLAM)는? 그리고 값이 ____ 인 키는 왜 0 으로 두고 그냥 돌리면 안 되는가

fw-13 은 된다 — 벤치 단계는 출처가 있는 임시값으로 진행하는 것이 허용되고, 거기서 확인하는 것은 경로다. 09 는 관문 뒤다: 관문을 지나면 주행에 쓰이는 값은 전부 MEASURED 여야 하고, 공칭 지름의 절반은 하중이 실린 유효 반지름이 아니다. ____ 옆의 0 은 값이 아니라 자리표시인데, 0 이 위험한 쪽으로 동작하는 키가 있다(최저 전압 0 mV = 절대 트립하지 않음). 그래서 그런 키를 쓰는 모듈은 _Static_assert 로 빌드를 세운다 — "모르면 돌지 않는다"가 "모르면 0 으로 돈다"보다 안전하다.

6. (일부러 틀리면) 설치 확인 고리에서 CLT 를 없는 판으로 바꾸면 일곱 줄이 MISSING 이 된다. 그런데 열 줄이 전부 OK 여도 fw-02 의 빌드가 컴파일러를 못 찾을 수 있다. 어떤 경우인가

확인 고리는 파일이 그 경로에 있는가만 본다. CubeMX 가 생성한 툴체인 파일은 컴파일러를 경로 없이 arm-none-eabi-gcc 라는 이름으로 부르므로, 빌드는 PATH 에서 그 이름이 잡히는가에 달려 있다. 파일은 있는데 PATH 에 없으면 "있다"와 "쓸 수 있다"가 갈린다. 그래서 §3-1-4 ③ 에서 which -a 를 따로 본다. 같은 이유로 cmake 가 둘일 때 어느 쪽이 먼저 잡히는지도 기록해 둔다 — 증상이 났을 때 의심할 자리가 하나 줄어든다.
