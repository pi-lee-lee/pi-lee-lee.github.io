06 · MCU 브리지

MCU 브리지를 C++ 로 쓴다 — /cmd_vel, /odom, /imu/data_raw

ROS 와 물리 세계가 처음 만나는 곳이다. 이 프로젝트에서 가장 긴 단계이고, 04 단계에서 익힌 C++ 노드 패턴이 처음으로 진짜 일을 한다. 저장소의 Python 판 rpi5_mcu_bridge 는 구조를 보여 주는 참고 구현이고, 이 단계의 산출물은 당신이 쓰는 rpi5_mcu_bridge_cpp 다. MCU 는 전원·모터·엔코더·IMU 를 쥐고 제어와 안전의 전권을 가진 장치이며, 브리지는 그 장치의 언어를 ROS 의 언어로 번역하는 얇은 층이다.

이 단계가 끝나면

키보드로 실제 모터를 굴리고, 로봇이 움직인 만큼 /odom 과 TF(odom → base_footprint)가 갱신되며, MCU 에 붙은 IMU 두 개(WT901, BNO055)의 값이 /imu/…/data_raw 로 흐른다. 두 IMU 를 캘리브레이션하고 비교해 기본 IMU 를 정했고, robot_localization 의 EKF 가 휠 오도메트리와 IMU 를 융합해 TF 를 발행한다. 브리지 노드는 C++ 로 직접 쓴 것이고, 직진 2 m·회전 360° 캘리브레이션을 5 % 이내로 맞춘 상태다. MCU 펌웨어는 속도 PID·워치독·안전 상태기계를 갖추고 Pi 없이도 단독 검증되어 있다.

그래프에서의 위치mcu_bridge 상자(제어 계층) — ROS 와 물리 세계가 만나는 경계. IMU 는 이 상자를 거쳐 들어온다
전제04 (C++ 노드), 05 (TF 트리), 06a (프로토콜 결정과 계약 v2)
예상 소요14~22시간 — ROS 트랙 4~5h + 펌웨어 트랙 6~10h + IMU 비교·EKF 2~4h + 통합·캘리브레이션 2~3h
언어C++ 브리지 · C/HAL 펌웨어 · Python 검증 스크립트
두 트랙을 동시에 하지 마십시오

순서는 ROS 트랙(§3-1~3-5, simulate:=true) → 펌웨어 트랙(§3-6, Pi 없이) → IMU 비교(§3-7) → 통합(§3-8) 이다. 양쪽이 동시에 미완성이면 통합에서 문제가 났을 때 원인이 ROS 인지, 펌웨어인지, 배선인지 구분할 수 없다. 각 트랙을 따로 "확실히 맞다"로 만들어 두면 통합 단계의 의심 범위는 연결로 좁혀진다. 근거는 06a 의 두 트랙 절.

설계 원칙: 단위 번역은 한 군데서만. ROS 세계는 m/s, rad/s, m/s² 만 안다. 하드웨어는 PWM 과 틱과 정수 mg 만 안다. 이 번역이 여러 곳에 흩어지면(예: 펌웨어에서 한 번 부호를 뒤집고 브리지에서 또 뒤집고) 시스템을 이해할 수 없게 된다.

두 번째 원칙: 제어와 안전의 전권은 MCU 에 있다. 저전압·과전류·과경사·워치독은 MCU 가 스스로 출력을 끊고 결과만 Pi 에 알린다. Pi 는 그 보고를 받아 목표를 취소할 뿐, 안전을 Pi 에 의존하지 않는다.

2. 원리 — 왜

2-1. 차동구동 역운동학 (명령 → 바퀴)

   v = 로봇 선속도 [m/s],  ω = 각속도 [rad/s],  L = 좌우 바퀴 접지점 간격 [m]

     v_left  = v − ω·L/2
     v_right = v + ω·L/2

손으로 검산해 보십시오.

  • 직진 (v=0.3, ω=0) → v_left = v_right = 0.3. 두 바퀴가 같다. ✓
  • 제자리 회전 (v=0, ω=1.0, L=0.145) → v_left = −0.0725, v_right = +0.0725. 크기 같고 방향 반대. ✓
  • 좌회전 (ω > 0, 반시계가 +) → 오른쪽 바퀴가 더 빠르다. 로봇 좌표계는 y 가 왼쪽이므로 반시계 회전이 +yaw 다 (REP-103, 05 단계).

이 프로젝트는 4륜 스키드 스티어다. v_left 는 왼쪽 두 바퀴의, v_right 는 오른쪽 두 바퀴의 목표이고 식은 바뀌지 않는다. 다만 바퀴 네 개는 각자 32비트 엔코더와 독립 PID 를 갖고, "보조 바퀴"는 없다. 회전할 때 바퀴가 옆으로 미끄러지므로(스키드 스티어) 회전량의 오도메트리는 믿을 것이 못 되고 그 자리를 IMU 가 메우며(§3-7, §3-10), 미끄러지는 바퀴 자체는 §3-6-9 의 슬립 억제가 실시간으로 출력을 줄인다.

2-2. 정운동학과 오도메트리 적분 (엔코더 → 위치)

   Δs = (Δd_right + Δd_left) / 2          ← 이동 거리
   Δθ = (Δd_right − Δd_left) / L          ← 회전량

   x += Δs · cos(θ + Δθ/2)                ← 중점법
   y += Δs · sin(θ + Δθ/2)
   θ += Δθ                                (−π ~ π 로 정규화)

왜 cos(θ + Δθ/2) 이고 cos(θ) 가 아닌가? 로봇은 그 구간에서 θ 에서 θ+Δθ 로 회전하며 이동했다. 시작 각도만 쓰면 곡선 주행 시 매 스텝 한쪽으로 치우친 오차가 누적된다. 중간 각도를 쓰면 2차 정확도가 된다. 50 Hz(20 ms) 에서는 Δθ 가 작아 차이가 미미해 보이지만, 회전하며 달리는 구간이 길어지면 사각형 주행 복귀 오차로 그대로 드러난다.

2-3. 틱 → 미터

   rad_per_tick = 2π / encoder_cpr
   Δd = Δticks × rad_per_tick × wheel_radius
encoder_cpr 은 반드시 "출력축(바퀴축) 기준"

모터에 달린 엔코더가 11 PPR 이고 기어비가 1:90 이면, 4체배(TIM 엔코더 모드가 A/B 상의 엣지 4개를 모두 센다) 포함 출력축 기준 CPR = 11 × 4 × 90 = 3960. 데이터시트의 "11 PPR" 을 그대로 넣으면 거리가 360배 틀린다. 로봇이 1 cm 움직였는데 3.6 m 갔다고 기록한다. 이 값은 hardware/INVENTORY.md 6절에 근거와 함께 적는다.

2-4. 왜 C++ 로 다시 쓰는가

이유이 노드에서 구체적으로
고정 주기의 결정성인터프리터·GC 가 없어 create_wall_timer 의 지터가 작다. dt 는 실측(now() − prev)으로 보정하지만, 명령 전송 간격이 흔들리면 MCU 의 워치독·제어 주기와 박자가 어긋난다
바이트 스트림 파싱헤더 동기·길이·CRC·리틀엔디안 해석은 바이트 배열 위에서 하는 일이다. C++ 은 그 일을 숨기지 않고 보여 준다 — 그것이 배울 내용이다. IMU 200 Hz 가 더해지면 초당 프레임이 250 개가 되어 파서의 효율도 의미가 생긴다
Lock 이 필요 없다기본 실행기(SingleThreadedExecutor)는 콜백을 한 번에 하나씩 순서대로 돌린다. on_cmd_vel 과 두 타이머 콜백이 동시에 실행될 수 없으므로 Python 판의 threading.Lock 에 해당하는 것이 없다. (08b 이후 MultiThreadedExecutor 로 옮기면 그때 std::mutex 나 콜백 그룹이 필요해진다 — 부록 A · rclcpp 레퍼런스 §10)

2-5. 통신 설계에서 이해해야 할 여섯 가지

① 시리얼은 스트림이다 — 프레임 경계가 없다

TCP 처럼 시리얼에도 "메시지"라는 단위가 없다. 바이트가 그냥 흐른다. 노드가 중간부터 읽기 시작하면 어디가 프레임의 시작인지 모른다. 그래서 헤더 바이트(0xAA 0x55)를 만날 때까지 한 바이트씩 버리며 동기를 맞추고, TYPE 과 LEN 을 읽어 그만큼 더 받은 뒤 CRC 로 "이게 정말 프레임이었는지" 확인한다. 페이로드 안에 우연히 AA 55 가 나올 수 있다 — 그때 LEN 과 CRC 가 걸러 준다 (이해 확인 6번). 타입마다 길이가 다르므로 LEN 필드가 v1 보다 하나 더 있다.

② /odom 은 RELIABLE, /imu/data_raw 는 BEST_EFFORT

Nav2 의 odom_smoother 는 SystemDefaultsQoS(= RELIABLE)로 /odom 을 구독한다. 발행자가 BEST_EFFORT 면 연결 자체가 성립하지 않는다. 06 단계에서는 멀쩡해 보이다가 09 단계에서 조용히 실패한다. 반대로 IMU 는 초당 100~200 개가 오는 센서 스트림이라 놓친 샘플을 재전송받아 봐야 늦은 값이다 — SensorDataQoS(BEST_EFFORT)로 낸다. robot_localization 은 odom·IMU 구독을 모두 SensorDataQoS 로 만들므로(ros_filter.cpp 의 custom_qos) 어느 쪽 발행자와도 연결된다 — RELIABLE 발행자 + BEST_EFFORT 구독자는 호환이다. 연결 뒤 ros2 topic info -v 로 양쪽 프로파일을 직접 본다.

③ 워치독은 양쪽에 있어야 한다

브리지의 워치독(cmd_timeout_s)은 "상위 노드가 명령을 안 보낼 때"를 막는다. 그런데 Pi 가 죽거나 USB 가 빠지면 브리지 노드 자체가 사라져서 아무 명령도 못 보낸다. 그때 MCU 가 마지막 속도를 유지하면 로봇은 계속 달린다. MCU 쪽 워치독이 최후의 보루다. 그리고 그 둘과 별개로 IWDG(하드웨어 워치독)가 펌웨어 자체가 멈춘 경우를 막는다.

④ 하나의 좌표계에는 부모가 하나뿐 — publish_tf

05 단계의 철칙이다. §3-10 에서 robot_localization 의 EKF 가 odom → base_footprint 를 발행하게 되면 브리지는 같은 TF 를 쏘면 안 된다. 그때 publish_tf:=false 로 둔다. 그리고 URDF 의 루트가 base_footprint 이므로 odom 의 자식도 base_footprint 여야 한다. base_link 를 자식으로 두면 base_link 의 부모가 둘(URDF 의 base_footprint, 브리지의 odom)이 된다.

⑤ 공분산을 0 으로 두면 안 된다

휠 오도메트리는 회전 누적오차가 크다. 공분산을 0 으로 두면 EKF 가 이 값을 "완벽하다"고 믿어 IMU 를 무시한다. 정확한 값은 캘리브레이션 뒤에 사각형 주행 오차로 대략 추정하되, 처음에는 x·y 0.001, yaw 0.01 정도의 겸손한 값으로 시작한다. IMU 쪽도 마찬가지다 — 정지 바이어스 실험(§3-7)에서 잰 분산을 넣는다.

⑥ MCU 의 시각(tick_ms)을 ROS 시각으로 옮긴다

엔코더 샘플과 IMU 샘플은 MCU 안에서 같은 타이머로 시각이 찍힌다. Pi 가 "받은 시각"을 stamp 로 쓰면 시리얼 지연과 지터가 그대로 타임스탬프에 들어가고, EKF 는 두 센서를 잘못된 순서로 융합한다. 그래서 브리지는 첫 프레임에서 offset = now − tick_ms 를 잡고 이후 stamp = tick_ms + offset 으로 환산한다. MCU 수정 진동자의 드리프트(수십 ppm, 하루에 수 초)는 천천히 따라가는 보정이 필요하다 — 코드의 TODO.

2-6. IMU 는 왜 MCU 에 붙이고, 어떻게 읽는가

전복·과경사 감지 후 즉시 정지, 경사에서의 출력 보정, 요 각속도로 직진 보정은 전부 제어 루프 안에서 엔코더와 같은 박자로 써야 하는 값이다. Pi 를 거치면 시리얼과 DDS 의 왕복 지연이 제어 루프에 들어간다. 그래서 IMU 는 MCU 에 붙이고, MCU 가 자기 제어에 쓰면서 동시에 샘플을 Pi 로 흘려보낸다. Pi 쪽에서 IMU 가 필요한 곳은 EKF 하나뿐이고, 100 Hz 면 충분하다.

그런데 "읽는다"의 실체가 페리페럴마다 다르다. 이 차이가 배선과 펌웨어 구조를 정한다.

페리페럴누가 시간을 정하는가CPU 비용이 프로젝트에서
엔코더 — TIM 엔코더 모드엔코더의 엣지. 하드웨어 카운터가 스스로 센다. 마스터/슬레이브 개념 없음0. 루프는 CNT 레지스터를 읽을 뿐TIM2/TIM5/TIM23/TIM24 — 바퀴마다 하나, 넷 다 32비트
BNO055 — I2CMCU 가 마스터. MCU 가 주소를 부르고 클록을 내며 바이트를 끌어온다. 센서는 시키지 않으면 아무것도 안 보낸다한 번 읽기(약 20 B, 400 kHz) ≈ 0.5 ms. DMA 로 CPU 는 비우지만 버스는 점유100 Hz(10 ms) 타이머에서 DMA 읽기. 1 ms 루프에는 못 넣는다
WT901 — UART대등한 전이중. 센서가 설정된 속도로 스스로 스트림을 보내고 MCU 는 수신자DMA + IDLE 인터럽트라 사실상 0USART6 230400, 200 Hz(5 ms). Pi 링크와 같은 수신 패턴
"1 kHz 루프에서 IMU 를 쓴다"의 정확한 뜻

두 센서 모두 내부 융합 프로세서가 새 값을 만드는 속도는 100~200 Hz 다. 1 kHz(1 ms 주기) 루프가 하는 일은 매 바퀴 최신 IMU 값이 담긴 변수를 읽어 그 바퀴의 판단(기울기 검사, 요 보정)에 쓰는 것이고, 그 변수는 새 샘플이 도착할 때만 갱신된다. 1 kHz 는 엔코더 PID 와 비상정지 반응을 위한 주기이지 IMU 의 샘플링 주기가 아니다. 전복 판정이 10 ms 늦는 것은 문제가 되지 않는다.

실내에서 자력계로 얻는 절대 방위는 모터와 철골 때문에 수십 도씩 틀어진다. 이 프로젝트는 각속도와 가속도만 쓰고, 회전은 자이로 z 축 적분이 맡는다. 두 센서의 융합 출력(오일러·쿼터니언)은 참고로 보되 EKF 에는 넣지 않는다.

// ── 프레임 상수 (06a 계약 v2): AA 55 | TYPE | LEN | PAYLOAD[LEN] | CRC8(TYPE..PAYLOAD) ──
constexpr uint8_t HEADER0 = 0xAA;
constexpr uint8_t HEADER1 = 0x55;
constexpr uint8_t TYPE_VELOCITY = 0x01;   // Pi → MCU
constexpr uint8_t TYPE_STATE    = 0x81;   // MCU → Pi
constexpr uint8_t TYPE_IMU      = 0x82;
constexpr uint8_t TYPE_EVENT    = 0x83;
constexpr size_t LEN_VELOCITY = 4;        // v_left i16, v_right i16
constexpr size_t LEN_STATE    = 17;       // L i32, R i32, batt u16, current u16, fault u8, tick u32
constexpr size_t LEN_IMU      = 17;       // id u8, ax ay az i16, gx gy gz i16, tick u32
constexpr size_t LEN_EVENT    = 7;        // code u8, detail u16, tick u32
constexpr size_t MAX_PAYLOAD  = 64;
constexpr size_t OVERHEAD     = 5;        // 헤더 2 + TYPE + LEN + CRC

constexpr double G_MPS2  = 9.80665;                          // 1 g
constexpr double DEG2RAD = 3.14159265358979323846 / 180.0;
constexpr double MG_TO_MPS2   = G_MPS2 / 1000.0;             // mg → m/s²        (06a §4-3)
constexpr double DDPS_TO_RADS = 0.1 * DEG2RAD;               // 0.1 °/s → rad/s  (= π / 1800)

// ── fault 비트 · 이벤트 코드 — 06a §4-2 표와 이름까지 같게. 펌웨어 frames.h 와 1:1 ──
constexpr uint8_t FAULT_WATCHDOG = 1u << 0;   // 워치독 정지 중 (프레임 끊김)
constexpr uint8_t FAULT_LOW_BATT = 1u << 1;

constexpr uint8_t FAULT_TILT     = 1u << 3;   // 과경사·전복
constexpr uint8_t FAULT_IMU      = 1u << 4;   // IMU 통신 실패
constexpr uint8_t FAULT_DRIVER   = 1u << 5;   // 모터 드라이버 fault 입력

constexpr uint8_t EVT_OVERCURR = 0x02;         // detail = mA

inline const char * event_name(uint8_t code)

    default:           return "unknown";      // 학습자 확장 코드는 여기와 06a 표에 함께 추가

  uint16_t detail = 0;         // 코드별 부가값 (mV, mA, 0.1°, ms, sensor_id, 풀린 비트)

// ── CRC-8 (다항식 0x07, 초기값 0x00) — 펌웨어의 crc8() 과 한 비트도 다르면 안 된다 ──
inline uint8_t crc8(const uint8_t * data, size_t len)
{
  uint8_t crc = 0x00;
  for (size_t i = 0; i < len; ++i) {
    crc ^= data[i];
    for (int b = 0; b < 8; ++b) {
      crc = (crc & 0x80) ? static_cast<uint8_t>((crc << 1) ^ 0x07)
                         : static_cast<uint8_t>(crc << 1);
    }
  }
  return crc;
}

// ── 리틀엔디안 읽기/쓰기 — 호스트의 엔디안에 기대지 않고 바이트를 직접 조립한다 ──
inline uint16_t rd_u16(const uint8_t * p) { return static_cast<uint16_t>(p[0] | (p[1] << 8)); }
inline uint32_t rd_u32(const uint8_t * p)
{
  return static_cast<uint32_t>(p[0]) | (static_cast<uint32_t>(p[1]) << 8) |
         (static_cast<uint32_t>(p[2]) << 16) | (static_cast<uint32_t>(p[3]) << 24);
}
inline int16_t rd_i16(const uint8_t * p) { uint16_t u = rd_u16(p); int16_t v; std::memcpy(&v, &u, 2); return v; }
inline int32_t rd_i32(const uint8_t * p) { uint32_t u = rd_u32(p); int32_t v; std::memcpy(&v, &u, 4); return v; }
inline void wr_u16(uint8_t * p, uint16_t v) { p[0] = v & 0xFF; p[1] = (v >> 8) & 0xFF; }
inline void wr_u32(uint8_t * p, uint32_t v) { for (int i = 0; i < 4; ++i) { p[i] = (v >> (8 * i)) & 0xFF; } }
inline void wr_i16(uint8_t * p, int16_t v) { uint16_t u; std::memcpy(&u, &v, 2); wr_u16(p, u); }
inline void wr_i32(uint8_t * p, int32_t v) { uint32_t u; std::memcpy(&u, &v, 4); wr_u32(p, u); }

// m/s → mm/s 정수. int16 범위(±32.767 m/s)로 포화시킨다.
//   정수 스케일링을 쓰는 이유: MCU 쪽에서 float 파싱을 피하고 프레임 크기를 고정하기 위해.
//   포화 처리를 빼면 큰 값이 넘쳐서 부호가 뒤집힌다 — 로봇이 반대로 튀어나간다.
inline int16_t to_mm_s_saturated(double v_mps)
{
  const double mm = std::clamp(std::round(v_mps * 1000.0), -32768.0, 32767.0);
  return static_cast<int16_t>(mm);
}

// ── 일반 인코더: 어떤 타입이든 같은 함수로 싼다. out 은 OVERHEAD + len 바이트 이상. 반환 = 전체 길이 ──
inline size_t encode_frame(uint8_t type, const uint8_t * payload, size_t len, uint8_t * out)
{
  out[0] = HEADER0;
  out[1] = HEADER1;
  out[2] = type;
  out[3] = static_cast<uint8_t>(len);
  if (len > 0) { std::memcpy(out + 4, payload, len); }
  out[4 + len] = crc8(out + 2, 2 + len);            // TYPE 부터 PAYLOAD 끝까지
  return OVERHEAD + len;
}

// Pi → MCU 속도 명령 (9 바이트)
inline std::array<uint8_t, OVERHEAD + LEN_VELOCITY> encode_velocity(double v_left_mps, double v_right_mps)
{
  uint8_t p[LEN_VELOCITY];
  wr_i16(p, to_mm_s_saturated(v_left_mps));
  wr_i16(p + 2, to_mm_s_saturated(v_right_mps));
  std::array<uint8_t, OVERHEAD + LEN_VELOCITY> f{};
  encode_frame(TYPE_VELOCITY, p, LEN_VELOCITY, f.data());
  return f;
}

// ── 완성된 프레임 하나 — 파서가 CRC 까지 확인한 뒤 넘겨 준다 ──
struct Frame
{
  uint8_t type = 0;
  uint8_t len = 0;
  std::array<uint8_t, MAX_PAYLOAD> payload{};
};

inline bool decode_state(const Frame & f, McuState & s, std::string & err)
{
  if (f.type != TYPE_STATE || f.len != LEN_STATE) { err = "state frame: wrong type/len"; return false; }
  const uint8_t * p = f.payload.data();
  s.left_ticks = rd_i32(p);
  s.right_ticks = rd_i32(p + 4);
  s.batt_mv = rd_u16(p + 8);
  s.current_ma = rd_u16(p + 10);
  s.fault = p[12];
  s.tick_ms = rd_u32(p + 13);
  return true;
}

inline bool decode_imu(const Frame & f, ImuSample & s, std::string & err)
{
  if (f.type != TYPE_IMU || f.len != LEN_IMU) { err = "imu frame: wrong type/len"; return false; }
  const uint8_t * p = f.payload.data();
  s.sensor_id = p[0];
  // 정수 스케일 → SI (06a §4-3): m/s² = mg × 9.80665 / 1000,  rad/s = 0.1 °/s × π / 1800   (단위 번역은 여기 한 곳에서만)
  s.ax = rd_i16(p + 1) * MG_TO_MPS2;
  s.ay = rd_i16(p + 3) * MG_TO_MPS2;
  s.az = rd_i16(p + 5) * MG_TO_MPS2;
  s.gx = rd_i16(p + 7) * DDPS_TO_RADS;
  s.gy = rd_i16(p + 9) * DDPS_TO_RADS;
  s.gz = rd_i16(p + 11) * DDPS_TO_RADS;
  s.tick_ms = rd_u32(p + 13);
  return true;
}

inline bool decode_event(const Frame & f, McuEvent & e, std::string & err)
{
  if (f.type != TYPE_EVENT || f.len != LEN_EVENT) { err = "event frame: wrong type/len"; return false; }
  const uint8_t * p = f.payload.data();
  e.code = p[0];
  e.detail = rd_u16(p + 1);
  e.tick_ms = rd_u32(p + 3);
  return true;
}

// ── 스트림 파서 — 시리얼은 프레임 경계가 없다. 바이트를 하나씩 먹여 상태기계로 잘라 낸다 ──
class FrameParser
{
public:
  // 완성된 프레임이 나오면 true 를 돌려주고 out 을 채운다.
  // 동기 손실·CRC 오류는 false 를 돌려주면서 err 에 이유를 적는다 (호출 전에 err 를 비워 둔다).
  bool push(uint8_t b, Frame & out, std::string & err)
  {
    switch (state_) {
      case S::H0:
        if (b == HEADER0) { state_ = S::H1; } else { ++dropped_; }
        return false;
      case S::H1:
        if (b == HEADER1) { state_ = S::TYPE; }
        else { ++dropped_; state_ = (b == HEADER0) ? S::H1 : S::H0; }   // "AA AA 55" 처럼 AA 가 겹치면 두 번째 AA 가 진짜 헤더일 수 있다
        return false;
      case S::TYPE:
        cur_.type = b;
        state_ = S::LEN;
        return false;
      case S::LEN:
        if (b > MAX_PAYLOAD) { state_ = S::H0; ++bad_len_; err = "payload too long (sync lost?)"; return false; }
        cur_.len = b;
        idx_ = 0;
        state_ = (b == 0) ? S::CRC : S::PAYLOAD;
        return false;
      case S::PAYLOAD:
        cur_.payload[idx_++] = b;
        if (idx_ >= cur_.len) { state_ = S::CRC; }
        return false;
      case S::CRC: {
        state_ = S::H0;
        uint8_t buf[2 + MAX_PAYLOAD];
        buf[0] = cur_.type;
        buf[1] = cur_.len;
        std::memcpy(buf + 2, cur_.payload.data(), cur_.len);
        if (crc8(buf, 2 + cur_.len) != b) { ++bad_crc_; err = "CRC mismatch (wiring / GND / baudrate / ModemManager?)"; return false; }
        out = cur_;
        ++frames_;
        return true;
      }
    }
    return false;
  }
  uint32_t frames() const { return frames_; }
  uint32_t dropped_bytes() const { return dropped_; }   // 헤더를 찾느라 버린 바이트 — 0 이 아니면 동기 손실이 있었다
  uint32_t bad_crc() const { return bad_crc_; }

private:
  enum class S { H0, H1, TYPE, LEN, PAYLOAD, CRC } state_ = S::H0;
  Frame cur_;
  size_t idx_ = 0;
  uint32_t dropped_ = 0, bad_crc_ = 0, bad_len_ = 0, frames_ = 0;
};

// ── 가짜 MCU — 하드웨어 없이 ROS 쪽 배선을 먼저 검증하기 위한 것 ─────────────
//   명령받은 속도가 그대로 실현되었다고 가정하고 엔코더 틱을 적분한다.
//   IMU 도 흉내낸다: 정지해 있으니 az = 1 g, 각속도 z 는 명령 ω 그대로. 그래야 EKF(§3-10)를 하드웨어 없이 검증할 수 있다.
class LoopbackMcu
{
public:
  LoopbackMcu(int encoder_cpr, double wheel_radius, double wheel_separation)
  : cpr_(std::max(1, encoder_cpr)), r_(wheel_radius), sep_(wheel_separation) {}

  void set_velocity(double v_left_mps, double v_right_mps)
  {
    vl_ = v_left_mps;
    vr_ = v_right_mps;
  }

  McuState step(double dt)   // dt 초가 흘렀다고 보고 엔코더를 적분한다
  {
    const double circumference = 2.0 * kPi * r_;
    if (circumference > 0.0) {
      l_accum_ += (vl_ * dt / circumference) * cpr_;
      r_accum_ += (vr_ * dt / circumference) * cpr_;
    }
    tick_ms_ += static_cast<uint32_t>(std::lround(dt * 1000.0));
    McuState s;
    s.left_ticks = static_cast<int32_t>(l_accum_);
    s.right_ticks = static_cast<int32_t>(r_accum_);
    s.batt_mv = 12000;
    s.current_ma = static_cast<uint16_t>(200.0 + 2000.0 * (std::fabs(vl_) + std::fabs(vr_)));   // 움직이면 전류가 는다
    s.fault = 0;
    s.tick_ms = tick_ms_;
    return s;
  }

  ImuSample imu_sample(double dt)   // dt 초마다 불린다고 보고 IMU 쪽 시계를 따로 올린다 — 상태 프레임(20 ms)과 stamp 가 겹치지 않게
  {
    imu_tick_ms_ += static_cast<uint32_t>(std::lround(dt * 1000.0));
    ImuSample s;
    s.sensor_id = 0;
    s.az = G_MPS2;                                         // 수평 정지: 중력만
    s.gz = (sep_ > 0.0) ? (vr_ - vl_) / sep_ : 0.0;        // 명령 각속도를 그대로 "측정"한 셈
    s.tick_ms = imu_tick_ms_;
    return s;
  }

private:
  static constexpr double kPi = 3.14159265358979323846;
  int cpr_;
  double r_, sep_;
  double vl_ = 0.0, vr_ = 0.0;
  double l_accum_ = 0.0, r_accum_ = 0.0;
  uint32_t tick_ms_ = 0, imu_tick_ms_ = 0;
};

}  // namespace rpi5_mcu

static int feed(FrameParser & parser, const std::vector<uint8_t> & bytes, std::vector<Frame> & out)
{
  int n = 0;
  for (uint8_t b : bytes) {
    Frame f; std::string err;
    if (parser.push(b, f, err)) { out.push_back(f); ++n; }
    else if (!err.empty()) { std::printf("  parser: %s\n", err.c_str()); }
  }
  return n;
}

3-3. serial_port.hpp — termios 로 시리얼 열기, 논블로킹 폴링

Boost.Asio 나 외부 serial 라이브러리를 쓰지 않는다. 의존성이 0 이고, 무엇보다 OS 가 시리얼을 어떻게 다루는지(보드레이트·프레이밍·타임아웃이 전부 커널의 termios 구조체 하나에 있다)를 눈으로 보는 것이 이 단계의 학습 내용이기 때문이다. v1 과 달리 MCU 가 상태·IMU·이벤트를 제각기 다른 주기로 보내므로, 읽기는 "한 프레임을 기다리는" 방식이 아니라 짧은 주기로 도착한 바이트를 전부 가져와 파서에 먹이는 논블로킹 폴링이다(VMIN=0, VTIME=0). 경로는 udev 가 만든 /dev/mcu 를 쓴다. ttyACM 장치는 ModemManager 가 건드리므로 udev 규칙의 ID_MM_DEVICE_IGNORE 가 적용되어 있어야 한다 — §3-8.

// include/rpi5_mcu_bridge_cpp/serial_port.hpp
#pragma once
#include <fcntl.h>
#include <termios.h>
#include <unistd.h>

#include <cerrno>
#include <cstdint>
#include <cstring>
#include <stdexcept>
#include <string>

// POSIX termios 기반 최소 시리얼 포트. 논블로킹 읽기(도착한 만큼만) + 블로킹 쓰기.
class SerialPort
{
public:
  SerialPort() = default;
  ~SerialPort() { close_port(); }
  SerialPort(const SerialPort &) = delete;              // fd 를 둘이 소유하면 안 된다
  SerialPort & operator=(const SerialPort &) = delete;

  void open_port(const std::string & path, int baudrate)
  {
    fd_ = ::open(path.c_str(), O_RDWR | O_NOCTTY);      // O_NOCTTY: 이 포트를 제어 터미널로 삼지 않는다
    if (fd_ < 0) {
      throw std::runtime_error(path + ": " + std::strerror(errno));
    }
    termios tio{};
    if (tcgetattr(fd_, &tio) != 0) { fail("tcgetattr"); }

    cfmakeraw(&tio);                    // 8N1, 에코·줄단위 처리·특수문자 해석 전부 끔 (바이너리 프레임에 필수)
    tio.c_cflag |= (CLOCAL | CREAD);    // 모뎀 제어선 무시, 수신 켜기
    tio.c_cflag &= ~CRTSCTS;            // 하드웨어 흐름제어 없음
    tio.c_cc[VMIN] = 0;                 // ★ 논블로킹 폴링: 읽을 것이 없으면 read() 가 0 을 즉시 돌려준다
    tio.c_cc[VTIME] = 0;

    const speed_t spd = to_speed(baudrate);
    cfsetispeed(&tio, spd);
    cfsetospeed(&tio, spd);
    if (tcsetattr(fd_, TCSANOW, &tio) != 0) { fail("tcsetattr"); }
    tcflush(fd_, TCIOFLUSH);            // 열기 전에 쌓인 쓰레기 바이트를 버린다
  }

  bool is_open() const { return fd_ >= 0; }

  void write_all(const uint8_t * data, size_t len)
  {
    size_t off = 0;
    while (off < len) {
      const ssize_t n = ::write(fd_, data + off, len - off);
      if (n < 0) {
        if (errno == EINTR) { continue; }
        fail("write");
      }
      off += static_cast<size_t>(n);
    }
  }

  // 도착해 있는 바이트를 최대 max 개 가져온다. 없으면 0. (기다리지 않는다)
  size_t read_some(uint8_t * buf, size_t max)
  {
    const ssize_t n = ::read(fd_, buf, max);
    if (n < 0) {
      if (errno == EAGAIN || errno == EINTR) { return 0; }
      fail("read");
    }
    return static_cast<size_t>(n);
  }

  void close_port()
  {
    if (fd_ >= 0) {
      ::close(fd_);
      fd_ = -1;
    }
  }

private:
  [[noreturn]] void fail(const char * what)
  {
    const std::string msg = std::string(what) + ": " + std::strerror(errno);
    close_port();
    throw std::runtime_error(msg);
  }

  static speed_t to_speed(int baud)
  {
    switch (baud) {
      case 9600: return B9600;
      case 19200: return B19200;
      case 38400: return B38400;
      case 57600: return B57600;
      case 115200: return B115200;
      case 230400: return B230400;
      case 460800: return B460800;
      case 921600: return B921600;
      default: throw std::invalid_argument("unsupported baudrate: " + std::to_string(baud));
    }
  }

  int fd_ = -1;
};

USB 자체에는 보드레이트가 없다. 호스트가 보낸 460800 을 ST-LINK 가 받아 자기 쪽 UART(MCU 의 USART3 과 결선된 선)를 그 속도로 설정한다. 그러므로 이 값은 펌웨어의 USART3 설정과 같아야 한다. 다르면 바이트가 깨져 CRC 오류로 나타난다. 460800 은 두 IMU 를 200 Hz 로 올릴 때의 약 10 kB/s 가 115200(≈11.5 kB/s)을 90 % 채우기 때문에 고른 값이다 — 460800(≈46 kB/s)이면 22 % (06a §4-3 대역폭 계산).

3-4. mcu_bridge_node.cpp — 노드

Python 판의 구조를 옮기되 타이머가 둘이다. 명령 타이머(50 Hz, 20 ms)는 속도 프레임을 보내고, 수신 타이머(500 Hz, 2 ms)는 도착한 바이트를 전부 파서에 먹여 완성된 프레임을 타입별로 처리한다. 파라미터 이름은 Python 판과 같게 두었으므로 robot_params.yaml 의 mcu_bridge: 블록이 그대로 들어간다(IMU 관련 두 개만 추가). // TODO(you) 다섯 곳은 빌드는 되지만 당신이 채워야 완성이다.

{
public:
  McuBridge()
  : Node("mcu_bridge")            // ★ YAML 의 키 'mcu_bridge:' 와 같아야 파라미터가 들어간다
  {
    // ── 1. 파라미터 선언 ─ 이름·기본값은 Python 참고 구현과 같다 (+ imu_frame, imu_primary) ──
    port_ = declare_parameter<std::string>("port", "/dev/mcu");
    baudrate_ = declare_parameter<int>("baudrate", 460800);           // 계약 v2
    simulate_ = declare_parameter<bool>("simulate", true);

    wheel_radius_ = declare_parameter<double>("wheel_radius", 0.0325);
    wheel_sep_ = declare_parameter<double>("wheel_separation", 0.145);
    encoder_cpr_ = declare_parameter<int>("encoder_cpr", 1000);

    max_v_ = declare_parameter<double>("max_linear_vel", 0.5);
    max_w_ = declare_parameter<double>("max_angular_vel", 1.5);
    cmd_timeout_ = declare_parameter<double>("cmd_timeout_s", 0.5);
    const double rate = declare_parameter<double>("odom_publish_rate", 50.0);

    publish_tf_ = declare_parameter<bool>("publish_tf", true);    // EKF 를 쓰면 false (§3-10)
    odom_frame_ = declare_parameter<std::string>("odom_frame", "odom");
    // URDF 의 루트 링크가 base_footprint 이므로 odom 의 자식도 base_footprint 다 (05 단계 철칙).
    base_frame_ = declare_parameter<std::string>("base_frame", "base_footprint");
    imu_frame_ = declare_parameter<std::string>("imu_frame", "imu_link");
    imu_primary_ = static_cast<int>(declare_parameter<int>("imu_primary", 0));   // 0 = WT901, 1 = BNO055
    period_ = 1.0 / std::max(1.0, rate);

    // 물리 제원이 0 이면 오도메트리가 0 으로 나눠지거나 항상 정지로 보인다. 조용히 틀리는 대신 크게 경고한다.
    if (wheel_radius_ <= 0.0 || wheel_sep_ <= 0.0 || encoder_cpr_ <= 0) {
      RCLCPP_ERROR(get_logger(),
        "wheel_radius / wheel_separation / encoder_cpr 가 설정되지 않았습니다. "
        "hardware/INVENTORY.md 6절을 실측해서 robot_params.yaml 을 채우십시오.");
    }

    // ── 2. 프로토콜 / 시리얼 ───────────────────────────────────────────────
    if (simulate_) {
      loopback_.emplace(encoder_cpr_, wheel_radius_, wheel_sep_);
      RCLCPP_WARN(get_logger(), "simulate:=true — 가짜 MCU 로 동작합니다 (엔코더 + 가짜 IMU).");
    } else {
      try {
        serial_.open_port(port_, baudrate_);
        RCLCPP_INFO(get_logger(), "시리얼 열림: %s @ %d", port_.c_str(), baudrate_);
      } catch (const std::exception & e) {
        RCLCPP_ERROR(get_logger(),
          "시리얼 열기 실패: %s\n"
          "  확인할 것: ① udev 규칙으로 /dev/mcu 가 만들어졌는가 (ls -l /dev/mcu)\n"
          "             ② 컨테이너에 장치가 전달되었는가 (docker-compose device_cgroup_rules)\n"
          "             ③ 사용자가 dialout 그룹인가 (groups)", e.what());
      }
    }

    // ── 3. 통신 인터페이스 ─────────────────────────────────────────────────
    //   /odom 은 RELIABLE (Nav2 가 RELIABLE 로 구독. EKF 는 SensorDataQoS 라 어느 쪽이든 받는다), IMU 는 SensorDataQoS (§2-5 ②).
    //   /mcu/fault 는 TRANSIENT_LOCAL — 늦게 뜬 감독 노드도 현재 fault 를 바로 받는다.
    sub_cmd_ = create_subscription<geometry_msgs::msg::Twist>(
      "cmd_vel", 10, std::bind(&McuBridge::on_cmd_vel, this, std::placeholders::_1));
    pub_odom_ = create_publisher<nav_msgs::msg::Odometry>("odom", rclcpp::QoS(10).reliable());
    pub_joints_ = create_publisher<sensor_msgs::msg::JointState>("joint_states", 10);
    pub_batt_ = create_publisher<sensor_msgs::msg::BatteryState>("battery_state", 10);
    pub_imu_ = create_publisher<sensor_msgs::msg::Imu>("imu/data_raw", rclcpp::SensorDataQoS());
    pub_imu_wt901_ = create_publisher<sensor_msgs::msg::Imu>("imu/wt901/data_raw", rclcpp::SensorDataQoS());
    pub_imu_bno055_ = create_publisher<sensor_msgs::msg::Imu>("imu/bno055/data_raw", rclcpp::SensorDataQoS());
    pub_fault_ = create_publisher<std_msgs::msg::UInt8>("mcu/fault", rclcpp::QoS(1).reliable().transient_local());
    pub_event_ = create_publisher<std_msgs::msg::String>("mcu/event", rclcpp::QoS(10).reliable());
    tf_broadcaster_ = std::make_unique<tf2_ros::TransformBroadcaster>(*this);

    {   // 기동 직후 fault = 0 을 한 번 발행한다. 이후 handle_state() 는 값이 바뀔 때만 발행하므로,
        // 이 한 번이 없으면 simulate 모드(항상 0)에서는 /mcu/fault 가 영원히 비어 있다.
      std_msgs::msg::UInt8 init_fault;
      init_fault.data = 0;
      pub_fault_->publish(init_fault);
    }

    // rclcpp::Time 은 "시계 종류"를 갖는다. now() 로 초기화하지 않으면 뒤의 뺄셈에서
    // "can't subtract times with different time sources" 예외가 난다.
    last_cmd_time_ = now();

    // 타이머 ① 명령 송신 50 Hz (20 ms). simulate 면 여기서 가짜 상태 프레임도 만든다.
    cmd_timer_ = create_wall_timer(
      std::chrono::duration<double>(period_), std::bind(&McuBridge::on_cmd_timer, this));
    // 타이머 ② 수신 폴링 500 Hz (2 ms). 도착한 바이트를 파서에 전부 먹인다. 읽을 것이 없으면 수 μs 에 끝난다.
    rx_timer_ = create_wall_timer(2ms, std::bind(&McuBridge::on_rx_timer, this));

    RCLCPP_INFO(get_logger(), "mcu_bridge(C++) 시작 | port=%s sim=%d r=%.4f L=%.4f cpr=%d imu_primary=%d",
      port_.c_str(), simulate_, wheel_radius_, wheel_sep_, encoder_cpr_, imu_primary_);
  }

  ~McuBridge() override { stop_motors(); }   // 종료 시 반드시 정지 명령. 안전 요구사항.

private:
  // ── /cmd_vel 콜백: 상위 스택(teleop, Nav2)이 보내는 속도 명령 ─────────────
  void on_cmd_vel(const geometry_msgs::msg::Twist & msg)
  {
    // 안전 제한. Nav2 가 튜닝 실수로 큰 값을 보내도 하드웨어를 보호한다.
    v_cmd_ = std::clamp(msg.linear.x, -max_v_, max_v_);
    w_cmd_ = std::clamp(msg.angular.z, -max_w_, max_w_);
    last_cmd_time_ = now();
    // Lock 이 없는 이유: 기본 실행기는 콜백을 한 번에 하나씩 돌린다. 타이머 콜백과 겹치지 않는다.
  }

  // ── 타이머 ①: 워치독 → 역운동학 → 명령 송신 (simulate 면 가짜 상태 생성) ─────
  void on_cmd_timer()
  {
    const rclcpp::Time t = now();

    // 워치독: 명령이 끊기면 즉시 정지 (Wi-Fi 가 끊겼는데 마지막 속도로 계속 달리는 사고를 막는다)
    if ((t - last_cmd_time_).seconds() > cmd_timeout_) {
      v_cmd_ = 0.0;
      w_cmd_ = 0.0;
    }
    // MCU 가 fault 를 보고하는 동안은 0 만 보낸다. 실제 차단은 MCU 가 이미 했다 — 이것은 상위 스택을 향한 "동의" 다.
    double v = v_cmd_, w = w_cmd_;
    if (fault_ != 0) {
      v = 0.0;
      w = 0.0;
      RCLCPP_WARN_THROTTLE(get_logger(), *get_clock(), 2000, "MCU fault=0x%02X — 명령을 0 으로 보냅니다", fault_);
    }

    // 차동구동 역운동학: (v, ω) → 좌/우 바퀴 선속도
    const double v_left = v - w * wheel_sep_ / 2.0;
    const double v_right = v + w * wheel_sep_ / 2.0;

    if (simulate_) {
      loopback_->set_velocity(v_left, v_right);
      handle_state(loopback_->step(period_));
    } else if (serial_.is_open()) {
      try {
        const auto frame = rpi5_mcu::encode_velocity(v_left, v_right);
        serial_.write_all(frame.data(), frame.size());
      } catch (const std::exception & e) {
        RCLCPP_WARN_THROTTLE(get_logger(), *get_clock(), 2000, "MCU 송신 오류: %s", e.what());
      }
    }
  }

  // ── 타이머 ②: 수신 폴링. 도착한 바이트를 전부 파서에 먹이고 완성된 프레임을 타입별로 처리 ──
  void on_rx_timer()
  {
    if (simulate_) {                       // 100 Hz(10 ms) 가짜 IMU: 2 ms 틱 5번마다 한 번
      if (++sim_div_ % 5 == 0) { handle_imu(loopback_->imu_sample(0.010)); }
      return;
    }
    if (!serial_.is_open()) { return; }

    uint8_t buf[512];
    size_t n = 0;
    try {
      n = serial_.read_some(buf, sizeof buf);
    } catch (const std::exception & e) {
      RCLCPP_WARN_THROTTLE(get_logger(), *get_clock(), 2000, "MCU 수신 오류: %s", e.what());
      return;
    }
    for (size_t i = 0; i < n; ++i) {
      rpi5_mcu::Frame f;
      std::string err;
      if (parser_.push(buf[i], f, err)) {
        dispatch(f);
      } else if (!err.empty()) {
        RCLCPP_WARN_THROTTLE(get_logger(), *get_clock(), 2000, "프레임 오류: %s (bad_crc=%u dropped=%u)",
                             err.c_str(), parser_.bad_crc(), parser_.dropped_bytes());
      }
    }
  }

  void dispatch(const rpi5_mcu::Frame & f)
  {
    std::string err;
    switch (f.type) {
      case rpi5_mcu::TYPE_STATE: { rpi5_mcu::McuState s; if (rpi5_mcu::decode_state(f, s, err)) { handle_state(s); } break; }
      case rpi5_mcu::TYPE_IMU:   { rpi5_mcu::ImuSample s; if (rpi5_mcu::decode_imu(f, s, err)) { handle_imu(s); } break; }
      case rpi5_mcu::TYPE_EVENT: { rpi5_mcu::McuEvent e; if (rpi5_mcu::decode_event(f, e, err)) { handle_event(e); } break; }
      default:
        RCLCPP_WARN_THROTTLE(get_logger(), *get_clock(), 2000, "알 수 없는 프레임 타입 0x%02X", f.type);
    }
    if (!err.empty()) { RCLCPP_WARN_THROTTLE(get_logger(), *get_clock(), 2000, "%s", err.c_str()); }
  }

  // ── MCU 시각(tick_ms) → ROS 시각. 첫 프레임에서 offset 을 잡는다 (§2-5 ⑥) ──
  rclcpp::Time stamp_from_tick(uint32_t tick_ms)
  {
    const int64_t tick_ns = static_cast<int64_t>(tick_ms) * 1000000LL;
    if (!tick_offset_ns_) {
      tick_offset_ns_ = now().nanoseconds() - tick_ns;
    }
    // TODO(you): MCU 수정 진동자의 드리프트(수십 ppm)를 천천히 따라가는 보정 — 예) 매 프레임 (now − (offset+tick)) 의 지수 이동평균으로 offset 을 미세 조정.
    //            그리고 tick_ms 가 32비트를 넘어 랩어라운드(49.7일)하는 경우.
    return rclcpp::Time(*tick_offset_ns_ + tick_ns, RCL_ROS_TIME);
  }

  void handle_state(const rpi5_mcu::McuState & s)
  {
    const rclcpp::Time t = stamp_from_tick(s.tick_ms);
    if (s.fault != fault_) {                                   // 바뀔 때만 발행 — TRANSIENT_LOCAL 이라 마지막 값이 유지된다
      std_msgs::msg::UInt8 m;
      m.data = s.fault;
      pub_fault_->publish(m);
      if (s.fault != 0) {
        RCLCPP_ERROR(get_logger(), "MCU fault 0x%02X (batt %u mV, current %u mA)", s.fault, s.batt_mv, s.current_ma);
      } else {
        RCLCPP_INFO(get_logger(), "MCU fault 해제");
      }
    }
    fault_ = s.fault;
    integrate_odometry(s, t);
  }

  void handle_imu(const rpi5_mcu::ImuSample & s)
  {
    sensor_msgs::msg::Imu m;
    m.header.stamp = stamp_from_tick(s.tick_ms);
    m.header.frame_id = imu_frame_;
    m.orientation_covariance[0] = -1.0;                        // orientation 을 채우지 않는다는 표시 (REP-145)
    m.angular_velocity.x = s.gx;  m.angular_velocity.y = s.gy;  m.angular_velocity.z = s.gz;        // rad/s
    m.linear_acceleration.x = s.ax;  m.linear_acceleration.y = s.ay;  m.linear_acceleration.z = s.az; // m/s², 중력 포함
    // 공분산: 0 이면 EKF 가 "완벽한 센서"로 믿는다. 처음엔 겸손한 값, §3-7 정지 실험의 분산으로 교체한다.
    for (int i : {0, 4, 8}) {
      m.angular_velocity_covariance[i] = 1e-4;                 // TODO(you): 실측 분산
      m.linear_acceleration_covariance[i] = 1e-2;
    }
    if (s.sensor_id == 0) { pub_imu_wt901_->publish(m); } else { pub_imu_bno055_->publish(m); }
    if (static_cast<int>(s.sensor_id) == imu_primary_) { pub_imu_->publish(m); }   // EKF 가 구독하는 것은 이것 하나
  }

  void handle_event(const rpi5_mcu::McuEvent & e)
  {
    char buf[48];
    std::snprintf(buf, sizeof buf, "%u:%u", e.code, e.detail);   // 예) "2:11300" = 과전류(0x02) 11300 mA — 06a §4-2 코드 표
    std_msgs::msg::String m;
    m.data = buf;
    pub_event_->publish(m);
    RCLCPP_WARN(get_logger(), "MCU event %s (code=%u detail=%u tick=%u)",
                rpi5_mcu::event_name(e.code), e.code, e.detail, e.tick_ms);
    // TODO(you): 학습자 확장 코드(예: 0x20 BNO055 CALIB_STAT, §3-6-6)를 event_name() 과 06a 표에 함께 추가
  }

  // ── 정운동학 + 중점법 적분 ──────────────────────────────────────────────
  void integrate_odometry(const rpi5_mcu::McuState & s, const rclcpp::Time & t)
  {
    if (!prev_) {                          // 첫 샘플: 기준점만 잡고 발행하지 않는다
      prev_ = Prev{s.left_ticks, s.right_ticks, t};
      return;
    }
    const double dt = (t - prev_->stamp).seconds();
    if (dt <= 0.0) { return; }

    // 누적 카운트의 차분. 부호 없는 뺄셈 뒤 재해석하면 32비트 랩어라운드가 일어나도 옳다 (부호 있는 오버플로는 UB).
    const int32_t d_l_ticks = static_cast<int32_t>(
      static_cast<uint32_t>(s.left_ticks) - static_cast<uint32_t>(prev_->left));
    const int32_t d_r_ticks = static_cast<int32_t>(
      static_cast<uint32_t>(s.right_ticks) - static_cast<uint32_t>(prev_->right));
    prev_ = Prev{s.left_ticks, s.right_ticks, t};

    // 틱 → 바퀴 회전각 [rad] → 접지점 이동거리 [m]
    const double rad_per_tick = 2.0 * kPi / std::max(1, encoder_cpr_);
    const double d_left_rad = d_l_ticks * rad_per_tick;
    const double d_right_rad = d_r_ticks * rad_per_tick;
    const double d_left = d_left_rad * wheel_radius_;
    const double d_right = d_right_rad * wheel_radius_;
    wheel_pos_[0] += d_left_rad;
    wheel_pos_[1] += d_right_rad;

    // 정운동학: 좌우 이동거리 → 로봇 변위
    const double d_s = (d_right + d_left) / 2.0;
    const double d_th = (wheel_sep_ > 0.0) ? (d_right - d_left) / wheel_sep_ : 0.0;

    // 중점법 적분 (곡선 주행 오차 감소)
    x_ += d_s * std::cos(theta_ + d_th / 2.0);
    y_ += d_s * std::sin(theta_ + d_th / 2.0);
    theta_ = std::atan2(std::sin(theta_ + d_th), std::cos(theta_ + d_th));   // −π ~ π 정규화

    publish_all(t, d_s / dt, d_th / dt, d_left_rad / dt, d_right_rad / dt, s);
  }

  // ── /odom, TF, /joint_states, /battery_state ────────────────────────────
  void publish_all(const rclcpp::Time & t, double v, double w, double wl, double wr,
                   const rpi5_mcu::McuState & s)
  {
    tf2::Quaternion q;
    q.setRPY(0.0, 0.0, theta_);          // 평면 주행: yaw 만 변한다
    const geometry_msgs::msg::Quaternion q_msg = tf2::toMsg(q);

    nav_msgs::msg::Odometry odom;
    odom.header.stamp = t;
    odom.header.frame_id = odom_frame_;
    odom.child_frame_id = base_frame_;
    odom.pose.pose.position.x = x_;
    odom.pose.pose.position.y = y_;
    odom.pose.pose.orientation = q_msg;
    odom.twist.twist.linear.x = v;
    odom.twist.twist.angular.z = w;
    // 공분산: 0 으로 두면 EKF 가 이 값을 '완벽하다' 고 믿고 IMU 를 무시한다 (§2-5 ⑤).
    odom.pose.covariance[0] = 0.001;     // x
    odom.pose.covariance[7] = 0.001;     // y
    odom.pose.covariance[35] = 0.01;     // yaw — 스키드 스티어라면 더 크게 (회전은 IMU 가 맡는다)
    odom.twist.covariance[0] = 0.001;
    odom.twist.covariance[35] = 0.01;
    // TODO(you): §3-9 캘리브레이션 뒤 사각형 주행 오차를 근거로 이 값을 다시 정한다.
    pub_odom_->publish(odom);

    if (publish_tf_) {                   // false 면 EKF(§3-10)가 이 TF 를 대신 발행한다
      geometry_msgs::msg::TransformStamped tf;
      tf.header.stamp = t;
      tf.header.frame_id = odom_frame_;

3-6-2. 프레임 구조체와 CRC — Pi 쪽과 바이트 단위로 같은 계약 v2

/* frames.h — Cortex-M 은 리틀엔디안이라 memcpy 한 번으로 Pi 의 프레임과 맞는다 */
#include <stdint.h>
#include <stddef.h>
#include <string.h>

#define FRAME_H0      0xAA
#define FRAME_H1      0x55
#define TYPE_VELOCITY 0x01   /* Pi → MCU */
#define TYPE_STATE    0x81   /* MCU → Pi, 50 Hz */
#define TYPE_IMU      0x82   /* MCU → Pi, 100~200 Hz */
#define TYPE_EVENT    0x83   /* MCU → Pi, 발생 시 */

#pragma pack(push, 1)                    /* 패딩 없이 바이트를 그대로 붙인다 */
typedef struct { int16_t v_left_mm_s; int16_t v_right_mm_s; } velocity_payload_t;                              /* 4 B  */
typedef struct { int32_t left_ticks; int32_t right_ticks; uint16_t batt_mv; uint16_t current_ma;
                 uint8_t fault; uint32_t tick_ms; } state_payload_t;                                            /* 17 B */
typedef struct { uint8_t sensor_id; int16_t ax_mg, ay_mg, az_mg; int16_t gx_ddps, gy_ddps, gz_ddps;   /* ddps = 0.1 °/s */
                 uint32_t tick_ms; } imu_payload_t;                                                            /* 17 B */
typedef struct { uint8_t code; uint16_t detail; uint32_t tick_ms; } event_payload_t;                           /* 7 B  */
#pragma pack(pop)

_Static_assert(sizeof(velocity_payload_t) == 4,  "velocity payload must be 4 bytes");
_Static_assert(sizeof(state_payload_t)    == 17, "state payload must be 17 bytes");
_Static_assert(sizeof(imu_payload_t)      == 17, "imu payload must be 17 bytes");
_Static_assert(sizeof(event_payload_t)    == 7,  "event payload must be 7 bytes");

/* fault 비트 · 이벤트 코드 — 06a §4-2 표. Pi 의 protocol.hpp 와 이름까지 같다 */
#define FAULT_WATCHDOG  (1u << 0)   /* 워치독 정지 중 */
#define FAULT_LOW_BATT  (1u << 1)
#define FAULT_OVERCURR  (1u << 2)
#define FAULT_TILT      (1u << 3)
#define FAULT_IMU       (1u << 4)   /* IMU 통신 실패 */
#define FAULT_DRIVER    (1u << 5)   /* 모터 드라이버 fault 입력 */
#define EVT_LOW_BATT    0x01        /* detail = mV */
#define EVT_OVERCURR    0x02        /* detail = mA */
#define EVT_TILT        0x03        /* detail = 0.1° 단위 */
#define EVT_WATCHDOG    0x04        /* detail = 끊긴 ms */
#define EVT_IMU_FAIL    0x05        /* detail = sensor_id */
#define EVT_RECOVER     0x10        /* detail = 풀린 fault 비트 */
#define EVT_CALIB_STAT  0x20        /* 학습자 확장 (06a 표에 없음 → 표와 protocol.md 에 추가): BNO055 CALIB_STAT */

static uint8_t crc8(const uint8_t *data, size_t len)   /* Pi 쪽과 동일: poly 0x07, init 0x00 */
{
  uint8_t crc = 0x00;
  for (size_t i = 0; i < len; ++i) {
    crc ^= data[i];
    for (int b = 0; b < 8; ++b)
      crc = (crc & 0x80) ? (uint8_t)((crc << 1) ^ 0x07) : (uint8_t)(crc << 1);
  }
  return crc;
}

/* 프레임 조립: out 은 5 + len 바이트. 반환 = 전체 길이. Pi 의 encode_frame() 과 같은 규칙 */
static size_t frame_build(uint8_t type, const void *payload, uint8_t len, uint8_t *out)
{
  out[0] = FRAME_H0; out[1] = FRAME_H1; out[2] = type; out[3] = len;
  memcpy(out + 4, payload, len);
  out[4 + len] = crc8(out + 2, 2 + len);           /* TYPE 부터 PAYLOAD 끝까지 */
  return 5 + len;
}

/* 단위 변환은 여기 한 곳 — Pi 의 decode_imu() 와 정확히 역관계여야 한다 */
static int16_t sat_i16(float v) { return (int16_t)(v >  32767.f ?  32767.f : v < -32768.f ? -32768.f : v); }
static int16_t mps2_to_mg(float a)    { return sat_i16(a / 9.80665f * 1000.f); }
static int16_t dps_to_ddps(float w)   { return sat_i16(w * 10.f); }    /* 0.1 °/s 단위, ±3276 °/s — 센서 범위 ±2000 °/s 가 잘리지 않는다 (06a §4-3) */
송신은 큐 + DMA 로

상태 22 B 는 460800 bps 에서 약 0.5 ms 다. 1 ms 인터럽트 안에서 블로킹 전송하면 루프가 밀린다. 프레임을 링 버퍼에 넣고 HAL_UART_Transmit_DMA 가 비었을 때 다음 것을 꺼내 보내는 tx_enqueue() 를 두어, 제어 루프·IMU 파서·안전 상태기계가 각자 프레임을 던지기만 하게 한다. IMU 200 Hz 와 상태 50 Hz 가 섞여 나가도 프레임 단위로는 섞이지 않는다.

3-6-3. 제어 루프 — 1 kHz(1 ms) 인터럽트에서

/* control.c — 구조만. 상수·핀은 당신의 하드웨어에 맞춘다 */
#define DT            0.001f                       /* TIM6 1 kHz */
#define WATCHDOG_MS   200                          /* 06a 계약: 200 ms 무명령 → 정지 */
#define TICK_TO_MM_S  (2.0f * 3.1415926f * WHEEL_RADIUS_MM / ENCODER_CPR / DT)   /* 틱/주기 → mm/s */

typedef struct { float kp, ki, kd, integ, prev_err, out_min, out_max; } speed_pid_t;

static float pid_step(speed_pid_t *p, float err)
{
  p->integ += err * DT;
  float u = p->kp * err + p->ki * p->integ + p->kd * (err - p->prev_err) / DT;
  p->prev_err = err;
  if (u > p->out_max)      { u = p->out_max; p->integ -= err * DT; }   /* 적분 와인드업 방지: */
  else if (u < p->out_min) { u = p->out_min; p->integ -= err * DT; }   /* 출력이 포화되면 적분을 되돌린다 */
  return u;
}

/* 통신 모듈 → 제어 모듈로 들어오는 것: set_target() 이 갱신한다 */
static volatile int16_t target_l = 0, target_r = 0;
static volatile uint32_t ms_since_cmd = 0;
volatile uint32_t ms_since_imu[2] = {0, 0};              /* [0] WT901 [1] BNO055 — 각 파서가 새 샘플마다 0 으로 되돌린다 */
/* IMU 파서(§3-6-5, 3-6-6)가 갱신하는 최신값 — 루프는 매 바퀴 이것을 "읽기만" 한다 (§2-6) */
volatile imu_payload_t imu_latest;
/* 바퀴 인덱스 관례: 0 = FL, 1 = FR, 2 = RL, 3 = RR — 짝수 = 왼쪽, 홀수 = 오른쪽. 엔코더 타이머·PWM 채널을 같은 순서로 둔다 */
enum { FL, FR, RL, RR, NW };
static TIM_HandleTypeDef *const enc_tim[NW]  = { &htim2, &htim5, &htim23, &htim24 };   /* 넷 다 32비트 (06a 핀 배정표) */
static const uint32_t     pwm_ch[NW]         = { TIM_CHANNEL_1, TIM_CHANNEL_2, TIM_CHANNEL_3, TIM_CHANNEL_4 };
/* BTS7960 IBT-2: RPWM = TIM1 CHx, LPWM = TIM8 CHx (같은 채널 번호). 부호-크기 구동 — 한쪽에 듀티, 반대쪽은 0.
   u ∈ [-1, 1]. 둘 다 0 이면 양쪽 로우사이드 ON = 브레이크. MOTOR_EN LOW 는 코스트(출력 tri-state) */
static void motor_set(int i, float u)
{
  const uint32_t ccr = (uint32_t)(fabsf(u) * __HAL_TIM_GET_AUTORELOAD(&htim1));
  __HAL_TIM_SET_COMPARE(&htim1, pwm_ch[i], u >= 0.f ? ccr : 0u);   /* RPWM */
  __HAL_TIM_SET_COMPARE(&htim8, pwm_ch[i], u <  0.f ? ccr : 0u);   /* LPWM */
}
static int32_t     prev_cnt[NW];
static speed_pid_t pid[NW];                             /* 바퀴마다 독립 PID — "보조 바퀴"는 없다 */
static float       trac[NW] = { 1.f, 1.f, 1.f, 1.f };   /* 슬립 억제 계수 0..1 (§3-6-9) */
uint32_t tick_ms = 0;

void control_step(void)                                /* TIM6 인터럽트에서 호출. dt = 0.001 s 고정 */
{
  ++tick_ms; ++ms_since_imu[0]; ++ms_since_imu[1];
  int32_t cnt[NW]; float meas[NW];
  for (int i = 0; i < NW; ++i) {
    cnt[i]  = (int32_t)__HAL_TIM_GET_COUNTER(enc_tim[i]);   /* 32비트 CNT 그대로. 랩어라운드 보정 없음 */
    meas[i] = (cnt[i] - prev_cnt[i]) * TICK_TO_MM_S;        /* 측정 속도 [mm/s] */
    prev_cnt[i] = cnt[i];
  }

  if (++ms_since_cmd > WATCHDOG_MS) { target_l = 0; target_r = 0; }   /* ① 소프트웨어 워치독 */

  /* ② 안전 상태기계 (§3-6-7): 전압·전류·기울기·워치독·IMU 끊김을 보고 fault 를 정한다. IMU 최신값이 여기 쓰인다 */
  const uint8_t fault = safety_step(adc_batt_mv(), adc_current_ma(), &imu_latest, ms_since_cmd, ms_since_imu);

  if (fault) {                                         /* ③ fault 면 출력 차단 — Pi 의 허락을 기다리지 않는다 */
    for (int i = 0; i < NW; ++i) { motor_set(i, 0.f); pid[i].integ = 0.f; }   /* 듀티 0 = 브레이크. 드라이버 fault 면 MOTOR_EN 을 3 µs 이상 LOW 로 래치 해제 */
  } else {                                             /* ④ 바퀴별 속도 PID + 슬립 억제 */
    traction_step(meas, &imu_latest, trac);             /* §3-6-9: 헛도는 바퀴의 계수를 낮춘다 */
    for (int i = 0; i < NW; ++i) {
      const float target = (i % 2 == 0) ? (float)target_l : (float)target_r;   /* 좌/우 구분은 여기서만 */
      const float u = pid_step(&pid[i], target - meas[i]) * trac[i];
      motor_set(i, u);                                              /* 부호 → RPWM/LPWM 선택, 크기 → 듀티 */
    }
  }

  if (tick_ms % 20 == 0) {                             /* ⑤ 50 Hz 상태 보고 — 계약은 쪽당 평균, 바퀴별 값은 MCU 안에서만 */
    const int32_t l_tick = (int32_t)(((int64_t)cnt[FL] + cnt[RL]) / 2);
    const int32_t r_tick = (int32_t)(((int64_t)cnt[FR] + cnt[RR]) / 2);
    state_payload_t s = { l_tick, r_tick, adc_batt_mv(), adc_current_ma(), fault, tick_ms };
    uint8_t f[5 + sizeof s];
    tx_enqueue(f, frame_build(TYPE_STATE, &s, sizeof s, f));
  }
  HAL_IWDG_Refresh(&hiwdg);                            /* ⑥ 하드웨어 워치독 갱신 — 이 함수가 멈추면 MCU 리셋 */
}

PID 게인은 P → I → D 순서로 잡는다. P 만으로 진동 직전까지 올리고, 정상상태 오차를 I 로 없애고, D 는 필요할 때만 조금. 바퀴를 띄운 상태에서 목표 속도를 계단으로 주고 엔코더 속도가 따라오는지 §3-6-8 의 probe 로 찍어 보는 것이 가장 빠르다.

/* 바이트 하나씩 먹이는 상태기계. 완성되면 type/len/payload 를 채우고 1 을 돌려준다 */
static int frame_push(uint8_t b, uint8_t *type, uint8_t *len, uint8_t *payload)
{
  static enum { H0, H1, TYPE, LEN, PAYLOAD, CRC } st = H0;
  static uint8_t t, l, i, buf[2 + 64];
  switch (st) {
    case H0: st = (b == FRAME_H0) ? H1 : H0; return 0;
    case H1: st = (b == FRAME_H1) ? TYPE : (b == FRAME_H0) ? H1 : H0; return 0;   /* AA 가 겹치면 두 번째가 헤더일 수 있다 */
    case TYPE: t = b; st = LEN; return 0;
    case LEN: if (b > 64) { st = H0; return 0; } l = b; i = 0; st = l ? PAYLOAD : CRC; return 0;
    case PAYLOAD: buf[2 + i++] = b; if (i >= l) st = CRC; return 0;
    case CRC: st = H0; buf[0] = t; buf[1] = l;
      if (crc8(buf, 2 + l) != b) return 0;               /* 깨진 프레임은 버린다 — 이전 명령이 유지되다 워치독이 멈춘다 */
      *type = t; *len = l; memcpy(payload, buf + 2, l); return 1;
  }
  return 0;
}

void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t size)
{
  if (huart == &huart3) {
    for (uint16_t k = 0; k < size; ++k) {
      uint8_t type, len, payload[64];
      if (frame_push(rx_buf[k], &type, &len, payload) && type == TYPE_VELOCITY && len == sizeof(velocity_payload_t)) {
        velocity_payload_t v; memcpy(&v, payload, sizeof v);
        set_target(v.v_left_mm_s, v.v_right_mm_s);       /* 제어 모듈의 유일한 입구. 안에서 ms_since_cmd = 0 */
      }
    }
    uart_pi_start();                                     /* 다시 무장 */
  } else if (huart == &huart6) {
    wt901_parse(wt_rx_buf, size);                        /* §3-6-5 */
    wt901_start();
  }
}

static void wt901_parse(const uint8_t *buf, size_t n)
{
  static uint8_t f[11]; static size_t k = 0;
  for (size_t i = 0; i < n; ++i) {
    const uint8_t b = buf[i];
    if (k == 0 && b != 0x55) continue;                  /* 헤더 동기 */
    f[k++] = b;
    if (k < 11) continue;
    k = 0;
    uint8_t sum = 0; for (int j = 0; j < 10; ++j) sum += f[j];
    if (sum != f[10]) continue;                           /* 체크섬 불일치 → 버림 */
    const int16_t d0 = (int16_t)(f[2] | (f[3] << 8)), d1 = (int16_t)(f[4] | (f[5] << 8)), d2 = (int16_t)(f[6] | (f[7] << 8));
    switch (f[1]) {
      case 0x51:                                          /* 가속도: raw/32768×16 g → mg */
        imu_latest.ax_mg = sat_i16(d0 * 16000.f / 32768.f);
        imu_latest.ay_mg = sat_i16(d1 * 16000.f / 32768.f);
        imu_latest.az_mg = sat_i16(d2 * 16000.f / 32768.f);
        break;
      case 0x52:                                          /* 각속도: raw/32768×2000 °/s → 0.1 °/s 단위 (×20000/32768), 바이어스 제거 */
        imu_latest.gx_ddps = sat_i16(d0 * 20000.f / 32768.f - gyro_bias_ddps[0]);
        imu_latest.gy_ddps = sat_i16(d1 * 20000.f / 32768.f - gyro_bias_ddps[1]);
        imu_latest.gz_ddps = sat_i16(d2 * 20000.f / 32768.f - gyro_bias_ddps[2]);
        imu_latest.sensor_id = 0;
        imu_latest.tick_ms = tick_ms;
        ms_since_imu[0] = 0;                              /* 안전 상태기계의 IMU 끊김 감시 (FAULT_IMU) */
        imu_send(&imu_latest);                            /* 각속도 프레임이 올 때마다 Pi 로 0x82 전송 (센서 속도 = 전송 속도) */
        break;
      default: break;                                     /* 0x53 각도·0x54 자기는 참고만 */
    }
  }
}

BNO055 캘리브레이션 절차 — CALIB_STAT 이 전부 3 이 될 때까지
  • 자이로(GYR): 몇 초 완전 정지.
  • 가속도(ACC): 로봇(센서)을 ±X, ±Y, ±Z 여섯 면이 각각 위를 향하게 놓고 면마다 몇 초씩 정지. 로봇에 붙인 채로는 어렵다 — 브래킷째 떼어 하거나, 필요한 면만 채우고 2 에서 타협한다.
  • 자기(MAG): 공중에서 8자 동작. NDOF 모드에서만 의미가 있고, IMU 모드(자력계 미사용)에서는 0 으로 남는 것이 정상이다.
  • SYS: 위 셋이 채워지면 따라온다. 전부 3 이면 오프셋 22 B 를 읽어 저장하고, 부팅 때 CONFIG 모드에서 되써서 매번 다시 하지 않는다.

이 절차를 ROS 에서 지켜보게 하려고 event_send(EVT_CALIB_STAT, st) 를 넣었다. 코드 0x20 은 06a 표에 없는 학습자 확장이므로 표와 protocol.md 에 먼저 적는다(0x10 은 "정상 복귀"로 이미 쓰인다). ros2 topic echo /mcu/event 에 32:xxx 가 1초마다 찍히고, 비트를 풀어 보면 어느 항목이 남았는지 보인다. Pi 쪽에서 비트를 풀어 로그로 예쁘게 찍는 것은 §3-4 handle_event 의 TODO 다.

3-6-7. 안전 상태기계 — 전권은 MCU 에

/* safety.c — 제어 루프에서 매 1 ms 호출. Pi 를 거치지 않고 출력을 끊고, 결과만 보고한다.
   비트·코드는 frames.h 의 FAULT_* / EVT_* (06a §4-2 표) */
#include "frames.h"
#define BATT_MIN_MV     9600     /* 예: 3S 리튬, 셀당 3.2 V — 배터리 사양으로 정한다 (INVENTORY 7절) */
#define CURR_MAX_MA     6000     /* 모터 드라이버·배터리 연속 전류 한계로 정한다 */
#define TILT_MAX_DEG    30.f     /* 실험으로 정한다 — 경사로 주행 각도보다 크고 전복 각도보다 작게 */
#define IMU_TIMEOUT_MS  100      /* 기본 IMU 가 이만큼 침묵하면 통신 실패 (100~200 Hz 센서 → 10~20 샘플 결손) */
#define RELEASE_HOLD_MS 1000     /* 조건이 사라진 뒤 이만큼 유지되어야 해제 */
#define IMU_PRIMARY     0        /* 0 = WT901, 1 = BNO055 — Pi 의 imu_primary 파라미터와 같게 */

static uint8_t  fault_bits;     /* 상태 프레임의 fault 필드로 나간다 */
static uint32_t clear_since_ms;

static float tilt_deg(const volatile imu_payload_t *imu)   /* 중력 벡터가 z 축에서 얼마나 기울었나 */
{
  const float ax = imu->ax_mg, ay = imu->ay_mg, az = imu->az_mg;
  return atan2f(sqrtf(ax * ax + ay * ay), az) * 57.2958f;
}

uint8_t safety_step(uint16_t batt_mv, uint16_t current_ma, const volatile imu_payload_t *imu,
                    uint32_t ms_since_cmd, const volatile uint32_t *ms_since_imu)
{
  uint8_t now = 0;
  if (ms_since_cmd > WATCHDOG_MS)                 now |= FAULT_WATCHDOG;   /* bit0 */
  if (batt_mv < BATT_MIN_MV)                      now |= FAULT_LOW_BATT;   /* bit1 */
  if (current_ma > CURR_MAX_MA)                   now |= FAULT_OVERCURR;   /* bit2 */
  if (ms_since_imu[IMU_PRIMARY] > IMU_TIMEOUT_MS) now |= FAULT_IMU;        /* bit4 — IMU 가 죽으면 기울기 판정도 못 믿는다 */
  else if (tilt_deg(imu) > TILT_MAX_DEG)          now |= FAULT_TILT;       /* bit3 */
  if (HAL_GPIO_ReadPin(DRV_FAULT_PORT, DRV_FAULT_PIN) == GPIO_PIN_RESET) now |= FAULT_DRIVER;   /* bit5, 드라이버의 nFAULT 핀 */

  const uint8_t rising = now & ~fault_bits;                /* 이번 1 ms 에 새로 선 비트만 → 비트마다 이벤트 1회 */
  if (rising & FAULT_LOW_BATT) { event_send(EVT_LOW_BATT, batt_mv);                         motor_power_off(); }  /* 릴레이/MOSFET 로 모터 전원 자체를 끊는다 */
  if (rising & FAULT_OVERCURR) { event_send(EVT_OVERCURR, current_ma);                      motor_power_off(); }
  if (rising & FAULT_TILT)     { event_send(EVT_TILT,     (uint16_t)(tilt_deg(imu) * 10.f)); }   /* detail = 0.1° 단위 */
  if (rising & FAULT_WATCHDOG) { event_send(EVT_WATCHDOG, (uint16_t)ms_since_cmd); }
  if (rising & FAULT_IMU)      { event_send(EVT_IMU_FAIL, IMU_PRIMARY); }
  /* 출력 차단(PWM 0)은 호출자 control_step 이 반환값을 보고 한다. 전원 차단은 위에서 즉시 */

  if (now) { fault_bits |= now; clear_since_ms = tick_ms; return fault_bits; }

  /* 해제 정책 — 학습자가 정한다 (06a 결정 기록):
     · 워치독·과경사·IMU 실패·드라이버: 조건 해소 후 RELEASE_HOLD_MS 유지되면 자동 해제
     · 과전류: 자동 해제하되 횟수를 세어 N 회 이상이면 래치
     · 저전압: 래치. 충전 후 재부팅 또는 명시적 해제 명령 — 06a 표의 선택 항목 0x02 설정 프레임에 key 를 하나 배정하는 것도 당신의 설계 */
  if (fault_bits && (tick_ms - clear_since_ms) > RELEASE_HOLD_MS && !(fault_bits & FAULT_LOW_BATT)) {
    const uint8_t cleared = fault_bits;
    fault_bits = 0; motor_power_on();
    event_send(EVT_RECOVER, cleared);                          /* 0x10, detail = 어느 비트가 풀렸는가 */
  }
  return fault_bits;
}
왜 Pi 가 아니라 여기인가 — 다시

저전압에서 Pi 가 "멈춰라"를 보내려면 Pi 프로세스가 살아 있어야 하고, 시리얼이 붙어 있어야 하고, 브리지가 깨어 있어야 한다. 셋 중 하나만 깨져도 로봇은 방전될 때까지 달린다. MCU 안의 1 ms 루프는 그 셋에 의존하지 않는다. Pi 는 /mcu/fault 와 /mcu/event 로 결과를 받아 목표를 취소하고 사람에게 알린다(10 단계). 이 관계는 "MCU 가 거부권을 가진다"로 요약된다.

3-6-8. Pi 없이 검증 — probe 스크립트 Mac / Pi 호스트

Nucleo 를 USB 로 꽂고(Mac 이면 /dev/tty.usbmodem*, Pi 호스트면 /dev/mcu) 계약 v2 를 Python 으로 독립 구현한 스크립트로 속도 프레임을 보내고 상태·IMU·이벤트 프레임을 해석한다. pip3 install pyserial 만 있으면 된다. 저장소 루트에 scripts/mcu_probe.py 로 저장한다. 이것은 §3-2 C++ 파서의 세 번째 독립 구현이기도 하다 — 셋이 같은 바이트를 같은 값으로 읽으면 계약이 맞다.

#!/usr/bin/env python3
"""MCU 단독 검증 (계약 v2): 속도 프레임을 50 Hz 로 보내고 상태/IMU/이벤트 프레임을 해석한다. ROS 불필요.
    python3 scripts/mcu_probe.py /dev/tty.usbmodem1103 0.1 0.1        # v_left v_right [m/s]
    python3 scripts/mcu_probe.py /dev/mcu 0 0 --baud 460800"""
import argparse, struct, sys, time
import serial

def crc8(data):
    crc = 0
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = ((crc << 1) ^ 0x07) & 0xFF if crc & 0x80 else (crc << 1) & 0xFF
    return crc

def frame(ftype, payload):
    body = bytes([ftype, len(payload)]) + payload
    return b'\xAA\x55' + body + bytes([crc8(body)])

def parse(buf):
    """버퍼에서 완성된 프레임을 잘라 (type, payload) 리스트와 남은 버퍼를 돌려준다"""
    out = []
    while True:
        i = buf.find(b'\xAA\x55')
        if i < 0:
            return out, buf[-1:]                       # 끝의 1 바이트가 0xAA 일 수 있으니 남긴다
        if len(buf) - i < 5:
            return out, buf[i:]
        ftype, ln = buf[i + 2], buf[i + 3]
        if len(buf) - i < 5 + ln:
            return out, buf[i:]                        # 아직 다 안 왔다
        body = buf[i + 2:i + 4 + ln]
        if crc8(body) == buf[i + 4 + ln]:
            out.append((ftype, bytes(buf[i + 4:i + 4 + ln])))
            buf = buf[i + 5 + ln:]
        else:
            print('BAD CRC', buf[i:i + 5 + ln].hex(' '))
            buf = buf[i + 2:]                          # 헤더 다음부터 다시 동기

ap = argparse.ArgumentParser()
ap.add_argument('port'); ap.add_argument('vl', type=float); ap.add_argument('vr', type=float)
ap.add_argument('--baud', type=int, default=460800); ap.add_argument('--sec', type=float, default=5.0)
a = ap.parse_args()

cmd = frame(0x01, struct.pack('<hh', int(a.vl * 1000), int(a.vr * 1000)))
n_imu = {0: 0, 1: 0}                                       # sensor_id 별 수신 개수
with serial.Serial(a.port, a.baud, timeout=0) as s:
    buf = b''
    t0 = time.time(); next_tx = t0
    try:
        while time.time() - t0 < a.sec:
            if time.time() >= next_tx:                     # 50 Hz 송신 — 안 보내면 MCU 워치독이 200 ms 뒤 멈춘다
                s.write(cmd); next_tx += 0.02
            buf += s.read(4096)
            frames, buf = parse(buf)
            for ftype, p in frames:
                if ftype == 0x81 and len(p) == 17:
                    L, R, batt, cur, fault, tick = struct.unpack('<iiHHBI', p)
                    print(f'STATE L={L:8d} R={R:8d} batt={batt/1000:5.2f}V cur={cur:5d}mA fault=0x{fault:02X} t={tick}')
                elif ftype == 0x82 and len(p) == 17:
                    sid, ax, ay, az, gx, gy, gz, tick = struct.unpack('<BhhhhhhI', p)
                    n_imu[sid] = n_imu.get(sid, 0) + 1
                    if n_imu[sid] % 50 == 0:                # 200 Hz 면 4 줄/초
                        print(f'IMU{sid}  a=({ax/1000:+.2f},{ay/1000:+.2f},{az/1000:+.2f})g  g=({gx/10:+.1f},{gy/10:+.1f},{gz/10:+.1f})deg/s t={tick}')
                elif ftype == 0x83 and len(p) == 7:
                    code, detail, tick = struct.unpack('<BHI', p)
                    name = {1: 'low-batt', 2: 'over-current', 3: 'tilt', 4: 'watchdog', 5: 'imu-fail', 0x10: 'recovered', 0x20: 'calib'}.get(code, '?')
                    print(f'EVENT {name} code={code} detail={detail} t={tick}')     # 06a 4-2 표 + 학습자 확장 0x20
            time.sleep(0.002)
    finally:
        s.write(frame(0x01, struct.pack('<hh', 0, 0)))     # 반드시 정지
        print('imu frames per sensor:', n_imu)

확인할 것: ① 바퀴가 명령 방향으로 돈다 ② L/R 카운트가 전진에서 둘 다 증가한다 ③ 5초 동안 BAD CRC 가 0 줄이다 ④ IMU0 이 초당 100~200 개, 정지 시 az ≈ +1.00 g, gz ≈ 0 ⑤ 스크립트를 죽여도(Ctrl+C) 0.2 초 뒤 바퀴가 멈춘다(MCU 워치독) ⑥ 배터리 커넥터를 뽑아 전압을 떨어뜨리면(또는 BATT_MIN_MV 를 잠시 높여) EVENT low-batt(code=1, detail=mV) 가 한 번 오고 STATE 의 fault 가 0x02(bit1) 로 선다 ⑦ 스크립트를 멈춘 채 두면 0.2 초 뒤 EVENT watchdog(code=4) 과 fault bit0, 다시 보내기 시작하면 1 초 뒤 EVENT recovered(code=16, detail=1). ②에서 한쪽이 감소하면 그 엔코더의 A/B 배선을 바꾸거나 CubeMX 의 엔코더 극성을 뒤집는다 — 펌웨어에서 부호를 뒤집지 말고 원인을 고친다 (이해 확인 8번).

3-6-9. 4륜 독립 제어와 슬립 억제 — 이 프로젝트의 기본 구성

바퀴 네 개는 각자 32비트 엔코더(TIM2/5/23/24)와 독립 PID 를 갖는다. "앞바퀴가 주, 뒷바퀴가 보조" 같은 구분은 없다. 좌/우 구분은 v_left/v_right 를 나눌 때만 쓰고, 그 뒤로는 바퀴가 각자 자기 속도를 맞춘다. 스키드 스티어는 제자리 회전 때 바퀴가 옆으로 미끄러지는데, 이때 어느 바퀴가 미끄러지는지는 IMU 가 알려 준다 — 요 각속도 ω(IMU) 가 있으면 바퀴 i 가 땅을 잡고 있을 때 내야 할 속도를 계산할 수 있기 때문이다.

   기대 바퀴 속도 (땅을 잡고 있다면)    왼쪽: v_exp = v_body − ω_imu · W/2     오른쪽: v_exp = v_body + ω_imu · W/2
   v_body = 네 바퀴 측정 속도의 중앙값 — 헛도는 바퀴 하나에 끌려가지 않는다
   슬립 비율  s_i = (v_i − v_exp_i) / max(|v_exp_i|, v_min)        → |s_i| 가 문턱 s_th 를 넘으면 그 바퀴가 헛돈다
   억제       trac_i ← max(trac_min, trac_i − k_down · (|s_i| − s_th))   헛돌면 즉시 낮춘다
              trac_i ← min(1, trac_i + k_up · dt)                       잡히면 천천히 되돌린다
   출력       u_i = PID_i(target_side − v_i) · trac_i
/* traction.c — 슬립 억제. 1 kHz 루프에서 PID 앞에 호출. W_MM = 바퀴 간 거리 [mm] (INVENTORY 6절) */
#include <math.h>
#define S_TH      0.20f      /* 슬립 비율 문턱 — §3-9 제자리 회전 실험에서 바닥별로 잡는다 */
#define K_DOWN    0.05f      /* 헛돌 때 계수를 낮추는 양 (루프당) */
#define K_UP      0.5f       /* 잡혔을 때 되돌리는 속도 (1/s) */
#define TRAC_MIN  0.30f      /* 완전히 끊지는 않는다 — 0 이면 그 바퀴는 영원히 "잡혔다"로 보인다 */
#define V_MIN     30.f       /* mm/s — 이보다 느리면 슬립 비율을 계산하지 않는다 (0 나눗셈·잡음) */

static float median4(float a, float b, float c, float d)
{ /* 정렬 후 가운데 둘의 평균 — 한두 바퀴가 튀어도 흔들리지 않는다 */
  float v[4] = { a, b, c, d };
  for (int i = 1; i < 4; ++i) for (int j = i; j > 0 && v[j-1] > v[j]; --j) { float t = v[j]; v[j] = v[j-1]; v[j-1] = t; }
  return 0.5f * (v[1] + v[2]);
}

void traction_step(const float meas[4], const volatile imu_payload_t *imu, float trac[4])
{
  const float w   = imu->gz * 0.1f * 3.1415926f / 180.f;       /* 0.1 °/s → rad/s (계약 v2 단위). 부호는 §3-7 의 축 실측을 따른다 */
  const float v_b = median4(meas[0], meas[1], meas[2], meas[3]); /* 차체 속도 추정 [mm/s] */
  for (int i = 0; i < 4; ++i) {
    const float v_exp = v_b + ((i % 2 == 0) ? -1.f : 1.f) * w * (W_MM * 0.5f);   /* 땅을 잡고 있을 때의 바퀴 속도 */
    const float den   = fabsf(v_exp) > V_MIN ? fabsf(v_exp) : V_MIN;
    const float s     = (meas[i] - v_exp) / den;                                 /* 슬립 비율 */
    if (fabsf(s) > S_TH) trac[i] = fmaxf(TRAC_MIN, trac[i] - K_DOWN * (fabsf(s) - S_TH));
    else                 trac[i] = fminf(1.f, trac[i] + K_UP * DT);
  }
}
  • 왜 목표가 아니라 출력을 줄이는가. 헛도는 바퀴는 속도 오차가 작아 보여도(빨리 돌고 있으니) 땅에 힘을 전달하지 못한다. 토크(= 듀티)를 낮춰야 다시 붙는다. 진짜 토크 제어는 모터별 전류 센서가 있어야 하고, 없으면 듀티가 토크의 근사다. 결정(2026-09-15): 전류 센서는 보류. 1차 구현은 듀티 근사 + BTS7960 IS(fault·스톨 감지)로 가고, §3-9 실험에서 IS 측정치를 기록한 뒤 센서 추가 여부를 다시 정한다 (INVENTORY 6절).
  • 왜 IMU 인가. 엔코더 넷이 서로만 기준으로 삼으면 넷이 같이 미끄러질 때 아무도 모른다. ω 는 IMU 가 땅과 무관하게 잰다. 200 Hz(5 ms) 샘플이면 1 kHz 루프에서 최신값을 읽어 쓰기에 충분하다 (§2-6).
  • 왜 중앙값인가. 평균은 헛도는 바퀴 하나가 끌어올린다. 네 값의 중앙값(가운데 두 값의 평균)은 한두 바퀴가 튀어도 흔들리지 않는다.
  • 파라미터는 실측에서. W 와 바퀴 반지름은 INVENTORY 6절, S_TH·K_DOWN·K_UP 은 §3-9 의 제자리 회전 실험에서 잡는다. 바닥(장판·타일·카펫)마다 값을 기록한다.
  • 계약은 그대로다. 상태 프레임의 l_tick/r_tick 은 쪽당 앞뒤 평균이다. 바퀴별 카운트와 trac_i 를 Pi 에서 보고 싶으면 진단용 프레임(예: 0x84)을 추가한다 — 계약 v2 의 TYPE 공간이 그것을 위해 남아 있다.
  • 회전 추정은 여전히 IMU 가 주역이다. 슬립을 억제해도 스키드 스티어의 휠 오도메트리 yaw 는 믿을 것이 못 된다. §3-9 의 360° 회전 캘리브레이션은 바닥마다 값이 달라지므로 EKF(§3-10)에서 휠 yaw 공분산을 크게 둔다.

#!/usr/bin/env python3
"""IMU 토픽 하나를 N 초 동안 받아 (1) 축별 평균·표준편차 (2) 자이로 z 적분 = 회전한 각도 를 출력한다.
    python3 scripts/imu_stats.py /imu/wt901/data_raw 30        # 정지 30 s → 바이어스·노이즈
    python3 scripts/imu_stats.py /imu/bno055/data_raw 20       # 그 사이 로봇을 정확히 360° 돌린다 → 적분값 vs 6.283"""
import math, sys, time
import rclpy
from rclpy.node import Node
from rclpy.qos import qos_profile_sensor_data
from sensor_msgs.msg import Imu

topic, secs = sys.argv[1], float(sys.argv[2])
rclpy.init()
node = Node('imu_stats')
n = 0; sums = [0.0] * 6; sq = [0.0] * 6; yaw = 0.0; last_t = None

def cb(m):
    global n, yaw, last_t
    v = [m.linear_acceleration.x, m.linear_acceleration.y, m.linear_acceleration.z,
         m.angular_velocity.x, m.angular_velocity.y, m.angular_velocity.z]
    for i, x in enumerate(v):
        sums[i] += x; sq[i] += x * x
    t = m.header.stamp.sec + m.header.stamp.nanosec * 1e-9          # ★ 메시지의 stamp(MCU tick 환산)로 적분한다
    if last_t is not None:
        yaw += m.angular_velocity.z * (t - last_t)
    last_t = t; n += 1

node.create_subscription(Imu, topic, cb, qos_profile_sensor_data)
t0 = time.time()
while rclpy.ok() and time.time() - t0 < secs:
    rclpy.spin_once(node, timeout_sec=0.1)
names = ['ax', 'ay', 'az', 'gx', 'gy', 'gz']
print(f'{topic}: {n} samples in {secs:.0f}s ({n/secs:.1f} Hz)')
for i, nm in enumerate(names):
    mean = sums[i] / max(n, 1); std = math.sqrt(max(sq[i] / max(n, 1) - mean * mean, 0.0))
    print(f'  {nm}: mean {mean:+.4f}  std {std:.4f}')
print(f'  yaw integral: {yaw:+.4f} rad = {math.degrees(yaw):+.1f} deg   (360° 회전이면 ±6.283 rad)')
node.destroy_node(); rclpy.shutdown()

3-8. 통합 — 실제 MCU 와 연결 Pi 호스트 → 컨테이너

바퀴를 띄운 상태에서 시작한다

배선 하나가 뒤집혀 있으면 첫 명령에서 로봇이 벽으로 간다. 받침대 위에 올려 바퀴가 허공에서 돌게 하고, 배터리가 아니라 벤치 전원(전류 제한)으로 시작하는 것이 가장 싸다. 방향·부호·워치독을 전부 확인한 뒤에 바닥에 내린다.

3-9. 캘리브레이션 — 바퀴 반지름, 좌우 간격, 그리고 회전은 IMU 로

robot_params.yaml 의 세 숫자(wheel_radius, wheel_separation, encoder_cpr)는 자로 잰 값에서 출발하지만, 타이어 눌림·기어 백래시·접지점 폭 때문에 실주행과 몇 % 어긋난다. SLAM 은 그 몇 % 를 지도의 겹침으로 되돌려준다. 세 가지 주행으로 보정한다. 각 실험을 3회 이상 반복해 평균을 쓴다.

실험방법보정식근거
① 2 m 직진바닥에 테이프로 시작선·2 m 선. /odom 의 x 를 0 으로 두고(브리지 재시작) 0.2 m/s 로 직진, 실제 이동 거리 dreal 를 줄자로r_new = r_old × d_real / d_odom거리는 반지름에 비례한다. CPR 이 틀렸어도 같은 식으로 흡수된다(반지름에 곱해지므로) — 그래서 CPR 은 데이터시트 값을 믿고 반지름만 보정한다
② 제자리 N 바퀴N = 5 회전(오차가 N 배로 커져 잘 보인다). 시작 방향에 테이프. /odom yaw 누적(§3-7 스크립트를 /odom 에 맞게 고쳐 쓰거나 Foxglove Plot)sep_new = sep_old × yaw_odom / (2π·N)yaw = (ΔR − ΔL) / sep. 오도메트리가 실제보다 많이 돌았다고 하면 sep 이 너무 작은 것
③ 2 m 사각형직진 2 m → 좌회전 90° × 4. 출발점으로 돌아왔을 때 /odom 위치가 (0, 0) 에서 얼마나 떨어졌나(보정하지 않고 측정만)①②를 합친 결과 검증. 폐합 오차가 변의 2~3 % 면 합격. yaw 공분산의 근거이기도 하다
스키드 스티어(4WD)면 ② 는 바닥마다 다르다

회전할 때 바퀴가 옆으로 미끄러지므로 "유효 간격"이 타일·카펫·장판마다 달라진다. 한 바닥에서 보정해도 다른 바닥에서 5~10 % 틀어진다. 이것이 회전 추정을 IMU 에 맡기는 이유다(§3-10). 그래도 ② 는 한다 — EKF 가 꺼졌을 때의 기준값이고, IMU 가 죽었을 때(FAULT_IMU)의 대비이기 때문이다. ② 를 할 때 §3-7 의 imu_stats.py 를 같이 돌려 휠 yaw · IMU 적분 · 실제 2πN 세 값을 한 표에 적는다.

3-10. EKF — robot_localization 으로 휠 오도메트리와 IMU 융합 컨테이너

왜 휠에서 위치가 아니라 속도를 넣는가

/odom 의 pose 는 브리지가 이미 적분한 값이라 누적 오차가 들어 있다. 그것을 EKF 에 "관측"으로 주면 EKF 는 드리프트를 사실로 믿고 IMU 가 아무리 반박해도 따라간다. 속도(twist)는 매 프레임의 차분이라 누적이 없다. ✅ 검증 체크포인트

🤔 이해 확인

1. 속도를 float 4바이트 대신 int16 mm/s 로 보내는 이유는? 잃는 것은 없는가?
엔디안·NaN·정밀도 표기 문제를 피하고, 두 바이트로 ±32.767 m/s 를 1 mm/s 해상도로 담는다 — 지상 로봇에 충분하다. 잃는 것은 1 mm/s 아래의 정밀도인데, 엔코더 해상도가 그보다 거칠어 실질적으로 없다. 같은 이유로 IMU 도 mg 와 0.1 °/s 정수로 보낸다.
2. 오도메트리 적분에서 왜 구간 시작의 heading 이 아니라 중점 heading 을 쓰는가?
구간 동안 로봇이 Δθ 만큼 돌면 실제 이동 방향은 시작 heading 과 끝 heading 의 사이다. 시작 heading 으로 적분하면 회전할 때마다 바깥쪽으로 밀리는 계통 오차가 쌓인다. 중점(θ + Δθ/2)은 1차 오차를 상쇄해 같은 50 Hz 에서 훨씬 정확하다 — 비용은 덧셈 하나.
3. /odom 은 RELIABLE, /imu/* 는 BEST_EFFORT(SensorDataQoS)로 발행하는 이유는?
/odom 은 EKF·Nav2 가 기본 프로파일(RELIABLE)로 구독하므로 BEST_EFFORT 로 내면 연결 자체가 안 된다. IMU 는 100~200 Hz 스트림이라 하나 놓쳐도 다음 값이 곧 오고, 재전송이 오히려 지연을 만든다. robot_localization 은 odom·IMU 를 둘 다 SensorDataQoS 로 구독해 어느 쪽이든 받지만, /odom 은 Nav2 때문에 RELIABLE 이어야 한다. QoS 는 "메시지의 성격"과 "구독자가 요구하는 것"으로 정한다.
4. 워치독이 MCU 200 ms, Pi 0.5 s 로 두 층인 이유는? 하나로 합치면 무엇을 못 막나?
MCU 워치독은 "Pi 가 죽었다 / USB 가 빠졌다 / 브리지가 멈췄다"를 막는다 — Pi 쪽 코드가 아무리 완벽해도 이 셋은 Pi 가 막을 수 없다. Pi 워치독은 "상위 노드(Nav2, teleop)가 멈췄는데 브리지는 살아 있다"를 막는다 — 브리지가 마지막 명령을 계속 재전송하면 MCU 워치독은 절대 발동하지 않기 때문이다. 층마다 막는 고장이 다르다.
5. Python 판이 있는데 브리지를 C++ 로 다시 쓰는 이유는? 단지 "빠르니까"인가?
속도는 부차적이다(50 Hz 는 Python 도 된다). 핵심은 ① 2 ms 폴링 타이머와 200 Hz IMU 처리에서 GIL·GC 지터가 없다 ② int16·uint32 랩어라운드·바이트 단위 파싱이 언어의 기본형으로 정확히 표현된다 ③ Nav2·tf2·robot_localization 이 모두 C++ 이라 같은 도구(gdb, perf, ament)로 전체를 본다 ④ 이 프로젝트의 기본 언어가 C++ 이고 다음 단계의 노드들이 전부 C++ 이다. Python 판은 답안지로 남긴다.
6. MCU 가 이미 출력을 끊었는데 fault 동안 브리지가 굳이 0 명령을 보내는 이유는?
안전 때문이 아니다(그건 MCU 가 했다). ① fault 가 풀리는 순간 MCU 가 마지막으로 받은 큰 명령을 그대로 실행해 튀어나가는 것을 막고 ② 상위 스택(Nav2)이 "명령을 냈는데 안 움직인다"는 상황을 /mcu/fault 로 알아 목표를 취소하게 한다(10 단계 감독 노드). 브리지의 0 은 MCU 결정에 대한 상위의 "동의"다.
7. /odom 의 공분산을 0 으로 두면 EKF 에서 무슨 일이 생기는가?
공분산 0 = "이 측정은 완벽하다". EKF 는 휠 오도메트리를 절대 의심하지 않고 IMU 의 반박을 전부 버린다 — 융합을 켠 의미가 사라지고, 스키드 스티어에서 회전이 휠 값 그대로 틀어진다. 반대로 IMU 공분산이 너무 작으면 자이로 바이어스가 그대로 yaw 드리프트가 된다. 값은 §3-7 의 정지 std 와 §3-9 ③ 폐합 오차에서 근거를 얻는다.
8. 전진 명령에 한쪽 엔코더 카운트가 감소한다. 펌웨어나 브리지에서 부호를 뒤집으면 안 되는 이유는?
뒤집으면 지금은 맞지만, 원인(A/B 배선 또는 CubeMX 극성)이 남아 있어 나중에 배선을 고치거나 보드를 바꾸면 조용히 다시 반대가 된다. 그리고 "왼쪽 모터의 A/B 는 뒤집혀 있다"는 사실이 코드 어딘가의 -1 로만 남아 아무도 모른다. 물리 원인은 물리 층에서 고치고, 코드는 계약(전진 = 카운트 증가)만 믿는다. INVENTORY 에 배선을 적는 이유이기도 하다.
9. base_frame 을 저장소 yaml 대로 base_link 로 두면 무엇이 깨지는가?
05 의 URDF 루트는 base_footprint 이고 robot_state_publisher 가 base_footprint → base_link 를 이미 발행한다. 브리지(또는 EKF)가 odom → base_link 를 쏘면 base_link 의 부모가 둘이 되어 TF 트리가 끊어지거나 흔들리고, tf2_echo odom laser_link 가 실패하거나 SLAM 지도가 떨린다. 한 프레임의 부모는 하나 — odom 의 자식은 URDF 루트여야 한다.
10. 엔코더(타이머), BNO055(I2C), WT901(UART) — 각각 데이터를 "누가, 언제" 만드는가? MCU 는 어느 쪽에서 마스터인가?
엔코더: 타이머 하드웨어가 A/B 엣지를 스스로 센다. CPU 는 1 ms 마다 CNT 를 읽기만 한다(읽는 순간이 샘플 시각). BNO055: MCU 가 I2C 마스터로 100 Hz 마다 레지스터 블록을 요청해야 데이터가 온다 — 안 물어보면 아무것도 안 온다. WT901: 센서가 설정된 속도로 11 B 프레임을 스스로 보내고 MCU 는 DMA 수신자다(Pi 링크와 같은 패턴). UART 에는 마스터 개념이 없고 대등하다. "1 kHz 루프에서 IMU 를 쓴다"는 세 경우 모두 "루프가 최신 값을 읽는다"이지 "1 kHz 로 센서를 읽는다"가 아니다.
11. 모든 MCU→Pi 프레임에 tick_ms 가 있다. Pi 가 받은 시각으로 stamp 하면 안 되는 이유는?
USB·커널·2 ms 폴링·DDS 를 거치며 수신 시각은 수 ms 흔들리고, 상태 프레임과 IMU 프레임이 같은 순간 샘플이어도 다른 시각으로 도착한다. EKF 는 stamp 순서로 예측·갱신하므로 이 지터가 그대로 속도 추정 노이즈가 된다. MCU 의 tick 은 샘플이 만들어진 시각이고 두 센서가 같은 시계를 쓴다. 브리지는 첫 프레임에서 오프셋만 잡아 ROS 시각으로 옮긴다(드리프트·랩어라운드 보정은 TODO).
12. IMU 는 100~200 Hz 인데 왜 제어 루프는 1 kHz(1 ms)인가? 200 Hz 로 낮추면?
루프 주기는 가장 빠른 응답이 필요한 것이 정한다: 속도 PID 와 과전류 차단이다. 모터 전류는 수 ms 안에 한계를 넘을 수 있고, PID 의 dt 가 짧을수록 미분항이 조용하고 응답이 빠르다. IMU 는 그 루프가 매 바퀴 읽기만 하는 최신값이다(5~10 바퀴 동안 같은 값). 200 Hz 로 낮추면 PID 가 느려지고 과전류 검출이 5 ms 늦어진다 — IMU 와는 무관하다. 반대로 IMU 를 1 kHz 로 올릴 필요도 없다.
13. EKF 를 켤 때 브리지의 publish_tf 를 false 로 하는 이유는? 둘 다 켜면 에러가 나는가?
에러는 안 난다 — 그래서 위험하다. 두 노드가 odom → base_footprint 를 번갈아 쏘면 tf2 는 마지막 값을 쓰므로 로봇 위치가 50 Hz 로 두 추정치 사이를 떨고, SLAM 지도가 번지고, Nav2 가 진동한다. ros2 topic info /tf -v 로 발행자를 세어 정확히 하나인지 확인한다. /odom 토픽 자체는 계속 발행해야 한다 — EKF 의 입력이다.
14. 두 IMU 모두 자력계가 있는데 실내에서 방위(heading)에 쓰지 않는 이유는?
실내는 철골·콘크리트 철근·모터·스피커 자석·전선 때문에 자기장이 장소마다 수십 도씩 왜곡된다. 자력계 heading 을 EKF 에 절대 방위로 넣으면 로봇이 책상 옆을 지날 때마다 yaw 가 튄다. 실내 로봇의 절대 방위는 SLAM(라이다 스캔 정합, 09)이 준다. 자이로는 상대 회전만 주지만 드리프트가 느리고 왜곡이 없어 EKF 의 vyaw 로 쓴다. BNO055 는 그래서 NDOF 가 아니라 IMU 모드로 둔다.
15. IMU 프레임의 각속도 단위가 0.1 °/s 다. 0.01 °/s 로 더 정밀하게 담으면 안 되는 이유는?
int16 은 ±32767 이다. 0.01 °/s 단위면 ±327 °/s 에서 포화되어 센서 범위(±2000 °/s)의 대부분을 잘라 버린다 — 로봇을 손으로 홱 돌리거나 충돌하면 값이 벽에 붙는다. 0.1 °/s 면 ±3276 °/s 로 센서 범위를 다 담고, 해상도 0.1 °/s(0.0017 rad/s)는 자이로 노이즈(§3-7 std)보다 작아 잃는 것이 없다. 단위는 "범위 ÷ 65536" 으로 정하고, 06a §4-3 표에 적어 두 트랙이 같은 수로 나눈다.
