08b · YOLO 객체 검출

"무엇이 어디에 보이는가"를 /detections 로 — YOLO 를 직접 돌린다

당신의 추상 구조 ② "카메라로 보이는 물체를 판정한다"의 앞부분 — 프레임 한 장 안의 판정 — 이 이 단계에서 코드가 된다. 같은 물체에 번호를 붙여 따라가고(추적), 라이다와 합쳐 거리를 재고, 물체 사이·벽까지의 거리를 구하는 뒷부분은 검출기 밖의 노드가 맡는다(08d). 검출기는 프레임 하나를 받아 박스를 내는 상태 없는 함수로 남긴다 — 그래야 08c 에서 백엔드만 바꿀 수 있다. Mac 에서 Python(ultralytics)으로 정답을 확인하고 ONNX 를 내보낸 뒤, Pi 의 C++ 노드가 OpenCV DNN 으로 같은 모델을 돌려 표준 메시지 vision_msgs/Detection2DArray 를 발행한다. Pi 5 의 CPU 라 느리지만, 출력 텐서를 내 손으로 해석해 본 사람만이 08c 에서 Hailo 가 무엇을 대신해 주는지 안다.

이 단계가 끝나면

YOLO 모델을 ONNX 로 내보내고 그 출력 텐서 [1, 84, 8400] 의 의미를 설명할 수 있다. 레터박스 전처리 → 추론 → 전치 → 점수 필터 → NMS → 원본 좌표 복원 → Detection2DArray 발행까지를 C++ 로 작성한 yolo_detector 노드가 /detections 를 내고, 08a 의 detection_overlay 가 그 박스를 사람 위에 그린다. 프레임 드롭 정책과 촬영 시각 복사가 왜 안전 문제인지 말할 수 있다.

그래프에서의 위치detector 상자(인지 계층) — /camera/image_raw → /detections
전제08a (rpi5_vision 패키지, detection_overlay)
예상 소요5~8시간

1. 개요 — 두 트랙, 하나의 인터페이스

  Mac 트랙 (Python, ultralytics)                      Pi 트랙 (C++, OpenCV DNN)
  ─────────────────────────────                      ─────────────────────────────
  yolov8n.pt 로 사진 한 장 검출  ← "정답"             /camera/image_raw
        │                                                   │
        ▼                                                   ▼
  ONNX 로 내보내기 (opset 12)   ──scp──►   yolo_detector: 레터박스 → 추론 → 후처리
        │                                                   │
        ▼                                                   ▼
  출력 shape 확인 [1,84,8400]                          /detections (vision_msgs/Detection2DArray)
                                                            │
                                                            ▼
                                                   detection_overlay (08a) → /camera/annotated

목표는 "무엇이 어디에 보이는가"를 표준 메시지로 내는 것이다. 그 메시지를 받는 쪽(overlay, 10 단계의 감독 노드)은 검출기가 CPU 로 돌든 Hailo 로 돌든 모른다. 08c 는 이 단계의 노드를 같은 토픽·같은 메시지로 실시간화하는 것뿐이다.

왜 Python 트랙은 Mac 에서 하는가

ultralytics 는 PyTorch 를 끌고 온다. 컨테이너에 넣으면 이미지가 1 GB 이상 커지고, Pi 5 에서 torch 로 추론하면 어차피 CPU 검출기보다도 느리다. 모델을 고르고·확인하고·내보내는 일은 Mac(또는 x86)이 빠르고, Pi 에는 결과물(.onnx)만 간다. 커스텀 학습도 같은 이유로 Pi 밖에서 한다(부록 C).

Pi 5 CPU 에서 기대할 것: yolov8n 을 640 입력으로 돌리면 한 프레임에 수백 ms — 1~3 FPS 급이다. 주행용으로는 부족하지만 파이프라인(전처리·후처리·메시지·overlay)을 검증하기엔 충분하고, 그 느림을 직접 재 보는 것이 08c 의 동기가 된다. 실측값은 §3-4 에서 표에 적는다.

2. 원리 — 왜

2-1. YOLO 는 무엇을 하는가

YOLO(You Only Look Once) 는 영상 한 장을 신경망에 한 번 통과시켜 화면을 격자로 나눈 각 셀마다 "여기에 물체가 있다면 박스는 (cx, cy, w, h) 이고 클래스별 확률은 이것"을 동시에 출력한다. 후보 영역을 먼저 뽑고 하나씩 분류하는 2단계 검출기와 달리 한 번에 끝나서 빠르다. v8 부터는 앵커 박스(미리 정한 모양의 후보)가 없어져 헤드가 그냥 좌표 4개 + 클래스 점수를 낸다 — 그래서 출력 해석이 단순하다.

모델파라미터특징우리에게
yolov8n (nano)3.2 M가장 작고 빠름. 작은 물체·먼 물체에 약함이 단계의 기준. Hailo Model Zoo 와 rpicam-apps 데모(01 §3-4)도 v8 이다
yolov8s (small)11 M정확도 ↑, 속도 약 1/2Hailo 에서는 후보. CPU 에서는 무리
yolov8m 이상26 M+서버·GPU 용—
YOLO11 / YOLO26 …—ultralytics 의 후속 세대. API 는 같고 출력 형식이 다를 수 있다이 페이지의 파서는 출력 shape 를 먼저 찍어 보고 맞춘다 (§3-2)

기본 가중치는 COCO 데이터셋의 80 클래스(person, bicycle, car, …, chair, couch, potted plant, …)로 학습되어 있다. 실내 주행에 당장 필요한 것은 person, chair, couch, dog, cat 정도다. 전용 클래스(우리 집 문턱, 충전 독)가 필요해지면 그때 커스텀 학습을 한다 — 지금은 아니다.

2-2. 입력 전처리 — 레터박스와 좌표 복원

모델의 입력은 640×640 정사각형이다. 카메라는 640×480 이다. 두 가지 방법이 있다.

단순 리사이즈 (640×480 → 640×640)레터박스 (비율 유지 + 패딩)
모양세로가 1.33 배 늘어난다640×480 그대로 두고 위아래 80 픽셀을 회색(114)으로 채운다
정확도학습 때 보지 못한 찌그러진 물체 → 점수 하락학습 조건과 같음. ultralytics 가 쓰는 방식
좌표 복원x·(w/640), y·(h/640)아래 식
 
  scale = min(S / w, S / h)              S = 640, 원본 w×h = 640×480 → scale = 1.0
  new_w = w·scale,  new_h = h·scale      → 640×480
  pad_x = (S − new_w) / 2,  pad_y = (S − new_h) / 2      → 0, 80

  원본 좌표 복원:   x_orig = (x_model − pad_x) / scale
                    y_orig = (y_model − pad_y) / scale
                    w_orig =  w_model / scale,   h_orig = h_model / scale

그 다음 cv::dnn::blobFromImage 가 ① 픽셀을 0~255 에서 0~1 로(1/255), ② BGR→RGB 로(swapRB — 모델은 RGB 로 학습됐는데 카메라는 bgr8 로 보내고 toCvShare(msg, "bgr8") 은 그것을 복사 없이 그대로 넘긴다. 08a §2-2), ③ HWC → NCHW 배열 [1, 3, 640, 640] 로 바꾼다. 채널 순서 변환을 cv_bridge 가 아니라 여기서 하는 이유는 복사를 한 번으로 끝내기 위해서다. 이 세 가지 중 하나만 틀려도 에러 없이 점수만 낮게 나온다 — 특히 swapRB 가 빠지면 빨강과 파랑이 바뀐 영상을 보고 점수가 조금씩 떨어지는데, 알아차리기 어렵다.

2-3. 출력 텐서 [1, 84, 8400] — 숫자의 출처

  8400 = 80×80 + 40×40 + 20×20     ← 640 입력을 stride 8, 16, 32 로 나눈 세 격자의 셀 수
         (작은 물체)  (중간)  (큰 물체)     320 입력이면 40²+20²+10² = 2100

  84   = 4 (cx, cy, w, h)  +  80 (COCO 클래스별 점수 0~1)
         ↑ 픽셀 단위, 640×640 레터박스 좌표계         ↑ objectness 가 따로 없다 (v8). 최대 클래스 점수가 곧 신뢰도

  메모리 배치:  [1][84][8400]  →  같은 셀의 84개 값이 8400 칸씩 떨어져 있다
                                  → 셀 단위로 돌려면 (8400 × 84) 로 전치해야 한 행 = 한 후보

8400 개 후보 전부가 나온다. 대부분은 점수가 0.01 이하인 쓰레기다. 후처리는 ① 각 행의 최대 클래스 점수가 conf_threshold 이상인 것만 남기고 ② 남은 것들 중 서로 겹치는 박스를 NMS 로 정리하는 일이다.

YOLOv5YOLOv8 / YOLO11nms=True 로 내보낸 경우
출력 shape[1, 25200, 85][1, 84, 8400][1, max_det, 6]
행/열이미 (후보 × 값). 전치 불필요(값 × 후보). 전치 필요x1, y1, x2, y2, conf, cls — NMS 완료
objectness있음 (5번째 열). conf = obj × cls없음. conf = max cls—
이 페이지파서가 분기해서 지원기준학습 목적상 쓰지 않는다 (후처리를 직접 한다)

2-4. NMS — 겹치는 박스 정리

한 사람 위에 이웃한 셀 여러 개가 각자 박스를 낸다. NMS(Non-Maximum Suppression) 는 점수 순으로 정렬한 뒤, 가장 높은 박스를 남기고 그것과 IoU(겹침 비율)가 nms_threshold 이상인 박스를 지우는 일을 반복한다.

값낮추면높이면
conf_threshold (기본 0.25)희미한 것도 잡힘. 오검출 ↑, NMS 부하 ↑확실한 것만. 먼 사람을 놓침
nms_threshold (기본 0.45)조금만 겹쳐도 지움 → 붙어 선 두 사람이 하나로많이 겹쳐야 지움 → 한 사람에 박스 두 개

2-5. 프레임 드롭 — 큐 1 + busy 플래그

카메라 30 fps, 추론 300 ms. 들어오는 프레임을 전부 처리하려 들면 초당 27 장이 밀리고, 1분 뒤에는 30초 전 영상을 보고 판단한다. 주행 중이면 사고다. 해법은 두 겹이다: ① 구독 큐 깊이 1 — 밀린 프레임은 DDS 층에서 버린다, ② 처리 중이면 콜백 진입 즉시 반환(busy_) — 실행기가 멀티스레드가 되어도 두 추론이 겹치지 않는다. 정석은 추론을 별도 스레드/콜백 그룹으로 빼서 다른 콜백(파라미터, 감시)이 굶지 않게 하는 것이다 — 부록 A 의 MultiThreadedExecutor.

2-6. header.stamp 는 촬영 시각

검출 메시지의 시각은 추론이 끝난 시각이 아니라 입력 이미지가 찍힌 시각이어야 한다. TF 는 "그 시각의 로봇 자세"를 조회한다. 추론에 300 ms 걸렸는데 완료 시각을 넣으면, 0.3 m/s 로 달리던 로봇은 검출된 사람을 9 cm 엉뚱한 곳에 놓는다. 코드에서는 arr.header = msg->header 한 줄이다. 한 줄이지만 원리를 알고 써야 한다.

2-7. OpenCV 버전 — 추측하지 말고 로드해 보고 판단한다

jammy(컨테이너)의 apt OpenCV 는 4.5.4 다. YOLOv8 ONNX 는 최신 opset 으로 내보내면 이 버전의 DNN 모듈이 모르는 연산자가 들어갈 수 있다. 그래서 내보낼 때 opset=12, simplify=True, dynamic=False 로 고정한다. 그래도 readNetFromONNX 가 실패하면 그때 아래 표로 판단한다 — 먼저 로드해 보고 에러 문구로. 미리 OpenCV 를 소스 빌드하는 것은 시간 낭비일 수 있다.

선택지비용고르는 기준
① opset 12 로 다시 내보내기1분항상 먼저. 에러 문구에 Unsupported, Can't create layer, Split, opset 이 보이면
② Dockerfile 에서 OpenCV 4.8+ 소스 빌드Pi 5 에서 1시간 이상, 이미지 +수백 MB①로도 안 되고 C++ 을 OpenCV 로 유지하고 싶을 때. 08c 의 Hailo 가 목표라면 굳이 안 해도 된다
③ ONNX Runtime C++ (aarch64 tgz)다운로드 + CMake 링크 설정, API 가 다름모델을 자주 바꿀 계획이고 최신 opset 이 필요할 때

// 비율을 유지한 채 size×size 정사각형에 넣고 남는 곳은 회색(114)으로 채운다.
// scale, pad_x, pad_y 를 돌려주는 이유: 검출 박스를 원본 좌표로 되돌릴 때 필요하다 (§2-2).
cv::Mat letterbox(const cv::Mat & src, int size, float & scale, int & pad_x, int & pad_y)
{
  scale = std::min(static_cast<float>(size) / src.cols, static_cast<float>(size) / src.rows);
  const int new_w = static_cast<int>(std::round(src.cols * scale));
  const int new_h = static_cast<int>(std::round(src.rows * scale));
  pad_x = (size - new_w) / 2;
  pad_y = (size - new_h) / 2;

  cv::Mat resized;
  cv::resize(src, resized, cv::Size(new_w, new_h), 0, 0, cv::INTER_LINEAR);
  cv::Mat canvas(size, size, src.type(), cv::Scalar(114, 114, 114));
  resized.copyTo(canvas(cv::Rect(pad_x, pad_y, new_w, new_h)));   // ROI 는 뷰다 — 그 자리에 써 넣는다 (08a §2-3)
  return canvas;
}

}  // namespace

    this->declare_parameter<std::string>("names_path", "");
    this->declare_parameter<int>("input_size", 640);
    this->declare_parameter<double>("conf_threshold", 0.25);
    this->declare_parameter<double>("nms_threshold", 0.45);
    this->declare_parameter<bool>("swap_rb", true);
    this->declare_parameter<std::vector<std::string>>("class_filter", std::vector<std::string>{});

    const auto model_path = this->get_parameter("model_path").as_string();
    const auto names_path = this->get_parameter("names_path").as_string();
    input_size_ = this->get_parameter("input_size").as_int();
    conf_thr_ = this->get_parameter("conf_threshold").as_double();
    nms_thr_ = this->get_parameter("nms_threshold").as_double();
    swap_rb_ = this->get_parameter("swap_rb").as_bool();
    class_filter_ = this->get_parameter("class_filter").as_string_array();

    // 1) 클래스 이름 — 한 줄에 하나. 출력 텐서의 열 순서와 같아야 한다.
    std::ifstream f(names_path);
    for (std::string line; std::getline(f, line);) {
      if (!line.empty()) {
        names_.push_back(line);
      }
    }
    if (names_.empty()) {
      RCLCPP_FATAL(this->get_logger(), "names_path 를 읽지 못했습니다: '%s'", names_path.c_str());
      throw std::runtime_error("names file");
    }

    // 2) 모델 로드 — 생성자에서 1회. 콜백마다 로드하면 매 프레임 수백 ms 가 날아간다.
    try {
      net_ = cv::dnn::readNetFromONNX(model_path);
    } catch (const cv::Exception & e) {
      RCLCPP_FATAL(this->get_logger(),
        "ONNX 로드 실패: %s\n"
        "  확인할 것: (1) 경로가 맞는가  (2) opset=12, simplify=True 로 내보냈는가\n"
        "  (3) 그래도 안 되면 OpenCV %s 가 이 모델의 연산자를 모르는 것 — 08b §2-7 표",
        e.what(), CV_VERSION);
      throw;
    }
    net_.setPreferableBackend(cv::dnn::DNN_BACKEND_OPENCV);
    net_.setPreferableTarget(cv::dnn::DNN_TARGET_CPU);
    RCLCPP_INFO(this->get_logger(), "model loaded: %s (%zu classes, input %d, OpenCV %s)",
                model_path.c_str(), names_.size(), input_size_, CV_VERSION);

    // 3) 인터페이스
    pub_ = this->create_publisher<vision_msgs::msg::Detection2DArray>(
      "/detections", rclcpp::QoS(1).best_effort());

    auto qos = rmw_qos_profile_sensor_data;   // BEST_EFFORT + VOLATILE …
    qos.depth = 1;                            // … 그리고 큐는 1: 처리 못 한 프레임은 버린다 (§2-5)
    sub_ = image_transport::create_subscription(
      this, "/camera/image_raw",
      std::bind(&YoloDetector::on_image, this, std::placeholders::_1), "raw", qos);
  }

private:
  void on_image(const sensor_msgs::msg::Image::ConstSharedPtr & msg)
  {
    // 처리 중이면 이 프레임은 버린다. 단일 스레드 실행기에서는 콜백이 겹치지 않지만,
    // 나중에 MultiThreadedExecutor 로 바꿔도 안전하도록 지금부터 이렇게 쓴다.
    bool expected = false;
    if (!busy_.compare_exchange_strong(expected, true)) {
      dropped_++;
      return;
    }
    const auto t0 = std::chrono::steady_clock::now();

    cv_bridge::CvImageConstPtr cv_ptr;
    try {
      cv_ptr = cv_bridge::toCvShare(msg, "bgr8");   // camera_ros 는 bgr8 → 복사 없이 공유 (08a §2-2)
    } catch (const cv_bridge::Exception & e) {
      RCLCPP_ERROR_THROTTLE(this->get_logger(), *this->get_clock(), 2000, "cv_bridge: %s", e.what());
      busy_ = false;
      return;
    }
    const cv::Mat & img = cv_ptr->image;

    // ── 전처리: 레터박스 → blob (NCHW, 0~1, BGR→RGB 는 swap_rb_ 가 담당) ──────────
    float scale = 1.f;
    int pad_x = 0, pad_y = 0;
    const cv::Mat lb = letterbox(img, input_size_, scale, pad_x, pad_y);
    cv::Mat blob = cv::dnn::blobFromImage(
      lb, 1.0 / 255.0, cv::Size(input_size_, input_size_), cv::Scalar(), swap_rb_, false);

    // ── 추론 ─────────────────────────────────────────────────────────────────
    net_.setInput(blob);
    std::vector<cv::Mat> outs;
    net_.forward(outs, net_.getUnconnectedOutLayersNames());
    cv::Mat out = outs[0];

    // 직접 확인: 첫 프레임에 출력 텐서 모양을 찍는다. [1 x 84 x 8400] 이어야 아래 파싱이 맞다.
    //            Mac 의 onnxruntime 이 보여 준 shape 와 같아야 한다 (§3-1).
    if (!shape_logged_) {
      RCLCPP_INFO(this->get_logger(), "output dims=%d shape=[%d x %d x %d]",
                  out.dims, out.size[0], out.size[1], out.size[2]);
      shape_logged_ = true;
    }

    // ── 후처리: [1, 84, 8400] → 8400 행 × 84 열 ──────────────────────────────
    const int num_classes = static_cast<int>(names_.size());
    cv::Mat rows;
    if (out.dims == 3 && out.size[1] == 4 + num_classes) {
      rows = out.reshape(1, out.size[1]).t();     // (84 x 8400) → 전치 → (8400 x 84)   [YOLOv8/11]
    } else if (out.dims == 3 && out.size[2] == 5 + num_classes) {
      rows = out.reshape(1, out.size[1]);         // (25200 x 85) 그대로                 [YOLOv5]
    } else {
      RCLCPP_ERROR_THROTTLE(this->get_logger(), *this->get_clock(), 2000,
        "예상 밖의 출력 모양 — names 파일의 클래스 수(%d)와 모델이 맞는가? §2-3 의 표를 보십시오", num_classes);
      busy_ = false;
      return;
    }
    const bool has_objectness = (rows.cols == 5 + num_classes);   // v5 형식이면 5번째 열이 objectness
    const int cls_offset = has_objectness ? 5 : 4;

    std::vector<cv::Rect> boxes;
    std::vector<float> confs;
    std::vector<int> class_ids;
    for (int i = 0; i < rows.rows; ++i) {
      const float * r = rows.ptr<float>(i);
      // 클래스 점수 구간을 복사 없이 감싼다 (외부 버퍼를 가리키는 Mat)
      cv::Mat scores(1, num_classes, CV_32F, const_cast<float *>(r + cls_offset));
      cv::Point cls_pt;
      double max_score = 0.0;
      cv::minMaxLoc(scores, nullptr, &max_score, nullptr, &cls_pt);
      if (has_objectness) {
        max_score *= r[4];
      }
      if (max_score < conf_thr_) {
        continue;                                 // 8400 개 중 대부분이 여기서 걸러진다
      }

      // (cx, cy, w, h) 는 레터박스 입력 좌표계 → 원본 좌표계로 되돌린다 (§2-2 의 식)
      const float cx = (r[0] - pad_x) / scale;
      const float cy = (r[1] - pad_y) / scale;
      const float w = r[2] / scale;
      const float h = r[3] / scale;
      boxes.emplace_back(static_cast<int>(cx - w / 2), static_cast<int>(cy - h / 2),
                         static_cast<int>(w), static_cast<int>(h));
      confs.push_back(static_cast<float>(max_score));
      class_ids.push_back(cls_pt.x);
    }

    std::vector<int> keep;
    cv::dnn::NMSBoxes(boxes, confs, static_cast<float>(conf_thr_), static_cast<float>(nms_thr_), keep);

    // ── 메시지 ───────────────────────────────────────────────────────────────
    vision_msgs::msg::Detection2DArray arr;
    arr.header = msg->header;   // ★ 촬영 시각. 추론 완료 시각이 아니다 (§2-6)
    for (int idx : keep) {
      const std::string & name = names_[class_ids[idx]];
      if (!class_filter_.empty() &&
          std::find(class_filter_.begin(), class_filter_.end(), name) == class_filter_.end()) {
        continue;
      }
      const cv::Rect & b = boxes[idx];
      vision_msgs::msg::Detection2D det;
      det.header = msg->header;
      det.bbox.center.position.x = b.x + b.width / 2.0;    // 08a 의 overlay 가 읽는 필드 경로 그대로
      det.bbox.center.position.y = b.y + b.height / 2.0;
      det.bbox.size_x = b.width;
      det.bbox.size_y = b.height;
      vision_msgs::msg::ObjectHypothesisWithPose hyp;
      hyp.hypothesis.class_id = name;
      hyp.hypothesis.score = confs[idx];
      det.results.push_back(hyp);
      arr.detections.push_back(det);
    }
    pub_->publish(arr);

    const double ms =
      std::chrono::duration<double, std::milli>(std::chrono::steady_clock::now() - t0).count();
    RCLCPP_INFO_THROTTLE(this->get_logger(), *this->get_clock(), 2000,
      "%zu det (%zu before NMS)  %.0f ms  dropped=%zu",
      arr.detections.size(), boxes.size(), ms, dropped_.load());
    busy_ = false;
  }

  cv::dnn::Net net_;
  std::vector<std::string> names_;
  std::vector<std::string> class_filter_;
  int input_size_{640};
  double conf_thr_{0.25};
  double nms_thr_{0.45};
  bool swap_rb_{true};
  bool shape_logged_{false};
  std::atomic<bool> busy_{false};
  std::atomic<size_t> dropped_{0};

  image_transport::Subscriber sub_;
  rclcpp::Publisher<vision_msgs::msg::Detection2DArray>::SharedPtr pub_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<YoloDetector>());
  rclcpp::shutdown();
  return 0;
}
읽으면서 확인할 것
  • out.reshape(1, 84).t() — 3차원 cv::Mat 을 2차원(84×8400)으로 보고 전치한다. .t() 는 새 행렬을 만든다(복사). 8400×84 float = 2.7 MB, 프레임당 한 번이라 괜찮다.
  • cv::Mat scores(1, num_classes, CV_32F, ptr) — 외부 버퍼를 가리키는 Mat. 복사가 없다. 8400 번 반복되는 곳이라 중요하다.
  • busy_ 를 되돌리는 return 경로가 세 곳이다. 하나라도 빠뜨리면 노드가 영원히 busy 가 된다 — 이런 것이 C++ 에서 RAII(스코프 가드)를 쓰는 이유다. // TODO(you): 소멸자에서 busy_ = false 를 되돌리는 작은 가드 구조체로 바꿔 보십시오.
  • 결과 박스가 화면 밖으로 나갈 수 있다(음수 좌표). overlay 는 그려도 문제없지만, 10 단계에서 "화면 중앙 1/3 안에 사람" 같은 판정을 할 때는 cv::Rect & cv::Rect(0,0,w,h) 로 잘라야 한다.

3-5. Python 으로 같은 파서 — C++ 결과를 검증하는 법 Mac Python

C++ 파서가 맞는지 어떻게 아는가? 같은 그림에 같은 모델을 다른 구현으로 돌려 비교한다. Mac 에서 30줄:

import cv2
import numpy as np
import onnxruntime as ort

sess = ort.InferenceSession('yolov8n.onnx', providers=['CPUExecutionProvider'])
inp = sess.get_inputs()[0]
S = inp.shape[2]                                            # 640
names = [l.strip() for l in open('coco.names') if l.strip()]

img = cv2.imread('test.jpg')                                # BGR
h, w = img.shape[:2]
scale = min(S / w, S / h)
nw, nh = round(w * scale), round(h * scale)
pad_x, pad_y = (S - nw) // 2, (S - nh) // 2
canvas = np.full((S, S, 3), 114, np.uint8)                  # 레터박스 — C++ 과 같은 식
canvas[pad_y:pad_y + nh, pad_x:pad_x + nw] = cv2.resize(img, (nw, nh))
blob = cv2.dnn.blobFromImage(canvas, 1 / 255.0, (S, S), swapRB=True)   # (1, 3, S, S) float32

out = sess.run(None, {inp.name: blob})[0]                   # (1, 84, 8400)
rows = out[0].T                                             # (8400, 84)  ← 전치
boxes, confs, cls = [], [], []
for r in rows:
    c = int(np.argmax(r[4:]))
    s = float(r[4 + c])
    if s < 0.25:
        continue
    cx, cy, bw, bh = (r[0] - pad_x) / scale, (r[1] - pad_y) / scale, r[2] / scale, r[3] / scale
    boxes.append([int(cx - bw / 2), int(cy - bh / 2), int(bw), int(bh)])
    confs.append(s)
    cls.append(c)
keep = cv2.dnn.NMSBoxes(boxes, confs, 0.25, 0.45)
for i in np.array(keep).flatten():                          # 버전에 따라 [[i]] 또는 [i] 로 온다
    x, y, bw, bh = boxes[i]
    print(f'{names[cls[i]]:12s} {confs[i]:.2f}  x={x} y={y} w={bw} h={bh}')

이 출력이 §3-1 의 ultralytics 결과와 (소수점 차이 안에서) 같으면 파서의 논리가 맞다. 이제 같은 사진을 Pi 의 C++ 노드에 넣어 세 번째 결과를 얻으면 된다 — 그런데 C++ 노드는 토픽만 받는다.

🤔 이해 확인

1. 출력의 8400 은 어디서 오는 숫자인가? 입력을 320 으로 바꾸면 몇이 되는가?
640 입력을 stride 8·16·32 로 나눈 세 격자 80×80 + 40×40 + 20×20 = 8400 개 셀이다. 셀마다 후보 박스 하나를 낸다. 320 이면 40²+20²+10² = 2100 이다. (모델이 낼 수 있는 후보 수이지 검출 수가 아니다 — 대부분은 점수 필터에서 사라진다.)
2. 왜 [1, 84, 8400] 을 전치해서 [8400, 84] 로 만드는가?
메모리에 값 종류(84) 단위로 늘어서 있어 한 후보의 84개 값이 8400 칸씩 떨어져 있다. 후보 하나를 한 행으로 만들어야 rows.ptr<float>(i) 로 연속 메모리를 읽으며 처리할 수 있다. YOLOv5 는 애초에 [1, 25200, 85] 로 후보 단위라 전치가 필요 없다 — 그래서 파서가 shape 를 보고 분기한다.
3. 레터박스로 넣은 640×480 영상에서 모델이 (320, 300) 에 박스 중심을 냈다. 원본 좌표는?
scale = min(640/640, 640/480) = 1.0, pad_x = 0, pad_y = (640−480)/2 = 80. x = (320−0)/1.0 = 320, y = (300−80)/1.0 = 220. 폭·높이는 scale 로만 나눈다. 원본이 1280×960 이었다면 scale = 0.5 라 x = 640, y = 440 이 된다.
4. NMS 를 생략하면 무엇이 보이는가? nms_threshold 를 0.9 로 올리면?
한 사람 위에 이웃 셀들이 낸 박스 수십 개가 겹쳐 그려진다(before NMS 개수가 그것이다). 0.9 로 올리면 IoU 가 0.9 이상으로 거의 완전히 겹치는 것만 지우므로 한 사람에 박스가 여러 개 남는다. 반대로 너무 낮추면 붙어 선 두 사람이 하나로 합쳐진다.
5. 검출 메시지의 header.stamp 에 추론 완료 시각을 넣으면 무엇이 잘못되는가?
TF 는 그 시각의 로봇 자세를 조회한다. 추론에 300 ms 걸렸다면 로봇은 이미 그만큼 움직였고, 검출된 물체를 300 ms 뒤의 자세 기준으로 놓아 수 cm~수십 cm 틀린다. 촬영 시각(입력 이미지의 header)을 그대로 복사해야 한다. 코드로는 한 줄이다.
6. 큐 깊이 1 과 busy_ 플래그는 각각 무엇을 막는가? 둘 다 필요한가?
큐 1 은 DDS 층에서 밀린 프레임을 버려 옛 프레임을 순서대로 처리하는 지연 누적을 막는다. busy_ 는 처리 중에 또 콜백이 들어오는 것(멀티스레드 실행기에서 가능)을 막아 추론 두 개가 겹치지 않게 한다. 단일 스레드에서는 busy_ 가 사실상 안 걸리지만, 실행기를 바꾸는 순간 없으면 사고가 나므로 처음부터 둔다.
7. YOLOv5 ONNX 를 이 노드에 넣으면 무엇이 달라져야 하는가?
출력이 [1, 25200, 85] 로 이미 후보 단위라 전치하지 않고, 5번째 열의 objectness 를 클래스 점수에 곱해 신뢰도를 만든다. 파서가 out.size[2] == 5 + num_classes 로 감지해 분기한다. 그 외(레터박스, NMS, 메시지)는 같다 — 그래서 "shape 를 먼저 찍어 본다"가 규칙이다.
8. conf_threshold 를 0.05 로 내리면 추론 시간은 그대로인데 왜 전체 처리 시간이 늘어나는가?
신경망 추론(forward) 시간은 입력 크기로만 정해진다. 그러나 점수 필터를 통과하는 후보가 수십 배 늘어 NMS 입력이 커지고, NMS 는 후보 수에 대해 대략 제곱으로 비싸진다. 로그의 before NMS 개수와 ms 를 같이 보면 확인된다.
