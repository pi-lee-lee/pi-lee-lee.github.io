C5 · YOLO 모델 준비 (Mac)

YOLO 모델 준비 — Mac 에서 정답을 만들고 ONNX 로 내보낸다

YOLO(You Only Look Once)는 영상 한 장을 신경망에 한 번 통과시켜 화면 안의 물체 박스와 종류를 한꺼번에 출력하는 검출 모델이다. 이 쪽은 Mac 에서 한다. 공개 모델 yolov8n 을 받아 사진 한 장으로 정답을 확인하고, Pi 의 C++ 노드(C6)가 읽을 ONNX 형식 파일로 내보내고, 그 파일의 입출력 모양과 클래스 이름 파일을 만든다.

이 쪽이 끝나면 보이는 것
  • Mac 에서 yolov8n.pt 로 시험 사진을 검출한 결과(클래스 · 점수 · 좌표)를 적었다. 이것이 C6 가 재현해야 할 정답이다.
  • yolov8n.onnx 를 만들고 입력 [1, 3, 640, 640] · 출력 [1, 84, 8400] 을 확인했다.
  • 클래스 이름 파일 coco.names(80 줄)가 있다.
  • Python 참조 파서가 ultralytics 와 같은 박스를 낸다. 두 파일이 Pi 의 rpi5_vision/models/ 에 있다.

필요한 것 — Mac, 인터넷(모델 파일 내려받기), C1 의 시험 사진 /tmp/test.jpg(사람이나 의자가 있는 장면).

환경Mac Python
선행C3 의 파이썬 가상환경 ~/camtools(없으면 §3-1 에서 만든다)
만드는 것rpi5_vision/models/yolov8n.onnx, rpi5_vision/models/coco.names, Mac 의 ~/yolo/ 작업 폴더
적는 곳노트 — 기준 검출 결과(§3-3)

1. 개요

Mac (Python, ultralytics)                        Pi 컨테이너 (C++, OpenCV DNN) — C6
yolov8n.pt 로 사진 한 장 검출  ← 정답              /stereo/left/image_raw
ONNX 로 내보내기 (opset 12)   ──── scp ────►       yolo_detector: 레터박스 → 추론 → 후처리
입출력 모양 확인 [1,84,8400]                       /detections

Mac 에서 하는 이유는 둘이다. ultralytics 는 PyTorch 를 함께 설치해 수 GB 를 차지하고, Pi 의 CPU 로 PyTorch 추론을 하면 C6 의 검출기보다도 느리다. 모델을 고르고 확인하고 내보내는 일은 Mac 이 빠르고, Pi 에는 결과 파일만 보낸다.

모델은 yolov8n(n = nano, 가장 작은 판)이다. COCO 데이터셋의 80 종류(person, bicycle, car, …, chair, couch, dog, cat …)로 학습되어 있다. 실내 주행에 필요한 사람 · 의자 · 반려동물은 들어 있다. Hailo 쪽(C7 · C8)도 같은 계열(yolov8)의 모델을 쓴다.

2. 원리 — C6 의 코드를 읽는 데 필요한 네 가지

2-1. 입력 — 레터박스

모델의 입력은 640 × 640 정사각형이고 카메라 영상은 640 × 480 이다. 세로를 늘려 맞추면 학습 때 보지 못한 찌그러진 물체가 되어 점수가 떨어진다. 비율을 유지한 채 넣고 남는 곳을 회색(114)으로 채우는 것이 레터박스다. 박스를 원본 좌표로 되돌릴 때 같은 숫자를 거꾸로 쓴다.

scale = min(S / w, S / h)           S = 640, 원본 640 × 480 → scale = 1.0
new_w = w · scale,  new_h = h · scale                     → 640 × 480
pad_x = (S − new_w) / 2,  pad_y = (S − new_h) / 2          → 0, 80

원본 좌표 복원:  x_orig = (x_model − pad_x) / scale      y_orig = (y_model − pad_y) / scale
                 w_orig =  w_model / scale                h_orig =  h_model / scale

그 다음 세 가지 변환이 더 있다. 픽셀 값을 0 ~ 255 에서 0 ~ 1 로, 바이트 순서를 BGR 에서 RGB 로, 배열 배치를 [높이][너비][채널] 에서 [1][3][640][640] 으로. OpenCV 의 blobFromImage 한 번이 셋을 다 한다. 셋 중 하나만 틀려도 오류 없이 점수만 낮아진다.

2-2. 출력 — [1, 84, 8400] 의 뜻

8400 = 80×80 + 40×40 + 20×20      640 입력을 8 · 16 · 32 픽셀 격자로 나눈 세 격자의 칸 수 (작은 물체 · 중간 · 큰 물체)
  84 = 4 (cx, cy, w, h)  +  80 (종류별 점수 0 ~ 1)        좌표는 640 × 640 레터박스 기준 픽셀

메모리 배치 [84][8400] : 한 후보의 84 개 값이 8400 칸씩 떨어져 있다 → [8400][84] 로 전치해야 한 행 = 한 후보

후보 8400 개가 전부 나온다. 대부분은 점수가 0.01 아래다. 후처리는 ① 각 행의 최대 점수가 임계값 이상인 것만 남기고 ② 남은 것 중 서로 겹치는 박스를 정리하는 일이다.

2-3. 겹친 박스 정리 (NMS)

한 사람 위에 이웃한 칸 여러 개가 각자 박스를 낸다. NMS(Non-Maximum Suppression)는 점수 순으로 정렬한 뒤, 가장 높은 박스를 남기고 그 박스와 겹침 비율이 임계값 이상인 박스를 지우는 일을 반복한다.

값낮추면높이면
conf_threshold (0.25)희미한 것도 검출. 오검출과 NMS 부하가 는다확실한 것만. 먼 사람을 놓친다
nms_threshold (0.45)조금만 겹쳐도 지운다 → 붙어 선 두 사람이 하나로많이 겹쳐야 지운다 → 한 사람에 박스 두 개

2-4. ONNX 내보내기 옵션

컨테이너의 OpenCV 는 4.5.4 다. 최신 연산자 집합으로 내보낸 파일은 이 판이 읽지 못할 수 있다. 그래서 opset=12, simplify=True, dynamic=False 로 고정한다. 그래도 로드에 실패하면 C6 의 표를 본다.

import cv2

model = YOLO('yolov8n.pt')
results = model('test.jpg', conf=0.25)
r = results[0]
for box in r.boxes:
    x1, y1, x2, y2 = box.xyxy[0].tolist()
    print(f'{model.names[int(box.cls)]:12s} {float(box.conf):.2f}  '
          f'x={x1:.0f} y={y1:.0f} w={x2 - x1:.0f} h={y2 - y1:.0f}')

3-4. ONNX 로 내보내고 모양을 확인한다 Python

~/yolo/export.py:

# export.py -- export yolov8n to ONNX for OpenCV 4.5.4 and check the tensor shapes (camera guide C5)
from ultralytics import YOLO
import onnxruntime as ort

model = YOLO('yolov8n.pt')
model.export(format='onnx', imgsz=640, opset=12, simplify=True, dynamic=False)   # -> yolov8n.onnx

sess = ort.InferenceSession('yolov8n.onnx', providers=['CPUExecutionProvider'])
for i in sess.get_inputs():
    print('input ', i.name, i.shape, i.type)     # images [1, 3, 640, 640] tensor(float)
for o in sess.get_outputs():
    print('output', o.name, o.shape, o.type)     # output0 [1, 84, 8400] tensor(float)

# class names, one per line, in the model's output order (= column order of the 80 scores)
with open('coco.names', 'w') as f:
    for k in range(len(model.names)):
        f.write(model.names[k] + '\n')
python3 export.py
wc -l coco.names        # 80
head -3 coco.names      # person  bicycle  car

출력 모양이 [1, 84, 8400] 이 아니면 그 값을 적어 둔다. C6 의 파서는 첫 프레임에 이 모양을 로그로 찍고, [1, 84, 8400](YOLOv8 · v11)과 [1, 25200, 85](YOLOv5) 두 가지를 처리한다.

3-5. Python 참조 파서 — C6 의 C++ 과 같은 계산 Python

C++ 파서가 맞는지 확인하는 수단이다. 같은 사진에 같은 ONNX 파일을 다른 구현으로 실행해 비교한다. ~/yolo/parse_onnx.py:

# parse_onnx.py -- run yolov8n.onnx with onnxruntime and do the same post-processing as the C++ node (C6)
import cv2
import numpy as np
import onnxruntime as ort

sess = ort.InferenceSession('yolov8n.onnx', providers=['CPUExecutionProvider'])
inp = sess.get_inputs()[0]
S = inp.shape[2]                                            # 640
names = [l.strip() for l in open('coco.names') if l.strip()]

img = cv2.imread('test.jpg')                                # BGR
h, w = img.shape[:2]
scale = min(S / w, S / h)
nw, nh = round(w * scale), round(h * scale)
pad_x, pad_y = (S - nw) // 2, (S - nh) // 2
canvas = np.full((S, S, 3), 114, np.uint8)                  # letterbox, same formula as C++
canvas[pad_y:pad_y + nh, pad_x:pad_x + nw] = cv2.resize(img, (nw, nh))
blob = cv2.dnn.blobFromImage(canvas, 1 / 255.0, (S, S), swapRB=True)   # (1, 3, S, S) float32

out = sess.run(None, {inp.name: blob})[0]                   # (1, 84, 8400)
rows = out[0].T                                             # (8400, 84)  <- transpose
boxes, confs, cls = [], [], []
for r in rows:
    c = int(np.argmax(r[4:]))
    s = float(r[4 + c])
    if s < 0.25:
        continue
    cx, cy, bw, bh = (r[0] - pad_x) / scale, (r[1] - pad_y) / scale, r[2] / scale, r[3] / scale
    boxes.append([int(cx - bw / 2), int(cy - bh / 2), int(bw), int(bh)])
    confs.append(s)
    cls.append(c)
keep = cv2.dnn.NMSBoxes(boxes, confs, 0.25, 0.45)
for i in np.array(keep).flatten():                          # [[i]] or [i] depending on the OpenCV version
    x, y, bw, bh = boxes[i]
    print(f'{names[cls[i]]:12s} {confs[i]:.2f}  x={x} y={y} w={bw} h={bh}')
python3 parse_onnx.py

3-3 의 결과와 같은 물체가 몇 픽셀 안에서 같은 자리에 나오면 파서의 계산이 맞다. C6 에서 C++ 노드에 같은 사진을 넣어 세 번째 결과를 얻는다.

🤔 이해 확인

이 쪽에서 설명한 내용만으로 답할 수 있다. 답을 펼치기 전에 먼저 말로 답해 본다.

1. 출력의 8400 은 어디서 나오는 숫자인가. 입력을 320 으로 바꾸면 몇이 되는가.

640 입력을 8 · 16 · 32 픽셀 격자로 나눈 세 격자 80 × 80 + 40 × 40 + 20 × 20 = 8400 칸이다. 칸마다 후보 박스 하나를 낸다. 320 이면 40² + 20² + 10² = 2100 이다. 검출 수가 아니라 후보 수다.

2. 레터박스로 넣은 640 × 480 영상에서 모델이 (320, 300)에 박스 중심을 냈다. 원본 좌표는 어디인가.

scale = 1.0, pad_x = 0, pad_y = 80 이므로 x = 320, y = 300 − 80 = 220 이다. 폭과 높이는 scale 로만 나눈다.

3. NMS 를 생략하면 무엇이 보이는가. nms_threshold 를 0.9 로 올리면?

한 사람 위에 이웃 칸들이 낸 박스 수십 개가 겹쳐 그려진다. 0.9 로 올리면 거의 완전히 겹치는 것만 지우므로 한 사람에 박스가 여러 개 남는다. 너무 낮추면 붙어 선 두 사람이 하나로 합쳐진다.
