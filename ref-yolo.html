부록 C · YOLO 사용법

YOLO — 추론, 내보내기, 출력 텐서 해석, 그리고 학습의 개요

08b(CPU 검출기)와 08c(Hailo)에서 쓰는 YOLO 를 ROS 와 분리해서 정리했다. Mac 에서 ultralytics 로 정답을 확인하고 ONNX 를 내보내는 일, 그리고 ONNX 의 raw 출력을 직접 박스로 바꾸는 일이 핵심이다. 커스텀 학습은 이 프로젝트의 필수 경로가 아니므로 개요만 둔다.

이 부록의 쓰임

기준 모델은 YOLOv8n 이다. 이유는 성능이 아니라 검증된 호환성이다 — Hailo Model Zoo 와 rpicam-apps 의 Hailo 자산(01 단계 데모)이 yolov8 계열이고, OpenCV DNN 으로 ONNX 를 읽는 경로도 널리 확인되어 있다. 더 새 모델은 같은 API 로 쓸 수 있지만 출력 형식이 다를 수 있으므로 §4 의 확인 절차를 반드시 거친다.

1. YOLO 가 무엇인가

YOLO(You Only Look Once) 는 영상 전체를 신경망에 한 번 통과시켜 "어디에 무엇이 있는가"를 동시에 내는 객체 검출기다. 영상을 격자로 나누고 각 셀이 박스 좌표와 클래스 점수를 예측한다. 후보 영역을 먼저 뽑고 분류하는 2단계 방식(R-CNN 계열)보다 훨씬 빠르기 때문에 로봇·임베디드에서 표준이 됐다.

   입력 640×640 ──► 백본(특징 추출) ──► 넥(다중 스케일 융합) ──► 헤드
                                                                 ├─ 80×80 격자 (작은 물체)  6400 셀
                                                                 ├─ 40×40 격자 (중간)       1600 셀
                                                                 └─ 20×20 격자 (큰 물체)     400 셀
                                                                        합계 8400 후보  ×  (4 박스 + 80 클래스)
   후처리: 점수 임계 → NMS(겹치는 박스 제거) → 최종 박스 몇 개
계열특징raw ONNX 출력(640, COCO)비고
YOLOv5 (2020)앵커 기반. objectness 점수 있음[1, 25200, 85] = cx cy w h obj + 80자료가 많다. 후처리가 v8 과 다르다
YOLOv8 (2023)앵커 프리. objectness 없음[1, 84, 8400] = (cx cy w h + 80) × 후보이 가이드의 기준. Hailo Model Zoo·rpicam 자산과 일치
YOLO11 (2024)v8 과 같은 헤드 형식, 더 작고 정확[1, 84, 8400]08b 코드가 그대로 동작하는 것으로 알려짐 — 내보낸 뒤 확인
그 이후(YOLO12, YOLO26 …)NMS 내장(end-to-end) 모델이 등장모델에 따라 [1, N, 6] 등현재 ultralytics 문서에서 확인. 출력이 다르면 08b 의 파서가 안 맞는다
YOLOv8 크기파라미터COCO mAP50-95상대 속도이 프로젝트

s11.2 M44.9≈ n 의 1/2~1/3Hailo 에서 정확도가 아쉬울 때
m25.9 M50.2느림—
l / x43.7 / 68.2 M52.9 / 53.9매우 느림—

ultralytics 공식 표(COCO val, 640 입력) 요약. 숫자는 버전에 따라 조금씩 갱신된다.

COCO 80 클래스 중 실내 로봇에 쓸 만한 것은 0 person, 1 bicycle, 15 cat, 16 dog, 24 backpack, 28 suitcase, 39 bottle, 41 cup, 56 chair, 57 couch, 58 potted plant, 60 dining table, 62 tv, 63 laptop 정도다. 벽·문·계단 같은 "구조물"은 COCO 에 없다 — 그것은 라이다와 지도가 맡는다. 클래스 인덱스와 이름의 대응은 model.names 로 뽑아 coco.names 파일로 만든다(§2).

라이선스: ultralytics 의 YOLOv8/11 코드와 가중치는 AGPL-3.0 이다. 학습·개인 프로젝트에는 문제가 없고, 제품에 넣을 때만 확인한다.

4. 출력 텐서 해석

4-1. [1, 84, 8400] 의 구조

   out[0]  →  84 × 8400 행렬
              ┌────────────── 8400 개 후보 (열) ──────────────┐
    행 0  cx   ·  ·  ·  ·  ·  ·  ·  ·  ·  ·  ·  ·  ·  ·  ·  ·     ← 박스 중심 x (레터박스 640 좌표계, 픽셀)
    행 1  cy
    행 2  w
    행 3  h
    행 4  score(person)
    행 5  score(bicycle)
     ⋮
    행 83 score(toothbrush)

   전치(transpose) → 8400 × 84 : 한 행이 후보 하나 = [cx cy w h s0 … s79]
   후보의 클래스 = argmax(s0…s79),  신뢰도 = 그 최댓값   (objectness 가 없으므로 곱할 것이 없다)
형식행 하나신뢰도후처리
v8/v11 raw [1,84,8400]cx cy w h + 80 점수max(점수)전치 → 임계 → 역변환 → NMS
v5 raw [1,25200,85]cx cy w h obj + 80 점수obj × max(점수)전치 불필요 → 임계 → 역변환 → NMS
nms=True 내보내기 [1,300,6]x1 y1 x2 y2 conf clsconf역변환만 (NMS 는 그래프 안)

4-2. 레터박스와 역변환

   원본 640×480 ──► 비율 유지 축소(r = min(640/640, 640/480) = 1.0 → 640×480) ──► 회색(114) 패딩으로 640×640
                                                                           pad_x = (640−640)/2 = 0,  pad_y = (640−480)/2 = 80

   r     = min(S / w0, S / h0)
   nw, nh = round(w0·r), round(h0·r)
   pad_x, pad_y = (S − nw) / 2, (S − nh) / 2

   역변환 (모델 출력 → 원본 픽셀):
   x_orig = (x_lb − pad_x) / r          w_orig = w_lb / r
   y_orig = (y_lb − pad_y) / r          h_orig = h_lb / r

단순 resize(640,640) 로 찌그러뜨려도 동작은 하지만 물체의 종횡비가 바뀌어 정확도가 떨어진다. ultralytics 의 predict 는 레터박스를 쓰므로, "정답"과 같은 결과를 내려면 같은 전처리를 해야 한다.

손으로 한 번 계산해 보기 — 640×480 카메라, 사람 박스

r = min(640/640, 640/480) = 1.0, nw = 640, nh = 480, pad_x = 0, pad_y = 80. 모델이 (cx, cy, w, h) = (320, 300, 120, 360) 을 냈다면 원본에서는 cx = (320 − 0)/1.0 = 320, cy = (300 − 80)/1.0 = 220, w = 120, h = 360. 즉 y 만 80 픽셀 위로 옮긴다. 이 80 을 빼지 않으면 박스가 실제보다 아래에 그려지고, 10 단계의 방위각 계산에는 영향이 없지만(u 만 쓴다) 높이 기반 거리 근사는 틀어진다. 입력이 320×240 이면 r = 2.0 이 되어 나눗셈이 실제로 작동한다 — 두 해상도로 다 확인한다.

4-3. NMS (Non-Maximum Suppression)

   같은 물체를 여러 셀이 동시에 예측한다 → 겹치는 박스 수십 개
   ① 점수 순으로 정렬  ② 가장 높은 것을 채택  ③ 채택된 박스와 IoU > nms_thr 인 나머지를 삭제  ④ 남은 것으로 반복

   IoU(A, B) = |A ∩ B| / |A ∪ B|      0 = 안 겹침, 1 = 동일
임계값낮추면높이면출발값
conf_threshold검출이 늘고 오검출도 는다확실한 것만 남고 작은/먼 물체를 놓친다0.25 (주행 안전용 사람 검출은 0.4~0.5 로 올려 오검출을 줄인다)
nms_threshold(IoU)겹친 박스를 더 공격적으로 합친다 → 붙어 있는 두 사람이 하나로중복 박스가 남는다0.45

클래스별 NMS(같은 클래스끼리만 억제)와 클래스 무관 NMS 가 있다. cv::dnn::NMSBoxes 는 넘긴 박스 전체에 대해 수행하므로 클래스별로 하려면 클래스마다 나눠 호출하거나, 박스 좌표에 클래스별 큰 오프셋을 더하는 트릭을 쓴다. 이 프로젝트는 클래스 무관으로 시작한다(사람과 의자가 같은 자리에 겹치는 일은 드물다).

4-4. Python 30줄 파서 — 08b 의 C++ 과 1:1 대응 Mac

import cv2, numpy as np, onnxruntime as ort

sess = ort.InferenceSession('yolov8n.onnx', providers=['CPUExecutionProvider'])
inp = sess.get_inputs()[0]
names = [l.strip() for l in open('coco.names')]

img = cv2.imread('test.jpg'); h0, w0 = img.shape[:2]
S = 640
r = min(S / w0, S / h0); nw, nh = int(round(w0 * r)), int(round(h0 * r))
px, py = (S - nw) // 2, (S - nh) // 2
lb = np.full((S, S, 3), 114, np.uint8)                       # 레터박스 캔버스
lb[py:py + nh, px:px + nw] = cv2.resize(img, (nw, nh))
blob = lb[:, :, ::-1].transpose(2, 0, 1)[None].astype(np.float32) / 255.0   # BGR→RGB, HWC→NCHW, 0~1

out = sess.run(None, {inp.name: blob})[0]                   # (1, 84, 8400)
pred = out[0].T                                              # (8400, 84)

boxes, scores, classes = [], [], []
for row in pred:
    cls = int(np.argmax(row[4:])); conf = float(row[4 + cls])
    if conf < 0.25:
        continue
    cx, cy, w, h = row[:4]
    x = (cx - w / 2 - px) / r; y = (cy - h / 2 - py) / r    # 좌상단, 원본 좌표로 역변환
    boxes.append([int(x), int(y), int(w / r), int(h / r)]); scores.append(conf); classes.append(cls)

keep = cv2.dnn.NMSBoxes(boxes, scores, 0.25, 0.45)
for i in np.array(keep).flatten():
    x, y, w, h = boxes[i]
    print(f'{names[classes[i]]:12s} {scores[i]:.2f}  x={x} y={y} w={w} h={h}')
    cv2.rectangle(img, (x, y), (x + w, y + h), (0, 255, 0), 2)
cv2.imwrite('parsed.jpg', img)

§2 의 r.boxes.xyxy 와 이 출력을 비교한다. 박스 개수와 좌표가 몇 픽셀 이내로 같으면 파서가 맞다. 이 30줄을 C++ 로 옮긴 것이 08b 의 yolo_detector 다 — 줄 단위로 대응된다.

6. 로봇에서의 실전 팁

주제요점
모델 크기 × 입력 크기n@640 이 기본. CPU 라면 n@320 이 4배 가까이 빠르지만 작은/먼 물체를 놓친다. Hailo 에서는 n@640 이 실시간이므로 굳이 줄이지 않는다. 실측 표를 만든다(08b §3-4)
클래스 필터주행 안전에는 person(과 반려동물)만 보면 된다. 필터는 파서 뒤가 아니라 NMS 앞에서 해야 다른 클래스 박스가 억제 대상을 뺏지 않는다
시간적 안정화한 프레임의 검출은 깜빡인다. 감독 노드는 "연속 N 프레임(예: 3) 검출 시 인정, M 프레임 미검출 시 해제"로 히스테리시스를 둔다(10 단계 정책). 검출 노드는 raw 를 내고 판단은 위에서
노출과 NoIR역광·어두운 복도에서 recall 이 떨어진다. NoIR 은 낮에 색이 붉어도 검출에는 큰 영향이 없고, 밤에는 IR 조명이 있어야 한다. 노출 안정(AeEnable)이 색보다 중요
검출 → 거리① 라이다 융합(정석): 박스 중심 u → θ = atan((u−cx)/fx) → 그 방위의 /scan 거리(10 단계). ② 근사: 사람 키 H(≈1.7 m) 가 h 픽셀이면 Z ≈ fy·H/h — 거칠지만 라이다 사각(높이)에 있는 물체에 유용
평가실제 주행 환경에서 5분 rosbag 을 찍고 오검출(FP)·미검출(FN)을 세어 본다. mAP 보다 "우리 복도에서 사람을 몇 번 놓쳤나"가 중요하다
프레임 드롭추론이 카메라보다 느리면 최신 프레임만 처리(08b). 큐를 쌓으면 1분 뒤 30초 전 영상을 보고 판단한다
 
# 시간적 안정화(히스테리시스) — 감독 노드(10)의 정책을 의사코드로. 검출 노드는 raw 를 그대로 낸다.
N_ON, N_OFF = 3, 5            # 연속 3프레임 검출 → 인정, 연속 5프레임 미검출 → 해제
seen, missed, person_near = 0, 0, False

def on_detections(dets):      # dets: 이 프레임의 Detection2DArray
    global seen, missed, person_near
    hit = any(d.results[0].hypothesis.class_id == 'person'
              and d.bbox.size_y >= 120                     # 박스 높이[px] 로 "가깝다" 근사
              for d in dets.detections)
    seen, missed = (seen + 1, 0) if hit else (0, missed + 1)
    if not person_near and seen >= N_ON:   person_near = True    # → PAUSED (goal cancel)
    if person_near and missed >= N_OFF:    person_near = False   # → 같은 목표 재전송
실측 표 (직접 채운다)yolov8n@640yolov8n@320yolov8s@640

7. Hailo 로 가는 길 (개요)

   .pt ──(ultralytics export)──► .onnx ──(Hailo Dataflow Compiler, x86 Linux)──► .hef ──► Hailo-8 (HailoRT)
                                                    ▲
                                  우리는 이 단계를 하지 않는다 — Hailo Model Zoo 의 기성 yolov8n.hef 를 쓴다
  • .hef(Hailo Executable Format)는 칩 전용 바이너리다. ONNX 를 그대로 올릴 수 없고, 컴파일(양자화 포함)은 x86 Linux 의 DFC 에서만 된다.
  • Model Zoo 가 yolov8n/s 등을 이미 컴파일해 제공한다. hailo-all 설치본의 /usr/share/hailo-models/ 에도 들어 있다(01·08c 단계).
  • NMS 온칩 여부: Model Zoo 의 YOLO hef 는 대개 NMS 후처리를 포함해 출력이 "클래스별 박스 리스트"로 나온다. §4 의 raw 파서는 필요 없고 대신 그 형식의 디코더가 필요하다. hailortcli parse-hef model.hef 로 출력 vstream 의 형태를 읽는다.
  • 커스텀 학습 모델을 Hailo 에 올리려면 DFC + 보정(calibration) 데이터셋이 필요하다 — 별도의 큰 주제.

이 프로젝트에서 쓰는 곳: 08c · Hailo-8 가속.

8. 자주 나는 문제

증상원인조치
yolov8n.pt 다운로드 실패네트워크/프록시브라우저로 받아 작업 폴더에 두면 그 파일을 쓴다
Mac 에서 pip install ultralytics 가 torch 에서 오래 걸림큰 휠정상(수백 MB). 컨테이너에는 넣지 않는 이유가 이것
검출이 0개conf 가 너무 높음, 사진이 너무 어둡거나 작음, 클래스 필터가 비어 있음conf=0.05 로 내려 뭐라도 나오는지, 원본 해상도 확인
박스는 맞는데 라벨이 엉뚱함coco.names 순서 ≠ model.names이름 파일을 §2 의 코드로 다시 생성. 커스텀 모델은 그 모델의 names
C++ 와 Python 박스 좌표가 수십 픽셀 차이레터박스 역변환 누락/부호, 입력 크기 불일치§4-2 손계산 예로 한 박스만 검산
C++ 가 Python 보다 검출이 적다Release 가 아니라 느려서 프레임 드롭이 아니라 — 임계값이 다름(conf/nms), 또는 클래스 무관 NMS 차이임계값을 똑같이 두고 같은 사진으로 비교
Pi 에서 1 FPS 미만Debug 빌드, 입력 640, 4스레드 경합Release, 320 실험, cv::setNumThreads(2). 근본 해결은 08c
Hailo 결과와 CPU 결과가 다르다양자화(INT8)·다른 학습 체크포인트·NMS 온칩 파라미터같은 장면에서 정성 비교. 소수점 일치는 기대하지 않는다
야간에 사람을 못 본다NoIR 이라도 광원이 없으면 영상이 없다IR 조명 추가, 노출 시간 상향(모션 블러와 교환)
