C4 · OpenCV 전처리 노드

OpenCV 전처리 노드 — 영상을 cv::Mat 로 받아 처리하고 다시 내보낸다

/stereo/left/image_raw 를 C++ 노드 안으로 가져와 OpenCV 로 처리하고 /stereo/left/image_proc 로 다시 내보낸다. 크기 축소 · 흑백 · 흐림 · 에지 · 윤곽선 다섯 가지를 파라미터로 바꿔 가며 실행하고, 처리 시간을 잰다. 이 쪽의 받기 → cv::Mat → 처리 → 내보내기 경로를 C6 의 YOLO 노드와 C8 의 Hailo 노드가 그대로 쓴다.

이 쪽이 끝나면 보이는 것
  • 패키지 rpi5_vision 에 C++ 노드 image_proc_node 가 들어가고 Release 로 빌드된다.
  • /stereo/left/image_proc 가 입력과 같은 fps 로 발행되고 Foxglove 에서 원본과 나란히 보인다.
  • ros2 param set 으로 재빌드 없이 처리 방식이 바뀐다.
  • 처리 방식마다 걸린 시간(ms)을 표에 적었다.

필요한 것 — C2 의 카메라 노드가 뜨는 상태.

환경컨테이너 C++ 벤치
선행C2 — rpi5_vision 패키지와 /stereo/left/image_raw
만드는 것rpi5_vision/src/image_proc_node.cpp, package.xml · CMakeLists.txt 교체
적는 곳노트 — §3-7 의 처리 시간 표

1. 개요

ROS 2 의 영상은 sensor_msgs/msg/Image 라는 바이트 배열 메시지로 흐른다. OpenCV 는 cv::Mat(행렬)을 다룬다. 둘 사이를 두 패키지가 잇는다.

패키지하는 일이 쪽에서 쓰는 함수
cv_bridgeImage 메시지 ↔ cv::Mat 변환. 인코딩(bgr8 · mono8 …)을 맞춰 준다toCvShare, toCvCopy, CvImage(...).toImageMsg()
image_transport영상 토픽의 발행 · 구독. 압축 토픽(/compressed)을 자동으로 함께 만든다create_subscription, create_publisher
camera ──/stereo/left/image_raw──► image_proc_node ──/stereo/left/image_proc──► Foxglove
                                    받는다 → cv::Mat → 처리 → 메시지 → 발행    (+ /stereo/left/image_proc/compressed 자동)

2. 원리

2-1. Image 메시지는 인코딩이 붙은 바이트 배열이다

std_msgs/Header header    # stamp = 촬영 시각, frame_id = stereo_left_optical_link
uint32 height             # 행 수
uint32 width              # 열 수
string encoding           # 픽셀 해석법: "bgr8", "rgb8", "mono8" ...
uint8  is_bigendian
uint32 step               # 한 행의 바이트 수 (640 × 3 = 1920)
uint8[] data              # step × height 바이트

같은 바이트를 rgb8 로 읽으면 빨강이, bgr8 로 읽으면 파랑이 된다. 이 카메라는 bgr8 로 보내고(C2 §2-3), OpenCV 의 기본 순서도 BGR 이다.

2-2. toCvShare 와 toCvCopy — 언제 복사가 일어나는가

toCvShare(msg, "bgr8")toCvCopy(msg, "bgr8")
돌려주는 것읽기 전용 CvImageConstPtr수정 가능한 CvImagePtr
인코딩이 같을 때메시지 버퍼를 그대로 가리킨다 — 복사 없음새 버퍼로 복사
인코딩이 다를 때변환하며 새 cv::Mat 을 만든다 — 사실상 복사변환 + 복사
쓰는 때읽고 계산만 할 때(이 노드, C6 · C8 의 검출기)그 위에 그릴 때(C6 의 그리기 노드)

640 × 480 컬러 한 장은 0.9 MB 다. 30 fps 면 초당 27 MB 를 복사하느냐 마느냐가 CPU 몇 % 의 차이다. 카메라 인코딩이 bgr8 이므로 toCvShare(msg, "bgr8") 은 복사가 없다.

2-3. 출력 메시지에 입력의 header 를 복사한다

stamp 는 촬영 시각이고 frame_id 는 좌표계 이름이다. 뒤의 노드는 "이 영상이 언제 어느 좌표계에서 찍혔는가"를 header 에서 읽는다. 처리 시각으로 바꾸면 로봇이 움직인 만큼 위치 계산이 어긋나고, frame_id 를 비우면 좌표 트리에 이어지지 않는다. 코드로는 한 줄이다.

2-4. 전송 품질 설정과 큐 깊이

  • 센서 데이터는 BEST_EFFORT(재전송 없음)로 받는다. 옛 프레임은 재전송받아도 쓸모가 없다. 발행 쪽이 RELIABLE 이든 BEST_EFFORT 든 BEST_EFFORT 구독자는 연결된다. 반대로 RELIABLE 로 구독하면 BEST_EFFORT 발행자와 연결되지 않고 오류 표시도 없다.
  • 큐 깊이는 처리 못 한 프레임을 몇 장 쌓아 둘 것인가다. 처리가 프레임 간격(33 ms)보다 빠른 이 노드는 5 여도 큐가 비어 있다. 처리가 수백 ms 인 검출기(C6)는 1 이어야 한다.

2-5. Release 빌드

OpenCV 라이브러리 자체는 최적화된 상태지만, 내가 쓴 코드(루프, cv::Mat 접근)는 Debug 빌드에서 최적화가 꺼져 몇 배 느리다. 영상 노드부터는 -DCMAKE_BUILD_TYPE=Release 를 항상 준다.

2-6. 이 노드가 쓰는 OpenCV 함수

함수하는 일비고
cv::resize크기 변경축소에는 INTER_AREA. 가로 · 세로 절반이면 픽셀 수 1/4, 시간도 약 1/4
cv::cvtColor색 공간 변환(BGR → 흑백 등)에지 · 윤곽선은 1 채널 흑백에서 한다
cv::GaussianBlur잡음 제거Canny 전에 하지 않으면 잡음이 전부 에지가 된다
cv::Canny에지 검출. 두 임계값높은 임계값을 넘는 강한 에지에 이어진 약한 에지만 남긴다
cv::findContours에지 영상 → 닫힌 윤곽선 목록RETR_EXTERNAL 은 바깥 윤곽만. 작은 조각은 면적으로 거른다
cv::drawContours · rectangle그리기원본 위에 그리므로 복사본(clone)에 그린다

인자와 다른 함수는 부록 B · OpenCV 사용법 에 C++ 과 Python 을 나란히 정리해 두었다.

3-4. 노드 소스 C++

rpi5_vision/src/image_proc_node.cpp. 처리 방식은 파라미터 mode 로 고르고, 콜백마다 파라미터를 읽어 ros2 param set 이 바로 반영되게 한다.

// image_proc_node -- /stereo/left/image_raw -> OpenCV -> /stereo/left/image_proc  (camera guide C4)
//
// mode: passthrough | gray | blur | edges | contours   (ros2 param set /image_proc_node mode edges)
#include <chrono>
#include <memory>
#include <string>
#include <vector>

#include "rclcpp/rclcpp.hpp"
#include "sensor_msgs/msg/image.hpp"
#include "cv_bridge/cv_bridge.h"                 // Humble uses .h (Jazzy and later: .hpp)
#include "image_transport/image_transport.hpp"
#include "opencv2/core.hpp"
#include "opencv2/imgproc.hpp"

class ImageProcNode : public rclcpp::Node
{
public:
  ImageProcNode()
  : Node("image_proc_node")
  {
    this->declare_parameter<std::string>("mode", "edges");
    this->declare_parameter<double>("scale", 0.5);          // 0.5 = half width and half height
    this->declare_parameter<int>("canny_low", 50);
    this->declare_parameter<int>("canny_high", 150);
    this->declare_parameter<double>("min_contour_area", 200.0);

    // Create the publisher before the subscription: the first callback may run right away.
    pub_ = image_transport::create_publisher(this, "/stereo/left/image_proc", rmw_qos_profile_sensor_data);

    // The free function takes a raw Node pointer, so it can be used inside the constructor
    // (image_transport::ImageTransport needs a shared_ptr, which does not exist yet here).
    sub_ = image_transport::create_subscription(
      this, "/stereo/left/image_raw",
      [this](const sensor_msgs::msg::Image::ConstSharedPtr & msg) { on_image(msg); },
      "raw", rmw_qos_profile_sensor_data);

    RCLCPP_INFO(this->get_logger(), "image_proc_node: /stereo/left/image_raw -> /stereo/left/image_proc");
  }

private:
  void on_image(const sensor_msgs::msg::Image::ConstSharedPtr & msg)
  {
    const auto t0 = std::chrono::steady_clock::now();

    // Read the parameters every frame (microseconds) so `ros2 param set` applies immediately.
    const std::string mode = this->get_parameter("mode").as_string();
    const double scale = this->get_parameter("scale").as_double();
    const int canny_low = this->get_parameter("canny_low").as_int();
    const int canny_high = this->get_parameter("canny_high").as_int();
    const double min_area = this->get_parameter("min_contour_area").as_double();

    cv_bridge::CvImageConstPtr cv_ptr;
    try {
      cv_ptr = cv_bridge::toCvShare(msg, "bgr8");   // camera sends bgr8 -> shared buffer, no copy
    } catch (const cv_bridge::Exception & e) {
      RCLCPP_ERROR_THROTTLE(this->get_logger(), *this->get_clock(), 2000,
                            "cv_bridge: %s (encoding=%s)", e.what(), msg->encoding.c_str());
      return;
    }

    const cv::Mat src = cv_ptr->image;     // header only; pixels are shared
    cv::Mat work;
    if (scale > 0.0 && scale != 1.0) {
      cv::resize(src, work, cv::Size(), scale, scale, cv::INTER_AREA);   // new buffer
    } else {
      work = src;                          // shared
    }

    // Output is always 3-channel bgr8 so Foxglove and later nodes see one encoding.
    cv::Mat out;
    if (mode == "passthrough") {
      out = work;
    } else if (mode == "gray") {
      cv::Mat gray;
      cv::cvtColor(work, gray, cv::COLOR_BGR2GRAY);
      cv::cvtColor(gray, out, cv::COLOR_GRAY2BGR);
    } else if (mode == "blur") {
      cv::GaussianBlur(work, out, cv::Size(9, 9), 0);
    } else if (mode == "edges") {
      cv::Mat gray, edges;
      cv::cvtColor(work, gray, cv::COLOR_BGR2GRAY);
      cv::GaussianBlur(gray, gray, cv::Size(5, 5), 0);     // in-place is allowed
      cv::Canny(gray, edges, canny_low, canny_high);
      cv::cvtColor(edges, out, cv::COLOR_GRAY2BGR);
    } else if (mode == "contours") {
      cv::Mat gray, edges;
      cv::cvtColor(work, gray, cv::COLOR_BGR2GRAY);
      cv::GaussianBlur(gray, gray, cv::Size(5, 5), 0);
      cv::Canny(gray, edges, canny_low, canny_high);
      std::vector<std::vector<cv::Point>> contours;
      cv::findContours(edges, contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);
      out = work.clone();                  // drawing modifies pixels: draw on a copy, not on the shared buffer
      for (const auto & c : contours) {
        if (cv::contourArea(c) < min_area) {
          continue;
        }
        cv::drawContours(out, std::vector<std::vector<cv::Point>>{c}, -1, cv::Scalar(0, 255, 0), 2);
        cv::rectangle(out, cv::boundingRect(c), cv::Scalar(0, 0, 255), 1);
      }
    } else {
      RCLCPP_WARN_THROTTLE(this->get_logger(), *this->get_clock(), 2000, "unknown mode '%s'", mode.c_str());
      out = work;
    }

    // Copy the input header: capture time and frame id must survive for TF lookups downstream.
    pub_.publish(cv_bridge::CvImage(msg->header, "bgr8", out).toImageMsg());

    const double ms =
      std::chrono::duration<double, std::milli>(std::chrono::steady_clock::now() - t0).count();
    RCLCPP_INFO_THROTTLE(this->get_logger(), *this->get_clock(), 2000,
      "mode=%s  %dx%d -> %dx%d  %.1f ms", mode.c_str(), src.cols, src.rows, out.cols, out.rows, ms);
  }

  // Subscriber and publisher must be members: a local variable would be destroyed at the end of the constructor.
  image_transport::Subscriber sub_;
  image_transport::Publisher pub_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<ImageProcNode>());
  rclcpp::shutdown();
  return 0;
}

3-7. 처리 시간을 적는다

로그의 ms 값을 읽어 표를 채운다. 참고 범위는 640 × 480 입력, Pi 5, Release 빌드 기준이다. 크게 벗어나면 빌드 종류와 입력 해상도부터 본다.

modescale 1.0 (ms)scale 0.5 (ms)참고 범위(scale 1.0)
passthrough________0.5 ~ 2 — 출력 메시지 복사 비용이 거의 전부
gray________1 ~ 3
blur (9 × 9)________3 ~ 8
edges________4 ~ 10
contours________6 ~ 15 — 장면에 따라 크게 변한다
top -p $(pgrep -f image_proc_node)      # 노드의 CPU %. 한 코어 = 100 %

scale 0.5 가 2 배가 아니라 약 4 배 빠른 이유: 가로 · 세로가 절반이면 픽셀 수가 1/4 이고, 처리 시간은 픽셀 수에 비례한다. C6 에서 검출 입력을 640 에서 320 으로 줄일 때 같은 계산이 적용된다.

🤔 이해 확인

이 쪽에서 설명한 내용만으로 답할 수 있다. 답을 펼치기 전에 먼저 말로 답해 본다.

1. toCvShare(msg, "bgr8") 은 언제 복사하고 언제 하지 않는가.

메시지의 인코딩이 요청한 bgr8 과 같을 때만 버퍼를 그대로 가리킨다(복사 없음, 읽기 전용). 다르면(mono8 · rgb8 을 요청) 변환하며 새 cv::Mat 을 만들므로 사실상 복사다. 이 카메라는 bgr8 로 보내므로 복사가 없다.

2. 출력 메시지에 입력의 header 를 복사하는 이유는 무엇인가.

stamp 는 촬영 시각, frame_id 는 좌표계 이름이다. 뒤의 노드와 좌표 변환은 이 둘로 "언제 어디서 찍혔는가"를 안다. 처리 시각으로 바꾸면 로봇이 움직인 만큼 위치가 어긋나고, frame_id 가 비면 좌표 트리에 이어지지 않는다.

3. 이 노드는 큐 깊이 5 로 구독해도 되는데 C6 의 검출기는 왜 1 이어야 하는가.

처리(몇 ms)가 프레임 간격(33 ms)보다 빠르면 큐가 늘 비어 있어 깊이가 의미 없다. 검출기는 처리(수백 ms)가 느려 큐가 항상 차고, 그러면 큐 길이만큼 옛 프레임을 처리하게 된다. 깊이 1 이면 밀린 프레임은 버려지고 최신 것만 처리한다.

4. cv::Mat out = work; 뒤에 out 위에 그리면 work 는 어떻게 되는가.

work 도 함께 바뀐다. 대입은 머리 정보만 복사하고 픽셀 버퍼는 공유하기 때문이다. 원본을 보존하려면 out = work.clone() 이 필요하고, contours 가 그렇게 되어 있다.
