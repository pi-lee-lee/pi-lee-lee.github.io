1. 개요 — 프레임이 없는 흐름에서 점 하나를 건져 낸다

l-02 까지의 통신은 한 번 묻고 한 번 받는 꼴이었다. 명령을 보내면 기기가 "이제 이만큼 보낸다"고 기술자로 예고하고, 그만큼 오면 끝이었다. SCAN 은 다르다. 기술자가 한 번 온 뒤로는 끝도 구분자도 없는 바이트가 계속 흐른다. 이 흐름 안에서 "여기부터 5바이트가 점 하나"라는 경계를 찾아내는 일이 이 쪽의 절반이고, 그 5바이트를 숫자로 바꾸는 일이 나머지 절반이다.

데이터시트는 이 라이다(Slamtec RPLIDAR A1M8)의 제조사 문서이고, 이 가이드는 rev.2.2 와 v3.0 두 판을 함께 읽는다. 데이터시트의 성능 표에 따르면 이 센서는 샘플 주기가 0.125 ms(공칭 샘플 주파수 ≥8000 Hz)이고 회전은 5.5 Hz(주기 약 182 ms) 근처다.1 다만 사양의 샘플 주파수가 곧 선 위의 점 수는 아니다. 선이 그만큼 나르지 못한다. 점 하나가 5바이트이고 이 회선의 상한이 11 520 B/s 이므로(l-01 §2-2) 이 명령에서 나올 수 있는 최대는 11 520 ÷ 5 다. 사양의 ≥8000 에 한참 못 미친다. 왜 그렇게 다른지는 l-05 가 도출한다. 그래도 바이트는 쉬지 않고 흐른다. 점 하나를 놓쳐도 다음 점이 오지만, 경계를 한 번 잃으면 그 뒤의 점이 전부 어긋난 채로 계속 그럴듯한 숫자로 나온다. 이 쪽이 검사 비트에 이만큼 지면을 쓰는 이유다.

2. 원리 — 왜 이 다섯 바이트를 점으로 간주할 수 있는가

2-1. 시작 바이트가 없는 흐름에서 경계를 찾는 법

본편 06a(MCU 아키텍처와 통신 프로토콜 쪽)의 계약 v2 는 펌웨어와 ROS 쪽이 함께 보는 MCU 통신 사양서다. 이 계약은 우리가 설계한 프레임이다. 그래서 머리 바이트를 붙이고 길이를 넣고 CRC 를 달았다. 형식을 우리가 정했으니 경계도 우리가 찾을 수 있다. 라이다는 반대다. 남이 정한 프레임을 우리가 찾아내야 한다. 그리고 이 센서의 점에는 머리 바이트가 없다. 있는 것은 덩어리 안에 섞여 있는 검사 비트 두 개뿐이다.

비트어디규칙왜 이것으로 경계를 찾을 수 있는가
Sb0 의 비트0새 바퀴의 첫 점에서만 1한 바퀴에 한 번만 1 이다 — 이것만으로는 경계를 못 찾는다
~Sb0 의 비트1언제나 S 의 반대임의의 자리에서 이 두 비트가 다를 확률은 1/2 이다
Cb1 의 비트0언제나 1여기까지 곱하면 1/4. 다섯 바이트씩 계속 맞아 들어가면 확률이 빠르게 0 으로 간다

따라서 한 자리를 보고 "여기가 점의 시작이다"라고 단정할 수는 없다. 1/4 은 꽤 큰 확률이다. 할 수 있는 것은 "여기가 시작이라면 다음 5바이트도, 그 다음 5바이트도 규칙을 지켜야 한다"를 따라가 확인하는 것이고, 어긋나는 순간 시작 자리를 한 칸 옮겨 다시 보는 것이다(§2-4). 경계를 한 번 맞히면 어긋나기 전까지는 그 뒤로도 계속 맞는다.

왜 이 두 비트가 "기기의 응답으로 하는" 자기검증인가

l-02 의 A5 5A 와 같은 종류의 장치다. 내가 이해한 대로 읽었더니 규칙이 정한 값이 그 자리에 있었다. 이 일치가 내 이해가 맞았다는 증거다. 반대로 S 와 ~S 가 같거나 C 가 0 이면, 틀린 것은 센서가 아니라 내가 고른 시작 자리다. 이 쪽에서 학습자가 세는 "걸러진 자리의 수"는 내 도구가 실제로 경계를 얼마나 자주 잃는지를 나타내는 양이다.

등급 — 이 5바이트 배치의 출처

데이터시트는 이 배치를 싣지 않았다. 두 판 모두 한 자리에서 "If you need detailed data format and communication protocol, please contact SLAMTEC." 라 적는다.2 다른 자리에서도 다시 "Please contact SLAMTEC if you want detailed communication protocol" 이라 적는다.3 목차에도 프로토콜 장이 없다. 그래서 "데이터시트에 따르면 b0 의 비트0 이 S 다"라고 쓸 수 없다. 이 쪽이 쓰는 출처는 셋이다:

  • ① Slamtec SDK 의 sl_lidar_cmd.h — 집필자가 웹에서 열어 확인했다.4 구조체 _sl_lidar_response_measurement_node_t 의 필드 주석은 syncbit:1;syncbit_inverse:1;quality:6; 와 check_bit:1;angle_q6:15; 이다. 매크로는 SL_LIDAR_RESP_MEASUREMENT_SYNCBIT (0x1<<0) · ..._QUALITY_SHIFT 2 · ..._CHECKBIT (0x1<<0) · ..._ANGLE_SHIFT 1 이다. 등급 확정. 다만 집필자가 파일을 내려받아 바이트를 본 것이 아니라 웹으로 읽어 옮긴 것이다. 그래서 원문을 git clone 해 대조하는 것은 §3-1-1 의 확인 과제로 남긴다.
  • ② 같은 모델을 쓴 1세대 기록 — 1세대는 이 프로젝트 이전에 같은 부품 일부로 만든 첫 로봇이고, 같은 모델의 라이다를 썼다. 등급은 NOMINAL(gen1-record) 이다. 출처는 있지만 이 프로젝트에서 잰 값은 아닌 임시값이라는 뜻이다(l-00 의 "값의 세 상태"). 1세대의 두 도구가 ① 과 같은 배치를 쓰고 실제로 점을 받았다.5 ⚠ 1세대 코드의 주석은 이 배치의 출처를 "datasheet" 라고 적었지만 위에서 보았듯 데이터시트에는 없다. 남의 주석이 붙인 출처를 그대로 옮기지 않는 것이 이 가이드의 규칙이다.
  • ③ 내 기기 — 위 둘이 다 틀렸더라도, 내 센서가 낸 바이트에서 S ≠ ~S 와 C == 1 이 5바이트 간격으로 계속 성립하면 그 일치가 이 배치가 내 기기에서 참이라는 증거다. ①② 는 가설이고 ③ 이 판정이다.

2-2. 고정소수점 — 정수만으로 소수를 나르는 법과, 그 식이 나오는 자리

각도는 90.5° 처럼 소수가 필요하고 거리도 1000.25 mm 처럼 소수가 필요하다. 그런데 이 5바이트 안에는 소수점이 들어갈 자리가 없다. 있는 것은 정수 비트뿐이다. 해법은 단순하다. 보낼 때 정수배로 곱하고 받을 때 나눈다. 곱하는 수를 2의 거듭제곱으로 정하면 곱셈·나눗셈이 시프트 한 번이라 연산 비용이 작다. q6 은 64배(2의 6제곱), q2 는 4배(2의 2제곱)라는 뜻이다.

이제 왜 시프트가 저렇게 생겼는지를 도출한다. SDK 헤더의 구조체는 이렇게 생겼다(§2-1 ①):

typedef struct _sl_lidar_response_measurement_node_t {
    sl_u8    sync_quality;       // syncbit:1;syncbit_inverse:1;quality:6;
    sl_u16   angle_q6_checkbit;  // check_bit:1;angle_q6:15;
    sl_u16   distance_q2;
} __attribute__((packed)) sl_lidar_response_measurement_node_t;

여기서 셋을 읽어 낸다.

  1. 두 개의 16비트 필드는 리틀엔디안이다. 이 센서는 낮은 바이트를 먼저 보낸다. 그러니 angle_q6_checkbit = b1 | (b2 << 8) 이고 distance_q2 = b3 | (b4 << 8) 이다. 이 한 줄이 틀리면 값이 그럴듯하게 틀린다. 오류는 나지 않는다(§2-5).
  2. 16비트 안에서 검사 비트가 맨 아래 한 칸을 차지한다. check_bit:1 이 먼저 선언되었으니 check_bit 가 비트0 이고, angle_q6 는 그 위 15비트다. 그래서 angle_q6 = (b1 | (b2 << 8)) >> 1 이다 — 헤더의 ..._ANGLE_SHIFT 가 1 인 것이 이 1칸이다.
  3. q6 배율을 되돌린다. 각도(도) = angle_q6 / 64.0. 마찬가지로 거리(mm) = distance_q2 / 4.0.

정리하면 식은 이 둘이다. 외우지 말고 위 세 걸음에서 다시 도출할 수 있으면 된다. 다음 센서의 헤더는 다르게 생겼을 것이다.

angle_deg = ((b2 << 8 | b1) >> 1) / 64.0        (= ((b1 >> 1) | (b2 << 7)) / 64.0 — 같은 식이다)
dist_mm   =  (b4 << 8 | b3)        / 4.0
quality   =   b0 >> 2                            (위 6비트. 마스크가 아니라 시프트다)

필드 폭에서 나오는 한계값도 같이 적어 둔다. 산술이므로 식을 같이 남긴다.

2-3. 거리 0 은 "아무것도 없다"가 아니라 "못 쟀다"

점을 풀다 보면 거리가 정확히 0 인 점이 섞여 나온다. 거리 0 을 어떻게 읽느냐에 따라 뒤의 다섯 쪽의 결과가 달라진다.

먼저 사실부터. 데이터시트의 점 형식 그림이 Distance 에 대해 적은 것은 설명과 단위 둘뿐이다.7 설명은 "Current measured distance value between the rotating core of the RPLIDAR A1 and the sampling point" 이다. 단위는 mm 다. 0 이 무엇을 뜻하는지는 적지 않았다.

0 을 "잴 수 없었음"으로 읽는 근거는 둘이다.

  • ① 물리 — 측정 기준점이 rotating core 이므로 0 mm 는 회전축 한가운데를 뜻한다. 그런데 사양의 최소 거리가 0.15 m 다. 따라서 0 은 물체의 위치일 수 없다.
  • ② 같은 모델의 기록 — NOMINAL(gen1-record). 1세대 도구의 주석이 dist_mm = ... (0 = invalid / no return) 이라 적었다.8

내 기기에서 확인하는 법은 §3-2-4 에 있다. 아무것도 없는 방향(허공·천장 쪽)에서 0 이 나오고, 손을 대면 그 방향만 0 이 아닌 값으로 바뀌는지 본다.

왜 이 한 줄이 중요한가

"없다"와 "못 쟀다"는 로봇에게 정반대의 뜻이다. 앞은 "지나가도 된다", 뒤는 "그 방향의 상태를 알 수 없다"다. 0 을 "거리 0 m 에 물체"로 읽으면 로봇 바로 앞에 없는 벽이 생긴다. 0 을 버리면서 "그 방향은 비었다"로 읽으면 로봇이 유리문을 향해 그대로 주행한다. l-09 의 격자가 칸을 점유 · 자유 · 미지 셋으로 나누는 이유가 여기에 있다. 이 가이드의 기록 형식이 무반사를 0 도 inf 도 아닌 null 로 적는 이유도 같다(l-04 가 그 결정을 다룬다). 이 쪽에서는 0 을 버리지 않는다. parse_point 는 거리 0 인 점도 정상으로 돌려준다. 버릴지 말지는 점을 쓰는 쪽이 정한다.

2-4. 재동기 방식이 수율을 바꾼다 — 같은 센서, 다른 점 수

검사가 틀렸을 때 어디서부터 다시 볼 것인가. 답이 하나가 아니고, 고른 답이 내가 받는 점의 수를 바꾼다. 두 방식이 있다.

(가) 5바이트를 읽고 실패하면 1바이트를 더 읽어 버린다(나) 버퍼를 이어 붙이고 그 안에서 1칸씩 민다
생김새read_exact(fd, b, 5, …) → 검사 실패 → read_exact(fd, b, 1, …) → 다시 5바이트read_some() 이 돌려준 만큼 ns.feed(buf, n, out) 로 넣는다 → feed() 가 i 를 1씩 밀며 buf_.data() + i 의 5바이트를 본다
실패 한 번의 대가이미 읽은 5바이트가 통째로 사라진다. 그 안에 있던 진짜 경계도 같이 사라진다버린 것은 1바이트뿐. 나머지 4바이트는 다음 자리에서 다시 검사된다
코드의 길이짧다길다(버퍼를 직접 관리해야 한다 — 다 못 쓴 꼬리를 다음 feed() 까지 남겨 둔다)
같은 시간에 얻는 점____ (내 값 — §3-3-4)____ (내 값 — §3-3-4)

같은 모델을 쓴 1세대의 기록은 (가)에 대해 아래와 같이 적었다(등급 NOMINAL(gen1-record)).9 "A stream buffer is used rather than 1-byte resync: resyncing byte-by-byte discards valid points and silently halves the yield." 1세대 저장소에는 두 방식이 모두 남아 있다 — 한 도구는 (가), 다른 도구는 (나)다.10

C++ 에서 (가) 를 쓰려면 read_exact()(l-02 §2-2)가 필요하다. read() 는 요청한 바이트 수가 아니라 그때 와 있는 만큼 돌려주기 때문이다. (나) 는 그 성질을 그대로 받는다 — 얼마가 오든 버퍼 뒤에 붙이고, 5바이트가 다 모인 자리까지만 본다.

⚠ "절반"은 내 기기의 값이 아니다. 같은 모델(A1M8)에서 그런 결과가 나왔다는 기록이고, 그 개체가 내 개체인지는 아직 확인되지 않았다. 게다가 이 값은 센서가 아니라 내 코드와 내 Pi 의 읽기 타이밍에 달려 있다. 몇 배가 되는지는 §3-3-4 에서 내가 잰다. 1배에 가깝게 나와도 그 값이 내 관찰이다. 왜 그럴 수 있는지는 §3-3-4 에 한 줄 적어 두었다.

⚠ 이 절의 낱말 중 "silently" 를 흘려 읽지 말 것. (가)는 오류를 내지 않는다. 점이 나오고 각도도 거리도 정상이다. 점이 적게 나올 뿐이다. 라이다에서 이 꼴의 고장이 가장 대가가 크다.

2-5. 검사 비트가 통과해도 산술은 틀릴 수 있다

§2-1 의 두 비트는 경계만 채점한다. 경계를 맞게 찾고도 그 5바이트를 잘못 읽는 경우가 여럿 있고, 검사 비트는 그 중 어느 것도 검출하지 못한다.

가장 잘 드러나는 예를 하나 든다. 아래는 5바이트 BD 01 2D A0 0F 을 §2-2 대로 푼 것이다.

  b0 = BD = 1011 1101    비트0 = S  = 1     새 바퀴의 첫 점이다
                         비트1 = ~S = 0     S 와 다르다 ─► 통과
                         비트2~7   = quality = 101111 = 47
  b1 = 01 = 0000 0001    비트0 = C  = 1     ─► 통과
  b2 = 2D                angle_q6 = (2D << 8 | 01) >> 1 = 0x2D01 >> 1 = 5760

이제 b1 과 b2 를, b3 과 b4 를 맞바꿔 읽어 본다. 리틀엔디안을 빅엔디안으로 잘못 읽는 아주 흔한 실수다. 바이트 자체는 그대로이므로 S · ~S · C 는 여전히 통과한다. 그런데 값은 90.0° · 1000.0 mm 에서 2.34375° · 10243.75 mm 로 바뀐다. 각도는 88도 옮겨 갔고 거리는 10배가 됐는데 아무 오류도 나지 않는다.

그래서 이 쪽은 시험 벡터로 산술을 채점한다

"점이 나온다"는 것은 경계를 찾았다는 증거일 뿐이고 값이 맞다는 증거가 아니다. §3-1-3 의 열 개 벡터는 각 벡터가 어떤 잘못을 검출하는지 집필자가 실제로 잘못된 구현을 만들어 실행해 보고 적은 것이다(§3-1-3 의 표). 벡터를 통과해야 §3-1-4 로 간다.

그리고 시험 벡터도 완전하지 않다. 벡터가 검출하지 못하는 것이 하나 남는다. 각도가 시계 방향으로 커지는지 반시계 방향으로 커지는지는 5바이트 안에 없다. 각도의 방향은 실물에서만 확인할 수 있다. 이 쪽의 실습 B 가 그 첫 관찰이고, l-08 이 정면으로 다룬다.

// PURE: no port, no time. tests/test_point.cpp includes only this file, so it runs with
// the lidar unplugged (and on the Mac with clang++).
//
// Byte layout -- Slamtec SDK sl_lidar_cmd.h, struct _sl_lidar_response_measurement_node_t:
//   u8  sync_quality       // syncbit:1; syncbit_inverse:1; quality:6;
//   u16 angle_q6_checkbit  // check_bit:1; angle_q6:15;        (little endian)
//   u16 distance_q2                                            (little endian)
#pragma once

#include <cstddef>
#include <cstdint>
#include <functional>
#include <optional>
#include <vector>

namespace lidar_lab {

using u8 = std::uint8_t;

inline constexpr u8 SYNC_MASK = 0x01;    // b0 bit0 = S                  (SL_LIDAR_RESP_MEASUREMENT_SYNCBIT)
inline constexpr int QUALITY_SHIFT = 2;  // b0 >> 2 = quality, 6 bits    (..._QUALITY_SHIFT)
inline constexpr u8 CHECK_MASK = 0x01;   // b1 bit0 = C, always 1        (..._CHECKBIT)
inline constexpr int ANGLE_SHIFT = 1;    // angle_q6 = u16(b1, b2) >> 1  (..._ANGLE_SHIFT)
inline constexpr std::size_t kNodeLen = 5;

// Bytes to advance when the framing check fails (1 .. 5): NodeStream's default.
// 3-3 compares 1 and 5 with lab_point --resync --step <n>, without editing this line.
inline constexpr std::size_t kResyncStep = 1;

// One decoded node, as parse_point() returns it.
//   deg      0.0 .. 511.984375  (the field is 15 bits; a healthy sensor stays under 360)
//   mm       0.0 .. 16383.75    (0.0 means COULD NOT MEASURE, not "nothing is there")
//   quality  0 .. 63            (raw level; the datasheet does not define the unit)
struct Sample {
  double deg;
  double mm;
  int quality;
};

// Invariants -- this is the entire framing check, there is no start byte:
//   - n must be 5. A short buffer is not an error, it means "not yet". Check n FIRST:
//     reading b[4] of a 4-byte buffer is a read past the end.

// A node that passed the framing check. start is the SAME S bit parse_point() checks
// for framing, read a second time for a different purpose: true on the first point of
// a new revolution (l-04 cuts revolutions on it).
struct Node {
  double deg;
  double mm;
  int quality;
  bool start;
};

// Bytes in, nodes out. Keeps the bytes that do not yet make a whole node for the next
// feed(), so the result does not depend on how the bytes were chunked.
class NodeStream {
 public:
  // resync_step: bytes to advance when the check fails at a position. Clamped to 1..5.
  explicit NodeStream(std::size_t resync_step = kResyncStep)
      : step_(resync_step < 1 ? 1 : (resync_step > kNodeLen ? kNodeLen : resync_step)) {}

  // Append n bytes, then call out() once for every node that passes the framing check,
  // in stream order. Counts: accepted() = nodes handed out, rejected() = positions where
  // the check failed.
  void feed(const u8* p, std::size_t n, const std::function<void(const Node&)>& out) {

    //   Delete the placeholder lines below when you start.

  std::size_t rejected() const { return rejected_; }
  std::size_t resync_step() const { return step_; }  // after clamping; also keeps the

 private:
  std::size_t step_;
  std::vector<u8> buf_;

  std::size_t rejected_ = 0;
};

// scripts/lidar_lab/include/lidar_lab/point_port.hpp -- read the port into a NodeStream.
// (l-03, given in full)
// NOT pure: reads the tty. The pure half is point.hpp.
#pragma once

#include <chrono>
#include <cstddef>
#include <functional>

#include "lidar_lab/point.hpp"
#include "lidar_lab/serial.hpp"

namespace lidar_lab {

inline constexpr std::size_t kChunk = 2048;  // bytes per read

// Read for `seconds`, feeding every chunk to ns and every node to on_node.
// Stops when the time is up, on a stop signal, or when on_node returns false.
// After false, the REST OF THAT CHUNK still goes through ns (accepted() counts it) but
// is not handed to on_node -- ns is left at a chunk boundary, not at a node boundary.
// ns comes from the caller, so ns.accepted() / ns.rejected() are readable afterwards.
inline void stream(int fd, double seconds, NodeStream& ns,
                   const std::function<bool(const Node&)>& on_node) {
  using clock = std::chrono::steady_clock;
  if (!(seconds > 0.0)) return;
  const auto deadline =
      clock::now() + std::chrono::duration_cast<clock::duration>(std::chrono::duration<double>(seconds));
  u8 buf[kChunk];
  bool go = true;
  while (go && !stop_requested()) {
    auto left = std::chrono::duration_cast<std::chrono::milliseconds>(deadline - clock::now());
    if (left.count() <= 0) break;
    const int wait = left.count() < kReadTimeoutMs ? static_cast<int>(left.count()) : kReadTimeoutMs;
    const std::size_t n = read_some(fd, buf, sizeof buf, wait);
    if (n == 0) continue;
    ns.feed(buf, n, [&](const Node& node) {
      if (go && !on_node(node)) go = false;
    });
  }
}

}  // namespace lidar_lab

stream() 은 세 경우에 돌아온다. seconds 가 지났을 때 · 정지 신호(Ctrl-C)를 받았을 때 · on_node 가 false 를 돌려줬을 때다. false 를 받은 뒤에도 그 덩이의 남은 바이트는 feed() 를 지나 accepted() 에 세어진다. on_node 에는 넘기지 않는다. 그래서 §3-1-4 의 accepted 는 찍힌 점의 수보다 클 수 있다. NodeStream 은 부르는 쪽이 만들어 넘기므로, stream() 이 돌아온 뒤 ns.accepted() · ns.rejected() 를 읽을 수 있다.

/* 완결 코드 T1 - scripts/lidar_lab/include/lidar_lab/point.hpp (parse_point) */
inline std::optional<Sample> parse_point(const u8* b, std::size_t n) {
  if (n != kNodeLen) return std::nullopt;           // short buffer: "not yet", not an error
  if ((b[0] & SYNC_MASK) == ((b[0] >> 1) & SYNC_MASK)) return std::nullopt;  // S == ~S
  if (!(b[1] & CHECK_MASK)) return std::nullopt;    // C must be 1
  const int quality = b[0] >> QUALITY_SHIFT;        // top 6 bits
  const unsigned angle_q6 = ((static_cast<unsigned>(b[2]) << 8) | b[1]) >> ANGLE_SHIFT;
  const unsigned dist_q2 = (static_cast<unsigned>(b[4]) << 8) | b[3];
  return Sample{angle_q6 / 64.0, dist_q2 / 4.0, quality};
}

코드 설명

  • if (n != kNodeLen) return std::nullopt; — 길이를 가장 먼저 본다. 짧은 버퍼는 오류가 아니라 "아직"이다. 이 검사보다 앞에서 b[4] 를 읽으면 4바이트 버퍼의 끝 너머를 읽는다(흔한 실수 첫 행).
  • if ((b[0] & SYNC_MASK) == ((b[0] >> 1) & SYNC_MASK)) return std::nullopt; — S(비트0)와 ~S(비트1)가 같으면 경계가 아니다. b[0] >> 1 이 비트1 을 비트0 자리로 내리므로 같은 마스크로 견줄 수 있다.
  • if (!(b[1] & CHECK_MASK)) return std::nullopt; — C 가 0 이면 경계가 아니다.
  • const int quality = b[0] >> QUALITY_SHIFT; — 위 6비트다. 마스크가 아니라 시프트로, 아래 두 비트(S · ~S)를 밀어낸다.

  • const unsigned angle_q6 = … >> ANGLE_SHIFT; — 리틀엔디안이다. b[1] 이 낮은 8비트, b[2] 가 높은 8비트다. 16비트를 만든 뒤 검사 비트 한 칸을 버린다(§2-2 둘째 걸음).

    static_cast<unsigned> 는 계산하는 타입을 밝힌다.

  • const unsigned dist_q2 = (static_cast<unsigned>(b[4]) << 8) | b[3]; — 거리 칸에는 검사 비트가 없다.
  • return Sample{angle_q6 / 64.0, dist_q2 / 4.0, quality}; — 64.0 의 .0 때문에 나눗셈이 double 로 된다. / 64 로 쓰면 정수 나눗셈이라 소수부가 잘린다(흔한 실수). 반환형이 std::optional<Sample> 이므로 값이 든 optional 이 된다.
  • 골격의 자리표시 세 줄((void)b; · (void)n; · return std::nullopt;)은 지웠다.

  • 다르게 써도 되는 곳 — 넷이다.13

    ① 캐스트를 빼고 (b[2] << 8) | b[1] 로 써도 시험을 통과한다. 이때 계산은 int 로 된다. 이 가이드는 계산하는 타입을 밝혀 쓴다.

    ② std::memcpy(&a16, b + 1, 2); 로 두 바이트를 복사해도 통과한다. 다만 기계가 리틀엔디안일 때만 같은 값을 낸다(Pi 와 Mac 은 둘 다 리틀엔디안이다). 시프트 조립은 기계의 바이트 순서와 상관없다.

    ③ 길이 검사를 if (n < kNodeLen) 로 써도 통과한다. feed() 는 늘 5를 넘긴다. 이 가이드는 "정확히 5"로 쓴다.

    ④ 반환의 꼴. 여기는 std::nullopt 하나로 "경계가 아니다"를 나타낸다. 예외를 던지거나 bool 과 출력 인자로 돌려주는 설계도 있다. std::optional 은 예외가 아니라 값이라, feed() 가 초당 수천 번 불러도 비용이 작다.

// scripts/lidar_lab/tests/test_stream.cpp -- grading vectors for NodeStream::feed().
// Includes only point.hpp (pure) and check.hpp: runs with the lidar unplugged.
// feed() calls parse_point(): fill T1 first, or every case here fails with it.
//   pi$ scripts/lidar_lab/build/test_stream && scripts/lidar_lab/build/test_stream_ub
//
// Five nodes, made with the encoder at the top of tests/test_point.cpp (q 47, mm = 1000 + k):
//   A  BD 01 2D A0 0F   90.0 deg  S = 1        D  BE 81 2E AC 0F   93.0 deg  S = 0
//   B  BE 81 2D A4 0F   91.0 deg  S = 0        E  BD 01 2F B0 0F   94.0 deg  S = 1
//   C  BE 01 2E A8 0F   92.0 deg  S = 0
// In A B C D E, two windows that do not start on a node also pass the check: the ones that
// start on the 2nd byte of A and of B (01 2D ... and 81 2D ...). A right feed() never looks
// there; a feed() that steps wrongly can. 77 is a stray byte: S = ~S = 1, never a boundary.
#include <cstddef>
#include <initializer_list>
#include <string>
#include <vector>

#include "lidar_lab/point.hpp"
#include "check.hpp"

using namespace lidar_lab;

namespace {

const char* const A = "BD 01 2D A0 0F";
const char* const B = "BE 81 2D A4 0F";
const char* const C = "BE 01 2E A8 0F";
const char* const D = "BE 81 2E AC 0F";
const char* const E = "BD 01 2F B0 0F";

struct Run {
  std::vector<Node> nodes;
  std::size_t accepted = 0;
  std::size_t rejected = 0;
};

// Feed `hex` to a NodeStream(step) in pieces of the given sizes (the last piece takes the
// rest). Each piece is its own exactly-sized vector, so a read past it is a read past the
// allocation and the _ub build reports it.
Run feed_in(const std::string& hex, const std::vector<std::size_t>& pieces, std::size_t step) {
  const std::vector<u8> all = from_hex(hex);
  NodeStream ns(step);
  Run r;
  std::size_t at = 0;
  for (std::size_t k = 0; at < all.size(); ++k) {
    std::size_t n = k < pieces.size() ? pieces[k] : all.size() - at;
    if (n > all.size() - at) n = all.size() - at;
    const std::vector<u8> piece(all.begin() + static_cast<std::ptrdiff_t>(at),
                                all.begin() + static_cast<std::ptrdiff_t>(at + n));
    ns.feed(piece.data(), piece.size(), [&](const Node& x) { r.nodes.push_back(x); });
    at += n;
  }
  r.accepted = ns.accepted();
  r.rejected = ns.rejected();
  return r;
}

std::vector<std::size_t> ones(std::size_t n) { return std::vector<std::size_t>(n, 1); }

// "4 nodes [90.0, 91.0, 92.0, 93.0], accepted 4, rejected 0" (at most 6 angles, then "...")
std::string show(const Run& r) {
  std::string deg = "[";
  for (std::size_t i = 0; i < r.nodes.size() && i < 6; ++i)
    deg += (i ? ", " : "") + str(r.nodes[i].deg);
  deg += r.nodes.size() > 6 ? ", ...]" : "]";
  return str(r.nodes.size()) + " nodes " + deg + ", accepted " + str(r.accepted) +
         ", rejected " + str(r.rejected);
}

std::string show_node(const Run& r) {
  if (r.nodes.empty()) return "none";
  const Node& n = r.nodes[0];
  return "(" + str(n.deg) + ", " + str(n.mm) + ", " + str(n.quality) + ", " + str(n.start) + ")";
}

// The positions (0 = first node out) of the nodes whose start is true.
std::string starts(const Run& r) {
  std::vector<std::size_t> at;
  for (std::size_t i = 0; i < r.nodes.size(); ++i)
    if (r.nodes[i].start) at.push_back(i);
  return str(r.nodes.size()) + " nodes, start at " + str(at);
}

std::string cat(std::initializer_list<const char*> parts) {

/* 완결 코드 T2 - scripts/lidar_lab/include/lidar_lab/point.hpp (NodeStream::feed) */
void feed(const u8* p, std::size_t n, const std::function<void(const Node&)>& out) {
  buf_.insert(buf_.end(), p, p + n);
  std::size_t i = 0;
  while (i + kNodeLen <= buf_.size()) {
    auto s = parse_point(buf_.data() + i, kNodeLen);
    if (s) {
      out(Node{s->deg, s->mm, s->quality, (buf_[i] & SYNC_MASK) != 0});
      ++accepted_;
      i += kNodeLen;
    } else {
      ++rejected_;
      i += step_;
    }
  }
  buf_.erase(buf_.begin(), buf_.begin() + static_cast<std::ptrdiff_t>(i));
}

코드 설명

  • buf_.insert(buf_.end(), p, p + n); — 받은 바이트를 버퍼 끝에 붙인다. p + n 은 마지막 바이트 다음 주소다.
  • while (i + kNodeLen <= buf_.size()) — 5바이트가 다 들어 있는 자리까지만 본다. i < buf_.size() 로 쓰면 마지막 네 자리에서 버퍼 끝 너머를 읽는다(흔한 실수 마지막 행).
  • auto s = parse_point(buf_.data() + i, kNodeLen); — i 번째 칸의 주소와 길이 5를 넘긴다. auto 는 오른쪽의 타입(std::optional<Sample>)을 그대로 받는다.

  • out(Node{s->deg, s->mm, s->quality, (buf_[i] & SYNC_MASK) != 0}); — 넷째 칸 start 는 같은 b0 의 S 비트다. != 0 이 그 비트를 bool 로 바꾼다.

    l-04 는 grep -n 'SYNC_MASK' 로 이 줄이 있는지 본다.

  • ++accepted_; i += kNodeLen; — 점 하나를 썼으니 다섯 칸 나아간다.
  • ++rejected_; i += step_; — 경계가 아니면 step_ 칸 나아간다. 숫자를 박지 않는다 — 실습 C 가 --step 으로 이 값을 바꾼다. test_stream 의 8번이 이것을 본다.

  • buf_.erase(buf_.begin(), buf_.begin() + static_cast<std::ptrdiff_t>(i)); — 본 자리까지 지운다. 남는 것은 최대 4바이트, 아직 다 오지 않은 점의 앞부분이다. 다음 feed() 가 그 뒤에 붙인다.

    반복자에 더하는 수는 부호 있는 거리라 std::ptrdiff_t 로 밝혀 바꾼다.

  • 골격의 자리표시 세 줄((void)p; · (void)n; · (void)out;)은 지웠다.

  • 다르게 써도 되는 곳 — 점을 찾을 때마다 그 다섯 바이트를 바로 지우는 꼴도 같은 점을 낸다. 다만 지울 때마다 뒤의 바이트를 당기므로 버퍼가 클수록 느리다. 버퍼 대신 고정 크기 배열과 읽기 위치 둘을 쓰는 꼴(링 버퍼)도 있다.

쓰는 API — std::vector 의 insert(위치, 처음, 끝) · erase(처음, 끝) · data() · size(). out(x) 는 std::function 에 든 것을 부른다. s->deg 는 optional 안의 칸을 꺼낸다.

      if (std::strcmp(a, "--count") == 0) {
        if (!to_long(v, 1, 100000, count)) return usage();
      } else if (std::strcmp(a, "--step") == 0) {
        if (!to_long(v, 1, 5, step)) return usage();
        resync_opt = true;
      } else if (std::strcmp(a, "--skip") == 0) {
        if (!to_long(v, 0, 16, skip)) return usage();
        resync_opt = true;
      } else if (std::strcmp(a, "--seconds") == 0) {
        char* end = nullptr;
        seconds = std::strtod(v, &end);
        if (end == v || *end != '\0' || !(seconds >= 0.1 && seconds <= 60.0)) return usage();
        resync_opt = true;
      } else {
        return usage();
      }
    } else {
      dev = a;
    }
  }
  if (resync_opt && !resync) return usage();  // those three belong to --resync
  install_stop_handler();
  const int fd = open_port(dev);
  if (fd < 0) return 1;
  motor(fd, true);
  for (int i = 0; i < 40 && !stop_requested(); ++i)  // spin-up 2 s as in l-01, Ctrl-C seen in 50 ms
    std::this_thread::sleep_for(std::chrono::milliseconds(50));
  const bool described = start_scan(fd);
  int rc = 0;
  if (resync) {
    if (described) {
      resync_run(fd, static_cast<std::size_t>(step), static_cast<std::size_t>(skip), seconds);
    } else {  // 3-3 needs a known start: without the descriptor the misalignment is unknown
      std::printf("no descriptor -- not running 3-3\n");
      rc = 1;
    }
  } else {
    if (!described) std::printf("no descriptor -- reading points anyway (2-1)\n");
    first_points(fd, static_cast<int>(count));  // the framing check finds boundaries anyway
  }
  stop(fd);          // stop scanning (laser state: l-02 2-3)
  motor(fd, false);  // motor off (L2)
  ::close(fd);
  return rc;
}

가짜 기기의 점 k 는 각도 90 + k × 58/64°, 거리 1000 + k mm, 품질 47 이고, 점 0 만 S = 1 이다. 그래서 점 0 의 바이트는 손 계산에 쓴 BD 01 2D A0 0F 와 같다. 10 ms 마다 23 점(115 B)을 보낸다. 9 ~ 12 의 수는 이 바이트에서 정해지므로 실행마다 같다.

// first_points() and resync_run() (point_run.hpp). A fake device on a socket pair stands in
// for the tty: no lidar, no port, no motor.
//   pi$ scripts/lidar_lab/build/test_point_run && scripts/lidar_lab/build/test_point_run_ub
//
// How a vector works
//   - a child process (fork) plays the device. Node k of its flow: q 47, deg 90 + k * 58/64,
//     mm 1000 + k, S = 1 on node 0 only (the encoder of tests/test_point.cpp), so node 0 is
//     BD 01 2D A0 0F. It writes 23 nodes (115 B) every 10 ms, about the real line rate.
//       raw     the flow from the start, `nodes` nodes, then silence. It ignores what we send.
//       busy    a scan already running: the flow until it reads STOP (A5 25), silence 5 ms
//               later; on SCAN (A5 20) the descriptor A5 5A 05 00 00 40 81, then the flow.

void alarm_after(double s) {  // 0 = cancel
  itimerval t{};
  t.it_value.tv_sec = static_cast<long>(s);
  t.it_value.tv_usec = static_cast<long>((s - static_cast<long>(s)) * 1e6);

enum class Mode { raw, busy, silent };

void node_bytes(long k, u8* b) {
  const unsigned u = (static_cast<unsigned>(k * 58 + 90 * 64) << 1) | 1u;  // deg * 64 = 5760 + 58 k
  const unsigned d = static_cast<unsigned>((1000 + k) * 4);
  b[0] = static_cast<u8>((47 << 2) | (k == 0 ? 1 : 2));
  b[1] = static_cast<u8>(u & 0xFF);
  b[2] = static_cast<u8>(u >> 8);
  b[3] = static_cast<u8>(d & 0xFF);
  b[4] = static_cast<u8>(d >> 8);
}

// Blocks (polls) while the socket is full; false once the other side has closed.
bool write_all(int fd, const u8* b, std::size_t n) {
  while (n > 0) {
    ssize_t w = ::write(fd, b, n);
    if (w < 0) {
      if (errno != EAGAIN && errno != EWOULDBLOCK && errno != EINTR) return false;
      pollfd p{};
      p.fd = fd;
      p.events = POLLOUT;
      if (::poll(&p, 1, 100) < 0) return false;
      continue;
    }
    b += w;
    n -= static_cast<std::size_t>(w);
  }
  return true;
}

pid_t spawn_device(int sfd, int report, int ours, int ours_report, Mode mode, long nodes) {
  pid_t pid = fork();
  if (pid != 0) return pid;
  close(ours);
  close(ours_report);
  signal(SIGPIPE, SIG_IGN);
  fcntl(sfd, F_SETFL, fcntl(sfd, F_GETFL) | O_NONBLOCK);
  u8 got[64];
  std::size_t n = 0;
  std::size_t seen = 0;  // bytes of got[] already looked at for a command
  bool flowing = mode != Mode::silent;
  long k = 0;            // next node of the flow
  long limit = mode == Mode::raw ? nodes : -1;
  clock_type::time_point quiet_at{};
  bool quiet_due = false;
  bool open = true;
  const auto t0 = clock_type::now();
  while (open && since(t0) < 8.0) {
    pollfd p{};
    p.fd = sfd;
    p.events = POLLIN;
    if (::poll(&p, 1, 10) > 0) {
      ssize_t r = ::read(sfd, got + n, sizeof got - n);
      if (r == 0) break;  // the other side closed: report
      if (r > 0) n += static_cast<std::size_t>(r);
    }
    for (; mode == Mode::busy && seen + 1 < n; ++seen) {
      if (got[seen] != 0xA5) continue;
      if (got[seen + 1] == 0x25) {  // STOP: the flow ends 5 ms later
        quiet_due = true;
        quiet_at = clock_type::now();
      } else if (got[seen + 1] == 0x20) {  // SCAN: descriptor, then a new flow from node 0
        const u8 desc[] = {0xA5, 0x5A, 0x05, 0x00, 0x00, 0x40, 0x81};
        open = write_all(sfd, desc, sizeof desc);
        flowing = true;
        quiet_due = false;
        k = 0;
      }
    }
    if (quiet_due && since(quiet_at) >= 0.005) {
      flowing = false;
      quiet_due = false;
    }
    if (flowing) {
      u8 burst[23 * 5];
      std::size_t len = 0;
      for (int j = 0; j < 23 && (limit < 0 || k < limit); ++j, ++k, len += 5)
        node_bytes(k, burst + len);
      if (len == 0) flowing = false;
      else if (open) open = write_all(sfd, burst, len);
    }
    if (n == sizeof got) break;
  }
  if (::write(report, got, n) < 0) _exit(1);
  _exit(0);
}

struct Rig {
  int fd = -1;        // our end: what the function gets
  int report = -1;
  pid_t pid = -1;
};

Rig start(Mode mode, long nodes = 0) {
  Rig g;
  int s[2];
  int r[2];
  if (socketpair(AF_UNIX, SOCK_STREAM, 0, s) != 0 || pipe(r) != 0) {
    std::printf("socketpair / pipe failed\n");
    return g;
  }
  g.pid = spawn_device(s[1], r[1], s[0], r[0], mode, nodes);
  close(s[1]);
  close(r[1]);
  g.fd = s[0];
  g.report = r[0];
  return g;
}

// Close our end, collect what the device read (hex), end the child.
std::string finish_rig(Rig& g) {
  close(g.fd);
  std::string sent = "(no report)";
  pollfd p{};
  p.fd = g.report;
  p.events = POLLIN;
  if (::poll(&p, 1, 2000) > 0) {
    u8 b[64];
    ssize_t r = ::read(g.report, b, sizeof b);
    sent = r > 0 ? hex(Bytes(b, b + r)) : "(nothing)";
  }
  kill(g.pid, SIGKILL);
  waitpid(g.pid, nullptr, 0);
  close(g.report);
  return sent;
}

// Run f() with stdout going to a temporary file; -> what it printed.
template <class F>
std::string captured(F f) {
  std::fflush(stdout);
  std::FILE* tmp = std::tmpfile();
  if (!tmp) return "(no tmpfile)";
  const int saved = dup(1);
  dup2(fileno(tmp), 1);
  g_stop = 0;
  alarm_after(6.0);  // watchdog
  f();
  alarm_after(0.0);
  g_stop = 0;
  std::fflush(stdout);
  dup2(saved, 1);
  close(saved);
  std::string out;
  std::rewind(tmp);
  char buf[4096];
  std::size_t r;
  while ((r = std::fread(buf, 1, sizeof buf, tmp)) > 0) out.append(buf, r);
  std::fclose(tmp);
  return out;
}

std::vector<std::string> lines(const std::string& s) {
  std::vector<std::string> v;
  std::string cur;
  for (char c : s) {
    if (c == '\n') {
      v.push_back(cur);
      cur.clear();
    } else {
      cur += c;
    }
  }
  if (!cur.empty()) v.push_back(cur);
  return v;
}

// The lines that start with `prefix`.
std::vector<std::string> with(const std::vector<std::string>& v, const std::string& prefix) {
  std::vector<std::string> out;
  for (const std::string& l : v)
    if (l.compare(0, prefix.size(), prefix) == 0) out.push_back(l);
  return out;
}

// "first raw   bd 01 2d a0 0f -> 90.0 90.90625 91.8125": the first raw line, then the deg of
// the point lines, at most 6 (the rest of a point line is print_node(), given in full).
std::string raw_and_degs(const std::vector<std::string>& v) {
  const std::vector<std::string> raw = with(v, "first raw");
  const std::vector<std::string> pts = with(v, "point       ( ");
  std::string s = raw.empty() ? "(no first raw line)" : raw[0];
  s += " ->";
  for (std::size_t i = 0; i < pts.size() && i < 6; ++i)  // 14 = the length of "point       ( "
    s += " " + pts[i].substr(14, pts[i].find(" deg") - 14);
  if (pts.size() > 6) s += " ... (" + str(pts.size()) + " point lines)";
  return s;
}

std::string first_or_none(const std::vector<std::string>& v) { return v.empty() ? "none" : v[0]; }

// "accepted 23 nodes, rejected 0 boundaries" -> 23, or -1 if the line is not in that shape.
long accepted_of(const std::string& l) {
  unsigned long a = 0;
  unsigned long r = 0;
  char tail[2];
  if (std::sscanf(l.c_str(), "accepted %lu nodes, rejected %lu boundarie%1s", &a, &r, tail) != 3 ||
      r != 0)
    return -1;
  return static_cast<long>(a);
}

제목의 L1 · L2 는 l-01 이 정한 안전 규칙이다(L1 = 보이지 않는 레이저, L2 = 도는 머리).

힌트 T3 — start_scan() · first_points() · 멈추고 비우고 묻고, 첫 5바이트를 버리지 않는다

할 일 — start_scan(): 흐름을 멈추고 비운 뒤 SCAN 을 보내고, 기술자 7바이트를 16진으로 찍고, 기술자였는지를 돌려준다. first_points(): 다음 5바이트를 원본 그대로 찍고 NodeStream 에 넣는다. 그 뒤 stream() 으로 앞 count 점을 찍고 멈춘 다음, 두 수를 찍는다.

채점은 test_point_run 의 1 ~ 8 이 한다(1 ~ 4 = start_scan(), 5 ~ 8 = first_points()).

완결 코드

/* 완결 코드 T3 - scripts/lidar_lab/include/lidar_lab/point_run.hpp (start_scan · first_points) */
inline bool start_scan(int fd) {
  stop(fd);
  drain(fd);
  send(fd, CMD_SCAN);
  u8 raw[kDescriptorLen];
  const std::size_t got = read_exact(fd, raw, kDescriptorLen, kReadTimeoutMs);
  std::printf("descriptor  ");
  for (std::size_t i = 0; i < got; ++i) std::printf("%02x", raw[i]);
  std::printf("\n");
  return parse_descriptor(raw, got).has_value();
}

inline void first_points(int fd, int count) {
  constexpr double kSeconds = 2.0;  // upper bound on the time spent looking for them
  NodeStream ns;
  int printed = 0;
  auto on_node = [&](const Node& n) {
    print_node(n);
    return ++printed < count;
  };
  u8 first[kNodeLen];
  const std::size_t got = read_exact(fd, first, kNodeLen, kReadTimeoutMs);
  std::printf("first raw  ");
  for (std::size_t i = 0; i < got; ++i) std::printf(" %02x", first[i]);
  std::printf("\n");
  bool more = true;
  ns.feed(first, got, [&](const Node& n) { more = on_node(n); });  // those bytes go in too
  if (more) stream(fd, kSeconds, ns, on_node);
  std::printf("accepted %zu nodes, rejected %zu boundaries\n", ns.accepted(), ns.rejected());
}

코드 설명

  • stop(fd); drain(fd); send(fd, CMD_SCAN); — 차례가 요점이다. 포트를 열 때 이미 스캔이 흐르고 있었다면, 멈추고 비우지 않은 채 읽은 첫 7바이트는 기술자가 아니라 점이다(l-02 §2-4).
  • read_exact(fd, raw, kDescriptorLen, kReadTimeoutMs) — 7바이트를 모은다. 모은 수(got)가 7 보다 적을 수 있다. 찍는 반복문도 got 까지만 반복한다.
  • std::printf("%02x", raw[i]); — 한 바이트를 두 자리 16진으로 찍는다. 이 쪽의 꼴은 소문자 붙여 쓰기다(a55a…).
  • return parse_descriptor(raw, got).has_value(); — 판정은 l-02 의 순수 함수에 맡긴다. 여기서는 기술자였는지만 돌려준다.
  • constexpr double kSeconds = 2.0; — 점을 얼마 동안 찾을지. 숫자에 이름을 붙여 한 곳에서 바꾼다. 몇 점을 찍을지는 인자 count 로 받는다. main() 이 --count 의 값(기본 10)을 넘긴다.

  • auto on_node = [&](const Node& n) { … }; — 점마다 print_node() 로 한 줄 찍는다. count 개를 찍었으면 false 를 돌려준다.

    [&] 라서 바깥의 printed 를 고칠 수 있다. false 를 받은 stream() 은 그 덩이를 마치고 돌아온다.

  • read_exact(fd, first, kNodeLen, kReadTimeoutMs) 와 그 뒤 두 줄 — 기술자 다음 5바이트를 원본 그대로 찍는다. §3-1-4 의 손 계산이 이 줄과 견준다.

  • ns.feed(first, got, [&](const Node& n) { more = on_node(n); }); — 찍은 5바이트도 NodeStream 에 넣는다. 넣지 않으면 첫 점이 사라져, 첫 point 줄이 first raw 가 아닌 다음 점을 푼 값이 된다(흔한 실수 둘째 행).

    more 는 첫 점에서 이미 멈추라는 답이 왔는지를 담는다.

  • if (more) stream(fd, kSeconds, ns, on_node); — 나머지는 point_port.hpp 의 전량 함수가 읽는다. 같은 ns 를 넘기므로 두 수가 이어서 세어진다.
  • std::printf("accepted %zu nodes, rejected %zu boundaries\n", …); — %zu 는 std::size_t 를 찍는 서식이다.
  • 골격의 자리표시(안내 printf · (void)fd; · return false;, first_points() 의 (void)fd; · (void)count;)는 지웠다.

  • 다르게 써도 되는 곳 — 기술자를 descriptor(fd)(l-02)로 받아도 판정은 같다. 다만 그 함수는 해석된 값만 돌려주고 원본 7바이트는 돌려주지 않는다 — 이 쪽은 그 7바이트를 노트에 적으므로 직접 읽는다.

쓰는 API — l-02 의 stop(fd) · drain(fd) · send(fd, cmd) · read_exact(fd, buf, n, timeout_ms) · parse_descriptor(b, n). 상수는 l-02 의 kDescriptorLen(기술자 길이 7)이다. 이 쪽의 stream() · NodeStream::feed()(§3-1-2)와 print_node()(이 파일, 전량).

두 인자는 이렇게 쓰인다.

  • --skip <n> — resync_run()(T4)이 기술자 뒤에서 이만큼 바이트를 읽어 버린다. 1 이면 흐름이 1바이트 어긋난 채로 시작한다. 이것이 이 실습의 요점이다.
  • --step <n> — resync_run() 이 NodeStream ns(step) 으로 넘긴다. 생성자가 1 ~ 5 로 잘라 step_ 에 담고, feed()(T2)가 검사에 실패한 자리에서 이만큼 나아간다.

T4 의 골격은 §3-1-4 의 point_run.hpp 안에 있다. lab_point --resync 는 기술자를 받은 뒤 resync_run() 을 부른다. 기술자가 오지 않으면 no descriptor -- not running 3-3 을 찍고 1 을 돌려준다 — 어긋남의 출발점을 알 수 없기 때문이다.

3-3-3. 직접 채우기 — 네 번 실행한다

할 일 — 기술자 다음에서 skip 바이트를 읽어 버린다. 그다음 NodeStream ns(step) 으로 seconds 동안 세면서 앞 20 점의 각도를 모으고, 두 줄(step= skip= accepted= rejected= · angles …)을 찍는다.

채점은 test_point_run 의 9 ~ 13 이 한다. 가짜 기기는 점 200 개를 보내고, 시험은 0.4 초 동안 세게 한다.

완결 코드

/* 완결 코드 T4 - scripts/lidar_lab/include/lidar_lab/point_run.hpp (resync_run) */
inline void resync_run(int fd, std::size_t step, std::size_t skip, double seconds) {
  constexpr int kPrintAngles = 20;
  u8 junk[16];
  const std::size_t n_skip = skip < sizeof junk ? skip : sizeof junk;
  read_exact(fd, junk, n_skip, kReadTimeoutMs);
  NodeStream ns(step);
  std::vector<double> angles;
  stream(fd, seconds, ns, [&](const Node& n) {
    if (angles.size() < static_cast<std::size_t>(kPrintAngles)) angles.push_back(n.deg);
    return true;
  });
  std::printf("step=%zu skip=%zu accepted=%zu rejected=%zu\n", ns.resync_step(), n_skip,
              ns.accepted(), ns.rejected());
  std::printf("angles");
  for (double a : angles) std::printf(" %.1f", a);
  std::printf("\n");
}

코드 설명

  • constexpr int kPrintAngles = 20; — 찍을 각도의 수다. 세는 시간은 인자 seconds 로 받는다. main() 이 --seconds 의 값(기본 4.0)을 넘기므로 네 회차가 같은 시간 동안 센다.
  • u8 junk[16]; 과 다음 줄 — 버릴 바이트를 담을 작은 배열이다. skip 이 배열보다 크면 배열 크기로 자른다(main() 은 16 까지만 받는다). 배열 끝 너머에 쓰지 않게 하기 위해서다.
  • read_exact(fd, junk, n_skip, kReadTimeoutMs); — 읽어서 버린다. 이 한 줄이 흐름을 어긋나게 한다. n_skip 이 0 이면 아무것도 읽지 않는다.
  • NodeStream ns(step); — 실패한 자리에서 나아갈 칸 수를 넘긴다. feed()(T2)가 이 값을 step_ 으로 쓴다.

  • stream(fd, seconds, ns, [&](const Node& n) { … return true; }); — 각도는 앞 20 개만 모으고, 람다는 끝까지 true 를 돌려준다. 그래야 시간 내내 센다.

    20 개를 모은 뒤 false 를 돌려주면 첫 덩이만 세고 끝난다(흔한 실수 둘째 행).

  • std::printf("step=%zu …", ns.resync_step(), n_skip, …); — ns.resync_step() 은 1 ~ 5 로 자른 뒤의 값, 곧 실제로 쓴 걸음이다. n_skip 은 실제로 버린 바이트 수다.
  • std::printf(" %.1f", a); — 각도를 소수 한 자리로 찍는다. 이웃끼리 조금씩 커지는지만 보면 되기 때문이다.
  • 골격의 자리표시 넷((void)fd; · (void)step; · (void)skip; · (void)seconds;)은 지웠다.

  • 다르게 써도 되는 곳 — 버릴 바이트를 std::vector<u8> junk(skip); 에 읽어도 같다(상한도 필요 없다). 이 가이드는 크기가 정해진 작은 배열과 상한으로 쓴다.15

쓰는 API — read_exact()(l-02) · stream() · NodeStream(§3-1-2) · std::vector 의 push_back(x).

덩어리 안에 검사 비트 둘이 들어 있기 때문이다. b0 의 비트0·비트1 이 서로 반대여야 하고(S ≠ ~S), b1 의 비트0 이 1 이어야 한다(C == 1). 임의의 자리가 이 둘을 우연히 만족할 확률은 1/2 × 1/2 = 1/4 로, 한 번으로는 아무것도 증명하지 못한다.

증명이 되는 것은 5바이트 간격으로 규칙이 계속 성립할 때다. n 개가 이어지면 우연일 확률이 4의 n제곱분의 1로 떨어진다. 그래서 경계 찾기는 "한 점을 판정하는 일"이 아니라 "가설을 세우고 이어 가 보는 일"이다. 06a 의 계약 v2 와 정확히 반대다. 계약 v2 는 우리가 머리 바이트와 길이와 CRC 를 설계했으므로 한 번에 단정할 수 있다.

3. angle_q6 는 왜 16비트 전체가 아니라 15비트인가? 그리고 그 1비트 때문에 >> 1 이 필요해지는 과정을 구조체에서 다시 도출해 보라

16비트 필드의 맨 아래 한 칸을 검사 비트 C 가 쓰기 때문이다. SDK 헤더의 주석이 check_bit:1;angle_q6:15; 이고, 먼저 선언된 것이 낮은 비트다. 그래서 16비트를 통째로 만든 뒤(b1 | (b2 << 8) — 리틀엔디안) 오른쪽으로 한 칸 시프트하면 각도가 나온다. 헤더의 ..._ANGLE_SHIFT 가 1 인 것이 이 한 칸이다.

남는 것이 15비트이므로 담을 수 있는 최대는 32767 ÷ 64 = 511.984375° 다. 360° 를 넘는 자리가 남아 있다는 것이 중요하다. 14비트로 마스크하면 360° 근처가 오류 표시 없이 접히고, 그 점은 한 바퀴에 한 번 나타나 l-04 의 회전 자르기를 어긋나게 한다. 시험 벡터 2·5 는 오직 이 잘못을 검출하려고 있다.

4. 거리 0 을 "그 방향은 비어 있다"로 읽으면 무엇이 잘못되는가? 그리고 그 판단의 근거는 어느 등급인가

"비었다"는 지나가도 된다는 뜻이고 "못 쟀다"는 그 방향의 상태를 알 수 없다는 뜻이다. 유리문·검은 천·측정 범위 밖은 전부 "못 쟀다"인데, 이 점들을 "비었다"로 읽으면 로봇이 그쪽으로 주행한다. 반대로 0 을 "거리 0 m 에 물체"로 읽으면 로봇 바로 앞에 없는 벽이 생긴다. 이 셋을 분리하는 것이 l-09 의 점유 · 자유 · 미지 세 상태다.

근거의 등급은 미확인 1차다. 데이터시트는 0 의 뜻을 적지 않았다. 같은 모델(A1M8)을 쓴 1세대 코드가 0 = invalid / no return 이라 적었을 뿐이다(NOMINAL(gen1-record)).17 그 개체가 내 개체인지는 아직 확인되지 않았다. 내 기기에서 확인하는 절차가 §3-2-4 셋째 행이다.

5. (일부러 틀리면) parse_point 에서 b3 과 b4 를 맞바꿔 읽으면 무엇이 보이는가? 검사 비트는 왜 이 잘못을 검출하지 못하는가

아무 오류도 나지 않고 점이 계속 흐른다. 검사 비트 S · ~S · C 는 전부 b0 과 b1 에 있어서 b3 · b4 를 어떻게 읽든 관여하지 않는다. 그래서 프레이밍은 통과하고 거리만 엉뚱해진다. 예를 들어 A0 0F 를 뒤집어 읽으면 1000.0 mm 가 10243.75 mm 가 된다(§2-5).

이것이 이 쪽이 시험 벡터를 두는 이유다. 벡터 1·2·3·6 이 거리 바이트 순서의 잘못을 검출한다. 반대로 벡터 4(거리 0)와 5(양쪽이 FF)는 두 바이트가 같거나 대칭이라 검출하지 못한다. 벡터를 고르는 일 자체가 설계다.

6. 재동기 걸음을 5로 두면 점의 개수만으로는 무엇이 잘못됐는지 알 수 없다. 무엇을 봐야 하는가

이웃한 점들의 각도가 조금씩 커지는가를 봐야 한다. 경계를 제대로 찾고 있으면 센서가 도는 대로 각도가 순서대로 늘어난다. 경계를 잃은 채 우연히 검사 비트가 맞은 5바이트만 통과시키고 있으면 각도가 불규칙하게 튄다.
