영상을 cv::Mat 로 받아 처리하고 다시 내보내기 — C++ 영상 처리 노드

08 단계에서 /camera/image_raw 가 흐르기 시작했다. 이 단계는 그 영상을 내 C++ 코드 안으로 가져와서 OpenCV 로 만지고, 다시 ROS 토픽으로 내보내는 통로를 뚫는다. 이 통로(cv_bridge + image_transport)는 08b 의 YOLO 검출기와 08c 의 Hailo 검출기, 10 단계의 감독 노드가 전부 그대로 쓴다.

1. 개요 — OpenCV 가 ROS 와 만나는 지점

OpenCV 는 cv::Mat(행렬) 을 중심으로 한 영상 처리 라이브러리다. 원본은 C++ 이고 Python 의 cv2 는 그 바인딩이다 — 그래서 두 언어의 함수 이름과 인자 순서가 거의 같다. 이 단계에서 C++ 로 익힌 것은 Python 에서도 그대로 통한다.

ROS 2 의 영상은 sensor_msgs/msg/Image 라는 평범한 바이트 배열 메시지로 흐른다. OpenCV 는 그것을 모른다. 둘 사이에 두 개의 다리가 있다.

다리하는 일이 단계에서 쓰는 API
cv_bridgesensor_msgs/Image ↔ cv::Mat 변환. 인코딩(rgb8/bgr8/mono8…)을 맞춰 준다toCvShare, toCvCopy, CvImage(...).toImageMsg()
image_transport영상 토픽의 발행·구독. raw 외에 compressed 같은 전송 플러그인을 자동으로 붙인다create_subscription, create_publisher

이 단계에서 만드는 노드는 두 개다.

  camera ──/camera/image_raw──► image_proc_node ──/camera/image_proc──► Foxglove (눈으로 확인)
  (08)                            (08a §3-2)          리사이즈·엣지·컨투어

                                  ┌─► detector ──/detections───┐       (08b YOLO / 08c Hailo)
  /camera/image_raw ──────────────┤                            ▼
                                  └─────────────────► detection_overlay ──/camera/annotated──► Foxglove
                                                      (08a §3-6)  박스 + 라벨 + 지연(ms)
  • image_proc_node — 영상 파이프라인의 기본형. 받는다 → cv::Mat → 처리 → 다시 메시지 → 발행. 처리 시간을 재는 습관을 여기서 들인다.
  • detection_overlay — 검출 결과(vision_msgs/Detection2DArray)를 영상 위에 그린다. 08b/08c 에서 검출기를 바꿔 끼워도 이 노드는 손대지 않는다. 03 단계에서 배운 "느슨한 결합"이 눈에 보이는 형태다.

2. 원리 — 왜

2-1. sensor_msgs/Image 는 무엇인가

ros2 interface show sensor_msgs/msg/Image
std_msgs/Header header    # stamp = 촬영 시각, frame_id = camera_optical_link (05 단계의 광학 좌표계)
uint32 height             # 행 수
uint32 width              # 열 수
string encoding           # ★ 픽셀 해석법: "rgb8", "bgr8", "mono8", "16UC1" …
uint8  is_bigendian
uint32 step               # 한 행의 바이트 수 (= width × 채널 × 바이트 크기, 패딩이 있으면 더 큼)
uint8[] data              # step × height 바이트. 그냥 바이트 덩어리다

메시지 자체는 해석법(encoding)이 붙은 바이트 배열일 뿐이다. 같은 바이트를 rgb8 로 읽으면 빨강이, bgr8 로 읽으면 파랑이 된다. OpenCV 의 관례는 BGR 이다(역사적 이유). 카메라 드라이버가 무엇을 보내는지는 확인하는 것이지 추측하는 것이 아니다.

ros2 topic echo /camera/image_raw --field encoding --once      # bgr8 이 나와야 한다 (아래 노트). 추측하지 말고 직접 본다
ros2 topic echo /camera/image_raw --field step --once          # 640 폭 × 3 채널이면 1920
encoding채널·타입cv::Mat 타입어디서 만나는가
rgb8 / bgr83채널 8비트CV_8UC3컬러 카메라. 두 이름은 바이트 순서만 다르다
rgba8 / bgra84채널 8비트CV_8UC4GPU·디스플레이 경로
mono81채널 8비트CV_8UC1흑백, 엣지 맵, 마스크
mono16 / 16UC11채널 16비트CV_16UC1깊이 카메라(mm 단위)
32FC11채널 floatCV_32FC1깊이(m), 디스패리티
yuv422_yuy2 등packed—카메라 원본 포맷. cv_bridge 가 변환해 준다
libcamera 의 포맷 이름과 ROS 인코딩 이름은 1:1 이 아니다 — 우리 카메라는 bgr8 로 온다

08 단계에서 format: "RGB888" 을 줬지만 camera_ros 는 encoding 을 bgr8 로 붙인다. libcamera 의 포맷 이름은 DRM fourcc 의 리틀엔디안 명명을 따라 RGB888 이 메모리 바이트 순서로는 B,G,R 이고, camera_ros 의 포맷 매핑이 그것을 ROS 이름으로 바르게 옮긴 결과다. 즉 OpenCV 관례와 이미 같다. 그래도 위 명령으로 실제 값을 확인하는 것이 규칙이고, 코드에서는 원하는 인코딩을 항상 명시한다 — 드라이버나 설정이 바뀌어도 cv_bridge 가 맞춰 주기 때문이다.

2-2. toCvShare 와 toCvCopy — 언제 복사가 일어나는가

cv_bridge::toCvShare(msg, "bgr8")cv_bridge::toCvCopy(msg, "bgr8")
반환CvImageConstPtr — 읽기 전용CvImagePtr — 수정 가능
인코딩이 같을 때메시지의 data 를 그대로 가리킨다. 복사 없음. 메시지 shared_ptr 를 붙잡아 수명을 보장한다항상 새 버퍼로 복사
인코딩이 다를 때 (bgr8 메시지에 "mono8" 이나 "rgb8" 을 요청)변환하면서 새 cv::Mat 을 만든다 = 이때는 사실상 복사다변환 + 복사
쓰는 때읽고 계산만 할 때 (검출기, 통계)그 위에 그리거나 픽셀을 바꿀 때 (overlay)

"share" 라는 이름이 복사 없음을 보장하지는 않는다. 인코딩이 같을 때만 공유한다. 우리 카메라는 bgr8 로 보내므로 toCvShare(msg, "bgr8") 은 복사 없이 메시지 버퍼를 가리킨다 — 메시지 → cv::Mat 까지 공짜다. 반대로 "mono8" 을 요청하면 매 프레임 640×480 바이트를 변환·복사하고, "rgb8" 을 요청하면 채널 순서를 바꾸느라 640×480×3 바이트를 복사한다. 모델 입력이 RGB 라서 순서를 바꿔야 한다면(08b) cv_bridge 에 맡기지 말고 blobFromImage 의 swapRB 에 맡겨 변환을 한 번으로 끝낸다. 이 판단을 하려면 먼저 지금 복사가 일어나는지 알아야 한다.

2-3. cv::Mat 의 메모리 모델 — 복사를 피하는 것이 C++ 을 쓰는 이유

cv::Mat a = src;                 // 헤더만 복사. 픽셀 버퍼는 공유(참조 카운트). a 를 고치면 src 도 바뀐다
cv::Mat roi = src(cv::Rect(0, 0, 100, 100));   // ROI 도 뷰다. roi 에 그리면 src 의 그 영역이 바뀐다
cv::Mat b = src.clone();         // 깊은 복사. 독립된 버퍼
src.copyTo(roi);                 // 기존 버퍼(뷰)에 "그 자리에" 써 넣는다 — 08b 의 레터박스가 이 성질을 쓴다
cv::resize(src, dst, ...);       // 출력 인자 dst 는 필요하면 함수가 알아서 할당한다

Python 의 numpy 도 같은 뷰/복사 구분이 있지만, C++ 에서는 메시지 → Mat → 처리 → 메시지 사슬 전체를 복사 없이 이을 수 있다. 640×480 컬러 한 장은 0.9 MB 이고 30 fps 면 초당 27 MB — 불필요한 복사 한 번이 곧 CPU 몇 % 다. 08c 에서 "CPU 를 비운다"는 목표는 여기서부터 시작된다.

cv::Mat out = work; 뒤에 out 위에 그리면

work 도 같이 바뀐다. 같은 버퍼이기 때문이다. 원본을 보존한 채 그리려면 clone() 이 필요하다. §3-2 의 contours 모드가 그렇게 되어 있는 이유를 코드에서 찾아보십시오.

2-4. image_transport — 왜 그냥 create_publisher 를 안 쓰는가

쓸 수는 있다. 하지만 image_transport 로 발행하면 image_transport_plugins 가 설치된 환경에서 /camera/image_proc/compressed(JPEG) 토픽이 자동으로 같이 생긴다. Pi 안의 노드끼리는 raw 로(압축 비용 없음), Mac 의 Foxglove 로 갈 때는 compressed 로(Wi-Fi 는 raw 27 MB/s 를 못 견딘다) — 구독자가 골라 쓴다. 구독 쪽도 마지막 인자 "raw" / "compressed" 로 전송 방식을 고른다.

ImageTransport 클래스가 아니라 자유 함수를 쓰는 이유

image_transport::ImageTransport 클래스의 생성자는 rclcpp::Node::SharedPtr 를 요구한다. 그런데 노드의 생성자 안에서는 아직 그 노드를 가리키는 shared_ptr 가 없다 (std::make_shared<MyNode>() 가 끝나야 생긴다). 생성자에서 shared_from_this() 를 부르면 bad_weak_ptr 예외가 난다. 자유 함수 image_transport::create_subscription(this, …) 는 raw 포인터 rclcpp::Node* 를 받으므로 생성자 안에서 바로 쓸 수 있다. 이 프로젝트의 모든 영상 노드는 이 형태다.

2-5. 센서 QoS, 큐 깊이, 그리고 처리 시간을 재는 습관

  • QoS 는 rmw_qos_profile_sensor_data (BEST_EFFORT · VOLATILE · depth 5). 드라이버가 RELIABLE 이든 BEST_EFFORT 든 이 구독자는 연결된다 (03 §2-7 의 호환 규칙). 반대로 RELIABLE 로 구독하면 드라이버가 BEST_EFFORT 일 때 조용히 아무것도 안 온다.
  • 큐 깊이는 "밀린 프레임을 몇 장까지 쌓을 것인가"다. 처리가 카메라보다 느리면 큐가 차고, 그 뒤로는 항상 큐 길이만큼 옛 프레임을 보게 된다. 가벼운 처리(이 노드)는 5 여도 괜찮지만 무거운 검출기는 1 이어야 한다 (08b 에서 그렇게 쓴다).
  • 콜백 안에서 오래 걸리면 다른 콜백이 전부 밀린다 (04 §3-2 의 실행기). 그래서 콜백마다 std::chrono::steady_clock 으로 처리 시간을 재고 로그로 남긴다. "느린 것 같다"가 아니라 "12.4 ms 다"로 말하는 습관이 08b 에서 병목을 찾는 유일한 방법이다.

2-6. 이 단계에서 쓰는 연산 — 각각 한 줄

함수하는 일왜 이 순서인가
cv::resize해상도 변경. INTER_AREA 는 축소에 적합픽셀 수가 처리 시간을 정한다. 절반 크기 = 1/4 시간
cv::cvtColor색공간 변환 (BGR→GRAY, GRAY→BGR …)엣지·임계값은 1채널에서 한다
cv::GaussianBlur가우시안 커널로 노이즈 제거Canny 전에 하지 않으면 노이즈가 전부 엣지가 된다
cv::Canny엣지 검출. 두 임계값(low/high)의 히스테리시스high 를 넘는 강한 엣지에 이어진 low 이상의 약한 엣지만 남긴다
cv::findContours이진 엣지 맵 → 닫힌 윤곽선 목록RETR_EXTERNAL 은 바깥 윤곽만. 작은 조각은 면적으로 거른다
cv::boundingRect, drawContours, rectangle, putText외접 사각형 계산과 그리기그리기는 원본 위에 하므로 복사본이 필요하다

각 함수의 인자와 더 많은 연산(임계값, 모폴로지, 색 마스크, 캘리브레이션)은 부록 B · OpenCV 사용법 에 C++/Python 을 나란히 정리했다.

3-2. image_proc_node.cpp

src/image_proc_node.cpp. 직접 치면서 복사가 일어나는 줄과 공유되는 줄을 구분해 보십시오.

#include <chrono>
#include <memory>
#include <string>
#include <vector>

#include "rclcpp/rclcpp.hpp"
#include "sensor_msgs/msg/image.hpp"
#include "cv_bridge/cv_bridge.h"                 // Humble 은 .h (Jazzy 부터 .hpp)
#include "image_transport/image_transport.hpp"
#include "opencv2/core.hpp"
#include "opencv2/imgproc.hpp"

class ImageProcNode : public rclcpp::Node
{
public:
  ImageProcNode()
  : Node("image_proc_node")
  {
    // 파라미터 — 선언이 곧 인터페이스다 (04 §3-6). 값은 콜백에서 매번 읽는다.
    this->declare_parameter<std::string>("mode", "edges");   // passthrough | gray | blur | edges | contours
    this->declare_parameter<double>("scale", 0.5);
    this->declare_parameter<int>("canny_low", 50);
    this->declare_parameter<int>("canny_high", 150);

    // 발행자를 구독자보다 먼저 만든다: 첫 콜백이 도는 순간 pub_ 가 존재해야 한다.
    pub_ = image_transport::create_publisher(this, "/camera/image_proc", rmw_qos_profile_sensor_data);

    // 구독. ImageTransport 클래스가 아니라 자유 함수를 쓰는 이유는 §2-4.
    sub_ = image_transport::create_subscription(
      this, "/camera/image_raw",
      std::bind(&ImageProcNode::on_image, this, std::placeholders::_1),
      "raw", rmw_qos_profile_sensor_data);

    RCLCPP_INFO(this->get_logger(), "image_proc_node: /camera/image_raw -> /camera/image_proc");
  }

private:
  void on_image(const sensor_msgs::msg::Image::ConstSharedPtr & msg)
  {
    const auto t0 = std::chrono::steady_clock::now();

    // ros2 param set 이 즉시 반영되도록 매 프레임 읽는다 (비용은 마이크로초 단위)
    const std::string mode = this->get_parameter("mode").as_string();
    const double scale = this->get_parameter("scale").as_double();
    const int canny_low = this->get_parameter("canny_low").as_int();
    const int canny_high = this->get_parameter("canny_high").as_int();

    cv_bridge::CvImageConstPtr cv_ptr;
    try {
      cv_ptr = cv_bridge::toCvShare(msg, "bgr8");   // 직접 확인: camera_ros 는 bgr8 → 복사 없이 공유. "mono8" 을 요청하면 여기서 변환(복사)된다
    } catch (const cv_bridge::Exception & e) {
      RCLCPP_ERROR_THROTTLE(this->get_logger(), *this->get_clock(), 2000,
                            "cv_bridge: %s (encoding=%s)", e.what(), msg->encoding.c_str());
      return;
    }

    cv::Mat src = cv_ptr->image;     // 헤더만 복사. 픽셀은 공유 (§2-3)
    cv::Mat work;
    if (scale > 0.0 && scale != 1.0) {
      cv::resize(src, work, cv::Size(), scale, scale, cv::INTER_AREA);   // 새 버퍼
    } else {
      work = src;                    // 공유
    }

    // 출력은 항상 bgr8 3채널로 맞춘다 — Foxglove 와 다음 노드가 한 가지 인코딩만 기대하게
    cv::Mat out;
    if (mode == "passthrough") {
      out = work;
    } else if (mode == "gray") {
      cv::Mat gray;
      cv::cvtColor(work, gray, cv::COLOR_BGR2GRAY);
      cv::cvtColor(gray, out, cv::COLOR_GRAY2BGR);
    } else if (mode == "blur") {
      cv::GaussianBlur(work, out, cv::Size(9, 9), 0);
    } else if (mode == "edges") {
      cv::Mat gray, edges;
      cv::cvtColor(work, gray, cv::COLOR_BGR2GRAY);
      cv::GaussianBlur(gray, gray, cv::Size(5, 5), 0);         // 같은 Mat 을 입력·출력으로 써도 된다
      cv::Canny(gray, edges, canny_low, canny_high);
      cv::cvtColor(edges, out, cv::COLOR_GRAY2BGR);
    } else if (mode == "contours") {
      cv::Mat gray, edges;
      cv::cvtColor(work, gray, cv::COLOR_BGR2GRAY);
      cv::GaussianBlur(gray, gray, cv::Size(5, 5), 0);
      cv::Canny(gray, edges, canny_low, canny_high);
      std::vector<std::vector<cv::Point>> contours;
      cv::findContours(edges, contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);
      out = work.clone();            // 원본 위에 그리므로 복사본이 필요하다 (§2-3 의 경고)
      for (const auto & c : contours) {
        if (cv::contourArea(c) < 200.0) {
          continue;                  // 작은 조각은 버린다 — 이 값도 파라미터로 빼 보십시오
        }
        cv::drawContours(out, std::vector<std::vector<cv::Point>>{c}, -1, cv::Scalar(0, 255, 0), 2);
        cv::rectangle(out, cv::boundingRect(c), cv::Scalar(0, 0, 255), 1);
      }
    } else {
      RCLCPP_WARN_THROTTLE(this->get_logger(), *this->get_clock(), 2000, "unknown mode '%s'", mode.c_str());
      out = work;
    }

    // header 를 그대로 복사한다: 촬영 시각(stamp)과 frame_id 가 살아 있어야 TF 조회가 맞는다
    pub_.publish(cv_bridge::CvImage(msg->header, "bgr8", out).toImageMsg());

    const double ms =
      std::chrono::duration<double, std::milli>(std::chrono::steady_clock::now() - t0).count();
    RCLCPP_INFO_THROTTLE(this->get_logger(), *this->get_clock(), 2000,
      "mode=%s  %dx%d -> %dx%d  %.1f ms", mode.c_str(), src.cols, src.rows, out.cols, out.rows, ms);
  }

  // 인터페이스 객체는 반드시 멤버로 (04 이해 확인 2번)
  image_transport::Subscriber sub_;
  image_transport::Publisher pub_;
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<ImageProcNode>());
  rclcpp::shutdown();
  return 0;
}

3-5. 같은 노드를 Python 으로 — 언제 Python 이면 충분한가 Python

패키지 등록 없이 스크립트로 바로 실행할 수 있다(rclpy 는 환경만 source 되어 있으면 된다). rpi5_vision/scripts/image_proc_py.py:

import time

import cv2
import rclpy
from cv_bridge import CvBridge
from rclpy.node import Node
from rclpy.qos import qos_profile_sensor_data
from sensor_msgs.msg import Image


class ImageProcPy(Node):
    def __init__(self):
        super().__init__('image_proc_py')
        self.declare_parameter('scale', 0.5)
        self.bridge = CvBridge()
        self.pub = self.create_publisher(Image, '/camera/image_proc', qos_profile_sensor_data)
        self.sub = self.create_subscription(
            Image, '/camera/image_raw', self.on_image, qos_profile_sensor_data)

    def on_image(self, msg: Image):
        t0 = time.perf_counter()
        scale = self.get_parameter('scale').value
        src = self.bridge.imgmsg_to_cv2(msg, 'bgr8')          # numpy 배열. bgr8 이라 변환 없음 (버퍼는 감싼다)
        work = cv2.resize(src, None, fx=scale, fy=scale, interpolation=cv2.INTER_AREA)
        gray = cv2.cvtColor(work, cv2.COLOR_BGR2GRAY)
        gray = cv2.GaussianBlur(gray, (5, 5), 0)
        edges = cv2.Canny(gray, 50, 150)
        out = cv2.cvtColor(edges, cv2.COLOR_GRAY2BGR)
        out_msg = self.bridge.cv2_to_imgmsg(out, 'bgr8')
        out_msg.header = msg.header                            # 촬영 시각·frame_id 유지
        self.pub.publish(out_msg)
        ms = (time.perf_counter() - t0) * 1000.0
        self.get_logger().info(f'edges {ms:.1f} ms', throttle_duration_sec=2.0)


def main(args=None):
    rclpy.init(args=args)
    node = ImageProcPy()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        if rclpy.ok():
            rclpy.shutdown()


if __name__ == '__main__':
    main()
# C++ 노드를 끄고 (같은 토픽을 두 노드가 내면 Foxglove 가 번갈아 받는다)
python3 /ros2_ws/src/rpi5_vision/scripts/image_proc_py.py

같은 edges 처리의 ms 를 C++ 값 옆에 적어 보십시오. OpenCV 함수 자체는 같은 C++ 코드라 큰 차이가 없을 것이다 — 차이는 메시지 ↔ numpy 변환, Python 루프, GC 에서 난다. 함수 몇 개를 이어 붙이는 수준이면 Python 이 충분하고, 픽셀 루프·고정 주기·복사 회피가 필요하면 C++ 이다. 이 프로젝트가 검출기를 C++ 로 쓰는 이유는 08b 의 8400행 후처리 루프 때문이다.

src/detection_overlay.cpp:

#include <algorithm>
#include <cstdio>
#include <memory>
#include <string>

#include "rclcpp/rclcpp.hpp"
#include "sensor_msgs/msg/image.hpp"
#include "vision_msgs/msg/detection2_d_array.hpp"   // Detection2DArray → detection2_d_array.hpp (snake_case 규칙)
#include "cv_bridge/cv_bridge.h"
#include "image_transport/image_transport.hpp"
#include "opencv2/imgproc.hpp"

class DetectionOverlay : public rclcpp::Node
{
public:
  DetectionOverlay()
  : Node("detection_overlay")
  {
    pub_ = image_transport::create_publisher(this, "/camera/annotated", rmw_qos_profile_sensor_data);

    // 검출 결과는 "최신 것 하나"만 있으면 된다 → depth 1, BEST_EFFORT (검출기도 그렇게 발행한다)
    det_sub_ = this->create_subscription<vision_msgs::msg::Detection2DArray>(
      "/detections", rclcpp::QoS(1).best_effort(),
      [this](const vision_msgs::msg::Detection2DArray & msg) {
        last_det_ = msg;             // 캐시만 한다. 그리기는 영상 콜백에서
        has_det_ = true;
      });

    sub_ = image_transport::create_subscription(
      this, "/camera/image_raw",
      std::bind(&DetectionOverlay::on_image, this, std::placeholders::_1),
      "raw", rmw_qos_profile_sensor_data);
  }

private:
  void on_image(const sensor_msgs::msg::Image::ConstSharedPtr & msg)
  {
    cv_bridge::CvImagePtr cv_ptr;
    try {
      cv_ptr = cv_bridge::toCvCopy(msg, "bgr8");   // 위에 그릴 것이므로 복사본 (toCvShare 는 const)
    } catch (const cv_bridge::Exception & e) {
      RCLCPP_ERROR_THROTTLE(this->get_logger(), *this->get_clock(), 2000, "cv_bridge: %s", e.what());
      return;
    }
    cv::Mat & img = cv_ptr->image;

    if (has_det_) {
      for (const auto & det : last_det_.detections) {
        const auto & b = det.bbox;
        const int x1 = static_cast<int>(b.center.position.x - b.size_x / 2.0);
        const int y1 = static_cast<int>(b.center.position.y - b.size_y / 2.0);
        const int x2 = static_cast<int>(b.center.position.x + b.size_x / 2.0);
        const int y2 = static_cast<int>(b.center.position.y + b.size_y / 2.0);
        cv::rectangle(img, cv::Point(x1, y1), cv::Point(x2, y2), cv::Scalar(0, 255, 0), 2);

        std::string label = "?";
        if (!det.results.empty()) {
          char buf[64];
          std::snprintf(buf, sizeof(buf), "%s %.2f",
                        det.results[0].hypothesis.class_id.c_str(), det.results[0].hypothesis.score);
          label = buf;
        }
        cv::putText(img, label, cv::Point(x1, std::max(y1 - 6, 12)),
                    cv::FONT_HERSHEY_SIMPLEX, 0.6, cv::Scalar(0, 255, 0), 2);
      }

      // 이 프레임의 촬영 시각 − 검출 결과의 촬영 시각 = "얼마나 옛 결과를 보고 있는가"
      const double lag_ms =
        (rclcpp::Time(msg->header.stamp) - rclcpp::Time(last_det_.header.stamp)).seconds() * 1000.0;
      char info[96];
      std::snprintf(info, sizeof(info), "det: %zu  lag: %.0f ms", last_det_.detections.size(), lag_ms);
      cv::putText(img, info, cv::Point(8, 22), cv::FONT_HERSHEY_SIMPLEX, 0.6, cv::Scalar(0, 255, 255), 2);
    }

    pub_.publish(cv_ptr->toImageMsg());   // header 는 toCvCopy 가 이미 복사해 두었다
  }

  image_transport::Subscriber sub_;
  image_transport::Publisher pub_;
  rclcpp::Subscription<vision_msgs::msg::Detection2DArray>::SharedPtr det_sub_;
  vision_msgs::msg::Detection2DArray last_det_;
  bool has_det_{false};
};

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  rclcpp::spin(std::make_shared<DetectionOverlay>());
  rclcpp::shutdown();
  return 0;
}
last_det_ 에 락(mutex)이 없는 이유

기본 rclcpp::spin 은 단일 스레드 실행기다. 검출 콜백과 영상 콜백은 절대 동시에 실행되지 않는다(04 §3-2). 그래서 멤버를 그냥 읽고 써도 안전하다. 나중에 MultiThreadedExecutor 로 옮기면 이 전제가 깨지므로 그때는 std::mutex 또는 콜백 그룹으로 상호 배제를 걸어야 한다 — 08b 의 busy_ 플래그가 그 준비다.

지연(lag) 표시가 있는 이유 — 동기화의 정석은 따로 있다

영상은 30 fps 로 오고 검출은 (08b 에서) 수백 ms 마다 온다. 이 노드는 마지막 검출을 현재 프레임 위에 그리므로 박스가 물체보다 늦게 따라온다. 화면의 lag 값이 그 지연이다. 검출 결과를 그 검출이 나온 바로 그 프레임 위에 정확히 그리려면 message_filters::sync_policies::ApproximateTime 으로 두 토픽을 타임스탬프 기준으로 짝지어야 한다(부록 A). 지금은 지연을 보이게 하는 것이 목적이다 — 08c 에서 Hailo 로 옮기면 이 숫자가 얼마나 줄어드는지 비교한다.

✅ 검증 체크포인트

🤔 이해 확인

1. toCvShare(msg, "bgr8") 은 언제 복사를 하고 언제 하지 않는가?
메시지의 encoding 이 요청한 bgr8 과 같을 때만 메시지 버퍼를 그대로 가리킨다(복사 없음, 읽기 전용). 우리 카메라(camera_ros, RGB888)는 bgr8 로 오므로 이 경우다. encoding 이 다르면("mono8" 이나 "rgb8" 을 요청) 변환하면서 새 cv::Mat 을 만들므로 사실상 복사다. "share" 는 보장이 아니라 가능하면 공유한다는 뜻이다. 그래서 카메라의 실제 encoding 을 확인해야 비용을 안다.
2. 출력 메시지에 입력의 header 를 복사하는 이유는?
stamp 는 촬영 시각이고 frame_id 는 광학 좌표계 이름이다. 뒤의 노드(검출기, 융합, TF 조회)는 "이 영상이 언제 어느 좌표계에서 찍혔는가"를 header 로 안다. 처리 시각으로 바꿔 버리면 로봇이 움직인 만큼 위치 계산이 틀어지고, frame_id 를 비우면 TF 트리에 붙지 못한다.
3. Release 빌드가 영상 노드에서 특히 중요한 이유는?
OpenCV 라이브러리 자체는 이미 최적화된 바이너리지만, 내 코드(픽셀 루프, cv::Mat 접근, 컨테이너 조작)는 Debug 에서 최적화가 꺼져 수 배 느리다. 08b 의 8400행 후처리 루프처럼 내 코드 비중이 큰 노드일수록 차이가 크다. "C++ 인데 Python 보다 느리다"면 먼저 빌드 타입을 본다.
4. 이 노드는 큐 깊이 5 로 구독해도 되는데 08b 의 검출기는 왜 1 이어야 하는가?
큐는 "처리 못 한 프레임을 몇 장 쌓아 둘 것인가"다. 처리(수 ms)가 프레임 간격(33 ms)보다 빠르면 큐는 비어 있어 깊이가 무의미하다. 검출기는 처리(수백 ms)가 훨씬 느려서 큐가 항상 차고, 그러면 항상 큐 길이만큼 옛 프레임을 처리하게 된다. 깊이 1 이면 밀린 프레임은 버려지고 최신 것만 본다.
5. image_transport::ImageTransport 클래스를 노드 생성자 안에서 쓰면 왜 실패하는가?
그 클래스는 rclcpp::Node::SharedPtr 를 요구하는데, 생성자가 실행되는 동안에는 std::make_shared 가 아직 끝나지 않아 이 노드를 가리키는 shared_ptr 가 존재하지 않는다. shared_from_this() 는 bad_weak_ptr 를 던진다. raw 포인터 this 를 받는 자유 함수 image_transport::create_subscription / create_publisher 를 쓰면 된다.
6. 박스를 그리는 일을 검출기 안에 넣지 않고 detection_overlay 라는 별도 노드로 둔 이유는?
검출기의 책임은 /detections 를 내는 것뿐이어야 한다. 그리기를 분리하면 ① 08c 에서 검출기를 Hailo 판으로 바꿔 끼워도 overlay 는 그대로 동작하고, ② 운용 중에는 overlay 를 아예 안 띄워 CPU 를 아끼며, ③ 10 단계의 감독 노드처럼 /detections 만 필요한 소비자가 영상 없이 구독할 수 있다. 03 단계의 "느슨한 결합"이다.
7. cv::Mat out = work; 뒤에 cv::rectangle(out, …) 을 하면 work 는 어떻게 되는가?
work 도 같이 바뀐다. = 는 헤더만 복사하고 픽셀 버퍼는 공유하기 때문이다. 원본을 보존하려면 out = work.clone() 이 필요하고, contours 모드가 그렇게 되어 있다. passthrough 처럼 그리지 않는 경로에서는 공유가 오히려 원하는 동작(복사 없음)이다.
